## 3. 但线上冠军被规则修正打坏了（这是本轮唯一要紧的事）

同一条命令（`tools/eval-5p.mjs 20 5 77000`，我上午跑过）：

| 引擎 | 线上冠军 1st |
|---|---|
| v1.4.6（今天上午） | **38.0%** |
| v1.5.5（现在） | **15.0%**（top2 53.3% → 44.1%） |

权重一个字节没动（md5 一致），改的是**全息屏障的语义**（v1.5.4 `target: self → other`）。因果已隔离：

| 场/模式 | 基线 | **拿掉全息屏障** | 它的使用率 |
|---|---|---|---|
| multi/A | 5.9% | **19.9%**（Δ +14.0） | 6.6% |
| multi/E | 25.6% | **50.3%**（Δ +24.7） | 11.0% |
| long/A | 8.7% | 18.3%（Δ +9.7） | 3.6% |
| long/E | 12.0% | 33.0%（Δ +21.0） | 9.6% |

（"拿掉"后的 19.9% ≈ 我上午在同一场同一批种子测到的 19.7% ⇒ 缺口全部来自这一张卡。）

两点教训值得写进他们的约定：
1. v1.5.4 §3 的依据是"9 个冠军对全息屏障使用率全是 0.0%"—— 那是**技能报告自己的口径**（富经济 + 单场）下的读数；
   换原生经济场测，使用率是 3.6~11.0%。**"某卡无实战影响"必须由训练口径的 A/B 判，不能由报告判。**
2. **改卡的语义 = 改所有已训练产物的输入分布**。这张卡此前是"1 费自保"，网络把它当自保选；
   现在它给别人套盾 ⇒ 冠军不仅白选一招，还**更频繁地选**（状态分布被移动）。
   ⇒ 建议加一条守门：**`rules.js` 里 `target`/`pierce`/`cost` 任一变更 ⇒ 必须重跑一次线上冠军考卷**，
   并把"修前/修后"两个数一起写进 CHANGELOG；否则"patch 级修正"会静默改掉交付质量。
3. **眼下就有更好的在库产物**：long-33 同场 45.3%。要么换线上冠军，要么明确"线上仍是 3 血族、长程挂长程冠军"。

- **反弹三行脚本在 5 血下比 3 血更强**（我上午：long/A 63.7%、long/E 100%；今天复现 62.8% / 100.0%），
  而**8 个冠军没有一个打得过它**。⇒ "风格化"的第一因不是网络窄，
  而是**这张 0 ジ 卡在长程模式里就是全局最优**（不出手 + 别人互相反弹致死 + 到点比血量）。
- **反弹墙的洞在部分 seed 上已经自己好了**：4 座纯反弹墙，线上/long-33/sty-31 = **100%**，
  而 long-31/32/34 = 16.0%（= 谁都不打时的并列地板）、long-36 24.0%、**long-35 0.0%**。
  ⇒ 这是**双峰**，不是"弱杠杆"：有的 seed 见没见过这个对手，决定了它会不会反制。
  他们 v1.5.2 的"加 4 个风格冠军当陪练没用"不能推广成"池子是弱杠杆"——
  **池子里现在仍然没有单一防御 specialists**（`BOT_FN_N` 里查不到 reflectspam/guardspam/baguaspam）。
- 我上午提的 `G/H/I/J` 四类墙仍在：`defend/wall` 是混合防御，不等于 0 ジ 纯反弹。

## 5. 建议的下一步（按性价比）

1. **立刻**：线上多人冠军要么换成在库最强（long-33 同场 45.3%），要么重训一个 3 血冠军 ——
   现在挂着的是被语义修正打坏的产物，且 meta 里仍写着 `firstRate:0.3764`（**产物自带的成绩已经不成立**）。
2. **守门**：规则语义变更 ⇒ 强制重测线上冠军考卷（np-test 里加一条"跑一遍 eval-5p 并比对存档数字"太慢，
   可以在 `meta` 里记 `examScoreAtBuild` + `rulesFingerprint`，页面/工具发现指纹不匹配就报"成绩已过期"）。
   这条能一次性解决"产物与引擎版本错配"这一整类问题（他们踩过 v1.3.24 的包版本、今天是语义版本）。
3. **反制洞**：往 `BOT_FN_N` + 训练池加 `reflectspam / guardspam / protowall`（3~4 行），
   用他们现成的配对 A/B 机制跑臂。验收判据就用今天的表：**4 座反弹墙从 16% → ≥50%**，
   同时标准考卷不掉分。**这比再调 fit/权重更可能有用**，因为双峰说明缺的是"见过"，不是"选不出"。
4. **深经济的验收口径**：别再报 max ep（long-34 的 284 是囤积不是强度），改报
   **cost≥3 的落地伤害/局** 与 **哨声前 HP 领先占比**（后者能量出"赢"还是"熬")。
5. 上午提的两条仍未动：`rules.js:40` 蓄能 desc 仍写"可累加"（与 R9' 矛盾，且就是 UI 悬停文本）；
   `resolve.js` 双枪第二发我这次没复查（v1.5 改过 resolve，可能已顺手动过，需要的话我再测）。
