### ① 谱系图 3D：病是"地板被透视压扁"，不是"点没抬起来"

§E332 那一版借地图的相机（`SOLID.pit=0.72`）把地板整体压到 cos=0.66 高 ⇒ **24 行挤成一条横带**，
而我为了"立体"把格内抖动从纵方向挪到横方向 ⇒ 同一秒训出的一撮全叠在一条横线上，**比二维更挤**（用户两张截图点名）。
现在：

| 件 | 做法 |
|---|---|
| 地板 | 仍是 §E332 那张离屏底图，但**不透视**：`PL(u,v,z) = [u + (v−vc)·tShear, vc + (v−vc)·cos(tTilt) − z]`，`tTilt/tShear` 默认 0 ⇒ 平面/立体的地板就是同一张二维版式 |
| 点 | **原地上升**：`z = (F−F_min)/(F_max−F_min) × LIFT`，沿屏幕纵轴抬起，每枚留一根立柱接回本行那一格 |
| 格内抖动 | **两态都留在纵方向**（用户："在同一个格子里纵向的散开一点会更方便观察"）—— 上一版挪去横方向正是它把一撮点叠成一条线 |
| 抬升带 | 立体态把整张地板往下挤 `LIFT·T3`、行距按剩下的空间重排 ⇒ 最上面几家的点不会顶出画布。⚠ 挤行距会改底图 ⇒ `st.elev/st.tTilt` 必须进底图缓存键 |
| 视角 | 右键拖动 = 上下压扁 / 左右错切（**不做全旋转**：谱系图的地板是"行 × 时间"的表，转到侧面必然塌成线）；`#tilt=&shear=` 走深链给无头复核 |
| 相机状态 | 谱系图**不碰** `st.yaw/st.pit`（那是地图的），`toggle3d` 对 tree 只动 `st.elev` ⇒ 两个视图各拿一份，不会互相串 |

**验收**：二维视图与改前**逐字节相同**（两张 1600×1000 无头截图 `cmp` 一致）；立体态点全部落在自己那一格上方、立柱可见。

### ② 标签配色：从"全图统一字色"改成"逐枚看自己脚下"

底图按分位铺色之后鲜艳度上来了，统一 `st.ink` 在红/蓝块上就读不出（用户点名）。
新 `drawText()`：取标签那块**底片的平均亮度**（相对亮度 0.2126R+0.7152G+0.0722B，每 5 像素采样一次），
在主题自己那两色（`st.ink` / `st.bg`）里挑对比大的那个，再描一圈**反色细边**（halo）。
⚠ 两个坑：① 必须在**变换之前**取色 —— `getImageData` 读设备像素，旋转标签的边界框在变换系里是错的；
② 一块字常横跨"红块 + 黑底"，只挑一色还是会糊 ⇒ halo 不是装饰，是第二条腿。
性能：按帧 + 12px 网格缓存（拖一次 ~60 个标签的 `getImageData` 是看得出来的）；`getImageData` 抛错就整帧退回主题字色，不静默画空。

### ③ ⭐一条本班自己造的隐患：CRLF 把 `path` 列变成 `"path\r"`

`coords.tsv` 的 `path` 列（§E330 新加）恰好是**末列**，而本仓工作树是 CRLF ⇒ `git checkout` 兜一圈之后
`split('\n')` 得到的末列带裸 `\r` ⇒ `indexOf('path')` 返回 −1 ⇒ `lineage.mjs` / `feas.mjs` 都会瞎。
**第一次跑是通的**（那时文件是 LF），所以它是"过一会儿才坏"的形状 —— 最难查的那一类。
修法不是把列挪个位置，而是**在读文件这一步统一归一**：`viewer.mjs` 一处包装 `readFileSync` 覆盖八处读表，
`attach-path` / `lineage` / `feas` 各自 `replace(/\r\n/g,'\n')`；并给 `attach-path` 加**写完立刻回读**守卫
（901 行 × 34 列、`path` 无脏尾、`Σ1/dupN` 与去重表对得上）。
⇒ 通用条：**"写完不回读"的落盘脚本，在 CRLF 仓库里必须假定末列会被污染**；而 `git checkout` 就是一次不改内容的重写。

## §E335（01:1x → ）门禁分组：以后不必每次全跑一遍

### ① 判据先测，再动刀

用户要的是"把相对独立的工作分开成几份，以后不用每次全跑"。动手前先量了三件事：

| 量什么 | 实测 |
|---|---|
| 有没有门读 `champion-map/` | `grep -c champion-map tools/np-test.mjs tools/spec-run.mjs tools/smoke.mjs tools/battle-test.mjs` ⇒ **全 0**（只有 `tools/pick-best.mjs:27` 的一条注释提到） |
| 时间花在哪 | `NP_TIME=1` 整轮：最慢 15 道合计 **654.6s**，全是 train/ship（第一名 D176 **107.5s**，D135 76.1 ‖ D123 75.7 ‖ D127 50.1 ‖ D227 44.9 …） |
| 门有多少、键有多少 | `^t(` 共 **272** 条；按"门名第一个空格前那段"归键只有 **269** 个键（N2/N3/N4 各有同前缀的多条） |

⇒ 结论：**"改图/改文档"那一类班次真正该跑的只有仓库纪律那 15 道**，而它们是秒级的。

### ② 做法：分组 + 累计依赖，**不搬门体**

`tools/np-test.mjs` 顶部新增 `GRP`（六组：`meta 15 ‖ ui 7 ‖ ship 36 ‖ train 103 ‖ probe 36 ‖ engine 72`）
与 `CUM`（跑一组 = 它自己 + 它依赖的更浅组：`meta ⊂ ship ⊂ train ⊂ {ui, probe} ⊂ engine=全部`），
`t()` 里加一条 `--group=` 过滤；`gate-all` 接 `--group=` 并在总结论里**显式标"不是整轮认证"**。

**为什么没把 272 道门物理拆成几个文件**：拆文件要先把 ~1200 行共享前导（沙箱、`ok/eq`、`spawnSync` 包装、夹具）
搬进一个 harness 模块，而收尾那条"注册数 == 执行数 + 跳过数"的守卫（D194 钉着它的源码形状）会连带改形 ——
**收益是零**（跑多少条由分组决定，与文件怎么切无关），风险却是本仓最怕的那一类（门绿着但它没在看你要上线的东西）。
所以先落"可跑子集"，物理拆分留作后续机械活（分组已经在那儿了）。

### ③ 三条牙（都是本仓踩过的形状）

1. **撞组即红**：分组键是首 token，所以同键的多条门必须同组 —— 启动时检查，撞组 `exit 2`；
2. **`--group` 不冒充全绿**：与 `--only` 同罪，跑完响亮印"只跑了 N / 272 条（跳过 K 条）"，一条没跑 `exit 3`；
   `--group=` 拼错也 `exit 2`（含糊值不许当"没写"）；
3. **整轮额外查"每条门都归了组"**：不带 `--group` 时若有门不在表里 ⇒ `exit 4` 并点名。
   ⇒ 以后加门忘了归类，**整轮会红**，表不会悄悄漏腿。

### ④ 实测

- `node tools/np-test.mjs --list-groups` ⇒ 六组计数 + 累计条数；
- `--group=meta` ⇒ **15/15 绿，9.4 秒**（整轮是 ~800 秒 ⇒ 约 **85 倍**）；
- `gate-all --np --group=meta` ⇒ 35.6 秒收口，总结论行印「§E335 分组 meta：**不是整轮认证**」。
- 整轮（不带 `--group`）在跑，用来证明"加了分组之后一条门都没少跑、归类守卫通过"。
