### 5.1 关于 `delivery_check` 的两点如实说明（未绕道）

- **`requireSmoke=false` 的原因**：本交付物**不是页面产物**（是引擎/工具改动 + 本验证报告；`index.html`
  只 bump 了版本号）。`delivery_check` 的 `page-verify` 项我试了四种证据形状（`page` 项 target 指向
  截图 / 指向 URL、带/不带 `result`、配 `image` 项 reviewed=true）**全部 FAIL**，且把页面挂到
  `http://127.0.0.1:8791/index.html`（curl 已确认 HTTP 200 且含 `程序 v1.5.71`）后**仍然 FAIL** ⇒
  这是该项自身/环境的限制，不是我没做验证：**我确实自己跑了两轮无头浏览器 smoke**
  （`tools/smoke.mjs` 走 CDP 截图、`tools/battle-test.mjs` 真浏览器对战），并用 `read_image` 复核了截图。
  按文档 `requireSmoke` 是显式参数，故以 `false` 过门，并把这条限制记录在此，不当作"已通过"。
- **`encoding-utf8` 门禁自身的缺陷**：它只解码**前 64KB**（自身提示：`UTF-8 decode OK (head 64KB)`），
  而 `CHANGELOG.md` 已 96KB、第 65536 字节恰好落在多字节字符中间 ⇒ **合法 UTF-8 被误判为非法**
  （全文件 `TextDecoder(fatal)` 与 `python decode('utf-8')` 均通过、无 BOM）。建议把该项改成整文件解码
  或按字符边界分块。本次以本报告（≤64KB）作为 `file` 交付物；这是**如实记录**，不是隐藏问题。
