# Epirus 多人（N 人）规则裁定清单 — v0.2（已实现）

> 目标：把 2 人引擎推广到 **3~5 人**（引擎按 N 人写，理论上限只受性能限制）。
> 约定同 `RULES-2P.md`：**先定文档，再改代码**；每条裁定编号 `N1..N13`，代码注释逐条对应。
> 与 2 人规则冲突时，以本文为准（本文只写"多人特有"的部分，未提及者沿用 `RULES-2P.md`）。

## N1 范围与模式

- 支持 N = 3 / 4 / 5；`state.p` 为长度 N 的数组，`state.actions` 长度 N，`state.n` = N。
- 模式：`multi`（全技能，**血量一律 3**，与标准模式一致；原草案"4~5 人 4 血"未采用——先保证可玩与回归一致）。
- 多人专用技能：**双枪射手**在 N≥3 时启用；**镜面反射**本版未实现（见 N11）。
- `createState(modeKey, rng, n)` 的 `n` 省略或非法时 = 2，完全保留 1.0 行为。

## N2 回合结构与结算顺序

- 所有人**同时**选一个技能 + 目标（自指技能无目标）。
- 结算按优先级 5→4→3→2→1；同优先级内按**座位号（pid）升序**（除小雷链外不影响结果，仅影响日志顺序）。
- 回合末统一判定死亡、挑衅义务、符咒老化、禁用递减（沿用 2 人流程）。

## N3 目标

- 攻击 / 负面技能**必须**指定目标；架势 / 自增益技能无目标。
- 目标解析（`EpirusState.resolveTarget`）：2 人 = 另一个玩家；N 人 = `opt.target`，非法（自己 / 已死 / 不存在）时退化为**第一个存活对手**。
- **死者不可被指定为目标**；目标在本回合中途死亡时，尚未结算的攻击对其**落空**（不转移）。
- **双枪射手**：指定**两个不同**目标（`opt.target` / `opt.target2`），按枪的口径各结算 1 点（可被反弹 / 触发地雷）。

## N4 同优先级相抵（pairwise）

- 仅当 A 的攻击与 B 的攻击**同优先级**时二者相抵；高优先级阻止低优先级。
- 实现为**两两结算**（`clashPass` 对所有攻击类行动做 O(k²) 配对），已被作废的行动不再参与后续配对。
- 环（A→B→C→A）按**逐边 pairwise** 处理：只有互为目标的边相抵；**不**做"整环全部无效化"。
- 2 人时退化为原来的单对逻辑（回归不变）。

## N5 小雷（雷击之枪）

- 对目标：无效化其本回合的**攻击类**行动（不阻止防御 / 架势）。
- 互为目标 → 双方该行动均无效（与 2 人一致）。
- 三人环 A→B→C→A：按 **pid 升序逐条结算**——A 的小雷先作废 B，B 的行动被作废后不再结算，C 的小雷再作废 A（结果：A、B 作废，C 成立）。
- 若只有 A→B 而 B 未对 A 用小雷，则只有 B 的行动被无效化。

## N6 大雷（真正的落雷）

- 对目标 2 电伤；目标本回合**正在使用的那个技能**被禁用（基数 4 回合，同 2 人）。
- 目标当回合使用防御类 → 2 电全挡。
- **不产生连带伤害**：只有"双方互为目标且都用大雷"（`bothBig` 的 N 人推广：目标的大雷也指向自己）时互不无效化。

## N7 防御矩阵

- 防御 / 反弹 / 八卦阵 / 金刚盾 / 原型制御 / 藤甲 / 全息屏障 等按"**施法者→目标**"逐对结算，规则与 2 人一致。
- 反弹类（反弹 / 藤甲）：把指向自己的伤害弹回**该**施法者；同回合被多人攻击 → 逐个弹回。

## N8 未实现：聚光炮

- 技能表中不存在该技能；草案中的"蓄力→全体 2 光伤"留待后续（需要新的蓄力状态字段）。

## N9 铁索连环

- 多人下链条是**图**（两两相连的边）：`p.chains` 为 pid 数组（2 人时长度为 1）。
- 触发：同回合**互相**使用摄魂指法的一对玩家之间建立连边。
- 任一连环者受伤害时，**与它直接相连**的其他玩家各受同量同类型伤害（**不递归**，即连环伤害不再触发下一跳）。
- 一方确认死亡（无回魂）时，把该 pid 从所有玩家的 `chains` 中移除。

## N10 挑衅

- 挑衅指定目标（被挑衅者）；被挑衅者下回合必须使用攻击类技能（`TAUNT_SATISFY`），否则回合末 -1 HP。
- 多人下可同时作用于多个目标（各自独立结算义务）。

## N11 未实现项

- **镜面反射**：语义为"复制作用者的技能对另一个目标使用"，涉及行动重放，留待后续（`multi` 模式已排除，UI 标注"未实现"）。
- **聚光炮**：技能不存在（见 N8）。
- **合二为一**：涉及共享血量 / 共享行动 / 胜负判定耦合，留待后续。
- **反复横跳**：需要重做"目标锁定时机"，留待后续。

## N12 死亡与胜负

- 回合结算完毕后统一判定死亡（沿用 2 人流程）。
- **最后一名存活者获胜**；若同回合全员死亡 → 平局。
- 回合上限 60：**剩余 HP 最高者获胜**；并列最高 → 平局（`checkOver`）。
- 死亡者：不再行动、不可被指定为目标、其架势 / 连环 / 蓄能珠立即失效。
- 回魂 / 梦魇 等隐藏技能在多人下沿用：回魂在"本回合死亡且曾挑衅"时触发，复活后仍参与胜负判定。
- UI：人类玩家被淘汰后自动"观战到底"（AI 自行打完剩余回合），不再要求出招。

## N13 训练（多人）— 未开始

- 对手池：N-1 个脚本对手（沿用 2 人池的机器人）。
- 适应度按**名次**：第 1 名 1.0、第 2 名 0.6、其余 0.2；全员存活到回合上限时按剩余 HP 排名。
- 冠军择优仍要求"对每个基准的平均名次"过门槛。
- 现状：`js/train/*` 与冠军权重仍是 2 人口径（`policy.js` 的特征只读 `1-pid` 的那个对手）；多人局用脚本 AI（简单=随机 / 中等=balanced / 困难=自适应）。
