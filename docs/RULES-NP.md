### N24 长程模式（5 血）+ 摄魂指法门槛按模式配——用户裁定 2026-09-12

**背景**：用户提出「线下玩会通过多人混乱的场面实现平衡，但程序里面显示得太明显」，
建议做一个 **5 血长程模式**；并指出若做 5 血，应把**摄魂指法**（`SK.DRAIN`）的启用血量
从写死的 HP≤1 调到 **2 或 3**，且要求实测平衡影响。

**裁定**：
1. 新增 `long` 模式：**hp=5、3-5 人、maxRounds=100、drainHpMax=3**。
   `standard` / `multi` 口径**一律不变**（摄魂仍 HP≤1、上限仍 60）。
2. 摄魂门槛改为**按模式可配**（`state.mode.drainHpMax`，缺省 1 ⇒ R25 原口径保留）。
3. 回合上限也必须按模式配（见下），否则 5 血局会被 60 截断。

**为什么长程模式必须同时放大回合上限**：实测（1400 局/臂）3 血平均 **43.3 回合**、
5 血只有 **49.8 回合**（+15% 而非 +67%），且 5 血时主体**场均承伤只有 4.28 < 5**
⇒ 不是被打死，而是到上限按"血最多者胜"结束。配 `maxRounds:100` 后 5 血为
**72.3 回合 = 43.3 × 5/3**，与血量成正比。策略特征 `round/MAX_ROUNDS` 的分母同步改读本局上限
（否则 5 血下该特征超出训练时的 [0,1] 分布）。

**平衡实测（1400 局/臂；3 血基线 冠军 1st 38.4%、5 血基线 32.6%）**：

| 模式 | 摄魂门槛 | 注入率 | 1st | Δ |
|---|---|---|---|---|
| 3 血 | HP≤1（R25） | 0.3% | 39.5% | +1.1pt |
| 5 血 | HP≤1 | 0.3% | 34.4% | **+1.8pt** |
| 5 血 | HP≤2 | 1.2% | 32.3% | −0.3pt |
| 5 血 | HP≤3 | 2.4% | 29.5% | **−3.1pt** |

**"HP≤1"的机会率在 3 血/5 血完全相同（0.3%）** ⇒ 那扇窗并没有相对变窄。
摄魂指法费用 3 ジ、收益 1 伤 + 1 自愈，**只在绝境里划算**；放宽门槛只是增加"做亏本买卖"的机会。
**结论：门槛对平衡是负向的，唯一有效旋钮是费用。**

**轨迹类卡的三类瓶颈（同一实验的副产品，必须分开看）**：

| 卡 | 3 血 Δ | 5 血 Δ | 瓶颈 |
|---|---|---|---|
| 地雷（3 ジ） | −1.3pt | **+4.0pt** | 攒钱耗时 ⇒ **5 血可解冻** |
| 坦克（2 ジ） | +3.7pt | +0.4pt | — |
| 转移伤害（2 ジ） | −30.8pt | −28.1pt | **反应型**：需同回合承伤 N≥2，与赛程长度无关 |
| 贴贴×天火（叠 3） | 引爆 0 次 | **引爆 0 次** | **组合型**：符咒 `age≤3` vs 1 ジ/回合的铺符速率 |

### N23 激光眼单发即可失效整个防御族——用户裁定 2026-09-11

**背景**：激光眼是同费的"防御类专用反制"，但原实现要求**两个激光眼**才能破
原型制御/全息（`resolve.js` 里 `ta.key !== SK.PROTO && ta.key !== SK.HOLO` 的例外，
否则落到 `laserNoEffect`）。用户认为"**单个激光眼还打不破原型制御有点拉了**"。

**裁定**：**单个激光眼即可失效所有防御类技能 + 转移伤害。**

**实现**：去掉 `SK.PROTO` / `SK.HOLO` 例外 ⇒ 只留 `R.GUARD_FAMILY.indexOf(ta.key) >= 0`
一个分支；`laserNoEffect` 路径成为死代码（已确认全局无其它引用）。
`rules.js` 的 desc 同步为"无效化目标**任意**防御类(含原型制御/全息)/转移伤害"。

**同时确认（用户纠正）**：**小雷无法失效最基础的防御、反弹和原型制御** ——
这与现有实现一致（`rules.js` 的 desc 本就写着"防御/反弹/原型制御豁免"），**无需改动**。

**用例**：`N23`（单个激光眼打原型制御 → 不出现 `laserNoEffect`）；反证已验（恢复例外则失败）。

### N22 大雷（真正的落雷）的"效果传导"——用户裁定 2026-09-11

**核心机制**：大雷 pri=4，**高于**转移伤害(1)/枪(2)/ジ 等一切非防御动作
⇒ 大雷先结算，其"失效"作用于一**组**角色（**不是全场**）。

**受影响集合（"单次传导"，只传一层，不再链式扩散）**，设大雷目标为 T：
1. **T 本人**；
2. 若 **T 本回合声明了转移伤害**，则其**转移对象**；
3. **本回合攻击 T 的人**（因为那次攻击本会被转移，而转移已失效 ⇒ 该攻击本身也失效）。

**与 T 无交互的人完全不受影响。**

**用户给的判定例子**（a,b,c,d 四人）：
- a 对 b 用**大雷**；b 对 c 用**转移伤害**；c 只用**ジ**；d 对 b 用**枪**
- 结果：
  1. **b、c、d 三人都受 2 点伤害**（a 不受）
  2. **c 的ジ 与 d 的枪也无效** —— **c 因此不能 +ep**
  3. **b 的转移伤害 与 d 的枪被禁用 3 回合**
- **反例（用户补充）**：若 d 的枪打的是 **c 或 a**（不是 T=b），则 d 完全正常
  ⇒ 证明受影响集合**不是全场**，而是上面那三条。

**由此可推**：
- 大雷的伤害**无法被转移出去**（转移伤害已被失效）；
- **其他人对"正在使用转移伤害的人"的攻击也无法被转移**——转移已失效；
- 更进一步：**那个攻击本身被大雷失效，所以也不产生伤害**。

**实现要点（待改）**：
- `resolve.js` 的大雷层目前只对**目标**做 `setVoid`，**没有传导集合**；
- 伤害只投递给**目标**，**没有 AoE**；
- 大雷伤害投递为 `pierce:{reflect:true}`、**需补 `pierce.transfer:true`**（用户已确认大雷不可被转移）；
- **"沿转移伤害传导"这条语义在代码中无对应实现**。

**用户补充裁定（2026-09-11）**：
1. **ジ 不进 3 回合禁用**（已确认）——但**本回合仍失效、不给 ep**。
2. **防御族可以防住大雷**（但**都防不住小雷**）。
3. **八卦阵照常判定**（走它原有的概率判定，不因大雷而特判）。
4. **金刚盾与藤甲"会参加传导伤害的情况"**。

**第 2/4 条的完整口径（用户 2026-09-11 最终澄清）**：
- **所有防御类理论上都可以挡住大雷**（但**都防不住小雷**）——防御者本人**不吃那 2 点伤害**。
- **八卦阵照常判定**（走原有概率，不因大雷特判）。
- **金刚盾与藤甲的特殊性在于"它们有作用目标"**：
  - `金刚盾` 的作用目标是**判定攻击**；
  - `藤甲` 的作用目标是**上火弱**；
  ⇒ **使用防御的本人不受伤害，但那个作用目标会吃到传导伤害**。

**⇒ 由此得到一条统一口径**：受影响集合里的成员若用**有目标的技能**，
传导伤害会**落到该技能声明的目标上**（而不是防御者本人）。

**⚠️ 与当前实现的一处冲突（待改）**：
大雷伤害目前投递为 `pierce: { reflect: true }` ⇒ **反弹类态势被穿透**。
但按本轮裁定"**所有防御类都可以挡住大雷**"，`pierce.reflect` 应当**去掉或收窄**
（只在"是否触发反弹反击"的意义上生效，不该影响**格挡**）。
**实现前需要确认这一点**：大雷到底是"反弹可以格挡、但不触发反弹反击"，还是"反弹也不能格挡"。

### N20 地雷（多人 AoE 口径）—— 用户裁定 2026-09-11

**背景**：`resolve.js` 的 `mineChain` 一直是 2 人时代的实现——**只让"攻击者"受 1 点火伤**，
`rules.js` 的 desc 也是同一口径。但 2 人局里「全场其他角色」与「攻击者」**恰好是同一人**，
所以两种读法**在 2 人下无法区分**，multi 框架加入时未回头核对 ⇒ 该偏差**只在 N≥3 显形**。

**正确规则（用户裁定）**：

1. **直接触发**：地雷持有者被**非狙击枪**的技能攻击 → **全场其他存活角色各受 1 点火焰伤害**。
   持有者自己被攻击的伤害照常结算；地雷这一波**直接触发没有次数上限**。
2. **间接触发**：某角色因**吃到地雷伤害**而触发自己已装的地雷 → 属于间接触发。
   - 同一波里所有间接触发**合并为 1 次伤害**；
   - 这一次伤害**不打influence地雷持有者**（即"所有间接触发的地雷使用者不受到这一次伤害"）。
3. **计数例子（3 人全装雷，其中 1 个被直接攻击）**：总伤害事件 = **2 次**
   （1 次直接 + 1 次间接）；3 个持雷者各受 **1** 点；非持雷者受 **2** 点。
   **2 个雷被直接攻击** → 总伤害事件 = **3 次**（2 直接 + 1 合并间接）。
4. **狙击枪**：狙击枪对持雷者的攻击**不触发**该雷；
   但**其他攻击（含地雷伤害本身）仍会触发**——即豁免只针对"狙击枪那一次攻击"。
5. **火弱（藤甲 debuff）**：火弱是挂在**被攻击者**身上的 debuff；
   地雷造成的伤害**仅对挂了该 debuff 的角色 +1**（逐目标各自计算）。
6. **无来源**：**地雷造成的伤害没有来源**（`source = null`）⇒ 不会被铁索连环共享、
   不会被转移伤害转移、**不会被大雷传导**。

**实现要点（待做）**：
- `resolve.js: mineChain` 重写为 AoE + 直接/间接两态；
- `damage` 事件的 `source` 记为 `null`（v1.3.19 刚给事件补的 `source` 字段正好用于此）；
- `rules.js:71` 的 desc 同步改为 AoE 口径；
- **必须补 N≥3 的 spec 用例**（2 人用例天然测不出差异，这正是它长期漏掉的原因）：
  3 人全装雷 / 2 雷被直接攻击 / 狙击枪豁免只针对那一次 / 火弱逐目标 / 无来源不被铁索共享。

## N1 范围与模式

- 支持 N = 3 / 4 / 5；`state.p` 为长度 N 的数组，`state.actions` 长度 N，`state.n` = N。
- 模式：`multi`（全技能，**血量 3**，与标准模式一致；原草案"4~5 人 4 血"未采用——先保证可玩与回归一致）
  ＋ **v1.4.0 起新增 `long` 长程模式（3-5 人 · 5 血 · `maxRounds=100` · 摄魂门槛 `drainHpMax=3`）**，见 N24。

- `createState(modeKey, rng, n)` 的 `n` 省略或非法时 = 2，完全保留 1.0 行为。

## N2 回合结构与结算顺序

- 所有人**同时**选一个技能 + 目标（自指技能无目标）。
- 结算按优先级 5→4→3→2→1。
- **同优先级 = 同时结算**（2026-09-10 修正）：层入口对全场行动拍**快照**，层内一律按快照判定，
  最后统一落地 void 与伤害。此前写的是"同优先级内按座位号（pid）升序，除小雷链外不影响结果"——
  **这是错的，影响极大**：先结算者会把后者作废，低 pid 在"同归"局面里系统性免伤。
  实测三方互放大雷（P0→P1 / P1→P2 / P2→P0）旧口径得到 HP 3/1/1（P0 毫发无伤），修正后三人各吃
  直击 2 + 连带 2 = 全灭；3× 同一策略（破防脚本）的座位 1st 率由 **73.5 / 14.5 / 0.0** 变为
  **32.9 / 31.5 / 35.7**（`tools/seat-diag.mjs`，200 局）。回归见 `tools/np-test.mjs`
  "N2 同优先级同时结算" 与 "N2 座位偏置" 两条。
- 2 人局保持恒等（升序）顺序：成对相抵本质对称，且 v1.0 已冻结 → 行为不变（spec 36/36）。
- 回合末统一判定死亡、挑衅义务、符咒老化、禁用递减（沿用 2 人流程）。

## N3 目标

- 攻击 / 负面技能**必须**指定目标；架势 / 自增益技能无目标。
- 目标解析（`EpirusState.resolveTarget`）：2 人 = 另一个玩家；N 人 = `opt.target`，非法（自己 / 已死 / 不存在）时退化为**第一个存活对手**。
- **死者不可被指定为目标**；目标在本回合中途死亡时，尚未结算的攻击对其**落空**（不转移）。
- **双枪射手**：指定**两个不同**目标（`opt.target` / `opt.target2`），按枪的口径各结算 1 点（可被反弹 / 触发地雷）。

## N4 同优先级相抵（pairwise）

- **仅当两次攻击「互为目标」（A→B 且 B→A）且同优先级时，二者相抵**（都不生效）。
- 同理，**高优先级阻止低优先级也只在互为目标时成立**。
- ⚠️ 2026-09-09 修正：初版实现只比优先级、**完全没看目标**，导致"两家同时打第三人"会互相抵消
  （对局记录里 P2/P3 同时枪击玩家1 → 双方攻击相抵、玩家1 毫发无伤）。已按本文档口径修复。
- 因此：**两家同时打同一第三人 → 两击都落地**；高优先级打别人不会顺带作废第三方对同一目标的攻击。
- 2 人时"互为目标"天然成立 → 行为与 v1.0 完全一致（回归 36/36）。
- 环（A→B→C→A）按**逐边 pairwise** 处理，不做"整环无效化"。

## N5 小雷（雷击之枪）

- 对目标：无效化其本回合的**攻击类**行动（不阻止防御 / 架势）。
- 互为目标 → 双方该行动均无效（与 2 人一致）。
- 三人环 A→B→C→A：按 **pid 升序逐条结算**——A 的小雷先作废 B，B 的行动被作废后不再结算，C 的小雷再作废 A（结果：A、B 作废，C 成立）。
- 若只有 A→B 而 B 未对 A 用小雷，则只有 B 的行动被无效化。

## N6 大雷（真正的落雷）

- 对目标 2 电伤；目标本回合**正在使用的那个技能**被禁用（基数 4 回合，同 2 人）；非防御类技能无效化。
- 目标当回合使用防御类 → 2 电全挡。
- **连带伤害（原文效果 3，2026-09-09 补实现；2026-09-10 对齐代码口径）**：
  若与目标 T 本回合发生交互，则该第三方也吃连带，**与直击同口径**：
  - **对 T 使用技能者** → 受 **2 点电伤** + 该技能**被无效化** + **禁用 3 回合**；
  - **被 T 使用技能者** → 受 **2 点电伤** + 其行动**同样被作废**（代码现状）；
  - **施法者自身不参与连带**（否则等于自伤）；已死/无关者不参与。
  - 本段旧文案写的是"各受 **1 点**"，与代码不符（`js/core/resolve.js` 大雷层用
    `amt: 2` 且注释即写"同样 2 点电伤 + 行动作废 + 禁用 3 回合"）。**按用户裁定以代码为准**
    （大雷 5 ジ 的费用与强度不动，连带维持 2 点）。
  - ⚠️ 已知遗留：原文效果 3 对"被 T 使用技能者"是否也该作废其行动，语义上可争议
    （该第三方并未对 T 动手）。当前代码对两种情形一律作废，本表如实记录；若要改为"不作废"，
    需同时重估大雷强度。
  - 连带伤害走 `deliverDamage`（`pierce.reflect`，与直击同口径：雷电不被反弹，防御/金刚盾/原型制御可挡）。
  - 2 人时不存在第三方 → 行为与 v1.0 一致。
- 双方互为目标且都用大雷（`bothBig`）时互不无效化。

## N7 防御矩阵

- 防御 / 反弹 / 八卦阵 / 金刚盾 / 原型制御 / 藤甲 / 全息屏障 等按"**施法者→目标**"逐对结算，规则与 2 人一致。
- 反弹类（反弹 / 藤甲）：把指向自己的伤害弹回**该**施法者；同回合被多人攻击 → 逐个弹回。

## N9 铁索连环

- 多人下链条是**图**（两两相连的边）：`p.chains` 为 pid 数组（2 人时长度为 1）。
- 触发：同回合**互相**使用摄魂指法的一对玩家之间建立连边。
- 任一连环者受伤害时，**与它直接相连**的其他玩家各受同量同类型伤害（**不递归**，即连环伤害不再触发下一跳）。
- 一方确认死亡（无回魂）时，把该 pid 从所有玩家的 `chains` 中移除。

## N10 挑衅

- 挑衅指定目标（被挑衅者）；被挑衅者下回合必须使用攻击类技能（`TAUNT_SATISFY`），否则回合末 -1 HP。
- 多人下可同时作用于多个目标（各自独立结算义务）。

## N11 未实现项

- 本版 3~5 人的**可选技能与隐藏技能已全部实现**：镜面反射（N14）、反复横跳（N15）、聚光炮（N16）、合二为一（N17）。
- 未做：**6 人以上**（引擎支持任意 N，但未测性能与平衡，按用户要求暂不做）、**N 人自对战训练**（见 N19）。

## N12 死亡与胜负

- 回合结算完毕后统一判定死亡（沿用 2 人流程）；**死亡会写一条 `death` 事件**（对局记录可复查）。
- **最后一名存活者获胜**；若同回合全员死亡 → 平局。
- 回合上限 60：**剩余 HP 最高者获胜**；并列最高 → 平局（`checkOver`）。
- **死亡者不再行动**：`attemptAction` 直接拒绝（`invalid`）；`startTurn` 每回合**重置行动槽**，
  防止死者沿用上回合行动；`autoGameN` / UI 的 AI 也跳过死者。
  ⚠️ 2026-09-09 修正：初版死者仍能出招/回能量。
- 死亡者不可被指定为目标；其架势 / 连环 / 蓄能珠立即失效。
- 回魂 / 梦魇 等隐藏技能在多人下沿用：回魂在"本回合死亡且曾挑衅"时触发，复活后仍参与胜负判定。
- UI：人类玩家被淘汰后自动"观战到底"（AI 自行打完剩余回合），不再要求出招。
- **边界裁定（2026-09-10 补）**：若回合结算后**全员 HP ≤ 0**，但其中某人挂着 `reviveNext`
  （回魂者"尚未确认死亡"，等待回合末复活），则该人**判为胜者**，而非按 N10 的"同回合全灭 → 平局"。
  实测约 2/1500 局命中此分支。此时 UI 会出现"你赢了"而玩家 HP 显示 0——**行为可辩护**
  （回魂者确实未确认死亡），但显示上易误解；若要彻底消除歧义，可改为"让回魂回合真正打完再判"。
  当前按"未确认死亡即算存活"处理（`checkOver`）。

## N14 镜面反射（可选技能，多人专用）

- 花费 3 ジ，优先级 3，分类「特殊」。**需要两个目标**：复制对象 t1（被作用者1）、输出对象 t2（被作用者2），且 t1 ≠ t2。
- 结算：复制 **t1 本回合的技能**，由**使用者自己**对 t2 施加其效果。
  - 只复制「对他人造成伤害」的效果（含伤害类型与穿透属性）；**不复制**状态附加（禁用 / 无效化 / 贴符 / 挑衅 / 转移等）。
  - t1 若使用架势 / 自增益 / 能量类（ジ / 蓄能 / 聚能环 / 避雷针 / 地雷 / 净化 / 无极变速 / 防御家族）→ 无可复制，仅消耗。
  - **双枪射手** → 只复制一个「枪」（原文特殊）。
  - 复制体的伤害来源是**使用者**，因此反弹 / 地雷按使用者结算。
  - t1 本回合行动已被作废（voided）→ 无可复制。
- 结算时机：本回合优先级 3 之后立即结算（**不重排**优先级；复制来的伤害不再参与相抵）。
- 复制不消耗额外资源，也不触发 t1 的副作用。

## N15 反复横跳（隐藏技能）

- 触发：**多个角色同时使用镜面反射**，且它们的 (t1 → t2) 边**构成环**。
- 效果：**所有镜面反射使用者**各受 1 点光&火伤害。
- 与 N16 互斥：已被聚光炮占用的那一对边不参与环判定。

## N16 聚光炮（隐藏技能，优先级 2）

- 触发：A、B 两人**互为复制对象**（A 的 t1 = B，B 的 t1 = A）且**输出对象相同**（t2A = t2B = X）。
- 效果：X 受 1 点光&火伤害。
- 该对边不再参与 N15 的环判定。

## N17 合二为一（隐藏技能）

- 触发：**≥2 个角色同时对同一个角色**使用雷击之枪。
- 效果：被作用者**额外**受 1 点电伤害（小雷本身的无效化照常结算）。

## N18 光&火伤害（复合属性）

- 聚光炮 / 反复横跳 造成的是**光&火**伤害：单次 1 点，同时视为光与火。
- 因此：藤甲火弱（N/R22）**+1**、吸血鬼公爵光弱（R47）**+1**，两者可叠加。

### 技能多样性：诊断与天花板（2026-09-10，v1.3.7）

**诊断（`tools/skill-diag.mjs`）先分清"买不起"与"买得起也不选"** —— 强制把 ep 补到 6：

| 经济条件 | 有效技能数 exp(H) | 分布 |
|---|---|---|
| 原生 | 1.88 | ジ 67.6% + 激光剑 32.4% |
| 只自己有钱 ep→6 | 2.06 | **狙击枪 74.2%** + 激光剑 18.7% + ジ 7.1% |
| 全员有钱 ep→6 | 2.06 | 同上 |

→ **给它无限钱只是换一招 spam（激光剑→狙击枪）** ⇒ 不是经济问题，是**策略坍缩**：
softmax 动作价值 + 低温贪心，而目标函数里只有胜负、没有任何"广度"压力 ⇒ argmax 必塌到一招。
加重因素：旧 `hold`+`conv` 奖励**literally 在为「ジ→激光剑」这一个循环付钱**；训练池里
`champion` 是权重 **1.5** 的对手（自己打自己，越练越尖）；播放温度 0.15 放大坍缩。

**解法：目标函数加"技能覆盖熵"**（唯一不指向特定循环的广度信号）
`div = DIV_BETA * H(该个体动作分布) / ln(#技能)`；经济奖励由"特定循环"改为**按费用分档**
（`0.08*heavy≥2 + 0.08*heavy≥4`），并拆掉 `hold`。

**效果（β=0.60，1500 代 × pop16 × gpo8，76s）**：
- 有效技能数 **1.88 → 3.22**；**用到技能种类 2 → 9**
  （ジ 59.7% / 激光剑 26.1% / 反弹 3.6% / 枪 3.4% / 防御 3.0% / 八卦阵 2.7% / 坦克 1.1% / 雷击之枪 0.3%）。
- 多样性代价约 4pt：1st 60.1% → 56.5%（但 β=0.60 对 β=0.30 head-to-head **88.9% / 64.7%**，
  对脚本对手对 1st **59.4%**，是三者里最强的）。

**天花板在哪（关键结论）**：β 从 0.30 翻倍到 0.60，有效技能数几乎不动（3.39 → 3.22），
说明熵奖励在 **~3.3 处饱和**。原因有二，**都不是奖励能解决的**：
1. **ジ 占比 ~60% 是算术必然**：`js/core/resolve.js:501` 的 `case SK.JI: me.ep += 1` 是**唯一** ep 收入
   （无每回合自动回能），稳态下"每次出手花 c 个ジ就要先出 c 次ジ" ⇒ ジ 占比恒为 **c/(c+1)**
   （c=2→67%、c=3→75%）。观测 58~60% 已接近该结构极限。
2. **少数攻击技在富经济下碾压**：喂饱后塌到单招（β=0.30 时坦克 92.2%；β=0.60 时激光剑 63.3%+聚能环 28.4%）
   ⇒ 即使经济放开，长尾技能也不会被大量使用，属**平衡性问题**。

### 每回合回 ep 与聚能环：机制已就绪，但实测否决了默认启用（v1.3.8）

**已实现的机制**（可选，默认关闭，不影响 2 人与线上口径）：
- `js/core/state.js`：`createState(modeKey, rng, n, opts)` 支持 `opts.regen`，写入 `state.epRegen`；
- `js/core/resolve.js`：`startTurn` 开头按 `state.epRegen` 给存活者发 ep（事件 `ep` / reason=`每回合回能`）；
- `js/train/evo.js`：`oneGameN(choosers, seed, n, opts)` 透传；`scoreMemberN` 用 `TRAIN_REGEN` 控制权重（默认 0）。

**聚能环的机制**（用户指出的要点，已核实）：`js/core/state.js:95` —— `ep: p.ringStreak === 0 ? 3 : 0`，
**首次 3 ジ、之后永久 0 费**；`js/core/resolve.js:508` —— `const g = me.ringStreak >= 3 ? 3 : me.ringStreak; me.ep += g`。
即收益为 +1 → +2 → +3 → +3…，**从第 3 次起每回合白拿 3 ep，是 ジ（+1）的 3 倍**，第 4 回合起严格领先。

**实测（`tools/skill-diag.mjs` 变体，冠军在 60 局 × 三种经济下）**：

| regen | 最高 ep | 环最长连用 | 有效技能数 | 分布 |
|---|---|---|---|---|
| 0（标准） | 1 | **0** | 3.02 | ジ 49% / 枪 35% / 藤甲 14% / 防御1 / 反弹1 / 八卦阵1 |
| 1 | 1 | **0** | **1.00** | **藤甲 100%** |
| 2 | 204 | **16** | 1.73 | ジ 82% / **聚能环 16%** / 雷击之枪 2% |

**三条结论**：
1. **regen=1 无效**：+1/回合刚好够每回合放一个 1 ジ 技能 → 经济锁**换了个不动点**（藤甲 100%），
   仍然攒不起 3 点启动环。
2. **regen=2 能解锁聚能环**：AI 确实学会并连用到 **16 连**（说明机制可学，不是学不会）。
3. **但聚能环是严格支配策略**（免费永续 +3/回合）→ 学会之后就是"永动刷环"，
   有效技能数反而从 3.02 掉到 **1.73**。**拓宽分布的目标与它冲突。**

**追加更正（v1.3.9）——"环支配"这个结论是我自己的奖励被 hack 造成的，作废**：
当时我加的 `engine = 0.06 * min(1, epGain/12)` 是**按"获得的 ep 总量"发钱**，而环 +3/回合、ジ +1
→ **等于给刷环发三倍工资**；再叠加 `save`（max ep）项，囤到 204 也满分。
用户指出这点后按他的设计改为**分段 shaping**：

```
0 ~ 4 ep   → 攒钱奖励（鼓励手上有货，够放 2~5 ジ 技能）  STOCK_BONUS = 0.05
5 ~ 10 ep  → 不奖不罚（中间区交给策略自己权衡）
11+ ep     → 囤积惩罚（资源积着不转化 = 浪费）          HOARD_PEN = 0.12
```

**重测结果（regen=2，1500 代，同经济评测）**：
| 指标 | 旧的 engine 奖励 | 分段 shaping |
|---|---|---|
| 最高 ep | **204** | **2** |
| 环最长连用 | 16 | **0** |
| 贵技能(≥2 ジ)出手占比 | 16% | **100%** |
