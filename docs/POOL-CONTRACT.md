## 1. 为什么池必须**内嵌**进 bundle，不能运行时取包

我一开始选的是"运行时按 path 取包"（理由：省 1MB、名单改动不用重烘 bundle）。**这个判断是错的**，错在没有先核实产品入口：

- 游戏的运行方式是**双击 `index.html`**（`server/train-server.mjs:3` 的注释原话："游戏仍双击 index.html 即玩"），
  而训练服务器**不 serve 静态目录** ⇒ 页面跑在 `file://` 上；
- `file://` 页面里 `fetch('docs/artifacts/x.bak')` 会被 Chrome 拦（同源策略对 file  scheme 的默认处理）⇒ 运行时取包**在真实入口下不成立**；
- 页面现在的取包路径本来就是"全局变量 + localStorage"：`js/ui/ui.js:317 loadMultiChamp()` 读
  `localStorage['epirus.champion3p']`，取不到再回退内嵌全局 `window.EPIRUS_CHAMPION_3P`（由 `index.html:149` 的 script 标签带来）。

⇒ **契约决定**：池 = 一个 committed 的 `<script>` 文件 `js/bundled-champion-pool.js`，把成员包**内嵌**进去。
体积账（实测）：一枚 ≈110 KB，困难档 9 枚 ≈ **965 KB**。缓解：
① 独立 `<script defer>`，不阻塞首屏；② `?v=` 缓存戳由 `bumpChampionVersion()`（`server/train-server.mjs:110-121`）
统一刷新（它把 index.html 里**所有**脚本引用的 `?v=` 换成同一个构建标记 ⇒ 新标签自动被覆盖，不必另写机制）；
③ 池成员少而精（困难档就是 7~10 枚），中/低档主要靠脚本与低 Hp 包，不必全量入池。

## 3. 抽签语义（产品侧唯一的实现点）

现在的全貌：`js/ui/ui.js:477` 每席每次决策都调 `champForCount(state.p.length)`，而它内部只认**人数**不认席位 ⇒
所有 AI 席拿到同一颗包（缓存单例在 `js/ui/ui.js:315`）。剂量四元组 `(eps, epsK, epsMode, ramp)` 在这一处消费，
档位表在 `js/train/bots.js:1056-1067`（`DIFF_TIERS`，`kind:'champ'` 四档 + `kind:'style'` 的"极限·读招"走脚本）。

**契约**：

1. `champForCount(n)` 改成 **`champForSeat(pid, n, seed)`**（唯一的签名变更点；调用侧 `js/ui/ui.js:477` 已经在逐席调用）。
   - `n <= 2` ⇒ **完全走老路**（2P 槽），池只作用于 ≥3 人的多人桌。理由不是省事：§E286 实测 3P 包在 1v1 上是分布外的
     （替身夺冠 27.5% vs 2P 包 15.5%，且剂量梯**反号**），把池搬到 2 人桌等于造一个假档。
   - `n >= 3` ⇒ 从 `tier` 对应的成员里抽 `n-1` 枚（AI 席数）。
2. **确定性**：抽签只用本局已有的随机流（`state.seed` 派生），**不引入新的时间源** ⇒ 同 seed 同档 ⇒ 逐场组成逐字相同。
   这条是 `D234` ④ 的判据，也是所有池读数可复算的前提。
3. **禁四席全同**（裁定②）：抽完若 `distinct(组成) == 1` ⇒ 重抽其中一席，最多 8 次；
   8 次后仍全同（只可能发生在该档成员数 == 1 时）⇒ **允许全同但必须打印降级**，不许静默。
4. **成员数不足**（该档 < AI 席数）⇒ 允许重复（裁定②本来允许部分重复），但组成里每一枚都必须是该档成员。
5. 剂量四元组仍按 `tier` 给（难度与池是**两个正交自由度**：难度 = 抽完包之后再叠 ε）。
   ⚠ 这意味着"困难"不再等于"强包"，而是"强档池 + ε=0"；`lv:hunter` 仍不带包（`kind:'style'`）。
6. **本机导入优先**（`localStorage['epirus.champion3p']`）⇒ 有本机包时**退回单包语义**并在页面明说"池未生效（本机包优先）"。
   不许把用户自己的包悄悄塞进池里当一席。

## 4. 兜底（一律"响亮失败"，不许静默换包）

| 情形 | 行为 |
|---|---|
| `js/bundled-champion-pool.js` 缺失/解析失败 | 退回 `js/bundled-champion-3p.js` 单包 + 页面打印降级原因（沿用 `champForCount` 现有的"回退并明说"写法） |
| 表里某枚的 pack 文本解不出（`js/champion-pack.js` 的 `P.unpack` 返回 null） | **该枚整枚出局**，不参与本局抽签，并打印 id；不许用 null 顶上 |
| 某档成员数 = 0 | 退回单包语义 + 打印 |

## 6. 门禁（立新门 `D234`，不塞进别人的门）

立新门的理由与它每条腿抓的**具体坏法**（规矩不必死守，但门必须有牙）：

| 腿 | 判据 | 不立这条会怎样 |
|---|---|---|
| ① | `pool-members.tsv` 每枚的 `path` 必须被 `git ls-files` 查到 | 池成员 170 枚里现在只有 24 枚 tracked ⇒ CI/干净克隆里"这枚存在"是假的（今晚 `D191` 的④就是这一族红过一次） |
| ② | bundle 里每条目的 `wid` 必须与表一致 | "名字对、包不对"——`coords.tsv` 的 `SHIPPED-Ldemo` 坑换了一种形态重演 |
| ③ | 自动成员 `promoteVerdict` 不许 `block`；`untested` 必须在判词里印出枚数 | 把 `v7beadseed-82`（送盾 17.3/局）这类重新请进池；"没测 ≠ 过关" |
| ④ | 同 `seed` 重放两遍 ⇒ 逐场组成逐字相同 | 池读数不可复算，且"这次好"可能是抽到好签 |
| ⑤ | 构造"该档只有 1 枚"与"解不出的一枚"两种输入 ⇒ 必须走降级并打印（不许静默） | 兜底写错时产品会**看起来正常**地少一席 |
| ⑥ | 契约的三处读者（页面取包点 / `tools/probe-pool.mjs` / 真源表）必须都在，且量具必须走共享的 `chooserFor` + `humanPrototypes` | 文档写了没人执行；或量具自造一份抽签/原型 ⇒ 池读数与页面不是同一件事 |
| ⑦ | 把 `champion-pack.js` 与 `EpirusPolicy` 各跑进上下文比 API，再把 bundle 第一条**真解一遍** | 页面用错对象（`EpirusChampionPack.unpack` 不存在）⇒ 整池静默退回单包，而标签照样说"池在生效"（只有浏览器实机能看见） |
| ⑧ | 同一批人席表**带基准 / 剥掉基准**各喂一次 ⇒ 后者必须一条结论都不给 | "算不出"被读成"零格否决 = 合格"⇒ 已被人类判死的包会以自动成员身份进池（10-12 实测两枚，`v7w3c-82` 踩 4 格） |

归组：`ship`（它判的是出厂装配）。⚠ `D234` 的输入必须全在 git 里（腿①自己就是查这件事），否则它自己会变成又一个"CI 上永远 SKIP"。
