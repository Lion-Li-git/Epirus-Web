# 踩过的坑 / 规矩（Epirus-Web）—— 只留**会复发**的

> 为什么单独一个文件：这些不是"版本变化记录"（那些在 `CHANGELOG.md`），而是**做这件事时反复踩到的规矩**。
> 原先它们堆在 `HANDOFF.md` §5 里，让交接文档越滚越长；v1.5.18 起挪到这里，HANDOFF 只记"现在 + 下一步"。
> 编号沿用历史编号（1–20 来自 v1.5.2~v1.5.12 时期，21–25 是 v1.5.18 新增），**别因为编号大就跳过**。

## A. 工具 / 流程

1. **别把"等待"写进 tool call**（用户 2026-09-12 指出，千问定位）：我写了个 15 分钟的轮询循环，
   导致 **DSH 整个卡死**、实验被带走。**改成"一次只看一眼"（`timeoutMs ≤ 60s`），让实验自己写日志**。
2. **长任务先报【预估】、跑中报【进度】**（用户要求）。基准吞吐：**5 人 250 代热启动 ≈ 1 分钟**、
   **一个 1400 局考卷 ≈ 8 秒**。
3. **补丁与提交必须 `&&` 串联**，并在提交前 `grep` 校验 —— 我两次因为 Python 补丁失败
   （SyntaxError / 锚点不匹配）而**提交了声明里有、磁盘上没有**的 CHANGELOG 条目。
4. **别在同一条命令里叠多个 heredoc**：`python - <<'PY' … PY` 后面再跟 `git commit -F - <<'MSG'`，
   第一个 heredoc 会吃掉后面全部内容（本轮犯过，什么都没提交）。
5. **`git commit -m "…"` 的信息里不要有内层双引号**（会截断成 pathspec）。
6. **`sed -i 's/…v1.4.6/…/'` 不匹配时不报错** ⇒ 版本号会静默漂移（README 曾停在 v1.4.6、index.html 停在 v1.4.1）。
   **改用任意版本的正则** `s/v[0-9.]+/vX.Y.Z/`；且 **np-test D8** 已在守护三方一致。
7. **node 的 `/tmp` = `D:\tmp`**（不是 Git Bash 的 `%TEMP%`）⇒ 给 node 传 /tmp 下的文件必须 `$(cygpath -w …)`。
   这是会话内**第 4 次**踩。
8. **`.cmd` 里不能写中文注释**（GBK 码页会把行拆成非法命令）⇒ 两个 `.cmd` 都是纯 ASCII。
9. **按命令行模式杀进程会杀掉自己**（我的 kill 命令里含匹配串，把当前 shell 也匹配上了）。
   要按 pid 精确杀，或用不会出现在杀手指令里的模式。
10. **跨 heredoc 写 JS 正则会丢反斜杠**（`[\\/]` 变成 `[\/]`）⇒ 写完必须回读字节验证；
    实在要用就换成**不含反斜杠**的写法（如 `/^.*[^0-9A-Za-z_.-]/`）。

## B. 测量 / 方法（都是花钱买来的）

11. **n=1 不得下结论** —— 曾**三次**同类翻车：v1.4.1 把 38.4%→21.8% 归因于轮换（真因是"从零冷启动 vs 热启动谱系"）；
    v1.4.9 想据 `wall2-31` 换冠军（多 seed 后不显著）；v1.4.9 的反弹墙效应（n=6 仍不显著）。
    **单跑极差**：标准考卷 3.8~8.5pt、**反弹墙 100pt**。
12. **每个新口径都要带自检计数 + 反证对照**。范例：`--ban=sword`（使用率 0%）应给出 **≈0 的变化**
    （实测 −0.1pt）⇒ 证明消融器材本身不改变行为。没有反证对照的 Δ 不可信。
13. **"白名单/清单两处各写一遍"必出事**（漏加名字）—— 已踩**三次**（v1.3.59 漏 server、v1.4.8 漏 worker、
    v1.4.14 漏 `opp-pool.mjs` 本身）。现在由 **single source（`server/opp-pool.mjs`）+ np-test D7/D9** 守住。
    v1.5.18 又抓到三处同型（反摆烂 env / 体检指标 / 2P 基准表）⇒ 各配 D24 / D27 / `tools/p2-baselines.mjs`。
14. **口径会决定结论**（最贵的教训之一）：`枪` 的 mono-spam Δ = **−15.5pt**（读作"坑"）而消融 `Δ_lost` = **+0.5~3.8pt**
    （读作"该留着"）；`雷击之枪` mono −44pt（读作"没用"）而消融 −2.6pt + 环场 **+20pt**。
    **已在用的技能看消融；反制卡看场**。
15. **没有门禁会自己变绿**（v1.4.15）：`tools/smoke.mjs` 从 **v1.4.0 起就是红的**，4 个断言全在
    「长程（5 血）模式必须能在页面选到」这条线上 —— 而 v1.4.0 的交付清单里**只落了 `ui.js` 的消费者，
    没落 `index.html` 的 `<option>`**（"两处各写一半"）。它躺了 5 个版本。
    ⇒ **交付清单里"文件 A + 文件 B"这种条目，做完必须由一条会失败的用例去点名**。
16. **`workers` 是会改变结果的行为输入**（v1.5.0）：同 seed/池/起点，`EPIRUS_WORKERS` 16 → 12 训出的权重**不同**
    （sha1 `A4A1A894…` vs `92AF513B…`）。机理：worker 是独立沙箱，个体随机流在 worker 内推进量随
    `chunk = ceil(pop/workers)` 变化。⇒ **同 seed / 同池 / 同起点 / 同 worker 数**才是可复现；
    想"少用几个 worker 省机器"就等于**悄悄换了一个冠军**。
17. **给训练池加"对手名"时又漏了一处（同型第三次）**（v1.5.2）：只改了「开跑前校验」和「串行回退」，
    漏了**终局名人堂评估**那段 —— 它自己又写了一遍"名字→函数"映射，跑到 250 代才炸成 `sel is not a function`。
    ⇒ **规矩**：训练侧"名字→函数"**只允许一个入口**（`server/opp-champs.mjs` 的 `makeOppSelResolver`），
    且**开跑前把每个名字真解一次**。守门 `np-test D12`。附带：worker 里的硬错误必须 **reject 穿透**
    （否则 Promise 永不 resolve，只会挂到 30 分钟墙上时钟报"训练超时"，真因被埋掉）。
18. **"冠军的行为"与"某个风格脚本的行为"必须分清**（v1.5.13，用户实测踩到）：多人局难度下拉的**默认**是
    `st:combocounter` **脚本**，不是冠军 ⇒ 用户拿它当"冠军"看，于是"枪使用率很高"与 skill report 对不上；
    冠军 `eco-34` 的枪使用率是 **0%**。⇒ 想看冠军就把难度选成「**冠军（最强）**」；skill report 的「使用率」
    是**富裕经济**口径（每回合把 ep 补到 10），与真实对局不同 —— 它的「Δ_lost 强度」列才是主口径。
19. **规则文档里"对谁"没写清时，实现很容易只对 2 人局正确**（v1.5.13 修用户报的狙击枪 bug）：
    旧实现只查"被击方这回合用了什么技能"、不看打谁 ⇒ 多人局里目标用枪打第三个人也会废掉狙击，
    而 2 人局恰好等价 ⇒ `spec R13/57` 一直绿。守门 `np-test D20`。**教训**：规则条目里凡出现
    "该玩家/攻击者/被作用者"这类指代，实现处要写一句"到底指向谁"，并配一条**多人局**用例。
20. **"按模式猜默认值"必须先证明该模式真的会触发那条规则**（v1.5.12 回滚 v1.5.11）：
    干净配对（`lngC` 自动 0.5 vs `lngD` 显式 0，6 seed，其余全同）产出**逐字节相同** ⇒ 长程里它是**空操作**。

## 26. `git add -A` 会把"工作区里早就没了"的文件提交成删除 —— 提交前必看 `D` 行

**事故**：v1.5.21 提交时用了 `git add -A`，把 `results/` 里**早已不在工作区**的历史文件
（22/34/57 回合对局记录、`epirus-champion (6/7/8).json`、`page-verify-v1516/1517.png`、`battle-0{1..4}.png`）
一并提交成删除（`18 files changed, … 6018 deletions`），**用户的对局记录当场从仓库里消失**，
只能 `git checkout <上一个提交> -- results/` 恢复（已补一次"恢复提交"）。
**排查**：`tools/*.mjs` 只 `rmSync` 自己 `mkdtempSync` 出来的临时 user-data-dir，**不是工具删的** ——
工作区里那批文件在提交之前就已经不在了（很可能是一次手工清理）。
**规矩**：提交前先 `git status --porcelain`，**只要看到 `D`（deleted）行就先确认"这是我故意删的吗"**；
不是就 `git checkout <last-good> -- <path>` 恢复后再提交。**宁可分两次提交，也不要让 `-A` 替你做决定。**
（同族教训见第 3 条"补丁必须 && 串联 + grep 校验"：都是"别让一条命令替你做它没被告知的决定"。）

## 27. 新守门一律**追加在文件末尾**；门禁结果只看**退出码/尾部输出**，绝不看静默的 grep

**事故（连环两次）**：v1.5.33 的 D44 与 v1.5.34 的 D45 都用"锚点插入"写进了**别的测试块中间** ⇒
`tools/np-test.mjs` 多出一个 `});` ⇒ **SyntaxError，整个守门脚本崩掉**。
更糟的是：两次提交时我的命令都是 `node tools/np-test.mjs | grep -E "✘|通过 " | tail -2`，
脚本崩溃时 grep **匹配不到任何东西 ⇒ 静默无输出**，而我把"没有输出"读成了"通过" ⇒ 坏文件被提交并推送了两次。

**规矩**：
1. **新测试追加在文件末尾**（用 `cat >>` 或"取文件尾部锚点"），**不要**按中间某行做插入 —— 那种锚点在语义上分不清
   "块内"还是"块边界"（D38/D39、D44/D45 都栽在这上面）；
2. 门禁结果**必须看退出码**（`node tools/np-test.mjs > /tmp/x 2>&1; echo $?; tail -3 /tmp/x`），
   **绝不**用 `grep | tail` 的"有/无输出"当判据 —— 静默既可能是"没有失败项"、也可能是"脚本根本没跑起来"；
3. 同族教训（见第 26 条）：**别让一条命令替你做它没被告知的决定**。

## D. v1.5.94–99（第九轮复核 + 教师示范接线）新增

28. **"接线在文件里" ≠ "接线在跑的那条路径上"** —— 同一个故障本轮连续出现**三次**，每次都把整臂变成空操作：
    - **env 拷贝**：`worker_threads` 的 `process.env` 是**创建时的拷贝**；而 `EPIRUS_IMIT_GENS` 是服务端在
      `runTrain` 里**事后**派生再写进 env 的 ⇒ worker 永远读到 0
      （`v7ringT` / `v7ringT2` 两批产物与对照 **逐位相同** = no-op）。
    - **函数分叉（真根因）**：runner 的训练 URL 带 `n=5` ⇒ 请求走 **`runTrainN`**（多人路径），
      而全部 IMIT 接线原先**只写在 `runTrain`**（2 人路径）⇒ N 人臂上 `imitB ≡ 0`。
    - **名字静默退回**：`EPIRUS_IMIT_TEACHER=deepsaver` 不是 `BOT_PICKS` 的键（正确名是 `pickDeepSaver`）⇒
      `accepted=false`，而库里 `IMIT_TEACHER || BOT_PICKS['heavyfire']` **静默退回默认教师** ⇒
      整臂**贴着错标签**跑完。
    ⇒ 四条规矩：① 回执必须打**在真正执行的那条路径**上（worker 侧也要打）；② 回执要含**生效值**
      （`gens / frac / teacher / accepted / override / β(gen0)`）；③ **最终反证 = 产物是否与对照逐位相同**
      （确定性流水线让它成为最强判据）；④ 解析与设值**只写一份**（`applyImitEnv`、`setImitPlanByName`），
      两条路径都调它。

29. **"样本敏感性"本身要按包验证，不能当常数用**：第 22 条那条曲线
    （同一个包 n5=3.08 / n10=2.99 / n20=4.24 / n40=4.54）只在**当时那个包**上成立；
    本轮 `v7role1-82` 在 **n=5~80 恒定 1.70~1.71** ⇒ 它的 `G<3` 是**真塌**，不是抽样假象。
    ⇒ 引用旧曲线之前，先在**手上这个包**上重测一遍。

30. **报均值必须同时报逐 seed 胜负**：6 seed 时"角色间熵 +51%"看着像真赢，
    扩到 9 seed 后翻成 **4 胜 5 负** —— 那个 +51% 全靠**对照的一个退化 seed**
    （角色间熵 0.002 = 蓄能囤积到 100%）撑着。⇒ 退化样本会污染均值；**逐 seed 胜负才是结论**。

31. **门的判据要写清"量的是什么"，而且"最坏的那一格/那一座"本身是小样本统计量**：
    - 座位门的判据是**极差**（<30pt），**不是**"有没有座位为 0"。`v7f5t-31` 在 n=400 时极差 26.9pt ✓ 过门，
      可它的**首座夺冠率是 0%**（其余四座 20~27%）。
    - **同一类错误本轮出现两次**：座位极差在默认 n=40.4pt（红）→ n=200 30.6pt（红，只超 0.6）→
      n=400/800 **26.9/26.3pt（绿）**；`G4` 的"最克那一格"在 **n=60 是「坦克线 57%」**，
      而 **n=120 与 n=200 都稳定指向「只枪 53%」** ⇒ **n=60 会选错格子**。
    ⇒ 两条硬规矩：① 阈值落在噪声带时，**判"过/不过"之前先把 n 拉大**；
      ② **报 `G4` 必须同时报 n**（否则"哪一格最克"这个结论本身不可信）。

33. **布尔化的经济判据会被"最小非零"刷分**（第十轮复核 §4-2）：`D78` 原先要求"得珠>0 **且** 花掉>0"，
    而候选② 得珠 835 / **花掉 1**（花/得 **0.12%**）就点亮了"闭环 ✓"，同时每局浪费 **20.9** 颗（≈在位包的 250 倍）。
    这是第七轮 §11 陷阱的**镜像**（当时是"干脆不用 ⇒ 浪费率 0% ⇒ 绿"）。
    ⇒ 规矩：**任何布尔化判据都要先问"最小非零能不能点亮它"**；经济类判据用**双条件**
    （花/得 ≥ 20% **且** 过期/局 ≤ 1），并且**把"囤积"与"使用"在同一个显示里分开**
    （`energy(含空转/过期珠)` —— 否则 25.4% 会被读成"开始用能量类"）。

34. **"偶然性"至少有两种，处置相反**（第十轮复核 §5）：用"解析候选熵 `H` + 采样背离率（1−p_max）"区分 ——
    - **策略内的偶然性**（高 `H`、背离 34%）：同一局面每局一个样 ⇒ **降温度/降 ε 可收窄**，代价是变呆；
      但它的**读数本身带采样噪声 ⇒ 必须报置信区间**。
    - **种子内的偶然性**（`H≈0`、块胜率 `[0,0,0,0]`）：网络已收敛到极峰，**确定地**产出这个形状 ⇒
      **降温度完全无效**，只能换配置 / 换 seed ⇒ **必须报"同配置换 seed 的复现率"**。
    ⇒ `H=0` 还意味着：**对已收敛到单卡的个体，熵/覆盖类项没有牙齿**（我的 `S` 是跨状态覆盖熵，同理会退化 ⇒
    要让 S 有牙齿得用**跨状态**的覆盖量（`roleOf` 8 角色 / 门禁 `G`），而不是同状态内的动作熵）。

35. **报"考卷分"也要报决策样本 n**（第十轮复核 §3-2 的扩展）：有的包里 A 卷只有 **136 个决策样本**
    （该场里它 0 号席常早亡）⇒ 与 `G4`/座位同理，**分数本身也是小样本统计量**。

32. **"产物=证据；没记账的产物等于没有结论"**：整晚 20 个产物零记录，其中一个座位极差 99pt。
    ⇒ 立了守门 **D82**：**24h 内落盘的 `.bak` 必须逐个在 CHANGELOG 被点名**（**缩写不算字面名字**）。
    它随后**多次抓到我自己**（漏点名、用 `v7f2t-{31,…}` 缩写）。

## 48. **想用"奖励/补贴"买一个动作之前，先量那个动作的门槛在决策时刻的分布**（v1.5.204；用户问"击杀奖励明明该利好大雷电磁炮，为什么重训没效果"）

**结论先摆**：不是奖励写错了，而是**它买的那个动作，现役包在 99% 的决策时刻根本够不着门槛** ——
所以把回款从 1ep 改成 2ep、改成"按伤害"、改成任何 ≤2ep 的形状，都**跨不过那道 5ep 的门**。

### 48.1 量出来的三层原因（现役 `v7cmin4-31` · multi · 各 200 局 · 用真规则实现的内存补丁）

**① 规则的实际语义 ≠ "击杀回 2ep"。** `tools/kill-reward-lib.mjs`：
- **规则 1（单点）**：本回合有人死亡 ⇒ 回 **1 ep** 给"所用技能优先级最高"的参与者；
- **规则 2（按伤害）**：每个参与者按**造成的有效伤害**回**等量** ep（overkill 不付）。
⇒ 一次 1 点伤害的补刀只回 **1 ep**。实测两档**实付几乎相同**：

| | 脚本池场 ep 收入/局 | **规则实付/局** | 占收入 | 有来源伤害/局 | 死亡/局 |
|---|---|---|---|---|---|
| 规则 0（关） | 5.03 | 0.00 | 0% | 13.37 | 4.8 |
| 规则 1 | 4.90 | **1.05** | 21.4% | 13.72 | 4.3 |
| 规则 2 | 4.69 | **1.05** | 22.5% | 13.66 | 4.3 |

**② 在最需要它的那个场地里，它一分钱都不付。**
破防场（4×只防御不还手）：**死亡 5.0 次/局**，但 **有来源伤害 0.00/局** ——
5 次死亡**全部**来自无来源的终局收缩（`damage.source == null`）⇒ **规则实付 0.00 ep/局**。
即：**激励恰好在"该换穿透线去清场"的场景里结构性缺席**（这正是第 46 条理想冠军第 3 条要治的那件事）。

**③ 即使付了，也跨不过门槛 —— 这条才是决定性的。** 大雷 = **5 ep**（电磁炮 2ep + 1 珠；ジ = 1ep/次）：

| 场地 | 决策时刻 ep 均值 | `ep≥5`（现在就能打） | `ep=3~4`（**+2 就翻过门槛**） | `ep<3` |
|---|---|---|---|---|
| 脚本池场（7.5 次决策/局） | **0.76** | **0.0%** | **2.4%** | 97.6% |
| 破防场（47 次决策/局，收入 24ep/局） | **0.49** | **0.0%** | **0.0%** | 100.0% |

⇒ 一个 +2ep 的回款能改变"能不能打大雷"的决策占比 = **2.4%（脚本池）/ 0.0%（破防场）**。

### 48.2 可搬走的三条规矩

1. **买动作之前先量"门槛在决策时刻的分布"**，不是量"理论上能不能"。
   本例第一眼看上去 ep 收入 24/局、回款 21% 的"占比"都不小，但**分布**一量就发现均值 0.49、`ep≥3` 占 0%
   —— **"占总收入的比例"是错的透镜，要看"离门槛的距离"。**
2. **奖励必须能"到达"那个场景**：先问触发条件（本例：要有**有来源**的击杀）在那个场景里成立吗。
   破防场 5 死亡/局却 0 归因 ⇒ 奖励再大也不发。
3. **同族的奖励形状之间先互相比一比**：规则 1 与规则 2 实付相同（1.05 vs 1.05）
   ⇒ "按伤害"这个精化在经济上**什么也没改变**。若两个形状读数几乎相同，**别把希望押在换形状上**。

> 与第 46 条合起来读：理想冠军的第 1 条（会为大招攒钱）与第 3 条（会清场）**不是"奖励不够"**，
> 而是**门槛不可达 + 激励不可达**这两件事。所以出口仍是用户自己指出的那两条：
> **改价**（把大雷费用/ ep 收入挪到"积累"真的可能发生的量级）或 **改判据**（把破防场纳入主判）。

## 49. **评测口径 ≠ 玩家看到的口径**；对"会不会发生"的判断必须换到产品口径复量一次（09-24 夜 · Qoder §H-6）

| `eps=0`（**门禁/评测**用的就是它） | **100.0%** | 0.0% | 0.0% |
| `eps=0.2, epsK=5, epsMode='soft'`（**产品**：`ui.js:464` 那一行） | **12.5%** | **87.5%** | **40.8%** |

⇒ 「现役 0% 胜 / 100% 平 ⇒ 它不会清场」这句话**只在 ε=0 成立**；玩家在多人 AI 局里看到的是 87.5% 胜。
   门禁继续用 ε=0 是**有意的**（可复现、评的是包本身，v1.5.152 因此另设"产品代理栏"）——
   **错的是把 ε=0 的绝对值直接写成"玩家会遇到的局面"**。本轮把 `METHODOLOGY §48` 结尾那句
   "第 3 条（会清场）是门槛/激励不可达"也一并降级：那条讲的是**跨期攒大雷**，与"破防场拖平"不是一回事。
- **会复发的形状**：同一份代码里两套口径只差一个参数，而**表头上不写口径**（`probe-ideal-champion` 修前只印包名/局数）。
  ⇒ 已把 `temp/eps/epsK/epsMode` 全印进表头。**读数旁边没有口径，就等于读数没有单位。**

## 50. 扫旋钮要扫**那根真的杆**（同一夜 · §H-3）
`policyChooserN(params, temp, eps, epsK, epsMode)` 有五个位置参数。第 2 个是 **softmax 温度**，第 3 个才是**探索率 ε**。
我第一版把"ε 扫描"接到了第 2 个参数上，扫出来 `0.47/0.43/0.43/0.44` —— **几乎不动**，
差点对这夜写下"ε 悬崖不存在"。真杆扫出来是 `0.43 → 0.18 → 0.08`（ε=0/0.2/0.4，soft）——悬崖在，而且**形状也要紧**：
同为 ε=0.2，`soft` 的破防场平局 12.5%，`uniform` 是 44.2%（差 3.5 倍）⇒ **探索的形状比大小更值得先量**。
- 规矩：**接旋钮前先读函数签名与被调用点**（这里 `ui.js:464` 一行就把"产品用的是哪三个值"写死了）；
  一个有多参数的函数，探针要**把每个参数都做成具名开关**，别复用同一个位置。

## 51. 广度类读数**对"恒亏动作"不设防**（同一夜 · §H-7）
`G 有效技能数` / `净兑现` 统计的是**非ジ出手**的种类与熵 ⇒ 一次"清除 0 枚"的空净化、一次"全场无符咒"的空天火，
**都算一张有效卡**。实测：把 v1.5.199 的净化闸门装上，`cbs1s2-band2` 的空净化 112→0 之后
`G(long) 3.83 → 2.95`、净兑现 `3.25(5 种) → 2.88(4 种)`，**直接从"过广度门"变成被 `G<3` 阻断**。
- ⇒ 报广度必须**同时报"其中多少是空转动作"**；否则"广度"会奖励**浪费得多样化**。
  与用户那句老话同源（"G_eff 像刷分"）与 §N24（命中加权广度）同族 —— 这一条是把病根往前推了一层：**不是刷分，是刷无效动作。**
- ⚠️ 我只量到总效应（3.83→2.95），**没**拆成"少数一张卡"与"行为真的变窄"两半 —— 拆法：把恒亏出手从计数里剔除后重算 G。

## 52. **硬编码的"期望值"是记账，不是常数**：换在位包必须同步，否则量具会自我否定（同一夜 · §H-2）
`probe-g4-anatomy.mjs` 的 §A 自检写着"必须复现 75%(long)/62%(multi)"，而那是 **v1.5.144 之前**那件线上包的读数；
现役同一装配实测 **38%/35%** ⇒ 结果**每次跑都打印「⛔ 复现失败 ⇒ 下面的读数先别读」**：装配没错、读数没错，
**是自检把自己废掉了**（而 `D1xx` 还把 `EXPECT = { long: 75, multi: 62 }` 逐字钉住 ⇒ 文本钉把腐化固定住了）。
- 修法（已做）：期望值改成在位包的现值 + **在旁边写明"哪件包 / n / 日期"**，并把门钉成"必须写清来历 + 不许再引用历史数字"，
  让下一次换包**漏改就红**（文本钉反过来当防腐用）。
- 通用规矩：**任何"期望值常量"都必须带着它属于谁**（包名/n/日期），且门要钉这件事 —— 只钉数值等于钉一颗定时炸弹。

### 51.1 【自我更正】"空转刷广度"这个猜想**被同一夜的数据否证**（§H-8）
把恒亏出手按事件逐条从计数里扣掉之后重算 `G`（镜像 40 局 · 5 席）：

| `co1s8-band1` | 0 | 0 | 4 | 2.63 → 2.58 | 2.1% |
| `v7aim3-93` | 0 | 0 | 0 | 4.03 → 4.03 | 0.0% |

   而**蓄能珠过期才是现在最大的空转**（现役 270 / `v7cmin4-82` 744 颗）—— 那正是第 48 条与第六道"珠经济未闭环"在说的事，**跟广度无关**。

## 53. 配重量具的两种自检：**与单一真源逐字对齐** + **判定旁边印分母**（09-25 凌晨 · Qoder §H-10）
交接 §4-E7 只要"座位极差统一按 n=400 报"，但要报就得同时报两个口径（评测 ε=0 / 产品 ε=0.2 soft），
而 `audit-lib.seatSymmetry` **不接受 Chooser 注入** ⇒ 只能复刻一份。复刻的代价是"我这份算的还算不算它"，所以钉了两道：
1. **复刻必须与真源逐字相同，否则整张表作废**：同一 seed 序列（`seedBase+g`）、同一 `slotSalt` 公式、同一判胜口径，只换 ε；
   跑之前先在 n=100/`seed0=12000` 上比对 5 席**回胜利计数**，不等就 `exit 8` 并打印两边的数。
   ⇒ 实测 `10/18/16/16/20` 逐字相同。这条把"复刻漂移"从**静默错误**变成**当场失败**（与 §47.4"静默跳过=关掉测量"同族）。
2. **两栏配对 ⇒ 差值只来自口径**：不配对的扫描（各口径各抽各的 seed）会把"抽样噪声"记到"口径"头上 ——
   我这夜前两版就吃了这个亏：`--reps` 跑出来的噪声带是 `[15.2~15.2]` 这种**假零带宽**，因为 `seatSymmetry` 的 seed 序列是写死的，重复只是重复。
   ⇒ 换 `seedBase` 才是重复；而真源那一栏没法换 seed ⇒ 只在**自检格**（`seedBase=12000`）上与真源对齐，其余格用我这份。
- **判定旁边必须印分母**：加了这栏之后才发现最要紧的数不是极差，而是**判胜率** ——
  `cbs1s2-band2` 在 ε=0 下判胜 **26~30%**（正好压在 `audit-lib.mjs:415` 的 `decisiveRate<0.3 ⇒ 'unjudgeable'` 线上抖），
  极差 30.8pt 是在不到 1/3 的局上算的；同批种子在 ε=0.2 soft 下判胜 98%、极差 12.1pt ⇒ **两栏判定相反**。
  仓里 `unjudgeable` 只出现在 `audit-lib.mjs:514` 的 `notes` 里 ⇒ **表格列看不见它**。
- **可搬走的规矩**：凡"一个阈值 + 一个可能很小的分母"的读数（极差、率、占比），**打印格式里就得带上分母**；
  只在"备注"里写"不可判"，等于把这条判定交给读表的人的记忆。

## 55. 把一条线搬到另一个口径之前，先量**两侧的分布**——"现役过不过"只是其中一个端点（09-25 凌晨 · Qoder §H-13）
`G 有效技能数 ≥ 3` 这条广度门线判在 ε=0 上。第 54 条量到"ε=0 下的 `G` 系统性偏低"之后，最容易写下的错结论是：**"那就搬到产品口径"**。
把 160 粒档案包（`docs/artifacts/*.bak` 每 9 取 1）在两口径各过一遍之后，这张表否掉了那个"那就"：

| 判据 | 评测口径 ε=0 | 产品口径 ε=0.2 soft |
|---|---|---|
| `G(multi) < 3` 被挡 | **84 粒（53%）** | **8 粒（5%）** |
| `G(long) < 3` 被挡 | 93 粒 | 4 粒 |
| 净兑现 `< 3` | 148 粒 | 117 粒 |
| 跨界方向 | **"ε=0 挡 → 产品过" 76 粒 : 反向 0 粒**（ΔG 中位 +2.51，157 正 / 3 负） | |

- 方向**完全单侧**，所以"偏严"是真的；**但搬过去之后那条线只剩 5% 的阻挡率 = 基本没有判别力** ——
  一条"谁都不会被挡"的门与一条"挡一半人"的门，**都不叫判据**。所以正解不是挪口径，而是三选一（都属判据侧）：
  (a) 留在 ε=0 但把线抬高；(b) **换成与探索无关的定义**（净兑现那一栏两口径都还严：148→117）；(c) 双口径并报、两栏都过才算。
- **会复发的形状**：拿"在位包在这条线下是红是绿"当换线的理由。现役在两口径下的确都红（0.00 → 4.63 点/局），
  但**同一批档案包**的分布从"53% 被挡"变成"5% 被挡" ⇒ 端点没变、分辨力消失了。
  ⇒ **换判据必须同时报：端点（现役） + 全池分布（多少粒被挡） + 跨界方向计数（正向 : 反向）。**
  这三样缺一样，都可能把"失去判别力"读成"修好了偏严"。
- 配套的一条口径卫生：**预注册里的判据要带样本量下限** —— 我这轮的落点写成"`freed ≥ 3×max(1,blocked)`"，
  在 n=3 的前置检查上直接打印出"②成立（两向差不多）"这种荒唐话（分母只有 3 粒）⇒ 已补 `n<30 或被挡<10 ⇒ 判"样本不足"`。

## 56. 用户的一句观感要拆成**两个各自可判的问题**，而且**每个分桶都要带 n、桶口径要写死**（09-25 凌晨 · Qoder §H-15）
原话："碰到一个人攒钱就会开始疯狂防御并且维持很久。" 这句话里其实缠着三件事，混在一起问就永远只能得到"是/不是"：
1. **"防御是不是因为对方在攒钱"** —— 这是**因果方向**问题 ⇒ 必须按"**该回合开始时**对手的 ep"分桶，读设防率随桶的变化。
   实测（现役 3p · 产品口径 · 200 局 · 高桶自适应合并后）：`9.3%(n=2431) → 4.6%(4772) → 3.4%(964)`（对手越有钱设防越少）⇒ **方向不支持**；`cbs1s2-band2` 是平的（6.9/8.3/7.4/8.9%）。
2. **"是不是维持很久"** —— 这是**游程长度**问题 ⇒ 读"同一席连续设防的最长回合数"与"≥3 连的局占比"，不是读设防率。
   实测：最长 **4 回合**、≥3 连只占 **4.5~6.0%** 的局；而 ε=0 对照那边**最长 1 回合、≥3 连 0.0%**。
3. **"这件事在不在门禁的视野里"** —— 前两问的答案都只在产品口径下非零 ⇒ 门禁那一侧读到的永远是 0，**"没报"与"没有"不是一回事**（§47.4 同族）。
- **桶口径必须写死在实现与读数里 —— 而我第一版写的口径当场被自己的门测死了**：原本读的是"事件流里 `ep` 前缀和"，假定"一回合内 5 条 `action` 全先于结算"。
  门 D151 第一版去验这条假定，实测**一局里 64 次结算落在 action 之前/之间、只有 13 次是干净分界** ⇒ 假定不成立；而且前缀和**只加不减**（对手花了不扣），
  量出来的是"它一辈子挣过多少"，不是"它手里现在有多少"。⇒ 正确读法只有一个：**在被评席做决策的那一刻直接读 `state.p[0].ep`**，回合号用 `state.round`（实测单调）。
  **教训**：凡是"从事件流重建某个状态量"的读数，都要先去引擎里**读那个量本身**对一遍；重建省下的那几行，代价是整条判据可能是假的。
- **每个比例都要带分母，且小分母不许当 0%**：`ep≥10` 那一桶只有 20 次出手（现役）——直接算成"20.0%"就会看起来像一个发现。
  ⇒ 本量具的落点写的是"**分母不足 ⇒ 这条因果没量到**"，而不是任何方向的结论。（与第 53 条"判定旁边印分母"同规。）
- **同一条轴不许自己当自己的对照**：上面第 1 问的分桶变量（对手 ep）在这个装配里**与回合数同向单调**（替身只攒不花 ⇒ 第 2 回合 ≈ ep0~1、第 12 回合 ≈ ep5+）。
  ⇒ 这种时候"高桶设防率低"既可能是"不冲着他"，也可能只是"晚期不摆架势"。修法有两层：
  读数层——**把混淆变量并排印出来**（本量具现在每桶印"该桶平均回合"）；结论层——**把强度从"看到负相关"降到"没看到正相关"**。
  真要分离就得换装配（对手 ep 振荡），那是另一件量具的活。**能印就不能猜。**

## 57. "A 导致 B"这类观感，**单档装配永远答不了**——要造一个把两条轴分开的第二档，在同一坐标上配对（09-25 凌晨 · Qoder §H-19）
"`cbs1s2-band2` 的设防率随对手 ep 从 7.9% 涨到 51.8%"**本身不算证据**：这一档装配里对手是纯攒钱替身，第 r 回合它的 ep≈r−1 ⇒ **ep 轴与回合轴重合**，
"它看见钱才防"与"它越晚越防"是同一句话。分开的方法是把 ep 压住、其他不变，再在**同一回合号**上比：
- `hold`（钱一路堆）第 6/8/10/12/14 回合：`29.8 / 38.1 / 38.1 / 42.8 / 44.8%`
- `cycle`（堆到 4 就全花掉，同回合对手只有 ep 3~4）：`14.8 / 17.0 / 12.6 / 16.4 / 19.0%`
- 而第 4~5 回合两档 ep 还相同时，两条曲线**逐字重合**（15.3% / 19.8% 两档相同）⇒ 分岔恰好发生在 ep 分岔处。
⇒ 这才叫"看到响应"。同一套配到线上包上：两档各回合都是 3~8%、无系统差 ⇒ **线上包没有这个响应**。
- **可搬走的三条**：① 造装配时**先问哪两条轴会天然重合**（这里 ep 与回合号；同类还有"局长与死亡数""广度与出手数"），重合就只能描述、不能判因果；
  ② 判因果要造**第二档把其中一条轴钉住**，并证明两档在"该轴尚未分岔"的那段曲线重合（这是免费的安慰剂对照）；
  ③ 报告要写"同一坐标配对差多少倍"，而不是"某一轴单调"——后者读者会自动脑补成因果。
- **配对之外还要一个"安慰剂窗口"**：两档在**该轴还没分岔的那几回合必须逐字重合**（这里 r4/r5 两档都是 12.1% / 16.6%，n=619/650），
  分岔之后才分开（r6 起 29.7% vs 15.8% … r14 45.2% vs 14.9%）。重合段是免费的"两档没别处不一样"的证明，**没有它，两档差值随时可以是装配本身的差**。
  再补一刀：同一批读数只取"自上次自己决策以来没掉过血"的子样本，`ep5~9` 33.0%→32.7%、`ep≥10` 51.8%→**52.3%** ⇒ "挨过打才防"解释不了这条上升。
- **同一条读数的副作用**：它把用户实机报的病归到了一粒**候选**（`cbs1s2-band2`，我前一夜还记它"四栏最均衡"）而不是线上包 ⇒ 候选排序里若没有"对手攒钱时的设防持续性"这一栏，
  一只**会在产品口径下自己跟自己对成龟群**的包可以一路绿灯过门。这条已经写进早报的裁定件，**我没动任何门**。

## 58. 抓到一粒包的病之后，第一个要做的动作是**扫全池问"这是个例还是体质"**（09-25 凌晨 · Qoder §H-21）
`cbs1s2-band2` 有"对手有钱→就转防"的响应（倍差 5.6×、同席连防 34 回合）——这时最省事的叙事是"这粒候选不行，换一粒"。
把同一个读数扫最近 44 粒臂包（`--quiet=1` 汇总表 · 60 局/粒）之后：**倍差≥2 且高桶设防率≥20% 的有 13 粒 / 41 个不同权重 = 32%**，
而线上包与 `v7aim3-93` 只有 0.12~0.16×。⇒ 这不是"某粒臂运气差"，是**当前配方稳定养出这种体质**。
- **为什么这个区分值钱**：个例 ⇒ 换候选；体质 ⇒ 换候选没有意义（再抽一颗骰子，还是有 1/3 概率抽到同一种体质），要动的是**训练场或判据**。
  两者的代价差一个量级，而**只有扫一遍全池才能分清**——单粒包的读数本身永远说不出比例。
- **配套的两条卫生**：
  ① **扫之前先去重**（剥壳只哈希 `a` 数组）：这次 44 粒里其实只有 **41 个不同权重**——`cbs1s3/5/6` 与 `cbig1s3/5/6` 是三对逐字节相同的包
    （与 09-24 记的 `EPIRUS_SEL_LAND` 咬合率 3/6 同源：带内换人在同分带里换不出新东西）。不去重就会把 32% 报成 34%，还会把"两粒包都有病"当成两条独立证据。
  ② 汇总表要**同时印分子分母的桶值**（`ep0~1 → ep5~9 → ep≥10` 三桶 + 连防长度），只印倍差就会有人拿 n=41 的短局行去和 n=9000 的长局行比大小。
- **顺带得到的好处**：这张分布就是将来"设防持续性"那一栏的**线该画在哪**的底稿（倍差 2？连防 5？）——有分布就别拍脑袋。

## 59. 同一个"浪费率"可以来自**两种相反的病**；而"按决策计"与"按珠子计"两把尺不许互相校验（09-25 凌晨 · Qoder §H-27）
"珠浪费率高"是一个**总量**（`chargeProfile`：得珠 / 花掉 / 过期）。把同一个数按"蓄能之后**下一次决策**那一刻电磁炮买不买得起"拆开，两粒包立刻分到相反的方向：

| 包 | 蓄能后配到下一次决策 | ① 买不起（经济） | ② 买得起却没射（选择） | ③ 射了 | 真源浪费率（按珠子计） |
|---|---|---|---|---|---|
| 现役 3p | n=385 | 1.0% | **68.1%** | 30.9% | 48.2% |
| `v7cmin4-82` | n=1617 | **83.3%** | 11.7% | 5.0% | 88.2% |

⇒ 两粒都"浪费"，但**一粒要动经济（收入/价），另一粒要动打分/菜单** —— 拿总量提方案就会开错药。
- **"② 里它到底在干什么"必须并排印**：现役 262 次里 **256 次在按 ジ**（不是被别的卡抢了珠，是纯粹继续攒）；
  `v7cmin4-82` 是 ジ 143 / 蓄能 35 / 聚能环 11。这一栏把"空蓄能"与 §H-1 的"大雷可达时成交率 0.0%"接成**同一条**：**它把"攒"当成了动作本身**。
- **两把尺各量各的**：本表按**决策**计，真源按**珠子**计 ⇒ 两者天然不等（一颗珠可能被别的卡吃掉；一次蓄能也可能与手上已有的珠混在一起）。
  所以读数旁边必须并排印真源那一行并写明"**不许拿一个去校验另一个**" —— 我第一版就是看到"48% vs 68%"以为自己算错了，差点把发现当 bug 删掉。
- **窗口要判"东西还在不在"**：珠只保留到下一回合，而"该席下一次决策"可能已是两三个回合之后 ⇒ 必须先过一道 `beadAlive`，
  把"隔太久才决策"的那批**单列成 `beadGone`、不混进①②的分母**。我第一版没判，造出过 8 次假"买不起"（这批包实测 `beadGone`=0，但**判据要在，不能在读数里靠运气**）。

## 60. 用"响应量"分类时，必须同时量"水平量"——否则**最糟的那一类会被读成健康**（09-25 凌晨 · Qoder §H-30）
我把档案包按"对手有钱时设防率 ÷ 没钱时设防率"（倍差）分类，判据 `倍差≥2 且高桶≥20%`。45 粒 × 120 局重跑后发现：

## 61. 评一条判据时，**不许用定义标签的那个变量去算命中率**（09-25 凌晨 · Qoder §H-40）
我把档案包分成"响应型（倍差≥2 且高桶设防≥20%）/ 恒定龟缩型（低桶设防≥20%）/ 干净"三组，再去评候选判据"哪条线画得住"。

**这两行毫无信息量**：判据用的就是分组用的那个变量，100% 是定义给的，不是量出来的。

## 63. 想把"已经算过的数"当免费代理判据，第一件事是测**方向**，不是测阈值（09-25 上午 · Qoder §H-45）
问题本来是"能不能零成本加一栏"：门的 ε=0 镜像已经算了设防份额、伤害/回合、出手伤害份额、局长、蓄能/局、珠浪费，拿它们预测"有钱→转防"体质不就免费了？
194 粒对表的实测：**六栏最好的工作点只有 TPR 60% / FP 24%，组合两栏也只有 21%/16%——全在对角线附近**；更难看的是**方向是反的**：被产品口径判为龟的粒，在 ε=0 镜像里的设防份额中位数反而**更低**（49.3 vs 58.8），现役好包 `v7cmin4-31` 的 `按ジ%` 是七粒锚点里**最高**的 79.3%。
⇒ 任何以"设防份额"为键的判据会**优先误伤现役**。机制讲得通：ε=0 五席同包互不犯 ⇒ 高设防率是**那个口径下的常态**，不是体质；体质只在"桌上真坐一个攒钱的人"时显形。
- ⇒ 规矩：提"用现成读数当代理"之前，先跑**标签组 vs 对照组的中位数**看方向（一次 4 行代码的量），方向对了再谈阈值与 ROC；**方向反了就是反证，要如实写反证**，不许挑一个能分开的手势凑数。
- **同族**：第 61 条"不许用定义标签的变量给判据打分"（这里的问题是另一面——**用了不同变量，但它测的是另一件事**）；第 49 条"口径差会改写结论"（同一只包两个口径两个世界）。

## 64. 用"分桶比值"下因果结论之前，必须再跑一档**把桶变量钉住**的对照；单档比值会把时间轴记到钱头上（09-25 上午 · Qoder §H-53）
我有一副干净的因果装置：`hold`（对手永远出ジ ⇒ 钱一路堆）与 `cycle`（堆到 4 就全花掉 ⇒ ep 钉在 0~3）。用它证明了 `band2` 的"有钱→转防"是真的（同回合号上 2.46×）。
然后我把**只跑 `hold` 一档**的 1004 粒筛表当成了"体质流行率"（响应型 19.4%）。补跑 `cycle` 档逐粒同回合配对后：**192 粒"响应型"里 81.3% 的 Δ(hold−cycle) 设防率不到 15pt，中位只有 +4.1pt** ⇒ 它们不是"有钱才龟"，是"**越晚越龟**"——因为 `hold` 档里"对手 ep≥10"这个桶几乎等价于"这局已经打到 r25+"（桶平均回合 25~27）。
- ⇒ 规矩：**(a) 桶变量与时间轴同轴时，单档比值不构成因果证据**（先算"这个桶的平均回合是多少"，如果它随桶号单调涨，就必须钉时间再比）；**(b) 已有的对照档不是可有可无的加固，它是这条结论的准入条件**——我省掉它一次，就把 3.6% 报成了 19.4%（差五倍）；**(c) 报告流行率时要同时给"钉住时间后仍成立"的那一档数字**，两者并列，读者才不会拿粗筛去算代价。

## 65. 立阈值之前，先用**跨种子极差**买门票；贴线的那一段最容易是噪声，不是差异（09-25 上午 · Qoder §H-55/E19）
我量出一个看起来很干净的分离：26 粒"好包"的同回合配对 Δ 全 ≤ +14.2pt，两粒病例是 +17.2 / +22.0 ⇒ 顺手把线画在 15。
拿第二个种子复跑同一粒 `eco-34`：**+14.2 → +15.9，当场跨线**（判定从 C 型跳到 B 型）。同批两端却稳（`band2` +22.0→+24.8、现役 +1.9→+0.5）。
⇒ **不稳的不是两端，是贴线的中部**。所以"这条线分得开两端"和"这条线可判定"是两件事：前者是描述统计，后者要求**线两侧各留出一个大于噪声的带**。
- ⇒ 规矩：报任何阈值时**同时报那个阈值附近的测量噪声尺度**（本例：3 粒种子 × 60 局的跨种子极差 ≈ 1.3pt（大信号处）~ 4.8pt（贴线处）），并做三件事：

## 72. 新量具必须先测**自己的重测信度**，再谈它和别人的相关性；ρ 低可能是"没关联"，也可能是"我没测准"（09-26 夜班 · Qoder §E29b/§E29c）

|---|---|---|

| 梦魇/铁索连环/挑衅违约/过载血债算不算"打我"？ | **不算** —— 它们要么 `source` 为空、要么 `via` **不是一张真卡**（`R.byKey[via]` 不存在）⇒ 与"`landByKey` 含非卡键算出 44900% 份额"同族事故 |
| 一回合里既挡下又被穿透？ | 记**有效**（它确实挡下了东西），不重复计半 |
| 自损 / 打别人 / 反击伤害？ | 都不算"有人朝我来"（`source===我`、`to!==我`、`via:'counter'`） |
⇒ 规矩：**口头判据一旦落成代码，歧义处理就变成判据本身** —— 必须写在一处单一来源里、被门用**合成事件窗**逐条钉住（不要靠"真跑一局希望碰上某种局面"），并在探针/promote/门**共用同一个分类器**（否则三处各写一遍必漂移，本仓已为此写过 D150/D155 两条门）。
- 顺带一条收益：把"三档"实现完之后，它的**重测信度 r_tt = 0.85（防御手 ≥500 次的那一组 0.98）**，而我原来那把"空挡率"只有 0.07→0.26。
  ⇒ 用户那句"完全没人打他"比我的"没挡住东西"更好测 —— 因为它数的是**有没有被瞄准**（分母大、事件明确），而不是"反事实的如果没有防会怎样"。

## 81. 中期读数（interim look）在配对设计里**比终期读数更容易骗人**，而且符号全一致也救不了它（09-26 夜班 · Qoder §E51，我自己把 −0.022 读成了 −0.111）

|---|---|---|

3. 负方向的过度声明要**和正方向一样加倍审查** —— "某条路已死"这种结论会直接关掉后续实验，代价比"再多跑几对"高。

## λ 的**饱和机制**（Qoder 09-28 §E126 实测 · DS 补记入册）

`EPIRUS_ANCHOR`（离种子的距离惩罚，λ）不是"越大越保护"，**λ≥0.08 进入饱和区**：
λ 网格同 seed{31,71} 实测 `0`→0/2 · `0.03`→0/2 · `0.05`→1/2 · **`0.08`→2/2** · **`0.15` 与 `0.08` 产物逐位相同**。
机制：λ 大到一定程度后，"**离种子近**"这一项**压过胜负分差**，于是它成了当选理由的**单一占位量** ⇒ 再大就等于**几乎不训练**（产物退化成种子的复制）。
⇒ 读法：**λ 只有"还没占住当选理由"的那一段才有效**；要判断是否已饱和，最便宜的办法是**拿两档跑同 seed、看产物是否逐位相同**（相同 ⇒ 已饱和）。
⇒ 与 §N12 同族（单一量占住当选理由），也与本册"**先量判别力、再立门**"同规矩：**别把饱和后的值当成"更强"**。

## 82. `oracle − best_single` 只有在**挑包与算钱分家**时才是"上界"；在同一批格子上取 max、又没有第二份读数的，它是"取 max 的贪心"—— 零分布能造到十几 pt（09-29 下午 · Qoder §E149b 实测，我自己当天下午把一个假数当成了"还有 11pt 空间"）

**实测**：6 粒过闸包 × 2136 张异质桌 × 每桌 8 局，**同数据** `oracle − best_single` = **+11.60pt [10.88, 12.32]**；
把每张桌的 6 个读数**随机重新分配给包**（保住桌内联合分布与包边际）、跑**同一套**流程 × 200 次 = 零分布，**中位 13.16pt**、p95 13.78。
⇒ 实测**低于**纯噪声造出来的量级 ⇒ 那 11.60pt 里没有一块钱是"按环境换包"的空间。
**为什么这个零分布是干净的**：`oracle` 取的是每桌读数的 max，而**桌内置换不改变 max** ⇒ 零分布与实测的 oracle 项**逐字相同**；
差异全部落在 `best_single` 一项 —— 零分布里它等于"随机拿一粒"（= 池均值），实测里它是挑出来的最好一粒。所以 `13.16 − 11.60` 恰好就是那粒通才相对池均值的真实优势，**两者不能相加**。

**反例（不是所有 oracle 都坏，区别在有没有分半）**：`tools/analyze-5p-envfit.mjs` 同时印 in-sample 与 **split-half**（seed 档 0 挑包 / 档 1 算钱，两向平均）；
后者在"包无差异"的原假设下期望为 0 ⇒ §E142 **+12.35** / §E143 **+3.79** / §E147 **+3.36pt** 走的是 split-half，是可信的可实现上界。
而同一张同质表的 in-sample = +4.60pt，它的零分布中位 = **4.57pt** ⇒ **那一行基本全是偏置**（该工具自己也印着这句话，只是我读的是另一份没有分半的产物）。

⇒ **三条规矩**：
1. 报"上界"必须同时说明**挑包与算钱是不是分家的**；没分家的只许叫 `in-sample 上界`，并且**必须配一台零分布**（同一套流程 + 置换标签）才知道它值多少钱。
2. `--dump-per` 这类"**每桌只有一行**"的产物**天生没有分半** ⇒ 只许配"真造一台路由器"（dev 定参 / test 结算）来读，不许印 oracle 当上界。
3. 任何路由器必须同时跑一台**负对照**（切断标签与胜负的关联，保住边际分布）。
   ⚠ 负对照读数**与实验组逐字相同 = 那台对照在空转**（§E149 第一版："在桌内置换名字的座位"，而加性模型只看名字**集合** ⇒ 恒等置换）。
   这与 D202 ⑥ 的"门的输入字段名写错"同族：**对照要能红，才算对照**。

## 83. "**闸放行 ≠ 线接通**"：登记进名单、闸不报错，**不等于**那个值真的到达了作用点（09-30 夜 · DS 清单要求入册 · Qoder 落门 D206）

## 85. 静态钉要钉**结构**，不能钉"**那个词出现过**"；断言与消息必须用**同一个表达式**（09-30 夜 · Qoder 自己写的 D210⑨ 被自己的变异测试测出**假绿**）

**实测形状**：意图是"这台仪器必须两张桌都能起"，我写的是 `indexOf("'script'") >= 0 && indexOf("'human'") >= 0`。
把派发那一行 `['script', 'human']` 改成 `['script']` 之后**门照样绿**——因为 `flag('src', 'human')` 里也有 `'human'` 这个词，**它在文件里根本不唯一**。
⇒ 改成钉那一支的形状 `/\[\s*'script'\s*,\s*'human'\s*\]/` 才红。
**How to apply**：每条静态钉的变异测试要**专挑"词还在、结构没了"那种改法**（只改被钉结构本身，常常测不出这种假绿）；与第 73 条（新门当天做一次变异测试）是同族，但补了"**变异要往哪个方向拧**"。

## 86. 配对自助**必须播种**；比率的读数旁边必须有**看得见的分母**（09-30 夜 · Qoder §E169/§E169b，第 20、21 条口径陷阱）

  实际分母是"每局约 **0.1** 个'有珠且买得起'的时刻"——**两个数之间差的是几个样本**。

## 87. **一批桌子不构成一次复现**：进入裁定材料的效应量，至少要有**两批独立 seed 带**（09-30 晨 · Qoder §E170 实测，我自己把单批点估计当成效应量引了三个小时）

**为什么这条是被测出来的，不是想出来的**：本班全部产品口径读数都来自**同一批 120 块桌子**（`seed0=4100`）。配对自助把那 120 块重抽得非常诚实，但它只回答"**这批桌子内部**换个重抽顺序还成立吗"，
**没有回答"换一批桌子还成立吗"**——后者只有第二次抽样能回答。⇒ 我把今晚的头条与 `tie=1` 推到四批独立带（4100 / 8800 / 13300 / 21000，各 600 局/臂）上重跑：
- **站住的**：开档 vs 关档 **+11.67 / +7.33 / +12.67 / +15.67**（四批 CI 全离 0）；代价两腿每批复现且量级几乎不动（蓄能 −0.27~−0.35 ‖ 电磁炮 −0.20~−0.26 ‖ 环 −3.6~−4.2pt ‖ **珠转化率四批全归 0**）。
- **没站住的**：`tie=1` 那句"零代价 **+1.75~3.50pt** 收益"。同一批桌子上直接配对（参照臂 = 同批 `tie=0`）是 **+0.50 / −1.33 / −0.17 / −3.00，四批 CI 全部含 0**；
  而它**真正稳定复现的是代价**：防御占比 **+5.66~+6.48，四批 CI 全离 0**。⇒ 那句话是**首遍点估计被当成效应量**的典型形状。
- **顺带量到的"批次抖动"幅度可以当尺用**：同一档、同一装配、同一局数，**胜率点估计跨批抖 ±4pt**（+11.67 vs +7.33），**风格占比列跨批抖 ±1~3pt**（集火 +0.69/−3.54/+0.45/+0.66）。
**How to apply**：
1. **凡是写进裁定材料/README/早上那一页的"效应量"，要么有两批以上独立 seed 带，要么改写成区间措辞**（"约 +7~+16pt，四批"），不许把单批点估计写成"值是 X"。
2. 换 seed 带就是第二次抽样 ⇒ 复量**便宜**（本仓一台 600 局/臂 × 两桌约 3~5 分钟）；**判事之前先花这 5 分钟**，比事后写更正便宜一个数量级。
3. 复量要**同批内配对**（用 `--base=` 换参照臂），不许把两批的两个点估计相减当配对差 ⇒ 那正好丢掉"批次"这一层方差，也正是我这次犯的错。
4. 与第 19 条（风格指标是桌形的函数）配对使用：**第 19 条防"对手种类"，本条防"对手批次"**。

## 88. **"加不加这个维度"的对照实验必须自带两枚对照：一枚纯噪声（标定"加东西"的税）、一枚已知有用（标定这把尺的分辨率）**（09-30 · Qoder §E179 实测，第一版没有对照 ⇒ 一片 ⛔ 却什么都不能引用）

**为什么这条是被测出来的**：§E179 要给"往 `featuresV7` 追加一块对手信念维度"这笔换代钱先量信息。第一版的表只有"候选 Δ vs 参照"一列，跑完是六族全 ⛔、读数 −0.07~+0.61 一片，
**这句话什么都支持不了** —— 因为它分不清两种完全不同的世界：①"这些维度确实没信息"；②"这把尺吃不下任何新条件"。补两枚对照之后 6 秒内就分开了：
- `NC`（每席一个**随机** 4 档标签）三批独立 seed 带 **−0.24 / −0.13 / −0.09** ⇒ 纯噪声条件恒 ≤0，且"加一个条件"的税在这里 ≈ 0.1~0.2pt；
- `PX`（**现役网络本来就在用**的"更早两手的键"）三批 **+0.85 / +1.05 / +1.06** ⇒ 这把尺看得见约 1pt 的真信息 ⇒ **它是本尺的分辨率上界**；
- 于是候选族的读法才有意义：最强的 `D4` 只到 PX 的 **16~31%**、六族全上才到 52~71% ⇒ **"不是尺坏了，是这些维度确实薄"** —— 这一句是本次唯一能引用的负结果。

**How to apply**：
1. 任何"加变量值不值"的实验，**跑前**就把 `NC`/`PX` 两枚对照写进同一张表；只有"候选 Δ 落在 NC 与 PX 之间"这一种读法可引用。落在 NC 之下 = 交税；够不到 PX 的一半 = 不值一次换代。
2. **凡是带学习器的那一列（分类命中率、拟合分、fit），先看 NC 行掉多少**。本次该列上 NC = **−1.88pt**、PX = **−0.32pt** ⇒ 一个随机条件就能打掉一整列 ⇒ **那一列的正负只读得出"加条件的税"，读不出信息** ⇒ 判据必须换成**无学习器**的（条件格众数；格子太稀就退回边缘众数，**且退回计入分母**，否则就留下"只统计有把握的格子来刷分"的洞）。
3. **改判据（加守卫或撤守卫）必须把后果机械印在日志里**：列出"若把这条守卫加回来，哪些行的判定会翻面"。**只许对照行翻**；任何一条候选行因它翻面 ⇒ 那次修改就是挑对自己有利的尺，必须升级为结论级变更交用户裁定，不许自决。（本次实测：撤掉"覆盖率相对参照掉不过 2pt"只让 PX 两行翻面，六族候选无一翻面 ⇒ 修尺不改结论。）

## 89. 文档面只许钉"**指向不存在的东西**"（负向），不许钉"**某句话必须出现**"（正向）——后者同时造出假绿与假红（10-06 · 用户点名 · 实例是 D225⑩c 红了五笔提交）

## 90. "父指针是**路径**"与"父指针是**哈希**"不是一种证据 —— 路径要经过"现在住的是谁"这一步解析，而槽位文件会被覆写（10-06 · §E367 · 实例是我自己上一版的误诊）

**实测形状**：谱系图出现"子代比父代、甚至比祖父代还早"（`e35prod807` @09-26T06:37Z，父被解析成现役 `SHIPPED-Ldemo` @09-27T08:55Z，
祖父 `E51-t8-713` @09-26T17:10Z）。我第一版的诊断是"边是真的，只是槽位节点的 ts 是**进槽时刻**"，还据此把这类边改成虚线。
查了权重实际产生时间之后**这个诊断错了**：现役那份权重的 META.ts（09-27T08:55Z）与它最早可证的 git 实体（提交 3c17e23 @09-27T10:42Z）
只差 2 小时 ⇒ 不存在"权重其实更早"。真正的机制是 `lineage.mjs` 的第②③级退路拿 **`EPIRUS_SEEDPACK` 这个路径**去反查图上的节点
（`js/bundled-champion-3p.js` ⇒ 按 basename 反查 ⇒ 命中的是**今天的槽主**），于是"当时槽里那份已被覆写没留档的权重"被接成了现在这一枚。

**三条可复用的判据**：
① **想知道一份权重什么时候产出来**：包自己 META 的 ts（训练器保存那一刻）‖ `widhunt.mjs <前缀>` 扫全部历史 blob 逐枚算权重指纹，
   再对命中 blob 跑 `git log --all --find-object=<blob> --format=%ad | tail -1` 取最早可证 ‖ `ship-times.tsv`（槽文件逐提交算指纹得到的首次上槽表）。
   三者对得上才叫结论；**字符串命中不算**（同一个哈希会作为"子代的父字段"出现在别人的 META 里）。
② **任何"按名字/路径反查身份"的退路，都要配一条时间守卫**：解析到的实体比子代还新 ⇒ 那个解析结果不可用，
   **先按"那一刻的真实状态"重解析一次**（本仓的做法：`ship-times.tsv` 就是槽位时间轴，问一句"它跑的那一刻槽里是谁" ⇒
   §E368 那 5 枚全部改接到真父 `v7cmin4-31`），重解析不出来才退回"不可考"并写明原因（不许静默接上去，接上去就是一条看起来合理的假血统）。
   实录级（包自己记的哈希）**不受这条影响** —— 它倒挂该怀疑的是 ts，不是边。
③ **诊断错了要更正记账，不要改写历史**：v1.6.14 里那段原话保留，新条目在上面声明它错了（§E346 同一条规矩）。
   ⚠ 比"改错了"更贵的是**改错了还顺手把画法改了** —— 虚线机制本身没错（留作守卫漏网时的兜底），
   但文案如果继续讲那个错诊断，图上就写着一句假话（第 89 条说的"文档与实现对不上"，这次是"图与数据对不上"）。

**连带的未决面**：同一机制影响的远不止被抓到的 5 枚 —— 那张臂级表里有 **182 支臂**的 `seedpack` 都写着同一个槽文件路径，
只有 ts 恰好早于现役产出的那 5 枚在时间上露馅。⇒ 现在图上能区分来路（新列 `parentSrc` = `hash` / `seedpack` / `arm` / `demoted`），
但**推断级父边仍然画着**；要不要一律不画或改成虚线 = 用户裁（任务 #147）。

## 91. 新写的判据**必须做一次"把 bug 加回去"的变异**；而变异不红时第一反应不该是"阈值太松"，是**它看错了层**（10-06 · §E369 · 实例是我为刚修的 bug 写的那条自检）

**实测形状**：撤掉平面态那道 `clip(padL-5 …)` 之后，我给它配了一条自检：「平面态往左平移 900 ⇒ 必须有点出现在画布左 1/4」，
判据读的是 `scr[]`（命中表）。跑起来 27 PASS / 0 FAIL，看起来"接住了"。
**把那道 clip 原样加回去再跑 ⇒ 还是 27 PASS / 0 FAIL。** 因为 `scr[]` 记的是**几何落点**，
`clip()` 只决定"这一片有没有被画到屏幕上"，读表永远读得到 ⇒ 那条判据守在一个**没被这次修改影响**的层上，
它绿不绿跟 bug 在不在毫无关系。改成**读像素**（`getImageData`：中心 vs 自己半径之外四个方向，只测 `alphaOf ≥ 0.5` 且完整在画布内的点）
之后：修好的树上 102 枚里 91 枚"真画出来了"，把 clip 加回去 ⇒ **0/102，当场红**。

**三条可复用的判据**：
① **每条新判据的验收动作是"把 bug 复原一次"**，不是"看它绿"。绿只说明它没在拦别人，红才说明它在拦那一个 bug。
   与第 89 条同族但不同轴：89 条管"这条腿该不该存在"，这条管"这条腿存在了但**接错了线**"。
② **判据要落在被修的那一层**。几何 vs 像素、命中表 vs 实际绘制、源码字符串 vs 运行时行为、配置值 vs 生效后的读数 ——
   这四对是本仓反复踩的形状。写的时候问一句："bug 复原之后，我读的这一个量会不会**变**？" 答不出就先去复原一次。
③ **阈值不是①的替代品**。把 60% 改成 90%、把 12 枚改成 50 枚都不会让一条看错层的判据长出牙；
   反过来，一条真在看的判据在变异下会**整块塌掉**（91→0），这种"塌得干净"是可以拿去汇报的证据形状。

**同一族的第二条（同一次改动里差点白修）**：拟合要先算包围盒 ⇒ `PL` 的定义得挪到前面，而后面那一份原样留着。
**函数声明会提升，后一份静默覆盖前一份** ⇒ 页面照跑、`node --check` 照绿、`lint-viewer` 照绿、自检也照绿（因为覆盖后就是旧行为）。
⇒ 凡是"把一个定义搬到别处"的改动，搬完要**当场把原处删干净并搜一遍同名声明**；
这类错误没有任何一层会响，只有"变异一次"会响（把 fit 短路 ⇒ 那条旋转判据恰好红，见 §E369 的变异表）。

## 92. 把**旧产物**捞回来在新版本重量：身份守卫、兼容通路要有门钉着、两个时代的读数分列 —— 三条少一条这批数就是假的（10-07 · §E370 · 16 枚 v1.3.x 旧冠军）

**为什么要这一条**：演化页的低端一直是空的，因为槽位时间轴上 39 段里有 20 段"面板上没名字"（v1.3.0→v1.3.58 那四天）。
把它们量出来要穿过三层各自会静默说谎的地方：

① **身份守卫先于测量**。从 git 取"那一段的槽文件"时，段起点取错一个提交就整体偏移一格，
   而**量出来的数照样好看、照样能画**。⇒ 取出后必须 `widOf(内容) === 时间轴那一行的 wid`，逐字相等才继续；不等就红着退出。
   （与第 90 条同族：字符串命中 ≠ 身份。）
② **兼容通路必须本身有门**。旧形状（v4/v5/v6 动作段 14 维）嵌进 v7 容器之后，chooser 若按长度判形状就会悄悄切到新口径
   ⇒ 目标退化（实测破墙 12.25→7.70）。这条不是"我以为它走旧口径"，是**门 D56 用行为断言钉着**：
   同一份权重"原生跑"与"嵌入+标记跑"必须**逐场结果相同**。⇒ 引用旧包读数时要说得出"走旧口径"这件事由谁保证。
③ **两个时代的读数不许并成一句话**。量到的必须是"**这枚旧权重在今天的规则下值多少**"，
   而它自己 META 里的 `firstRate` 是**当年那台仪器**量的（今天的 Hp 10.8~26.2 ‖ 当年 0.376~0.618）。
   ⇒ 分列存放、分列引用；缺字段就如实留空（`037b2f71` 的 META 里根本没有 `firstRate`）。
   ⚠ 还有一条容易被忘的**解释边界**：旧包低分有一部分不是"策略差"，是**菜单缺维度**（看不见今天的新卡）
   —— 上槽体检里"反弹墙穿透卡零命中 13/16 枚"就是这个机制。⇒ 报数的时候要连着这条一起报，否则会被读成"当年的冠军都是菜"。

**顺带两条工具层的坑**（都在 `champion-map/oldpacks.mjs` 头注里）：喂绝对路径给"自己按 ROOT 解析路径"的工具会拼出
`D:\…\D:\…` 而 ENOENT 崩掉 ⇒ **崩了不能记成"体检没过"**（要分开记 `CRASH`）；一批重测要 110 分钟 ⇒
**认证那一遍不能与它并发**（浏览器三道的时间判据会失真，§E355b 同一件事）。

## 93. 读 TSV 时把整份文件 `.trim()` 一下，会**吃掉末行的空单元格** ⇒ 往后追加的列整体错位（10-07 · §E376 · 实例是 `coords.tsv` 末行 31 列被读成 26 列）

`readFileSync(f,'utf8').trim().split('\n')` 这一行在本仓的 `champion-map/` 里有 **61 处**（32 个文件）。它看着无害，但 `.trim()` 剥的是**整份文件尾部的所有空白**，
而 TSV 的制表符就是空白 ⇒ 只要**最后一行**末尾有空单元格（`…\t\t\t`），那几个字段就被连着削掉。

实测这一次：`ruler-figs` 重画完 `coords.tsv`（917 枚，末尾正是新加的那批，当选键四列 + kin 全是空的）⇒ 末行 31 列被读成 26 列，
`attach-hp` 再往尾部 append `Hp/De` 两列 ⇒ 那一行的 **Hp 落进 Sc 的位置**。只错一行、一声不响，而且错的正是这次新加的那批点。

三条要点：

① **只许剥行尾的换行，不许剥空白**：`.replace(/\r\n/g,'\n').replace(/\n+$/,'').split('\n')`。
   同一族的另一半是 **CRLF 的末列表头**：不先归一行尾，`split('\t')` 出来的最后一个键是 `'lineage\r'`，
   于是 `o.lineage` 恒为 `undefined` —— 今天它"没坏"只是因为下游 `attach-kin` 本来就要把那一列清空，**两件坏事撞成了同一个结果**（侥幸不是设计）。

② **追加列的工具必须幂等 + 自证行宽**。`attach-hp` 原来无条件 `concat(['Hp','De'])` ⇒ 连跑三次表尾就有三对同名 `Hp`，
   下游按名字查列只看得见第一对（旧数），而新数在最后一对里。现在它表头已有这两列就**原位覆盖**，并在写之前判"每行宽度 == 表头宽度"，
   不合格就不写文件（判据挪到写之前也是这一条的一部分：原来红在写之后，等于每次报错都顺手把表弄脏一次）。

③ **顺序是数据的一部分**。`attach-hp` 跑在 `attach-path` 之前还是之后，决定 `Hp/De` 落在表中间还是表尾 —— 两种都能跑通、都不报错，
   但产物的列序不一样。⇒ 把五步顺序写成一台 `champion-map/rebuild-coords.mjs`，别再让顺序只活在各个脚本的头注里。

## 94. 撤一个机制要**沿那层公式的输入撤**，不是沿用户点名的那个词撤；改了坐标映射，所有"以它为锚"的交互都在改动面上（10-07 · §E377 · 实例是我撤强制缩放时留下居中，和换缩放支点时没改滚轮锚点）

① **只撤被点名的那一半，另一半会变成新病**。用户原话是「你现在立体模式下会强行把表格全塞在窗口里**而进行缩放**，
   把这个东西去掉」⇒ 我第一版只删了缩放比 `s`，留着那层的居中 `ox = (w-bw)/2 - x0`。而 `x0` 是投影包围盒的左沿，
   **它跟着平移量线性移动** ⇒ 居中把左键拖动原样抵消，立体态拖动整个不起作用 —— 比"截断"更难用，而且用户上一轮
   刚说过"拉不回来"。红它的不是我看代码看出来的，是我给这次改动写的那条判据②（「平移之后 def-31 仍在画布外」）。
   ⇒ 撤机制时把那一层的**公式输入**逐个过一遍：哪些项还留着、留着的那一项读谁。别按名词删。

② **投影变了，锚点必须一起变**。把横轴缩放支点从画布原点挪到数据区左上角（否则 `tkx=0.4` 时整张数据区连日期刻度
   压进左栏，实测最左那枚 x=136 而分界在 340），滚轮那句"以光标为中心"的 `p' = m − f·(m − p)` 就得跟着改成
   `p' = (m − 支点) − f·((m − 支点) − p)`。这一处我**一开始根本没想起来** —— 是页内自检派了真 `WheelEvent` 才红出来的
   （实测横漂 41px）。同一族里还有一处：命中判定/光标高亮读的也是投影，凡改投影先列这几处。

③ **派真事件的那条判据，第一次红的原因往往不是它想钉的病**。那次红报的是「派了 wheel 而 tKx 没动」——
   因为上一段刚把 `tKx` 顶到钳位上限 12，再滚就夹住不动，测的是钳位不是锚点。⇒ 交互类判据里那句
   "状态没变 ⇒ 这条判据是空的"的守卫**必须写**（它救了我一次：没有它，我会以为自己改对了，而那条判据永远绿）。

**顺带一条方法层的收获**：这批"末行是新增点"的形状以后每次并入都会出现（新东西总排在末尾），
所以 `.trim()` 这一族不修完就永远是一颗定时雷 —— 本次只修了 `coords.tsv` 写路径上的 7 个文件
（`ruler-figs` / `attach-kin` / `attach-hp` / `attach-path` / `attach-dup` / `attach-sc` / `repair-coords`），
其余 20 多个只读表工具里同样的写法仍在，下次谁被它咬到就照这条改。

## 95. 同一根轴上不许有两把钟；"画了多少条"这类产量数必须与"该有多少条"对账（10-07 · §E378 · 实例是 16 枚旧冠军的横轴填了上槽时刻，而其余 901 枚填的是训出时刻）

**① 一把轴 = 一把钟。** 给一批新点接边之前，先问"它们的坐标与老点的坐标**读的是同一个事件**吗"。
这次那 16 枚在 `lineage.tsv` 里没有行，于是横轴拿什么填是**看图器自己挑的** —— §E376 挑了"上槽时刻"（并诚实写在左栏），
而其余 901 枚的 ts 一直是"训出时刻"。单看每一句都对，**接上血统边就现形**：父的上槽晚于子的训出 ⇒ 图上出现"父比子晚"。
而那个形状在本仓的图上**已经被占用**了 —— 琥珀虚线 = 假血统（§E367）。⇒ 两把钟混在一根轴上，不只是读数错，
是**会把真边标成假边**。

实测同一份数据、只换填哪把钟：**上槽 ⇒ 57 条真边只能接 53 条、退回 4 条；训出 ⇒ 接 56 条、只退回 1 条。**
那 3 条不是假边，是被错钟冤枉的。所以"换钟"不是美化数字，是把边接对。

判据的形状要挑对：不写"某枚的 ts 必须等于 2026-09-12T06:15Z"（那是钉一句话，第 89 条），
写 **`ts` 与 `sh` 不许同值、且 `ts ≤ sh`**（"两列不同源"是不变量）⇒ 谁把 ts 换回上槽时刻，当场红，且红在明细里点名几枚同值。

**② 产量数必须对账，否则"静默少画"不算故障。** `drawTree` 那句 `if (!pos[dd.pof]) continue` 让**父节点不在图上的边全部无声消失**：
实测 57 条 `parentSrc='hash'`（包自己 META 里记的、最硬的一级来路）的边，因为 `parentOf` 写的是一个**文件名**
（`champion-5p-ab2-base`）而图上没有那个节点，一条都没画过 —— 而页脚那句"淡蓝曲线 = 热启动父边（画了 N 条）"里的 N
从来没跟"有父边的枚数"并排看过。三个数（有父边的 / 父节点存在的 / 真画出来的）各自都正确，**只有并排才看得见洞**。

⇒ 立一条不变量而不是立一个数：**不许有任何父边指向图上不存在的枚**。计数会随库漂，洞的形状不会。
同理，被守卫**主动**挡下的边必须留名字（这次 `long-33` 标成 `demoted-time` 且判据点名它），
否则"少画一条"和"漏画一条"在下一个人眼里长得一模一样。

⚠ 反面教训也记一条：复原红测时**倒序改动忘了回滚**，被下一次 check 抓个正着（两条一起红）。
⇒ 复原的纪律是"改完立刻 check，绿了才写下一条"，不要攒到最后一次跑。

## 96. 一条门"红得没有信息量"时，先查它的主语是不是错位（10-08 · §E443 · 实例是 D205 腿④ 与页内那条高亮判据）

判据写的东西和它声称要防的病**不是同一件事**，就会同时出现"抓不到真病 + 冤枉好账"两种症状。两个实例都是这一形状：

- **D205 腿④**：判据是"最新一版 CHANGELOG 至少提到 3 个门号"，而它自己的说明写着"提到 0 个说明抽取式失效"。
  ⇒ 抽取式坏没坏，量的是抽取式；引了几次门号，量的是作者的抄写习惯。**主语错位**的必然后果：
  ① 往条目里粘三个在册 D 号它就绿（抓不到病）；② v1.6.25 那一版真的动了门（删了两条门腿）却没写 D 号 ⇒ 判红（冤枉好账）。
  改法是把它换回它本来要量的那件事：**对整段 v1.6.x 必须还数得出 ≥10 个门号**（数不出 = 正则或区段边界被改坏，那时"门号必须在册"那条会跟着假绿）。
- **页内「非选中那批不许压到 0.2 以下」**：取的是**全图最低 alpha**，于是把另一条规矩**故意**压到 0.16 的"未测过灰"也算进来了 ⇒ 在 5 个着色档恒红。
  两条规矩各自都对（"点一家不许把别人糊掉" ‖ "705/718 枚没测过的必须压暗才找得到那 13 枚"），红的是它们被同一条判据混在一起量。
  改法：先把那条分支抽成**单一来源的谓词**（`unmeasuredGray(d)`，判据与渲染共用，不留两份可以各自错），再两支分开量。

⇒ 可操作的三步：**①** 拿这条门的"失败明细"问一句——它红的时候，画面/产物到底坏在哪一句？答不出就是主语错。
**②** 想一个"能骗过它"的最小改动（粘三个门号就算账？）——骗得过就是代理式门腿，本仓 §E430 已按用户裁定删过两条同族。
**③** 改完必须**红测新形式**（把病复原一次看它红不红）：D205 新腿把正则改坏 ⇒ 当场红 0/1 ✅；高亮新腿把地板 0.34 改回 0.10 ⇒ 当场红并印出「非选中最低 0.10 ‖ 未测过 689 枚 ‖ 其最低 0.16」✅。
⚠ 与"喂字符串过关"的分界：改的是**判据的主语**，不是把判据调松；旧腿④的"≥3"换成新腿的"整段 ≥10"覆盖面更大而不是更小。

## 97. 训练侧：单臂读数不可当结论；选种要用出厂那道闸的口径（10-08 · §E439–§E445 · 17 臂实测）

同一套配方（逐字复用现役出生证 `META.recipe.env`，只换热启动种子与 RNG），17 臂量下来两件事：

1. **同一枚种子换一粒 RNG，臂的 Hp 能差 2.6 ~ 20.5 点**（`v7s9-82` → 31.4 / 51.9 ‖ `v7bead25-93` → 63.0 / 44.9 ‖ 对照包 `E51-t8-713` → 49.8 / 25.3）。
   ⇒ 任何"我这轮练好了"都必须配**至少一粒复现**；只报一臂的表在噪声带里随便挑都能挑出"最好看的那枚"。
2. **选种要用会被出厂判定接受的指标**。我第一轮按"库里 Hp 最高"挑（60~63 那批），结果 11 臂只有 1 臂过线——
   因为那批包全部 `ok=0`，卡在 `G(long) < 3`（长程广度），臂大概率继承同一个缺陷。

   这样挑出来 15 枚可用，而 Hp 最高那枚 60.1 本来就 ≫ 现役 47.3。
   ⇒ 顺带一条更值钱的账：**库里已经躺着 16 枚"过线 + 两批都赢现役"的包** ⇒ 最便宜的"变强"可能不是再训一轮，而是把 promote 的候选面从"本臂的当选者"扩到"全库"（这条动出厂判定，必须用户裁）。

## 98. 判据报"找不到 X"时，先让它自报数，再决定修画面还是修判据；线要用两侧读数划，不许用"目前能过"划（10-08 · §E449 · 实例是那条红了三轮的「指针往返」）

「画布上找不到它的选中环」这一句在**两种完全不同的病**上是同一句：环**一颗都没画**，与 画了但**数的手段数不到**。
前三个班次都因为它写不出数而只能挂"没动"。这一班先给它加读数（把扫到的颗数打进明细）⇒ 读数 **12 颗 / 17 颗（阈值 24）**
同时逼出两条真病：① 画面那条 —— 冠军的墨环 `stroke` 复用了选中环的当前路径、没重新 `beginPath`，
等于把黄环用墨色重描 ⇒ **用户点中冠军没有选中反馈**（这条一直存在，只是没人拿像素点过那个位置）；
② 仪器那条 —— 按颜色在整张画布上扫 `#ffd166`，量的是"这一族色出没出现过"，不是"环在哪儿"。

⇒ **通用动作**：一条报"找不到 / 数不出"的判据，先把它本该报的**数**补进明细，再谈修哪个。红了就换判据或红了就改阈值，都是拿结论当证据。

新判据（两帧差分定位 + 环色占比）的线是**两侧都量过**才划的：

| 靶子 | 改对的版本 | 把 bug 复原的版本（撤 `beginPath`） |
|---|---|---|
| 冠军（默认 / 立体 / `&flo=0.60` 三态） | 146 / 152 / 175 颗 = 68% / 70% / 81% | 38 / 37 / 84 颗 = 17% / 16% / 36% |
| 非冠军几枚 | 87 / 88 / 89 颗 | 一字不差（该病只发生在冠军身上） |

过程里**否掉两个我自己先写下的口径**，都是靠"把数打进明细 + 拿坏版本复跑"判的，不是靠"调到目前能过"：
① B 通道均值 —— 环混的是**底下那块地**（密度越高越偏蓝），同一版产物里非冠军能读出 B=76 与 131 两种数 ⇒ 线没法划；
② "过半颗数" —— dpr=1 一圈 2px 描边被抗锯齿切掉一半以上是常态（好版本也只有 53%~81%），而坏版本照样过半 ⇒ 既冤枉好账又抓不到真病（与第 96 条同一族）。

⇒ 三条要留住的规矩：
1. **只对某类对象有效的判据，必须自己点名那个对象在靶子里**（这条要求 `nLinp ≥ 1`：挑不到冠军时它等于没测，不许当绿）。
2. **判据的前置条件要在注释里写死可核**（差分的前提是"选中只多画这一圈"⇒ 已核实 `alphaOf` 的压暗走家族高亮而不是 `st.sel`；
   且取帧前把在飞的补间 `tw` 掐掉，否则动画会被当成环）。
3. **"点下去选中了别人"不必然是病**：邻枚的命中盘盖住本枚中心时（实测落点重合、gap 0.7px）按"选中者的落点落在它自己的命中盘里"判过并单独计数；
   线划在**选中者自己的半径**上而不是拍一个常数（写死 2.5px 会在密处冤枉正当遮挡）。注入 6% 纵向换算误差 ⇒ 派发落到空白，照样红 ✅。

## 99. 判据里不许留"只在出厂态成立"的前提；扫状态的面要扫宽到"会让版式与分布改动"的那几档（10-08 · §E451–§E452 · 三条恒红都是这一族）

同一晚三条门在深链状态下恒红，病因是**同一个**：判据把"出厂那一刻恰好成立的数"当成了永恒前提。

| 恒红的门 | 它写死的量 | 那个量的真相 |
|---|---|---|
| 强度窗口：现役被切掉要响亮说一句 | `st.flo = 0.8` | `flo` 是**占全库 F 值域的比例**，不是 F；`F = Hp/100 + T·S` ⇒ `#T=0.2` 换掉分布，0.8 推出来的窗把现役装了进去 ⇒ 那句话本来就不该出现 |
| phantom 命中 | `tested > 0` | `#labels=off` 时零标签是**设计**，不是标签层坏了 |
| 指针往返 | 开头量一次的 `rect` | 中间那几次 draw 会让图例/家族带改高度 ⇒ 画布挪了 68px；而 `refit` 挂在 ResizeObserver 上**要等一帧**，同步自检循环里它不会跑 ⇒ 位图是旧的、盒子是新的 |

⇒ 三条通用动作：
1. **常数换成"从当下状态现算"**：窗口改成按现役自己的 F 推（+0.02 再换算成比例）之后，这条在**任何** T 与任何进入路径下都成立 ——
   适用面比原来更宽，不是放水。同理 §E451 那条新判据把"栏宽"钉成"最宽家族名 + 60"，谁改宽谁红。
2. **"不适用"要写成显式分支，并且只放过那一种成因**：`labels === 'off'` 才免，开着标签却零标签仍判红
   （红测：把标签循环掐成零枚 ⇒ 当场红 ✅）。免错方向就等于把门拆了。
3. **换算类判据在派发那一刻要重新量 rect，并先确认"位图 = CSS 盒 × dpr"这条不变量**（不成立就 `fit0(); draw();` 补一次）。
   用户真点的时候浏览器用的永远是活盒 + 已重配的位图，自检里缓存一次 rect 就是在测一个用户看不到的画面。

⚠ 这三条都是**把状态面扫宽**才现形的：前面几班只扫 4 个模式 × 11 个颜色档，`labels=off` / `T=0.2` / `color=seed` 没进过清单。
⇒ 扫状态要扫"会改动几何、版式、分布"的那几类参数（窗口 / 标签开关 / T / 着色档 / 高亮 / 连线档），不是只扫模式与配色；
   本班最终 **26 个状态全部 54 PASS / 0 FAIL**。

## 100. 判据要从**控件**走起，不能只从状态走起；参照物要用"两档互相"，不能用"进入时的值"（10-08 · §E453 · 顺出搜索框大小写敏感等四处）

一个交互功能有三段：**控件 → st → 画面**。前面所有判据都从第二段起手（直接写 `st.color`、`st.flo`、`st.labels` 再画），
于是第一段整段是盲区 —— 下拉接错 id、滑杆 handler 忘了赋值、按钮只改文案不改状态，全都测不到。
补法：用 `dispatchEvent(new Event('change'/'input'))` 与 `new MouseEvent('click')` 点**真控件**，然后核两件事：

1. `st` 跟上了（并且**还原也要跟上** —— 自检点完不还原，用户回头看到的下拉就停在被点过的档位上，那是 §E371 那类"两本账"）；
2. 画面/分布跟着动了（只核 `st` 会放过"接上了但没人用它"：这条要求 `T` 真的改动 `winLo`、`size` 真的改动 `dotR`）。

⚠ 参照物选错会让判据在深链状态下自己红：
- 底色那条第一版写"点浅底之后字色必须与**进入时**不同" —— 从 `#bg=%23e6ebf5` 进来时字色已经是浅底那份，于是恒红。
  改成**两档各点一次互相比**，再加语义判据（浅底上字必须比底暗、深底上必须比底亮）——比"和刚才不一样"更强。
- 搜索片段第一版写死 `['bead','ring',…]`，§E440 去重后命中数掉到 1；第二版按**全库**现找，
  在 `#flo=0.169&fhi=0.541` 下"全库命中 6 枚、当下可见 0 枚"又红一次。
  ⇒ 取样集合必须与这条**宣称的范围**一致：这条测的是"图上看得见的那几枚被标出来"，就得从 `VIS && scr` 里面找。
- 同族：`inkLeft` 写死"三通道之和 > 430" = 深底上的亮字 ⇒ 浅底深链进来一个字都数不到，报"左栏文字没跟着平移"。
  改成"与**当下底色**之差 > 150"，两种主题都合，且不需要知道当前是哪一种。

⇒ 一句话：**判据里不许有"只有一种活法"的隐含前提**（一种主题、一个进入值、一批当下可见的点）。写死之前先问"深链换一档它还对吗"。

## 101. 对照物自己也要跨批复量："同一批复量逐字相同"不等于"换一批也可比"（10-08 · §E458 · 实例是我拿 Hp 排了换包的序）

`Hp` 是"页面口径夺1率"（`eval-5p 30 5 <seed> --eps=0.2 --eps-mode=soft` 的 `[冠军] 1st=`）。§E446 我做过一次仪器自证：
拿同一台机器复量种子包与现役，读数与 `coords.tsv` 里那列 **逐字相同** ⇒ 我据此认为"Hp 之间的差可以当排序证据"。
那个自证只覆盖了**同一批 RNG 的确定性**，没覆盖**跨批可比性**。换个种子批（55000）重量：

| | 批 77000 | 批 55000 |
|---|---|---|
| 现役 SHIPPED-Ldemo（对照物本身） | 47.3 | **53.0**（摆 5.7pt） |
| v7beadseed-93 − 现役 | +11.4 | **+3.4** |
| v7bead2-93 − 现役 | +2.9 | **−5.6（翻负号）** |

⇒ 三个结论：
1. **"复量相同"要写清楚复量的是哪一件事**：确定性（同输入同输出）与稳健性（换输入噪声后结论不变）是两条判据，
   我只做了前者就用了后者的口气。
2. **要比较两枚包，就用配对设计**（同座位表、同批种子、A−B 相减），公有噪声在差里消掉 ——
   `duel-run.mjs` 的"现役 vs 现役 必须恰好 0"就是这条配对设计的仪器自证；跨批各自量 Hp 再相减没有这个性质。
3. **对照物要跟着一起重跑**。这次如果我只跑候选不跑现役，会读到"v7beadseed-93 有 56.4，比面板上现役的 47.3 强"，
   而同一批里现役已经是 53.0 —— 差值凭空多出 5.7pt。

## 102. "产物对了"不能证明"我新写的那条路通了"（10-08 · §E465 · 一条 durable 退路空转了一整个早上）

给 pre-v7 包补"嵌入成 v7 之后的第二个身份"这件事，代码写完的**当天**页面自测 61/0、`lineage.tsv` 与预期逐字节相同 —— 我据此认为接好了。
实际是：`EpirusPolicy.embedLegacy()` 返回 **Float64Array**，而新抽的 `widOfArr()` 开头写 `if (!Array.isArray(a)) return null` ⇒
`if (e && …)` 恒假 ⇒ 那张 `BYWID_EMB` 表**一条也没登记进去**，整条 durable 路自写下就空转（不报错，因为 `null` 是合法返回值）。

三个叠加原因让产物看不出问题：
1. **优先级遮蔽**：检索是 `BYWID[h] || BYWID_EMB[h]`，本机恰好还有 `docs/artifacts/e370-out/*-v7.js` 那批**未入库**的 v7 导出，
   它们的原始哈希本来就等于嵌入后的哈希 ⇒ 第一条路永远命中，第二条路根本没被走过。
2. **判据看的是结果表**：页面自测读的是**已生成好的** `lineage.tsv`，表对 ⇒ 腿绿。它验的是"今天这张表解得开"，不是"这条路通不通"。
3. **空转的形态是 0 而不是报错**：`console.log` 里那句"登记 N 条"打了 0，但 N 从来不是判据。

⇒ 三条可复用的规矩：
- **新增一条退路/登记/旁路，判据要钉这条路自己的产出量**（这里钉"被当父用的旧槽位冠军，第二身份必须能从已入库文件推出"，
  不满足就 `exit 2`），而不是钉它最终影响的表。表对可能是别人顶上的。
- **写"从 A 推 B"的登记代码时，把 A 挪走跑一遍**（我把 `e370-out` 临时移出去模拟"换台机器 clone"）——
  只要产物在本机对、把可选依赖挪走就不对，那这条依赖就是**没入库的假设**。
- 一个恒 `null` 的分支是这条路上最贵的 bug 形态：**返回类型口径要写在函数注释里**（`widOfArr` 现在明写"收任何 array-like，
  `Array.isArray(Float64Array)` 是 false"），并且红测要能证明判据看得见它 —— 复原 Float64Array 那次立刻红，才算有牙。

## 103. 视觉"糊不糊"要按**分布**量，不能按"最亮那个像素"量；而"压暗"必须**局部**，不能整条共享一个系数（10-08 上午 · §E467/§E467a/§E467b/§E468）

用户说「线连太多了太糊了，考虑一下透明度叠加用对数」。我做了三版，前两版都被她打回，两次的根因不同但同源：

1. **第一版错在指标**：整条边取一个"平均密度"，然后拿"窗内最饱和像素"验收 ⇒ 量到 221→221"没效果"。
   那个指标量的恰好是**不该变的东西**：最密那一格 ±40px 的窗里必然穿过几条疏尾边，它们本来就该保持全 alpha。
   换成"到顶（墨 ≥200）的像素有几个"才对（436 → 26）—— 那才是"板"的直测。
   ⇒ 规矩：**改视觉效果之前先问"我的指标在量什么"**。指标说没效果时，第一反应要有"指标本身错了"这一支，不要直接怀疑做法。
2. **第二版错在被错指标牵着走**：为了把那个"没效果"救回来，我把每条边切成 8 段、按段密度**分桶批量 stroke**。
   分桶 ⇒ 同一条线以不同 alpha 分次落笔，而桶按 alpha 升序画 ⇒ 亮段压在暗段上，**重合处出现肉眼可见的断口**（用户：「这版不行，现在线条重合的部分反而出现了中断」）。
   ⇒ 规矩：**省 draw call 的手段不许改变单个图元的落笔连续性**。要沿一条线变化外观，用**渐变 strokeStyle**（还是一次 stroke），不要拆成多次落笔。
3. **第三版错在"局部性"**：字面的对数律 `基准/(1+ln d)^1.5` 数学上没错，但它连"一格 9~32 条"的中等密度也压到 1/3 alpha ⇒ 用户下一句就是「单根线看不见了」。
   同一件事的另一面：只要一条长线**蹭到**扇根那一格，取均值就会让它整条变淡。
   ⇒ 规矩：**压暗的粒度要贴到被压的地方**（沿曲线取 5 个位置各自的局部密度），并且判据要按密度分档 —— 现在钉的是"最疏那一档（一格 ≤8 条）中位墨 ≥30"，
   把拐点从 25 压到 1 立刻红（中位墨 16）。**"整体变淡"和"只在堆里变淡"在总量指标上看不出来，只有分档才分得开。**
4. **视觉属性一旦按"当前视图"现算，就必然带时间性伪影**（同一轮的第三条，用户：「平移旋转时会有抽搐」）：密度网格取在画布坐标上 ⇒ 平移 1px 整体换格 ⇒ 一条线的 alpha 离散跳档
   （实测偏航 0.05rad 跳 0.207，0.300→0.093 差三倍）。修法不是把网格挪到"纸面"就完事 —— 立体态会把行压缩，纸面也跟着变；
   要搬到**挤行之前**那一层（`padT0/rowH0`）才真正与相机无关。
   ⇒ 规矩：**能给图元算的属性，不要在投影之后算**；判据要直接量"同一图元在两个视图下的属性差"（这条腿现在钉 ≤0.02，改之前 0.207 红着）。
   顺带一条对"HDR 色调映射"方案的判断：**任何**把 n 映到 [0,1] 的单调曲线都会饱和，所以它不能让"22px 里压 523 条线"各自可辨，
   只能让"40 条到 500 条"不至于全白 —— 值不值得开 WebGL float FBO，要看用户要的是哪一件事，别替她决定。
5. **同批还抓到两条既存腿把深链当默认态**（`#kx=2.2&tx=-500` 下"旧包没画上"、`#ty=300` 下"样本不够"）：
   读屏幕像素/屏幕坐标的判据，**视图本身就是它的前提**，必须和 mode、color、窗口一起钉死；先拿 HEAD 产物复跑一遍确认红的是既存问题还是我带来的，别把别人的账记自己头上。

## 104. 臂与臂的分辨率要用"**同配方只换训练 seed**"实测，不能拿配对 SE 当它（10-08 · §E476 · 我把 `COUNTER_OPPS` 的 +6.82 当过一次真效应）

   ⇒ 机理与第 16 条同族（`EPIRUS_WORKERS` 16→12 就换冠军）：**动过旋钮管道 = 换随机流 = 换当选个体**。
3. **代价**：`COUNTER_OPPS` 的效应两粒 seed **反号**（+6.82 / −15.83），我 13:1x 那句"这批唯一稳定加分的是桌子"当场作废。
   ⇒ 规矩：**任何臂间差先问它 >4.4pt 没有**；要判 1~3pt 量级的效应，只有两条路 —— 多 seed 同号（§E146 的反巧合条款，两粒是下限），或把方差源本身消掉（选择侧改动，见第 105 条）。

## 105. "打赢脚本"与"打赢人"是两把尺，且它们在臂间**排序不一致** ⇒ 补弱项必须两把同判、人席那把做门槛（10-08 · §E475/§E476 · 用户口径"能打赢现役不代表全环境强度"的兑现）
1. **两把尺**：`eval-5p`/`pick-5p` 是"1 主体席 + 4 席脚本"；`tools/probe-human-seat.mjs` 是"1 席人类原型 + 4 席被测同包"（**产品形状**，页面上玩家遇到的就是它）。
2. **实测不一致**：`D4c2` 考卷比对照高 6.82pt，人席五格均值却从 17.6 恶化到 **32.0**（`只枪压制` 那格 19% → 41%；seed 7 那一粒打到 **100%**）；
   `K2c2` 考卷只高 1.57pt，人席从 11.8 恶化到 **30.8**。反过来 `SHIPc2` 人席略好（14.2 vs 14.8）而考卷差 2.90pt。
   ⇒ 把判据原型放上训练桌，学到的是"**打那三个固定脚本**"，不是"打人" —— 这是过拟合对手池的形状。
3. ⇒ 规矩：**任何"补弱项"臂，`probe-human-seat --modes=long` 是门槛（出现新的 ≥20pt 漏格直接判死），不是参考栏**；
   并且方差的主导项在"**用哪张桌选当选者**"（n=3 评分桌 → 产品桌翻号，`tools/pick-5p.mjs` 头注早就写着），
   所以要动效应最集中的地方是**选择侧**（训练照旧、当选改用产品形状 + 人席 veto），不是再换一根奖励旋钮。
4. **§E494 补的第三个实例，而且是同一族里最狠的一个**：`Hp`（页面口径夺1率，图上那把头号尺）**也是单批尺**。
   融合批 35 粒用 `Hp` 排第一的 `e493-s9-82XD4a`（Hp 60.7 ‖ 现役 47.3，看着 +13.4pt）上了双臂决斗只剩
   **A−B = +2.5 ±4.6（分不开）**，人席反而**比现役差 6.9pt**。⇒ 便宜尺的用途是**淘汰明显坏的**（例如考卷 28 的那一对），
   **进下一轮一律先过 `duel2`/`duel-run` 那把配对尺**，人席做门槛；不许拿 Hp 的差值当"强多少"报出去。

## 110. **A−B 换场决斗是"相克矩阵"，不是强度排序** ⇒ 引它之前必须查传递性，单场差值不许说成"强 X pt"（10-08 晚 · §E495b · 我自己把 +22.5 当等级用了三轮）
1. **实测（同一把 `duel2`，120 局 · n5 · long，自检"参照打自己 = +0.0"每次都过）**：

   | 对局 | seed 77000 | seed 88100 |
   |---|---|---|
   | `Y-l65` vs 现役 | **+22.5** | **+10.8** |
   | `Y-l65` vs K2 | **−5.0** | — |
   | `K2` vs 现役 | −1.7 | −4.2 |

   若 A−B 是强度差，`Y-l65 vs 现役` 应 ≈ (−5.0) + (−2.9) = **−7.9**，实测 **+16.7** ⇒ 差 **≈25pt**，是这把尺分辨率（±5pt）的五倍。
2. **为什么会这样**：A 臂是"候选在对手的场里"、B 臂是"对手在候选的场里"，两臂都是**针对那一副桌**的函数；
   换一副桌，策略的相对次序可以整体翻（这游戏有盾/反弹/大雷/蓄能这类互相克制的头）。⇒ 它天然是**成对交互项**，不是可加的量。
3. ⇒ 三条规矩：
   - 报"X 比 Y 强 N pt"**只能用在可加口径上**（对固定桌的夺 1 率、考卷、覆盖度、人席均值）；
   - 要用决斗做排序，就必须**两两全跑成矩阵**（3 枚 3 场、5 枚 10 场）并**明写传递性成不成立**，不成立就只报矩阵、不报名次；
   - 参照要跟着**用户的基准**换（她说"不如 K2"，参照就得是 K2 ⇒ `duel2.mjs` 这次加了 `--ref=`，自检随之变成"K2 打自己 = 0"）。
4. **这次被降级的结论**：§E484/§E494 我把 `+22.5` 当 Y-l65 的头条卖点报过三轮。它仍然说明"这枚克现役这一场"，
   但**不说明它比 K2 强**——而它并不比 K2 强（−5.0，且用户实机手感同向）。同一条候选剩下的三条可加证据（考卷 +2.8 ‖ 覆盖度 23/33 ‖ Δε −1.5）依然同向。



## 106. "逐行退路"会把**整列丢失**伪装成"个别缺测" ⇒ 新口径要在生成侧拒绝出图，并在产物侧钉住量纲（10-08 下午 · §E489 · 用户一眼看出「投影一下子变回很早的版本、区分度变得很低」）
1. **形状**：`viewer.mjs` 取坐标那句是 `x2: (PROJTSNE && r.xt) ? +r.xt : +r.x2` —— 它的设计意图是"这一枚**单独**没测过投影就退旧坐标"。
   而重建链跑完（那时链子里只有五步，`proj-tsne` 不在其中）⇒ `coords.tsv` 从 41 列掉到 **36 列**，`r.xt` 对**每一行**都是 undefined
   ⇒ 920 枚全部静默退回旧力导向，**一个字的警告都没有**，页内 69 条判据一条没红（它们判的是几何/接线/口径，没有一条判"坐标是哪套")。
2. **实测代价**：`proj-tsne` 自己的判据 kNN@10 保住率 **0.52 → 0.08**（同一份 12 维招法空间），这就是用户说的"区分度很低"。
   ⇒ 病不是新算出来的坐标错，是**产物装错了货而自检不知道要看**。
3. ⇒ 两条规矩：
   - **凡是"退路"只许用于个别缺测，不许用于整列缺失**：在生成侧加一道"列在不在 + 空值比例 > 2% 就拒绝出图"
     （`viewer.mjs` §E489 那段；退出码 2，并指名补投影的那条命令）。放在生成侧是因为浏览器已经装载完了才发现问题就太晚了。
   - **口径换了就把判据钉在"产物真的用的是新口径"上**，而且**不信旗标**：页内那条腿判的是每一枚坐标的**量纲**
     （t-SNE 实测 ±1.05 ‖ 旧力导向 x ±3.4 / y −4.9~17.7 ⇒ 界放 ±2.0，两边都有余量）。
     牙口实测：把一枚的 x2 改成 9.87 ⇒ 当场红在「越出 ±2 的 1 枚」。只钉 `PROJTSNE===1` 是不够的 —— 那种写法在"列在、某几行空"时照样绿。
4. **同族的第二条**：链子必须**自带它自己依赖的步**。`rebuild-coords.mjs` 的注释里早就写了"② attach-path 的 --ruler 不给全会退回猜路径"，
   却没有一条写"⑥ 投影"—— 因为那一步从来是**手动**跑的。本轮把它做成第⑥步，并在收尾核验里加"投影五列齐全且全是数"。

## 107. 计数器一律数**落到画面上的那个值**，不数"进没进那个分支" ⇒ 牙口测试要连计数器一起测（10-08 傍晚 · §E490 · 我自己写的那条腿被自己的牙口打回）
1. **经过**：用户裁定"融合的两根父边同色（红）"。我加了一条腿判"两根都真画成红"，写法是
   `if (sq) NSOUP1++`（`sq = dd.psrc === 'soup'`）+ 判据「NSOUP1 = 数据里该画的枚数」。
   然后按第 15 条做牙口：把 `kind` 从 3 改回 0（也就是**真的把那条边改回淡蓝**）⇒ **71 条判据全绿**。
   那台计数器量的是"这枚的来路是不是融合"，不是"这条边被画成了什么色"，所以它对着一个已经失效的分支照样 +1。
2. ⇒ 规矩：**凡是"这一帧真画了几条/几个"的计数，必须挪到最终值算完之后、按最终值加一**
   （这里是 `if (kind === 3)`，不是 `if (sq)`）。与第 91 条（不许信代码自己的说法，要信画面）同族，
   只是这次的"代码自己的说法"是我十分钟前刚写的那半行。
3. **牙口的正确用法**：不是"写完判据顺手想一个变异"，而是**把要防的那个 bug 一字不差地复原一次**。
   这次要防的是"第一父掉回淡蓝"，所以变异就必须正好是"第一父掉回淡蓝" —— 换成删掉整条边只会打到另一条腿（③）。
   复原之后 ③⑤ 两条同时红、且 ⑤ 点名「第一父红边 0 / 该画 3」，才算这条腿真的在看那件事。

## 109. 口径要**随行进产物**，下游要**拒绝混口径**——"记得重跑"不是守卫，"混了就出不了图"才是（10-08 晚 · §E492 · 场A 40→100 全库重跑）
1. **形状**：`feas*.tsv` 只有 `id/ok/fails/fieldA/…`，**不写样本量**；而 `viewer.mjs` 是按 `['feas-s1','feas-s2','feas-s3','feas']` 顺序读、
   "后写的覆盖先写的"合并成一张判定表。于是把 `FEAS_N_DEFAULTS.aggr` 从 40 改成 100 之后，只要有任何一片表没重跑，
   图上那一列 `fieldA` 就是**两把尺混着画**，而且事后从数据里**看不出哪一行是哪把量的**。
2. ⇒ 三条：
   - **样本量/口径写进每一行**（新增 `tag` 列 = `feasPlan` 的 `n=20/aggr100/seat100`），不是写进文件名、更不是写进注释；
   - **下游按 tag 对账，两种就 `exit 2`** 并报各自几枚（牙口实测：把一片改成 aggr40 ⇒ `⛔ 混了 2 种样本量：aggr100 × 614 ‖ aggr40 × 306`）；
   - **文案里的口径一律派生**：图上那两处（色档说明、悬停标题）原来把 `n=20/aggr40/seat100` 抄死在字符串里，
     `np-test` 里还有一条门把 `aggr40` 抄进正则 —— 三者现在都从 `FEAS_N_DEFAULTS` / 表里的 tag 拼。
     这条与 §E278（注释里不许复制数值）、第 89 条（不许钉死读数）同族：**抄下来的口径一定会在某个早上变成假话**。
3. **顺带量到的一件事**：改到 n=100 之后"过线总数 185 → 185"看着毫无变化，但逐枚对账有 **6 枚翻了结论**（3 枚过→不过全是场A 那一栏）。
   ⇒ 汇总数不变**不等于**判定没动；换样本量必须做**逐枚对账**，只看总量会把一次真实的改动读成空操作。



## 111. 组间比较要报**分布**，二值统计（"几粒掉进那一盆"）在 n=3 下最容易骗人（10-09 通宵 · §E502→§E504 · 我自己撤回一条写下去的机理）
1. 实测：§E502 三粒 seed 看到"处理臂防御占盆 **0/3** ‖ 对照臂 **2/3**"，长得极像一条机理（狙击场把示范推进的防御坑填平了）；
   同一配方加到 **12 粒**后**完全反转** —— 处理组 **4/12** 掉盆、对照组 **1/12**。那条解释我撤回了。
2. 为什么二值统计更骗人：它的方差是 `p(1−p)/n`，n=3 时 `0/3` 与 `2/3` 差约 p≈0.09 —— **一点都不显著**，
   但它比均值更"像结论"（0 对 2 是故事，43.3 对 51.0 只是数字）。
3. ⇒ 三条规矩：
   - **组间比较先报 `sd` 与极差，再报均值**（今晚 P 组 sd 5.0 / SP 组 sd 13.2 ⇒ 真正的答案是"这根旋钮把方差打开了"，不是"它把均值推动了"）；
   - 占比/计数类结论**下限 n=8**，不到就只写"这一格未判定"，不写方向；
   - 一旦加大样本推翻了小样本结论，**要在被推翻的那一条原文处写订正行**（不抹历史），因为那份小 n 读数还会在别的臂日志里被再次引用。
4. 与第 104 条同族：那条管"配对 SE 不等于臂间地板"，这条管"臂间地板之**后**还剩多少可信度" ——
   当组内极差（今晚 36.2pt）大于组间差（4.0pt）时，**均值差没有意义**，问题要从"哪根旋钮好"换成"分布里哪一粒能要"。

## 112. 按单一尺的 Top-N 入围，必须自带一枚"**不用那一招**"的对照，否则会把过拟合报成候选（10-09 通宵 · §E505）
1. 我只按"页面 Hp ≥ K2"挑了四粒，其中三粒是高狙击臂（`SP-s25` 狙 16.05、`SP-s29` 5.40、`SP-s26` 5.38）。

   ⇒ **"会狙击"不是这批臂赢的原因**；如果我按分数只报前三粒，就交出一枚"考卷 64.2 但人类原型坐那一席能拿 77% 夺冠率"的假候选。

## 113. 批量测量收尾必须打印"**名单数 vs 落盘数**"——少一行不会让任何判据变红（10-09 通宵 · §E504）

## 114. 决斗的 A−B **不可传递** ⇒ 任何"更强"都必须写成"在谁的场里对谁"（10-09 通宵 · §E524/§E526）
1. 实测（300 局 × 没参与筛选的种子 12345，mode=long，A=候选在参照场、B=参照在候选场）：
   `SP-s25` 对现役 **−12.0** 却有 **K2 +15.0**；`D4a` 对现役 **−17.0** 却有 **K2 +9.0**；`Q-s35` 对现役 **+3.3（分不开）** 却对 K2 **−11.0**。
2. 五人场的强弱本来就不是全序，但**这把尺的输出长得像名次**（一个带正负的数），于是"赢 K2"会被读成"比 K2 强 ⇒ 也就比现役强"。
3. ⇒ 规矩：引用决斗读数时**必须连参照一起引用**（"X 在 K2 场里 +15.0"而不是"X 更强"）；
   跨参照做传递推理（X>K2、K2≈现役 ⇒ X>现役）在这把尺上**没有依据**，要判定就得各配各打。
   与第 105 条（考卷尺与人席尺排序不一致）同族：那是**两把不同的尺**不可互推，这条是**同一把尺在不同场上**也不可互推。

## 115. "同一型对手"在两把尺里的**席位方向是反的** ⇒ 它们不是同一个量的两把尺（10-09 通宵 · §E527）

## 116. 对照分组要从**配方表**取，不能从"我跑了哪两支脚本"取（10-09 通宵 · §E527 自误自纠）
1. 实测：我把 G5 的 15 枚分成"A=guardSpam 池 / B=非 guardSpam 对照"两支脚本跑，

2. ⇒ 规矩：读表脚本里要有一张**显式的 `RECIPE(tag)` 映射**（今晚写在 `e527-out/read.mjs`），

## 117. 断言"子进程的副作用文件"的腿**不许走缓存**：缓存命中时子进程没跑，腿就变成"比上一次留下的产物"（10-09 · §E543，这是一条**假通过**通道）
1. 实测：`--group=ui` 报 `D123` 红（`默认关的产物必须与登记基线逐位相同 got=8cbf6b3446 want=aa743488cc`）。四步把自己洗清：
   干净克隆（分支基点 `f28fccb`）同一条腿 **rc=0** ‖ HEAD **冷跑**产物 `wh()` **逐字等于基线** ‖ 把 foreign 产物放在默认落点再冷跑，输出仍是基线（训练不读它）‖
   `NP_NOCACHE=1` 复跑 **rc=0**。真因在仪器：`tools/np-cache.mjs:61` 把 TMPDIR 前缀折叠成 `<TMP>` ⇒ `mkdtempSync` 的新目录也没能让键变 ⇒
   **命中缓存**，而 `spawnCached` 命中时**不启动子进程**（`np-cache.mjs:106-109`），随后腿读的 `docs/artifacts/train-3p-out.js`
   是**上一次被 5 分钟 timeout SIGTERM 杀出来的半成品**。
2. 为什么这条比"假红"更糟：**残留文件如果恰好等于基线，真回归会被报成绿**。缓存对"断言只读 stdout"的腿是安全的，
   对"断言读副作用文件"的腿**语义就是错的**——它缓存了"跑过"这件事，而判据需要的是"这一次真跑了"。
3. ⇒ 两条规矩：① 写腿的时候先问"**我的断言读的是返回值还是磁盘上的东西**"，读磁盘就不许走缓存（或把产物改道到本腿私有路径 + 跑前删，
   这样命中缓存时文件缺失会当场 `NOPARSE` 响亮红）；② **复跑一条腿之前，先确认它上一次是"跑完的"而不是"被杀的"**——
   `exit=143`（SIGTERM）之后现场是脏的，任何"复跑一下看看"都会把脏现场当成新读数。
4. 与第 113 条（少一行不会让任何判据变红）、第 108 条（空值被当成 0）同族：**三条都是"仪器在自己的报告里说谎"**，
   只是说谎的位置不同：少数据 / 空值 / 缓存命中。

## 118. 审计开关不能与被它改变的腿互相矛盾：`NP_NOCACHE=1` 一开，`D157`（缓存自检腿）就必红（10-09 · §E544）
1. 实测两遍 `--group=ui`（同一天、同一棵树，只差这个开关）：
   **带缓存 164/165，红的是 `D123`**（第 117 条那条脏现场）‖ **`NP_NOCACHE=1` 164/165，红的是 `D157`**，
   断言原文"**第二次必须命中**（实测本次增量 0）"——**关了缓存当然命不中**。`--group=meta` 两遍都 16/16。
2. 为什么这不算"另一个 bug"而是**口径问题**：`np-cache.mjs` 把 `NP_NOCACHE=1` 写成"逃生口（一律真跑）"，
   而有一条腿的**判据就是缓存会命中** ⇒ "用逃生口去审计一遍"这个动作在套件里**永远不可能全绿**。
   一个开关让一条腿按构造而红，等于把"审计模式"写进了被测系统的输入里。
3. ⇒ 两条规矩：① **自检某机制的腿，必须在该机制被关闭时显式跳过并响亮打印**（`SKIP`/`UNRUN` 那一档），不许 FAIL；
   ② 反过来，引用"我无缓存重跑过所以全绿"之前，先看红的这条是不是**依赖缓存的那个自检腿本身**——
   两遍对照才能把"仪器依赖模式"与"代码真有回归"分开，单遍（无论哪种模式）都不能。
4. 与本条第 2 项配套的正向结论：**两遍模式互证**（各自只红"依赖该模式"的那一条）比任何单遍"全绿"证据都强。

## 119. 合并两张测量表之前必须核对**采样量档**：同名的 `H` 在 exam=30 与 exam=120 下不是同一个变量（10-09 · §E549）

## 121. 一根行为列"能不能当选键"要分四段检验，最后一段必须**跑前写死停手条件**（10-09 · §E534→§E536→§E539→§E551）
1. **样本内分箱**（§E536 四分位过门率 44% → 22% → 6% → 5%）：这只是**假设**。同批数据自己切出来的单调性会高估自己，
   因为它参与定义了这根列的那批包又被拿来当证据。
2. **同质 cohort**（避开第 119 条的混档）：exam=120 的 n=75 里 `charges` ρ=**−0.52**、过 Holm ⇒ 关联是真的。
3. **独立抽样一遍**（n=24，切分只看这根列、不看任何结果列）：上半 33% ‖ 下半 17%，差 2 枚、Fisher 单侧 p=**0.32** ⇒ **判不动**（不是"通过"）。
4. **预登记的判决批**（n=60，新 seed 段；跑前写死"≥9 枚 = 可用筛 ‖ ≤3 枚 = 判死 ‖ 4~8 枚 = 弱筛"，
   并写死"跑完就交结论，不追加第三批、不换 seed 再抽"）：上半 23% ‖ 下半 13%，差 **3 枚**、Fisher p=**0.2531** ⇒ **判死**。
5. ⇒ 规矩：**报"这根列可用"之前必须走到第 4 段**；三段与四段同号但都不显著时，正确的结论是否定式的 ——
   "弱关联真实存在，但弱到不能当决策依据"（可用作排除法先验：别选 `charges≈0` 的包）。
6. ⇒ "再抽一批看看"**不是**修噪声的办法（那是把噪声抽成结论，正是本班在 §E521/§E527 里批评过的行为）；
   样本量翻倍只让**判死**更快落地。相关：第 1 条的噪声地板（同配方换 seed 考卷 4.4pt）‖ 第 119 条（先核采样量档）。



## 122. 路径级父指针可以升到「身份可核」，但**新增一个枚举值要一起改四处**（10-09 · §E555）
1. 起因是用户看图问：「你昨天刚训练的怎么会不确定父节点」。核对之后事实是：
   `train-3p` 写进包里的父**只有** `recipe.env.EPIRUS_SEEDPACK`（一个路径），没有 `hotstartFrom`（权重哈希）；
   而第 110 条那套线型分级（实线 = 有哈希为证）把它归进"路径推断" ⇒ 今晚 271 枚**连同 K2/D4a/E20-71** 全画成虚线。
   **父节点一直是确定的（K2）**，虚线这个记号却在说"不知道" —— 记号不够用，不是数据丢了。
2. 升法（关键是它**能否得**）：把 env 里那条路径指向的文件现算一遍权重指纹，与该节点在册的指纹比 ⇒
   相等才记 `seedpack-wid` 并与 hash 同级；不等或读不到就**留在原级**。这一问恰好挡住 §E330/§E367 那两种病
   （同名不同权重的拷贝、按"今天路径上住的是谁"反查出来的假父边 ⇒ 指纹直接不等）。实测 153 枚 SEEDPACK 边**全部核过**。
3. ⚠ 措辞不许越级：这一级**不等于哈希级**（哈希是训练服务当场记的，这条是 runner 的环境变量 + 事后核权重）⇒
   图例/页脚/明细三处统一写成"父身份可证（包里的哈希 ‖ 种子文件同权重）"，不许写回"哈希为证"。
4. **新增枚举值必须一起改的四处**（漏一处就是一条当场红的页内判据或一条自相矛盾的开关）：
   ① 生成器写值（`lineage.mjs` 的 `psrc`）；② 查看器分级（实线/虚线）；③ **来路白名单那条腿**（不含新值 ⇒ 判红）；
   ④ 按来路过滤的开关（"只画身份可证那一级"）。修 ③ 时顺手补上了漏在册很久的 `hash-emb` —— 同一个洞，两处都在。
5. 与第 120 条同族：那条是"同名不同档不是同一个变量"，这条是"**同一个记号承载了两件不同的事**（父是谁 / 凭什么知道）"；
   共同点是：**读图的人只会读记号，不会读你的实现**。

## 123. 判据的**采样范围**必须与它要测的病同型，否则"红"是范围错了不是东西坏了（10-09 · §E555④）
1. 现象：加进 63 枚代表之后页内那条"沿一条边走一圈不许有断口"红了，例 `B5-10-71` 中段 alpha 0.153、连续 4 个采样点没墨
   （判据：连续 ≥3 点没墨 = 断口）。第一反应是"密度涨了所以该红" —— 那是猜。
2. 查到的真相：那枚的来路是 `arm` ⇒ 画的是**虚线**，而虚线按设计 `setLineDash([4,4])`（每 4px 留白）。
   ⇒ 拿"连续没墨"去量虚线，量到的是**虚线自己的间隔**。§E467a 当年那个病是"**一条实线**被切成不同 alpha 的段"，两者不是一件事。
3. 为什么以前不红：步长 = 边数 / 24 ⇒ **边数一变，被抽中的那 24 条就换一批**。这条腿的通过与否取决于"这次抽没抽到虚线"，
   与它声称要测的东西无关（METHODOLOGY 5d 那一族：钉在"这一次重建后恰好采到什么"上的判据都是骰子）。
4. 修法：**把探针限定成实线（身份可证的父边 ‖ 融合红线）**，并把范围写进判据标题。
   ⚠ 这不是调阈值：没动"连续 3 点"、没动"墨量下限"，只把"量谁"改成与病同型的那批。
5. **How to apply**：任何一条红先问三句 —— 它量的是不是它说的那件事？抽样的集合随什么变（这里随边数）？
   改范围与改阈值是两件不同的事，**改范围要在判据标题里写明**，否则下一个人只会看到"它变绿了"。

## 124. 「本机整轮绿」不等于「CI 会绿」：判**绝对路径**要用 `isAbsolute`，盘符正则只覆盖一台机器（10-09 · §E558）

- 病（不是推测，复原过一次）：`tools/usage-probe.mjs` 用 `/^[A-Za-z]:[\\\/]/` 判"是不是绝对路径"。
  于是 D232 的 ④ 腿在 Windows 上拿到 `C:\Users\…\e497-usage-XXXX\u.tsv` ⇒ 命中 ⇒ 走对支；
  在 ubuntu runner 上拿到 `/tmp/e497-usage-XXXX/u.tsv` ⇒ **不命中** ⇒ 被当相对路径拼进仓库
  ⇒ `<repo>/champion-map/tmp/…` 那层目录不存在 ⇒ ENOENT ⇒ 子进程 exit 1 ⇒ `got=1 want=0`。
  ⇒ 这条门从它出生那一笔（`0ec7d39`）起在 CI 上就是红的，**连红 12 笔**，而本机每一遍都绿。
- **同一台机器上跑多少遍都验不到那一支**。本仓 CI 的 ubuntu 那一遍是唯一同时满足
  「冷 np-cache ‖ POSIX 路径 ‖ 干净检出」的那一遍 ⇒ 引用"本机全绿"时必须跟一句：**它没有验 ubuntu**。
- 三条可复用的判据：
  1. 判"绝对路径"只用 `path.isAbsolute`（`fs` 与 `path` 本来就在 import 里）。
     仓里 **同一个坑有两个人踩过两次**：`champion-map/feas.mjs:63` 早就写成"盘符 **或** `/` 开头"两支 ⇒ 见到这类正则就去问另一台机器。
  2. **复现环境必须与判定环境同构**：我第一次"干净克隆"其实是假干净 —— np-cache 住在
     `join(tmpdir(),'epirus-npcache')`，与主树**共用同一个目录**（实测堆到 400 条上限）⇒ 那条绿里有缓存命中。
     隔离办法有两种：把 `TMPDIR/TEMP/TMP` 指向空目录，或换一棵**字节不同**的树（LF 克隆会让键全变 ⇒ 自然冷跑）。
  3. **先拿判词原文，再决定复现哪些维度**。我在"缺产物 / 行尾 / 时区"三条假设上各花了一整遍 ≈15 分钟；
     日志里那一行 `✘ D232 …` 用 30 秒把范围收到一条门。**异常读数不该用"再跑一遍"解释掉，该用判词解释**（第 123 条的姊妹面）。
- 顺带一条记账规矩：DS 的新机制把"跳过"写进总结行，实际写成 `console.log(…) + (跳过…)` ⇒ **跳过数从来没打印过**。
  证据在 CI 日志里（D233 明明被跳过，总结行是光秃秃的 `通过 274 / 275`）⇒ **任何"某句话会显示出来"的自证，都要去日志里 grep 那句话本身**，
  不要只读代码（本条第 2 例：读代码只能证明"意图"，不能证明"输出"）。

## 125. 只在 Linux 上才红的病，本机行为腿抓不到 ⇒ **把那段判断抽成纯函数**，别退回源码正则（10-09 · §E558⑦ · 由 Claude 整改建议的规矩 1 纠正）

- 现场：D232 的 ④ 是行为腿（`spawnSync` 跑一枚真包）。这个 bug 的形状是"POSIX 绝对路径没被认出来"，
  而本机传给它的永远是 `C:\Users\…` ⇒ **④ 在本机怎么跑都绿**。
- 我第一版的处置是**补一条源码级负向钉**（扫 `usage-probe.mjs` 里有没有盘符正则），并在这一条里写了一句
  "POSIX 那一支只有 Linux 才构造得出来 ⇒ 只能钉源码"。**那句话是错的**，被整改建议的规矩 1 纠正：
  > 门禁只许测行为 = 跑代码、给输入、比输出；禁止读 `.md`、对源码做正则、匹配日志措辞。
  ⇒ 错在把"那段判断"和"那个文件系统"绑在一起看了。**绝对路径识别本身是纯函数**，输入就是一个字符串，
  两台上都构造得出来 —— 只要它住在可 import 的库里，门就能**给输入比输出**。
- 现在的形状：`tools/out-path.mjs` 的 `resolveOutPath(rawOut, ROOT, SUB)`，D232 的 ⑦ 喂四种输入比四个输出
  （本平台绝对路径原样返回 ‖ `/tmp/…` 不许被拼进仓库 ‖ 相对路径落 `champion-map` ‖ 空串必须响亮失败）。
  两向实测：装回**原样**的盘符正则 ⇒ ④ ✔（本机照旧看不见）而 **⑦ ✘**（`got=<repo>\champion-map\tmp\e497-…\u.tsv`）；
  修好的版本 ⇒ 两条都 ✔ ‖ rc=0。⇒ ⑦ 抓的正是 ④ 抓不到的那一支，而且**不需要 Linux 就能抓**。
- 通则：**"这条腿只能钉源码"通常是在说"这段逻辑还没抽出来"**。先问它能不能变成纯函数；
  变成纯函数之后行为测试就跨平台了，也不必破"只测行为"的规矩。
  （仓里同族的先例：D161 打 `guard-cost-lib.mjs`、D223 打 `bot-chooser-lib.mjs`、D155 打 `defense-axis.mjs` —— 都是"门直接对库做单元判定"。）
- 引用 CI 的两句话要分开：**`gates` = ubuntu 阻断档（np 整轮 + spec）**、**`browser` = windows 观察档（`continue-on-error`，不阻断）**。
  "CI 绿了"只有前一句算数；后者绿只说明浏览器那三道没炸。
