# 踩过的坑 / 规矩（Epirus-Web）—— 只留**会复发**的

> 为什么单独一个文件：这些不是"版本变化记录"（那些在 `CHANGELOG.md`），而是**做这件事时反复踩到的规矩**。
> 原先它们堆在 `HANDOFF.md` §5 里，让交接文档越滚越长；v1.5.18 起挪到这里，HANDOFF 只记"现在 + 下一步"。
> 编号沿用历史编号（1–20 来自 v1.5.2~v1.5.12 时期，21–25 是 v1.5.18 新增），**别因为编号大就跳过**。

## A. 工具 / 流程

1. **别把"等待"写进 tool call**（用户 2026-09-12 指出，千问定位）：我写了个 15 分钟的轮询循环，
   导致 **DSH 整个卡死**、实验被带走。**改成"一次只看一眼"（`timeoutMs ≤ 60s`），让实验自己写日志**。
2. **长任务先报【预估】、跑中报【进度】**（用户要求）。基准吞吐：**5 人 250 代热启动 ≈ 1 分钟**、
   **一个 1400 局考卷 ≈ 8 秒**。
3. **补丁与提交必须 `&&` 串联**，并在提交前 `grep` 校验 —— 我两次因为 Python 补丁失败
   （SyntaxError / 锚点不匹配）而**提交了声明里有、磁盘上没有**的 CHANGELOG 条目。
4. **别在同一条命令里叠多个 heredoc**：`python - <<'PY' … PY` 后面再跟 `git commit -F - <<'MSG'`，
   第一个 heredoc 会吃掉后面全部内容（本轮犯过，什么都没提交）。
5. **`git commit -m "…"` 的信息里不要有内层双引号**（会截断成 pathspec）。
6. **`sed -i 's/…v1.4.6/…/'` 不匹配时不报错** ⇒ 版本号会静默漂移（README 曾停在 v1.4.6、index.html 停在 v1.4.1）。
   **改用任意版本的正则** `s/v[0-9.]+/vX.Y.Z/`；且 **np-test D8** 已在守护三方一致。
7. **node 的 `/tmp` = `D:\tmp`**（不是 Git Bash 的 `%TEMP%`）⇒ 给 node 传 /tmp 下的文件必须 `$(cygpath -w …)`。
   这是会话内**第 4 次**踩。
8. **`.cmd` 里不能写中文注释**（GBK 码页会把行拆成非法命令）⇒ 两个 `.cmd` 都是纯 ASCII。
9. **按命令行模式杀进程会杀掉自己**（我的 kill 命令里含匹配串，把当前 shell 也匹配上了）。
   要按 pid 精确杀，或用不会出现在杀手指令里的模式。
10. **跨 heredoc 写 JS 正则会丢反斜杠**（`[\\/]` 变成 `[\/]`）⇒ 写完必须回读字节验证；
    实在要用就换成**不含反斜杠**的写法（如 `/^.*[^0-9A-Za-z_.-]/`）。

## B. 测量 / 方法（都是花钱买来的）

11. **n=1 不得下结论** —— 曾**三次**同类翻车：v1.4.1 把 38.4%→21.8% 归因于轮换（真因是"从零冷启动 vs 热启动谱系"）；
    v1.4.9 想据 `wall2-31` 换冠军（多 seed 后不显著）；v1.4.9 的反弹墙效应（n=6 仍不显著）。
    **单跑极差**：标准考卷 3.8~8.5pt、**反弹墙 100pt**。
12. **每个新口径都要带自检计数 + 反证对照**。范例：`--ban=sword`（使用率 0%）应给出 **≈0 的变化**
    （实测 −0.1pt）⇒ 证明消融器材本身不改变行为。没有反证对照的 Δ 不可信。
13. **"白名单/清单两处各写一遍"必出事**（漏加名字）—— 已踩**三次**（v1.3.59 漏 server、v1.4.8 漏 worker、
    v1.4.14 漏 `opp-pool.mjs` 本身）。现在由 **single source（`server/opp-pool.mjs`）+ np-test D7/D9** 守住。
    v1.5.18 又抓到三处同型（反摆烂 env / 体检指标 / 2P 基准表）⇒ 各配 D24 / D27 / `tools/p2-baselines.mjs`。
14. **口径会决定结论**（最贵的教训之一）：`枪` 的 mono-spam Δ = **−15.5pt**（读作"坑"）而消融 `Δ_lost` = **+0.5~3.8pt**
    （读作"该留着"）；`雷击之枪` mono −44pt（读作"没用"）而消融 −2.6pt + 环场 **+20pt**。
    **已在用的技能看消融；反制卡看场**。
15. **没有门禁会自己变绿**（v1.4.15）：`tools/smoke.mjs` 从 **v1.4.0 起就是红的**，4 个断言全在
    「长程（5 血）模式必须能在页面选到」这条线上 —— 而 v1.4.0 的交付清单里**只落了 `ui.js` 的消费者，
    没落 `index.html` 的 `<option>`**（"两处各写一半"）。它躺了 5 个版本。
    ⇒ **交付清单里"文件 A + 文件 B"这种条目，做完必须由一条会失败的用例去点名**。
16. **`workers` 是会改变结果的行为输入**（v1.5.0）：同 seed/池/起点，`EPIRUS_WORKERS` 16 → 12 训出的权重**不同**
    （sha1 `A4A1A894…` vs `92AF513B…`）。机理：worker 是独立沙箱，个体随机流在 worker 内推进量随
    `chunk = ceil(pop/workers)` 变化。⇒ **同 seed / 同池 / 同起点 / 同 worker 数**才是可复现；
    想"少用几个 worker 省机器"就等于**悄悄换了一个冠军**。
17. **给训练池加"对手名"时又漏了一处（同型第三次）**（v1.5.2）：只改了「开跑前校验」和「串行回退」，
    漏了**终局名人堂评估**那段 —— 它自己又写了一遍"名字→函数"映射，跑到 250 代才炸成 `sel is not a function`。
    ⇒ **规矩**：训练侧"名字→函数"**只允许一个入口**（`server/opp-champs.mjs` 的 `makeOppSelResolver`），
    且**开跑前把每个名字真解一次**。守门 `np-test D12`。附带：worker 里的硬错误必须 **reject 穿透**
    （否则 Promise 永不 resolve，只会挂到 30 分钟墙上时钟报"训练超时"，真因被埋掉）。
18. **"冠军的行为"与"某个风格脚本的行为"必须分清**（v1.5.13，用户实测踩到）：多人局难度下拉的**默认**是
    `st:combocounter` **脚本**，不是冠军 ⇒ 用户拿它当"冠军"看，于是"枪使用率很高"与 skill report 对不上；
    冠军 `eco-34` 的枪使用率是 **0%**。⇒ 想看冠军就把难度选成「**冠军（最强）**」；skill report 的「使用率」
    是**富裕经济**口径（每回合把 ep 补到 10），与真实对局不同 —— 它的「Δ_lost 强度」列才是主口径。
19. **规则文档里"对谁"没写清时，实现很容易只对 2 人局正确**（v1.5.13 修用户报的狙击枪 bug）：
    旧实现只查"被击方这回合用了什么技能"、不看打谁 ⇒ 多人局里目标用枪打第三个人也会废掉狙击，
    而 2 人局恰好等价 ⇒ `spec R13/57` 一直绿。守门 `np-test D20`。**教训**：规则条目里凡出现
    "该玩家/攻击者/被作用者"这类指代，实现处要写一句"到底指向谁"，并配一条**多人局**用例。
20. **"按模式猜默认值"必须先证明该模式真的会触发那条规则**（v1.5.12 回滚 v1.5.11）：
    干净配对（`lngC` 自动 0.5 vs `lngD` 显式 0，6 seed，其余全同）产出**逐字节相同** ⇒ 长程里它是**空操作**。

## 26. `git add -A` 会把"工作区里早就没了"的文件提交成删除 —— 提交前必看 `D` 行

**事故**：v1.5.21 提交时用了 `git add -A`，把 `results/` 里**早已不在工作区**的历史文件
（22/34/57 回合对局记录、`epirus-champion (6/7/8).json`、`page-verify-v1516/1517.png`、`battle-0{1..4}.png`）
一并提交成删除（`18 files changed, … 6018 deletions`），**用户的对局记录当场从仓库里消失**，
只能 `git checkout <上一个提交> -- results/` 恢复（已补一次"恢复提交"）。
**排查**：`tools/*.mjs` 只 `rmSync` 自己 `mkdtempSync` 出来的临时 user-data-dir，**不是工具删的** ——
工作区里那批文件在提交之前就已经不在了（很可能是一次手工清理）。
**规矩**：提交前先 `git status --porcelain`，**只要看到 `D`（deleted）行就先确认"这是我故意删的吗"**；
不是就 `git checkout <last-good> -- <path>` 恢复后再提交。**宁可分两次提交，也不要让 `-A` 替你做决定。**
（同族教训见第 3 条"补丁必须 && 串联 + grep 校验"：都是"别让一条命令替你做它没被告知的决定"。）

## 27. 新守门一律**追加在文件末尾**；门禁结果只看**退出码/尾部输出**，绝不看静默的 grep

**事故（连环两次）**：v1.5.33 的 D44 与 v1.5.34 的 D45 都用"锚点插入"写进了**别的测试块中间** ⇒
`tools/np-test.mjs` 多出一个 `});` ⇒ **SyntaxError，整个守门脚本崩掉**。
更糟的是：两次提交时我的命令都是 `node tools/np-test.mjs | grep -E "✘|通过 " | tail -2`，
脚本崩溃时 grep **匹配不到任何东西 ⇒ 静默无输出**，而我把"没有输出"读成了"通过" ⇒ 坏文件被提交并推送了两次。

**规矩**：
1. **新测试追加在文件末尾**（用 `cat >>` 或"取文件尾部锚点"），**不要**按中间某行做插入 —— 那种锚点在语义上分不清
   "块内"还是"块边界"（D38/D39、D44/D45 都栽在这上面）；
2. 门禁结果**必须看退出码**（`node tools/np-test.mjs > /tmp/x 2>&1; echo $?; tail -3 /tmp/x`），
   **绝不**用 `grep | tail` 的"有/无输出"当判据 —— 静默既可能是"没有失败项"、也可能是"脚本根本没跑起来"；
3. 同族教训（见第 26 条）：**别让一条命令替你做它没被告知的决定**。

## D. v1.5.94–99（第九轮复核 + 教师示范接线）新增

28. **"接线在文件里" ≠ "接线在跑的那条路径上"** —— 同一个故障本轮连续出现**三次**，每次都把整臂变成空操作：
    - **env 拷贝**：`worker_threads` 的 `process.env` 是**创建时的拷贝**；而 `EPIRUS_IMIT_GENS` 是服务端在
      `runTrain` 里**事后**派生再写进 env 的 ⇒ worker 永远读到 0
      （`v7ringT` / `v7ringT2` 两批产物与对照 **逐位相同** = no-op）。
    - **函数分叉（真根因）**：runner 的训练 URL 带 `n=5` ⇒ 请求走 **`runTrainN`**（多人路径），
      而全部 IMIT 接线原先**只写在 `runTrain`**（2 人路径）⇒ N 人臂上 `imitB ≡ 0`。
    - **名字静默退回**：`EPIRUS_IMIT_TEACHER=deepsaver` 不是 `BOT_PICKS` 的键（正确名是 `pickDeepSaver`）⇒
      `accepted=false`，而库里 `IMIT_TEACHER || BOT_PICKS['heavyfire']` **静默退回默认教师** ⇒
      整臂**贴着错标签**跑完。
    ⇒ 四条规矩：① 回执必须打**在真正执行的那条路径**上（worker 侧也要打）；② 回执要含**生效值**
      （`gens / frac / teacher / accepted / override / β(gen0)`）；③ **最终反证 = 产物是否与对照逐位相同**
      （确定性流水线让它成为最强判据）；④ 解析与设值**只写一份**（`applyImitEnv`、`setImitPlanByName`），
      两条路径都调它。

29. **"样本敏感性"本身要按包验证，不能当常数用**：第 22 条那条曲线
    （同一个包 n5=3.08 / n10=2.99 / n20=4.24 / n40=4.54）只在**当时那个包**上成立；
    本轮 `v7role1-82` 在 **n=5~80 恒定 1.70~1.71** ⇒ 它的 `G<3` 是**真塌**，不是抽样假象。
    ⇒ 引用旧曲线之前，先在**手上这个包**上重测一遍。

30. **报均值必须同时报逐 seed 胜负**：6 seed 时"角色间熵 +51%"看着像真赢，
    扩到 9 seed 后翻成 **4 胜 5 负** —— 那个 +51% 全靠**对照的一个退化 seed**
    （角色间熵 0.002 = 蓄能囤积到 100%）撑着。⇒ 退化样本会污染均值；**逐 seed 胜负才是结论**。

31. **门的判据要写清"量的是什么"，而且"最坏的那一格/那一座"本身是小样本统计量**：
    - 座位门的判据是**极差**（<30pt），**不是**"有没有座位为 0"。`v7f5t-31` 在 n=400 时极差 26.9pt ✓ 过门，
      可它的**首座夺冠率是 0%**（其余四座 20~27%）。
    - **同一类错误本轮出现两次**：座位极差在默认 n=40.4pt（红）→ n=200 30.6pt（红，只超 0.6）→
      n=400/800 **26.9/26.3pt（绿）**；`G4` 的"最克那一格"在 **n=60 是「坦克线 57%」**，
      而 **n=120 与 n=200 都稳定指向「只枪 53%」** ⇒ **n=60 会选错格子**。
    ⇒ 两条硬规矩：① 阈值落在噪声带时，**判"过/不过"之前先把 n 拉大**；
      ② **报 `G4` 必须同时报 n**（否则"哪一格最克"这个结论本身不可信）。

33. **布尔化的经济判据会被"最小非零"刷分**（第十轮复核 §4-2）：`D78` 原先要求"得珠>0 **且** 花掉>0"，
    而候选② 得珠 835 / **花掉 1**（花/得 **0.12%**）就点亮了"闭环 ✓"，同时每局浪费 **20.9** 颗（≈在位包的 250 倍）。
    这是第七轮 §11 陷阱的**镜像**（当时是"干脆不用 ⇒ 浪费率 0% ⇒ 绿"）。
    ⇒ 规矩：**任何布尔化判据都要先问"最小非零能不能点亮它"**；经济类判据用**双条件**
    （花/得 ≥ 20% **且** 过期/局 ≤ 1），并且**把"囤积"与"使用"在同一个显示里分开**
    （`energy(含空转/过期珠)` —— 否则 25.4% 会被读成"开始用能量类"）。

34. **"偶然性"至少有两种，处置相反**（第十轮复核 §5）：用"解析候选熵 `H` + 采样背离率（1−p_max）"区分 ——
    - **策略内的偶然性**（高 `H`、背离 34%）：同一局面每局一个样 ⇒ **降温度/降 ε 可收窄**，代价是变呆；
      但它的**读数本身带采样噪声 ⇒ 必须报置信区间**。
    - **种子内的偶然性**（`H≈0`、块胜率 `[0,0,0,0]`）：网络已收敛到极峰，**确定地**产出这个形状 ⇒
      **降温度完全无效**，只能换配置 / 换 seed ⇒ **必须报"同配置换 seed 的复现率"**。
    ⇒ `H=0` 还意味着：**对已收敛到单卡的个体，熵/覆盖类项没有牙齿**（我的 `S` 是跨状态覆盖熵，同理会退化 ⇒
    要让 S 有牙齿得用**跨状态**的覆盖量（`roleOf` 8 角色 / 门禁 `G`），而不是同状态内的动作熵）。

35. **报"考卷分"也要报决策样本 n**（第十轮复核 §3-2 的扩展）：有的包里 A 卷只有 **136 个决策样本**
    （该场里它 0 号席常早亡）⇒ 与 `G4`/座位同理，**分数本身也是小样本统计量**。

32. **"产物=证据；没记账的产物等于没有结论"**：整晚 20 个产物零记录，其中一个座位极差 99pt。
    ⇒ 立了守门 **D82**：**24h 内落盘的 `.bak` 必须逐个在 CHANGELOG 被点名**（**缩写不算字面名字**）。
    它随后**多次抓到我自己**（漏点名、用 `v7f2t-{31,…}` 缩写）。

## 48. **想用"奖励/补贴"买一个动作之前，先量那个动作的门槛在决策时刻的分布**（v1.5.204；用户问"击杀奖励明明该利好大雷电磁炮，为什么重训没效果"）

**结论先摆**：不是奖励写错了，而是**它买的那个动作，现役包在 99% 的决策时刻根本够不着门槛** ——
所以把回款从 1ep 改成 2ep、改成"按伤害"、改成任何 ≤2ep 的形状，都**跨不过那道 5ep 的门**。

### 48.1 量出来的三层原因（现役 `v7cmin4-31` · multi · 各 200 局 · 用真规则实现的内存补丁）

**① 规则的实际语义 ≠ "击杀回 2ep"。** `tools/kill-reward-lib.mjs`：
- **规则 1（单点）**：本回合有人死亡 ⇒ 回 **1 ep** 给"所用技能优先级最高"的参与者；
- **规则 2（按伤害）**：每个参与者按**造成的有效伤害**回**等量** ep（overkill 不付）。
⇒ 一次 1 点伤害的补刀只回 **1 ep**。实测两档**实付几乎相同**：

| | 脚本池场 ep 收入/局 | **规则实付/局** | 占收入 | 有来源伤害/局 | 死亡/局 |
|---|---|---|---|---|---|
| 规则 0（关） | 5.03 | 0.00 | 0% | 13.37 | 4.8 |
| 规则 1 | 4.90 | **1.05** | 21.4% | 13.72 | 4.3 |
| 规则 2 | 4.69 | **1.05** | 22.5% | 13.66 | 4.3 |

**② 在最需要它的那个场地里，它一分钱都不付。**
破防场（4×只防御不还手）：**死亡 5.0 次/局**，但 **有来源伤害 0.00/局** ——
5 次死亡**全部**来自无来源的终局收缩（`damage.source == null`）⇒ **规则实付 0.00 ep/局**。
即：**激励恰好在"该换穿透线去清场"的场景里结构性缺席**（这正是第 46 条理想冠军第 3 条要治的那件事）。

**③ 即使付了，也跨不过门槛 —— 这条才是决定性的。** 大雷 = **5 ep**（电磁炮 2ep + 1 珠；ジ = 1ep/次）：

| 场地 | 决策时刻 ep 均值 | `ep≥5`（现在就能打） | `ep=3~4`（**+2 就翻过门槛**） | `ep<3` |
|---|---|---|---|---|
| 脚本池场（7.5 次决策/局） | **0.76** | **0.0%** | **2.4%** | 97.6% |
| 破防场（47 次决策/局，收入 24ep/局） | **0.49** | **0.0%** | **0.0%** | 100.0% |

⇒ 一个 +2ep 的回款能改变"能不能打大雷"的决策占比 = **2.4%（脚本池）/ 0.0%（破防场）**。

### 48.2 可搬走的三条规矩

1. **买动作之前先量"门槛在决策时刻的分布"**，不是量"理论上能不能"。
   本例第一眼看上去 ep 收入 24/局、回款 21% 的"占比"都不小，但**分布**一量就发现均值 0.49、`ep≥3` 占 0%
   —— **"占总收入的比例"是错的透镜，要看"离门槛的距离"。**
2. **奖励必须能"到达"那个场景**：先问触发条件（本例：要有**有来源**的击杀）在那个场景里成立吗。
   破防场 5 死亡/局却 0 归因 ⇒ 奖励再大也不发。
3. **同族的奖励形状之间先互相比一比**：规则 1 与规则 2 实付相同（1.05 vs 1.05）
   ⇒ "按伤害"这个精化在经济上**什么也没改变**。若两个形状读数几乎相同，**别把希望押在换形状上**。

> 与第 46 条合起来读：理想冠军的第 1 条（会为大招攒钱）与第 3 条（会清场）**不是"奖励不够"**，
> 而是**门槛不可达 + 激励不可达**这两件事。所以出口仍是用户自己指出的那两条：
> **改价**（把大雷费用/ ep 收入挪到"积累"真的可能发生的量级）或 **改判据**（把破防场纳入主判）。

## 49. **评测口径 ≠ 玩家看到的口径**；对"会不会发生"的判断必须换到产品口径复量一次（09-24 夜 · Qoder §H-6）

⇒ 「现役 0% 胜 / 100% 平 ⇒ 它不会清场」这句话**只在 ε=0 成立**；玩家在多人 AI 局里看到的是 87.5% 胜。
   门禁继续用 ε=0 是**有意的**（可复现、评的是包本身，v1.5.152 因此另设"产品代理栏"）——
   **错的是把 ε=0 的绝对值直接写成"玩家会遇到的局面"**。本轮把 `METHODOLOGY §48` 结尾那句
   "第 3 条（会清场）是门槛/激励不可达"也一并降级：那条讲的是**跨期攒大雷**，与"破防场拖平"不是一回事。
- **会复发的形状**：同一份代码里两套口径只差一个参数，而**表头上不写口径**（`probe-ideal-champion` 修前只印包名/局数）。
  ⇒ 已把 `temp/eps/epsK/epsMode` 全印进表头。**读数旁边没有口径，就等于读数没有单位。**

## 50. 扫旋钮要扫**那根真的杆**（同一夜 · §H-3）
`policyChooserN(params, temp, eps, epsK, epsMode)` 有五个位置参数。第 2 个是 **softmax 温度**，第 3 个才是**探索率 ε**。
我第一版把"ε 扫描"接到了第 2 个参数上，扫出来 `0.47/0.43/0.43/0.44` —— **几乎不动**，

  一个有多参数的函数，探针要**把每个参数都做成具名开关**，别复用同一个位置。

## 51. 广度类读数**对"恒亏动作"不设防**（同一夜 · §H-7）
`G 有效技能数` / `净兑现` 统计的是**非ジ出手**的种类与熵 ⇒ 一次"清除 0 枚"的空净化、一次"全场无符咒"的空天火，

`G(long) 3.83 → 2.95`、净兑现 `3.25(5 种) → 2.88(4 种)`，**直接从"过广度门"变成被 `G<3` 阻断**。
- ⇒ 报广度必须**同时报"其中多少是空转动作"**；否则"广度"会奖励**浪费得多样化**。
  与用户那句老话同源（"G_eff 像刷分"）与 §N24（命中加权广度）同族 —— 这一条是把病根往前推了一层：**不是刷分，是刷无效动作。**

### 51.1 【自我更正】"空转刷广度"这个猜想**被同一夜的数据否证**（§H-8）
把恒亏出手按事件逐条从计数里扣掉之后重算 `G`（镜像 40 局 · 5 席）：

## 53. 配重量具的两种自检：**与单一真源逐字对齐** + **判定旁边印分母**（09-25 凌晨 · Qoder §H-10）
交接 §4-E7 只要"座位极差统一按 n=400 报"，但要报就得同时报两个口径（评测 ε=0 / 产品 ε=0.2 soft），
而 `audit-lib.seatSymmetry` **不接受 Chooser 注入** ⇒ 只能复刻一份。复刻的代价是"我这份算的还算不算它"，所以钉了两道：
1. **复刻必须与真源逐字相同，否则整张表作废**：同一 seed 序列（`seedBase+g`）、同一 `slotSalt` 公式、同一判胜口径，只换 ε；
   跑之前先在 n=100/`seed0=12000` 上比对 5 席**回胜利计数**，不等就 `exit 8` 并打印两边的数。
   ⇒ 实测 `10/18/16/16/20` 逐字相同。这条把"复刻漂移"从**静默错误**变成**当场失败**（与 §47.4"静默跳过=关掉测量"同族）。
2. **两栏配对 ⇒ 差值只来自口径**：不配对的扫描（各口径各抽各的 seed）会把"抽样噪声"记到"口径"头上 ——
   我这夜前两版就吃了这个亏：`--reps` 跑出来的噪声带是 `[15.2~15.2]` 这种**假零带宽**，因为 `seatSymmetry` 的 seed 序列是写死的，重复只是重复。
   ⇒ 换 `seedBase` 才是重复；而真源那一栏没法换 seed ⇒ 只在**自检格**（`seedBase=12000`）上与真源对齐，其余格用我这份。
- **判定旁边必须印分母**：加了这栏之后才发现最要紧的数不是极差，而是**判胜率** ——
  `cbs1s2-band2` 在 ε=0 下判胜 **26~30%**（正好压在 `audit-lib.mjs:415` 的 `decisiveRate<0.3 ⇒ 'unjudgeable'` 线上抖），
  极差 30.8pt 是在不到 1/3 的局上算的；同批种子在 ε=0.2 soft 下判胜 98%、极差 12.1pt ⇒ **两栏判定相反**。
  仓里 `unjudgeable` 只出现在 `audit-lib.mjs:514` 的 `notes` 里 ⇒ **表格列看不见它**。
- **可搬走的规矩**：凡"一个阈值 + 一个可能很小的分母"的读数（极差、率、占比），**打印格式里就得带上分母**；
  只在"备注"里写"不可判"，等于把这条判定交给读表的人的记忆。

## 54. 把**整个评测层**搬到另一个口径只有两条路，而且**必须自证搬到了**；换口径要**按列**重标定（09-25 凌晨 · Qoder §H-12）
`audit-lib.mjs` 的 9 个探针与 `evo.js` 的 4 处都写死 `policyChooserN(params, 0.15)` ⇒ 想量"这些门在产品口径下会怎么判"，只有两条不改仓库文件的路：
1. **`evo.js` 侧**：源码读进内存后做**字符串替换**再 `vm.runInNewContext`（内部调用走的是闭包绑定，改导出对象**无效**）；
2. **`audit-lib` 侧**：它是 ESM、不进气泡，但它调的是 `W.EpirusTrainer.policyChooserN` ⇒ **装载后把沙箱里那个属性包一层**，

  ⇒ 这是 §47.4「静默跳过 = 把测量关掉而汇总仍全绿」的**逆向版本**：这里的风险是"两栏一模一样"被读成"口径不影响"，而真相是"我根本没搬过去"。

- **先把"产品口径"这个词拆成两个，否则一定说错话**：5 人冠军槽 = `js/ui/ui.js:464` 的 `pickChampion(..., 0.15, 0.2, 5, 'soft')`；

- **方向性结论（这次量到的最有用的一条）**：**广度族在 ε=0 系统性偏低** —— 4/4 粒候选 `ΔG` 全为正（+1.45~+4.40），
  因为 `G` 数的是"非ジ出手的种类/熵"，**探索本身就会制造种类**。⇒ `G < 3` 这条线在评测口径下对**窄型候选偏严**

## 55. 把一条线搬到另一个口径之前，先量**两侧的分布**——"现役过不过"只是其中一个端点（09-25 凌晨 · Qoder §H-13）
`G 有效技能数 ≥ 3` 这条广度门线判在 ε=0 上。第 54 条量到"ε=0 下的 `G` 系统性偏低"之后，最容易写下的错结论是：**"那就搬到产品口径"**。
把 160 粒档案包（`docs/artifacts/*.bak` 每 9 取 1）在两口径各过一遍之后，这张表否掉了那个"那就"：

| 判据 | 评测口径 ε=0 | 产品口径 ε=0.2 soft |
|---|---|---|
| `G(multi) < 3` 被挡 | **84 粒（53%）** | **8 粒（5%）** |
| `G(long) < 3` 被挡 | 93 粒 | 4 粒 |
| 净兑现 `< 3` | 148 粒 | 117 粒 |
| 跨界方向 | **"ε=0 挡 → 产品过" 76 粒 : 反向 0 粒**（ΔG 中位 +2.51，157 正 / 3 负） | |

- 方向**完全单侧**，所以"偏严"是真的；**但搬过去之后那条线只剩 5% 的阻挡率 = 基本没有判别力** ——
  一条"谁都不会被挡"的门与一条"挡一半人"的门，**都不叫判据**。所以正解不是挪口径，而是三选一（都属判据侧）：
  (a) 留在 ε=0 但把线抬高；(b) **换成与探索无关的定义**（净兑现那一栏两口径都还严：148→117）；(c) 双口径并报、两栏都过才算。
- **会复发的形状**：拿"在位包在这条线下是红是绿"当换线的理由。现役在两口径下的确都红（0.00 → 4.63 点/局），
  但**同一批档案包**的分布从"53% 被挡"变成"5% 被挡" ⇒ 端点没变、分辨力消失了。
  ⇒ **换判据必须同时报：端点（现役） + 全池分布（多少粒被挡） + 跨界方向计数（正向 : 反向）。**
  这三样缺一样，都可能把"失去判别力"读成"修好了偏严"。
- 配套的一条口径卫生：**预注册里的判据要带样本量下限** —— 我这轮的落点写成"`freed ≥ 3×max(1,blocked)`"，
  在 n=3 的前置检查上直接打印出"②成立（两向差不多）"这种荒唐话（分母只有 3 粒）⇒ 已补 `n<30 或被挡<10 ⇒ 判"样本不足"`。

## 56. 用户的一句观感要拆成**两个各自可判的问题**，而且**每个分桶都要带 n、桶口径要写死**（09-25 凌晨 · Qoder §H-15）
原话："碰到一个人攒钱就会开始疯狂防御并且维持很久。" 这句话里其实缠着三件事，混在一起问就永远只能得到"是/不是"：
1. **"防御是不是因为对方在攒钱"** —— 这是**因果方向**问题 ⇒ 必须按"**该回合开始时**对手的 ep"分桶，读设防率随桶的变化。
   实测（现役 3p · 产品口径 · 200 局 · 高桶自适应合并后）：`9.3%(n=2431) → 4.6%(4772) → 3.4%(964)`（对手越有钱设防越少）⇒ **方向不支持**；`cbs1s2-band2` 是平的（6.9/8.3/7.4/8.9%）。
2. **"是不是维持很久"** —— 这是**游程长度**问题 ⇒ 读"同一席连续设防的最长回合数"与"≥3 连的局占比"，不是读设防率。
   实测：最长 **4 回合**、≥3 连只占 **4.5~6.0%** 的局；而 ε=0 对照那边**最长 1 回合、≥3 连 0.0%**。
3. **"这件事在不在门禁的视野里"** —— 前两问的答案都只在产品口径下非零 ⇒ 门禁那一侧读到的永远是 0，**"没报"与"没有"不是一回事**（§47.4 同族）。
- **桶口径必须写死在实现与读数里 —— 而我第一版写的口径当场被自己的门测死了**：原本读的是"事件流里 `ep` 前缀和"，假定"一回合内 5 条 `action` 全先于结算"。
  门 D151 第一版去验这条假定，实测**一局里 64 次结算落在 action 之前/之间、只有 13 次是干净分界** ⇒ 假定不成立；而且前缀和**只加不减**（对手花了不扣），
  量出来的是"它一辈子挣过多少"，不是"它手里现在有多少"。⇒ 正确读法只有一个：**在被评席做决策的那一刻直接读 `state.p[0].ep`**，回合号用 `state.round`（实测单调）。
  **教训**：凡是"从事件流重建某个状态量"的读数，都要先去引擎里**读那个量本身**对一遍；重建省下的那几行，代价是整条判据可能是假的。
- **每个比例都要带分母，且小分母不许当 0%**：`ep≥10` 那一桶只有 20 次出手（现役）——直接算成"20.0%"就会看起来像一个发现。
  ⇒ 本量具的落点写的是"**分母不足 ⇒ 这条因果没量到**"，而不是任何方向的结论。（与第 53 条"判定旁边印分母"同规。）
- **同一条轴不许自己当自己的对照**：上面第 1 问的分桶变量（对手 ep）在这个装配里**与回合数同向单调**（替身只攒不花 ⇒ 第 2 回合 ≈ ep0~1、第 12 回合 ≈ ep5+）。
  ⇒ 这种时候"高桶设防率低"既可能是"不冲着他"，也可能只是"晚期不摆架势"。修法有两层：
  读数层——**把混淆变量并排印出来**（本量具现在每桶印"该桶平均回合"）；结论层——**把强度从"看到负相关"降到"没看到正相关"**。
  真要分离就得换装配（对手 ep 振荡），那是另一件量具的活。**能印就不能猜。**

## 57. "A 导致 B"这类观感，**单档装配永远答不了**——要造一个把两条轴分开的第二档，在同一坐标上配对（09-25 凌晨 · Qoder §H-19）
"`cbs1s2-band2` 的设防率随对手 ep 从 7.9% 涨到 51.8%"**本身不算证据**：这一档装配里对手是纯攒钱替身，第 r 回合它的 ep≈r−1 ⇒ **ep 轴与回合轴重合**，
"它看见钱才防"与"它越晚越防"是同一句话。分开的方法是把 ep 压住、其他不变，再在**同一回合号**上比：
- `hold`（钱一路堆）第 6/8/10/12/14 回合：`29.8 / 38.1 / 38.1 / 42.8 / 44.8%`
- `cycle`（堆到 4 就全花掉，同回合对手只有 ep 3~4）：`14.8 / 17.0 / 12.6 / 16.4 / 19.0%`
- 而第 4~5 回合两档 ep 还相同时，两条曲线**逐字重合**（15.3% / 19.8% 两档相同）⇒ 分岔恰好发生在 ep 分岔处。
⇒ 这才叫"看到响应"。同一套配到线上包上：两档各回合都是 3~8%、无系统差 ⇒ **线上包没有这个响应**。
- **可搬走的三条**：① 造装配时**先问哪两条轴会天然重合**（这里 ep 与回合号；同类还有"局长与死亡数""广度与出手数"），重合就只能描述、不能判因果；
  ② 判因果要造**第二档把其中一条轴钉住**，并证明两档在"该轴尚未分岔"的那段曲线重合（这是免费的安慰剂对照）；
  ③ 报告要写"同一坐标配对差多少倍"，而不是"某一轴单调"——后者读者会自动脑补成因果。
- **配对之外还要一个"安慰剂窗口"**：两档在**该轴还没分岔的那几回合必须逐字重合**（这里 r4/r5 两档都是 12.1% / 16.6%，n=619/650），
  分岔之后才分开（r6 起 29.7% vs 15.8% … r14 45.2% vs 14.9%）。重合段是免费的"两档没别处不一样"的证明，**没有它，两档差值随时可以是装配本身的差**。
  再补一刀：同一批读数只取"自上次自己决策以来没掉过血"的子样本，`ep5~9` 33.0%→32.7%、`ep≥10` 51.8%→**52.3%** ⇒ "挨过打才防"解释不了这条上升。
- **同一条读数的副作用**：它把用户实机报的病归到了一粒**候选**（`cbs1s2-band2`，我前一夜还记它"四栏最均衡"）而不是线上包 ⇒ 候选排序里若没有"对手攒钱时的设防持续性"这一栏，
  一只**会在产品口径下自己跟自己对成龟群**的包可以一路绿灯过门。这条已经写进早报的裁定件，**我没动任何门**。

## 58. 抓到一粒包的病之后，第一个要做的动作是**扫全池问"这是个例还是体质"**（09-25 凌晨 · Qoder §H-21）
`cbs1s2-band2` 有"对手有钱→就转防"的响应（倍差 5.6×、同席连防 34 回合）——这时最省事的叙事是"这粒候选不行，换一粒"。
把同一个读数扫最近 44 粒臂包（`--quiet=1` 汇总表 · 60 局/粒）之后：**倍差≥2 且高桶设防率≥20% 的有 13 粒 / 41 个不同权重 = 32%**，
而线上包与 `v7aim3-93` 只有 0.12~0.16×。⇒ 这不是"某粒臂运气差"，是**当前配方稳定养出这种体质**。
- **为什么这个区分值钱**：个例 ⇒ 换候选；体质 ⇒ 换候选没有意义（再抽一颗骰子，还是有 1/3 概率抽到同一种体质），要动的是**训练场或判据**。
  两者的代价差一个量级，而**只有扫一遍全池才能分清**——单粒包的读数本身永远说不出比例。
- **配套的两条卫生**：
  ① **扫之前先去重**（剥壳只哈希 `a` 数组）：这次 44 粒里其实只有 **41 个不同权重**——`cbs1s3/5/6` 与 `cbig1s3/5/6` 是三对逐字节相同的包
    （与 09-24 记的 `EPIRUS_SEL_LAND` 咬合率 3/6 同源：带内换人在同分带里换不出新东西）。不去重就会把 32% 报成 34%，还会把"两粒包都有病"当成两条独立证据。
  ② 汇总表要**同时印分子分母的桶值**（`ep0~1 → ep5~9 → ep≥10` 三桶 + 连防长度），只印倍差就会有人拿 n=41 的短局行去和 n=9000 的长局行比大小。
- **顺带得到的好处**：这张分布就是将来"设防持续性"那一栏的**线该画在哪**的底稿（倍差 2？连防 5？）——有分布就别拍脑袋。

## 59. 同一个"浪费率"可以来自**两种相反的病**；而"按决策计"与"按珠子计"两把尺不许互相校验（09-25 凌晨 · Qoder §H-27）
"珠浪费率高"是一个**总量**（`chargeProfile`：得珠 / 花掉 / 过期）。把同一个数按"蓄能之后**下一次决策**那一刻电磁炮买不买得起"拆开，两粒包立刻分到相反的方向：

| 包 | 蓄能后配到下一次决策 | ① 买不起（经济） | ② 买得起却没射（选择） | ③ 射了 | 真源浪费率（按珠子计） |
|---|---|---|---|---|---|
| 现役 3p | n=385 | 1.0% | **68.1%** | 30.9% | 48.2% |
| `v7cmin4-82` | n=1617 | **83.3%** | 11.7% | 5.0% | 88.2% |

⇒ 两粒都"浪费"，但**一粒要动经济（收入/价），另一粒要动打分/菜单** —— 拿总量提方案就会开错药。
- **"② 里它到底在干什么"必须并排印**：现役 262 次里 **256 次在按 ジ**（不是被别的卡抢了珠，是纯粹继续攒）；
  `v7cmin4-82` 是 ジ 143 / 蓄能 35 / 聚能环 11。这一栏把"空蓄能"与 §H-1 的"大雷可达时成交率 0.0%"接成**同一条**：**它把"攒"当成了动作本身**。
- **两把尺各量各的**：本表按**决策**计，真源按**珠子**计 ⇒ 两者天然不等（一颗珠可能被别的卡吃掉；一次蓄能也可能与手上已有的珠混在一起）。
  所以读数旁边必须并排印真源那一行并写明"**不许拿一个去校验另一个**" —— 我第一版就是看到"48% vs 68%"以为自己算错了，差点把发现当 bug 删掉。
- **窗口要判"东西还在不在"**：珠只保留到下一回合，而"该席下一次决策"可能已是两三个回合之后 ⇒ 必须先过一道 `beadAlive`，
  把"隔太久才决策"的那批**单列成 `beadGone`、不混进①②的分母**。我第一版没判，造出过 8 次假"买不起"（这批包实测 `beadGone`=0，但**判据要在，不能在读数里靠运气**）。

## 60. 用"响应量"分类时，必须同时量"水平量"——否则**最糟的那一类会被读成健康**（09-25 凌晨 · Qoder §H-30）
我把档案包按"对手有钱时设防率 ÷ 没钱时设防率"（倍差）分类，判据 `倍差≥2 且高桶≥20%`。45 粒 × 120 局重跑后发现：
- **响应型** 13 粒（29%）——倍差抓到的；
- **恒定龟缩型** 14 粒（31%）——**对手 0~1ep 时就已经设防 20~97%**，倍差恒在 1 附近 ⇒ **被我的规则打成"无响应"**；
- 两类都不是 18 粒（40%）。合并 27/45 = **60%**，而我原先只报出 32%。
⇒ **凡用"斜率/比值"型判据（响应量）分类，必须并联一个"截距/水平"型判据**：比率对"分母与分子一起变大"的行为天生失明，
  而"不分场合一直防"对玩家体验的破坏**不依赖对手有没有钱**，往往更糟。
  同族的旧例子：§H-12 里"只记录变化幅度会漏掉基线不为零的项"、METHODOLOGY 47.6"从算式出发不实测会错在量级"。
- **顺带一条降级**：同一张表加了"玩家侧代价"两栏之后，我看到**三类的攒钱者夺冠率中位都是 0%** ⇒
  昨天写在 §H-23 的"换 band2 会让只攒钱的人 0%→13.3%"只是**那一粒包的特性**，不是家族规律 ⇒ 已撤回家族版表述，代价只按"局长中位 18→30、连防中位 5→31 回合"报。
  **教训**：一粒包上量到的"收益"不能升格成"这类包的规律"，除非按类别分组再算一次中位数。

## 61. 评一条判据时，**不许用定义标签的那个变量去算命中率**（09-25 凌晨 · Qoder §H-40）
我把档案包分成"响应型（倍差≥2 且高桶设防≥20%）/ 恒定龟缩型（低桶设防≥20%）/ 干净"三组，再去评候选判据"哪条线画得住"。
第一次列出的表里有两行是这样的：`高桶设防≥20% ⇒ TP=100% FP=7.6%`、`低桶设防≥20% ⇒ 恒定型 100% FP=0%`——
**这两行毫无信息量**：判据用的就是分组用的那个变量，100% 是定义给的，不是量出来的。
- ⇒ 规矩：给"判据/阈值"做评价时，先把**标签用到的变量**从候选判据里剔出去，或者**明写哪几行是自证式**；
  真正该报的是两个数：**① 干净组的误伤率**（这里 连防≥12 → 2/92=2.2%），以及 **② 标签之外的漏网名单**（响应型 49 粒里有 6 粒连防<12 且低桶<20%，这判据全抓不到 ⇒ 12%）。
- **同族的旧版本**：第 55 条"只端点不分布"、第 58 条"个例 vs 体质"、第 60 条"比值对水平失明"——都是同一件事的不同侧面：**读数与标签必须来自不同的量**。

## 62. 说"档案普查"之前，先按**等价类去重**并报**覆盖率**；按文件名等距抽样会系统漏掉整棵树（09-25 上午 · Qoder §H-46/§H-50）
我拿 `docs/artifacts/*.bak` 按"每 2 取 1"抽了 198 粒，跑完就把它当"档案里的比例"写了出去（响应 24.7% / 恒定 28.8% / 并集 53.5%）。
给锚点补测时才发现两件事：**① `.bak` 里大量文件是同权重不同名**（`v7xn1-31` 与 `v7cmin4-31` 每一栏读数逐字相同）⇒ 按权重向量哈希去重后 1449 粒只剩 **1004 个不同权重**；
**② 那 198 粒只覆盖 1004 类里的 162 类（16.1%）**，漏掉的恰好是**整棵 `v7*` 树**（716 类）——因为按文件名排序 + 固定步长抽样，会让同名前缀的族被整段错开。
重跑全档案后的真实数：**响应 19.4% / 恒定 9.5% / 并集 28.9%**。恒定龟那一档掉了 3/4，全部虚增来自 `chain*`/`kr*`/`ms*`/`champ*` 这些**消融与课程家族被过度代表**。
- ⇒ 规矩三条：**(a) 扫池先按"会被判定的那个对象"去重**（这里是权重向量，不是文件名），**(b) 报告里必须写"覆盖了 N 个等价类中的 M 个（%）"**，**(c) 分层（家族）结果与总数一起给**——总数会掩盖"某一族被抽爆"。
- **同族旧例子**：第 58 条"个例 vs 体质"（同一批里换个包还有没有）、第 55 条"只端点不分布"。**这一条是它们的抽样版**：不是读数骗我，是**抽样框**骗我。

## 63. 想把"已经算过的数"当免费代理判据，第一件事是测**方向**，不是测阈值（09-25 上午 · Qoder §H-45）
问题本来是"能不能零成本加一栏"：门的 ε=0 镜像已经算了设防份额、伤害/回合、出手伤害份额、局长、蓄能/局、珠浪费，拿它们预测"有钱→转防"体质不就免费了？
194 粒对表的实测：**六栏最好的工作点只有 TPR 60% / FP 24%，组合两栏也只有 21%/16%——全在对角线附近**；更难看的是**方向是反的**：被产品口径判为龟的粒，在 ε=0 镜像里的设防份额中位数反而**更低**（49.3 vs 58.8），现役好包 `v7cmin4-31` 的 `按ジ%` 是七粒锚点里**最高**的 79.3%。
⇒ 任何以"设防份额"为键的判据会**优先误伤现役**。机制讲得通：ε=0 五席同包互不犯 ⇒ 高设防率是**那个口径下的常态**，不是体质；体质只在"桌上真坐一个攒钱的人"时显形。
- ⇒ 规矩：提"用现成读数当代理"之前，先跑**标签组 vs 对照组的中位数**看方向（一次 4 行代码的量），方向对了再谈阈值与 ROC；**方向反了就是反证，要如实写反证**，不许挑一个能分开的手势凑数。
- **同族**：第 61 条"不许用定义标签的变量给判据打分"（这里的问题是另一面——**用了不同变量，但它测的是另一件事**）；第 49 条"口径差会改写结论"（同一只包两个口径两个世界）。

## 64. 用"分桶比值"下因果结论之前，必须再跑一档**把桶变量钉住**的对照；单档比值会把时间轴记到钱头上（09-25 上午 · Qoder §H-53）
我有一副干净的因果装置：`hold`（对手永远出ジ ⇒ 钱一路堆）与 `cycle`（堆到 4 就全花掉 ⇒ ep 钉在 0~3）。用它证明了 `band2` 的"有钱→转防"是真的（同回合号上 2.46×）。
然后我把**只跑 `hold` 一档**的 1004 粒筛表当成了"体质流行率"（响应型 19.4%）。补跑 `cycle` 档逐粒同回合配对后：**192 粒"响应型"里 81.3% 的 Δ(hold−cycle) 设防率不到 15pt，中位只有 +4.1pt** ⇒ 它们不是"有钱才龟"，是"**越晚越龟**"——因为 `hold` 档里"对手 ep≥10"这个桶几乎等价于"这局已经打到 r25+"（桶平均回合 25~27）。
- ⇒ 规矩：**(a) 桶变量与时间轴同轴时，单档比值不构成因果证据**（先算"这个桶的平均回合是多少"，如果它随桶号单调涨，就必须钉时间再比）；**(b) 已有的对照档不是可有可无的加固，它是这条结论的准入条件**——我省掉它一次，就把 3.6% 报成了 19.4%（差五倍）；**(c) 报告流行率时要同时给"钉住时间后仍成立"的那一档数字**，两者并列，读者才不会拿粗筛去算代价。
- **同族**：第 57 条"同回合 placebo 窗"（这里它救了我——192 粒上 r1~r5 两档 100% 重合，说明差确实来自钱而不是随机流）；第 53 条"要印分母"；第 61 条"别用定义标签的变量给自己打分"。
