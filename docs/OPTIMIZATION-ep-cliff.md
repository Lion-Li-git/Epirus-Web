# 优化分析（第十三轮 · 第三方复核者）：环不是病灶，**ep 特征在 16 之上冻结**才是

> 本轮只做了测量，**没有动线上包**（`js/bundled-champion-3p.js` 仍是 `268461f7c9f0`），也没有改引擎。
> 结论按"能省多少事"排序，每条都带**复跑入口**和**证伪判据**。凡我没跑的，标了「推断」。

## 0. 一句话

**"让 AI 学会打聚能环"这个目标要改写。** 实测下来：环在两类包上根本不处在同一个问题层——
在位包**连机会都没有**（9909 个决策点里 0 个可负担），arm A **有机会但环的价值被"直接给它钱"完全覆盖**
（环×8 = +14.4pt，白送 +18 ep = **+38.9pt**）。而两件事共用同一个根：网络的 **ep 输入在 16 之上逐位冻结**，
所以"攥着 40 点 ep 不打"这个状态**在表征里不存在** ⇒ 任何环奖励/兑现奖励都是在猜一个网络测不到的量。

## 1. 在位包：不是低估环，是看不到环（收入饥饿，实测）

| 读数 | 值 |
|---|---|
| 自对局决策点（80 局 × 5 席，multi） | 9909 |
| ep 直方 0/1/2/3/≥4 | 44.2% · 33.7% · 22.1% · **0.0%** · **0.0%** |
| 全程峰值 ep | **2** |
| 环可负担决策点 | **0（0.00%）** |
| 实际打环 | 0 |
| long 模式同口径 | 18859 点 · 峰 ep **2** · 可负担 **0** |

⇒ "ep<3 主导"不是一种风格偏好，是**算术死锁**：花的比攒的快，永远跨不过 3。
`tools/probe-convert.mjs`（60 局）独立复现了这条：`· 聚能环：**全程不可负担**（可负担点数 0）`。

⚠ **量具 bug（要修）**：`probe-convert` 的【收入饥饿】判据是"贵卡 **cost≥3** 且可负担<2%"，
而 `rules.js:45` 里环声明的 `cost` 是 **`null`**（真成本 3 写在 `state.js:106 computeCost`）
⇒ **环永远进不了那条筛子**。本轮最重要的贵卡被分类器系统性漏报。
修法：判据取 `S.computeCost(state,pid,key).ep` 的实际值，而不是 `def.cost`。

## 2. arm A（`v7ringA1-82`）：恰恰相反 —— 富死

| 读数 | multi | long |
|---|---|---|
| ep≥4 的决策点 | **68.5%** | 57.6% |
| 环可负担点 | 9708（**71.4%**） | 13775（60.1%） |
| 实际打环 | **0** | **0** |
| 自对局终局余 ep（反事实快照上） | **38.7** | **86.3** |
| 峰值 ep | **43** | **99** |

逐回合追踪（multi，快照 r7·ep3·hp2，同一 rng 流）：
```
对照：r7:ji/4e  r8:ji/5e  r9:ji/6e  r10:snipe/4e  r11:ji/5e …… r44:ji/38e  r45:ji/39e  r46:ji/40e → hp0 死
```
**连打 40 手 ジ、手里 40 点 ep、一次没兑现就死了。** ⇒ 病是**兑现**，不是收入。

## 3. 环的"价值"被一个安慰剂打回原形（按局聚类的区间）

反事实设计：只切被测席那**一手棋**，其余逐字相同（同快照、同 rng 起点）。
快照取 pid=0 回合开始（`autoGameN` 从中间续跑会**重复执行一次 `startTurn`**：回合 +1、梦魇扣血、行动槽清空都重复
⇒ 忠实性自检 **0/6 复现原结局**，那版 Δ 全部作废；改成自带驱动 + 首回合跳过 `startTurn` 后 **8/8 复现**）。

**同一张快照集、同一批 seed**（arm A · multi · 窗口"回合开始时 ep≥3 且环可负担" · 30 快照 / 16 局 · n=180 对）：

| 臂 | Δ胜 | 95%CI（按局 bootstrap） |
|---|---|---|
| 环×8 | **+14.4pt** | [5.7, 23.5] |
| **白送 +10 ep** | +20.6pt | [11.1, 30.6] |
| **白送 +18 ep** | **+38.9pt** | [26.7, 52.5] |
| **白送 +40 ep** | +39.4pt | [27.2, 53.3] |
| 环×8 再白送 10 | +16.1pt | [4.3, 28.0] |

另一张表（不同窗口：`round≤14 · hp≥2 · ep∈[3,6]` · 40 快照 / 21 局）里段长剂量反应是
环×1 −2.1 / 环×3 −7.5 / 环×5 +9.6pt，**三条的按局 CI 全跨 0**。
⇒ 合起来：**"白送钱"比"教它赚钱"管用 2.7 倍**，而环自己的剂量效应不稳；
环的一切好处都能被"它多攒了 10 点 ep"解释完。
再补一刀算术：环×3 与 ジ×3 的**净 ep 本来就该相同**（−3+1+2+3 = +3 = ジ×3），
且中途 ジ 一直领先（第 1 手环是净 −2）⇒ 环在收入上没有任何优势；
另外环臂还把被测席往 `ringForceTarget`（小雷点名滚环者）那格送，风险是净负。
⚠ 我第一版报过"环×3 = +15.0 ± 2.0SE"——那是 **30 个快照只来自 6 局**的簇内相关假象；按局重采 + 按局 bootstrap 之后它就不显著了。**报这类 Δ 必须按局聚类。**
⚠ 另外**安慰剂 ジ×3 不构成独立臂**：那条线本来就在打 ジ ⇒ 它与对照**逐字相同**（Δ=+0.0pt、CI [0,0]）。
想用"过 n 手"当安慰剂，必须选网络此刻**不会**做的动作（`probe-cashout.mjs` 里那三条兑现臂也是同一坑：
快照口径本身要求 argmax=ジ，所以"按 argmax 花钱"永远不触发）。

## 4. 根因：`policy.js` 的 ep 输入在 16 之上**逐位冻结**（实测）

同一快照只改 ep，其余不动：

| ep | p(ジ) | p(环) | p(最好的攻击) |
|---|---|---|---|
| 8 / 11 / 12 | 0.582 · 0.582 · 0.582 | 0 | 0.306 · 0.306 · 0.306 |
| 13 | 0.555 | 0 | 0.314 |
| **16 / 20 / 30 / 40** | **0.453 · 0.453 · 0.453 · 0.453** | 0 | **0.378 ×4** |

读码对得上（`js/train/policy.js`）：
- `:202` `Math.min(me.ep, 12)/12` ⇒ ep>12 全同；
- `:379` `max(-1,min(1,(p.ep - cost)/12))` ⇒ 当 `ep − cost ≥ 12` 时"可负担余量"也钉死；最大攻击 cost=4 ⇒ **ep≥16 后全部夹住**；
- `:238` `(me.ep - agg.maxEp)/12`、`:258`/`:405` `min(op.ep,12)/12` 同病（**看别人有多少钱也同样饱和**）。

⇒ 实测与读码双向确认：**"我攥着 40 点"与"我只有 16 点"是网络的同一个输入点。**
这条直接否决了一批做法：
- 环奖励（`setRingReward`/`ringRun3` 窄口径）——在奖励端加一个表征端测不到的信号；
- "ep≥3 才准花钱"这类门控启发式——门控里的 ep 同样饱和；
- 任何"资源广度"指标——`G_eff` 之类看不见余款。

同时它也解释了在位包的另一半：`p(ジ)` 在**所有 ep 档位都是 0.000**、argmax 恒为狙击 ⇒ 它从不攒，
所以第 1 节的死锁是它的**行为**造成的，不是夹住造成的（两包的病不同源，别用一套奖励治）。

## 5. 可优化的地方（按"性价比 × 证据强度"排）

**L1 抬 ep 特征的表示上限（根因，代价最大但唯一治本）**
把 `min(ep,12)/12` 改成不饱和编码（`log2(1+ep)`、或对数分桶 + 线性尾巴），`:238/:258/:379/:405` 同步。
⚠ **代价（必须先说清）**：特征语义一变 ⇒ 5689 个参数与 **旧包全部不兼容**，必须升 `PACK_VERSION`、
`FEAT_S` 变、**重训**、`np-test` 里所有钉死特征下标的断言（含 `RING_SELF_IDX` 探针）要改。
这不是"改一行"的事，是一次换代。
判据：重跑 `tools/probe-ep-saturation.mjs`，16/20/30/40 四档的 p(ジ) **必须不再逐位相同且单调下降**。

**L2 把奖励从"上环/广度"挪到"余款必须花掉"（不依赖 L1 就能做，先做这个）**
实测余 ep：multi 38.7 / long 86.3。加一项"终局余 ep 惩罚"或"ep→伤害转化率"奖励，
比任何环塑形都更贴病灶（白送钱的效应量就是它的上界证明：+39pt）。
判据：训练产物终局余 ep 显著下降 **且** A 卷不掉 **且** 出手/回合上升；三者缺一就是又养出一个"乱花钱"包。

**L3 别再开"强迫打环"臂（省 GPU）**
本轮两条独立否定 + 之前四次失败同型。若还想保留环这条线，**目标应改写成"反环能力"**：
它是实测有读数的那格（在位包反环考卷 53.3% vs 旧包 42.5%），而且 `ringForceTarget` 已经在训练侧有钩子。

**L4 修 `probe-convert` 的收入饥饿判据 + 段长口径的 UNRUN**（§1）——一行级，先修，否则下一轮还会被"没报"骗。

**L5 同一条夹住也糊住了"打最肥的人"**：`min(op.ep,12)/12` 与 `:258` ⇒ 对手余款 >12 时威胁评估变平。
G4「只枪」那格（在位 65% / 候选② 53%，门槛 45%）可能与 L1 是**同一个缺口的两面**。
判据：L1 之后重测 G4（n≥120 才报，见 §9 METHODOLOGY 的小样本教训）。**推断，未测。**

**L6 训练前的接线自检**（本轮新踩）：`autoGameN` **不能从中间状态续跑**（会重复 `startTurn`）。
凡是想做"从局面分支评估/反事实/搜索"的工具或训练改进（比如 MC 树、advantage 估计），
都得用 `tools/probe-ring-value.mjs` 里那个 `resumeN(state, choosers, skipStart)` 形状的驱动。
