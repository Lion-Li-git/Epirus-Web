# 评《冠军包 2.0 前期研究》（DS · 2026-10-27 晚）

> 评的对象：`docs/research/CHAMPION-2.0-RESEARCH-2026-10-27.md`（千问，253 行，状态=研究记录、未批准）。
> 本文只做可行性评估与改法建议，不实施、不开臂。所有引用到的仓内事实我都现读核过。

## 〇、结论（一句话）

**方向对、诊断基本成立、工程量可控；但作为"一次大调整"它的**风险排序**错了**——它把最贵的一步（集合编码 + 全环境条件化）放在最前面，
而把三个能决定"值不值得做"的便宜实验（容量 / 环境输入 / 当选面）留在了后面。建议加一道**可行性闸门**再开工。

| 维度 | 判断 |
|---|---|
| 诊断（单桌专才的成因） | ✅ 成立，且与我 10-27 的分层判断互相印证（固定槽 / 身份跳槽 / 单环境 / 平均当选） |
| 架构方向（集合编码 + 显式环境 + 共享主干） | ✅ 合理，且**比"把 OPP_SLOTS 从 4 改成 9"强**；本游戏是**同时选招**（无先后手），池化不丢顺序信息 ⇒ 可做 |
| 8–10 人规则风险清单 | ✅ 完备（原型累计反射 / AOE / 地雷随人数 / 回合上限与收缩 / 摄魂门槛 / 经济是否随人数缩放） |
| 工程顺序 | ⚠ 建议重排：先三闸门、后大改 |
| "遗忘"机制 | ⚠ 只写了"经验保留"，没写机制（回放 / 轮换 / 存档 / 当选面），这是他们自己 09-22 证据指向的那一处 |

## 二、计划立得住的部分（不用改）

- **规则基线 = 现行引擎**（不是原始程序、不是旧文档）—— 对；而且 8–10 人的平衡问题被显式列成"待裁"，没有顺手改 2–5 人规则。
- **集合编码而不是扩槽**：固定 4 槽 + 血量排序会造成身份跳槽（同一对手受伤后换槽，历史与效果在输入空间里跳位），这一条是真的结构病。
- **旧池不批量迁移**、v7 加载器保留、"兼容承诺 = 旧格式仍能用，不是旧权重变成新网络"—— 边界写得干净。
- **先做决策级性能基准、再谈 GPU** —— 与本仓一贯的"先量再加"一致。
- **训练侧判据不塞回产品门禁** —— 与 10-27 用户裁定的门禁面一致（现 171 条只守规则/加载/页面）。

## 三、我建议改的六处（按重要性排）

### ① 先回答"一枚通吃 vs 按人数派发"，再决定要不要集合编码（省一半工）

产品现状：2P 有独立池（9 枚）、多人共用一条池（30 枚）；N 在**开局时已知**，局中人数只会减（残局/回魂）。
⇒ 若产品可以按 N 分派，**2P 完全不需要 2.0 的架构收益**（它已经有专家）；2.0 的真实增量只剩"6–10 人"与"身份跳槽修正"。
建议的交付形态：**1.0 = 派发式（按 N 选包）+ 显式环境向量 + 身份跳槽修正**；**1.1 = 同容器跨环境**（stretch）。这样即使集合编码失败，也有一版可上线的中间态。

### ② 加一道"可行性闸门"：三个 ≤1 天的实验，先决定 2.0 的预期收益

| 实验 | 做法 | 若结果为真说明什么 |
|---|---|---|
| **E1 容量** | v7 同特征、同 5p 单桌，`h=24 → 48/96`，60 代 | 若 13 行明显改善 ⇒ **容量是瓶颈**，2.0 的网络重设计有独立价值；若不动 ⇒ 容量不是主因，收益全在条件化/选择 |
| **E2 环境输入（不换架构）** | v7 追加一个 8–12 维**通用环境块**（开局 N、存活数、maxHP、mode 标识、收缩起点、摄魂门槛），`f 213 → ~225`，重训 5p | 若行为出现"按环境分化"⇒ 缺的确实是环境可见性，集合编码的收益可预期；若不动 ⇒ 条件化不是加几维能解决的 |
| **E3 当选面** | 同训练、同环境，把当选从"平均 fit + veto"换成"每环境格下界/最差格优先" | 若红项数下降 ⇒ **主要是选择不是表示** ⇒ 应先把 A（选择器）做完再谈表示 |

这三个实验合起来就是"2.0 值不值"的闸门：**若 E1/E2/E3 都不动，2.0 的收益假设要重写**。
注意 E2 不违反"不为单扇门扩维"——它是通用环境块，不是补某一行的维。

### ③ 把"遗忘"写成机制（这是最大风险，计划里只有形容词）

他们自己的证据说"简单混训 + 加排练量都会互相遗忘"，所以机制必须指定，建议三件一起上：
1. **按环境格的经验回放**（每格保留最近 K 局或精英个体，训练时按格配额抽）；
2. **轮换/交替训练**（round-robin env，而不是把 N 混在一个 batch 里求平均）；
3. **每格精英存档 + 当选面按格**（island / MAP-Elites 风格；精英不许被平均 fit 淘汰）。
如果只做集合编码而不做这三件，最可能的结果是"换了个更贵的架构，仍然平均"。

### ④ 给"不同策略"下定义（否则 2.0 成功不可判）

建议在 C 阶段写死三组指标：
- **行为分歧**：同一状态集上，不同 N 的技能分布差异（KL / 熵差）、目标选择分布、防御-进攻比例；再加"跨 N 最优动作一致率"（越低越说明在条件化）。
- **逐格强度下界**：每个 N×HP 格的 1st ≥ soft 中位（不是全局平均）。
- **留出组合**：6p/7p 或 3 血长程作为 held-out，区分"条件化"与"逐格记忆"。
现有 13 行全是单环境强度/行为门，直接拿来当 2.0 判据会重演"平均吞双峰"。

### ⑤ 8–10 人：架构验证与平衡设计解耦

架构侧只需要 10p 的"规则冒烟 + 性能 + 前向合法候选"；平衡侧（AOE、原型累计反射、地雷随存活人数、回合上限/收缩、摄魂绝对门槛、经济是否按 N 缩放）应单独立项为 **ruleset 2.0 议题**。
理由：一旦平衡要改，用旧规则训出来的 2.0 包与它的验收读数全部作废；而架构验证不需要等平衡定稿。

### ⑥ v8 兼容写死为"响亮拒绝"，不是"静默降级"

计划说"独立加载分支"是对的，但本仓有大量"静默当旧格式跑"的先例（D191/D234 那族）。建议写死：
**v8 包只被 v8 感知的路径读；v7 路径遇到 v8 必须 exit 非 0 并点名**。179 个工具零改动继续吃 v7，v8 先只在训练与两把新尺里被认识。

## 四、成本估算（按现测速度外推，只作量级）

- 现役：5p / 60 代 / 24 局 / pop 24 ≈ **2–4 s/代**（单臂），即 60 代 ≈ 3–4 分钟；三臂并发实测 7 s/代。
- 集合编码 + 共享主干 + 轻量头：每决策多一次池化，估 **1.5–2×**；
- 10p：候选 O(N)=9、双目标 O(N²)=81（5p 是 4/16），席位 ×2 ⇒ 每代约 **5–10×**，60 代 ≈ **1–2 小时/臂**；
- 工程面（真正的大头）：v8 特征布局 + 加载器 + 所有量具路径（`promote`/`gate-drafts`/`audit`/`mirrorHealth`/`eval-5p`/图 meta）一次适配，估 **1–2 周**（含测试）；
- 原型（C 阶段四问）**2–4 天**；混训原型 **2–3 天** + 算力；全量批另计。

⇒ 结论：**若先做①②的闸门，1.0（派发式）可在两周内见到第一版；若直接做集合编码全量版，按现有人力更像"一个月+"的项目**，且中途没有任何可上线产物。

## 五、可证伪（什么情况下应该停 2.0）

- E1/E2/E3 三闸门全不动 ⇒ 2.0 的收益假设（"条件化 + 集合编码能换来跨环境"）缺乏证据，应先回到"每环境专家 + 派发"；
- C 阶段第 2 问（环境输入能否产生不同策略）为否 ⇒ 集合编码不解决问题，问题在训练目标/当选面；
- 原型混训仍出现"一格升、另一格塌"且存档/回放无效 ⇒ 需要 split-by-env 专家，而不是共享容器（这本身就是结论，不是失败）。
