## 〇、结论先放这里

1. **不要买容量。** 实测：线上包 **23/24 个隐元都在激活**，而**中心化后的等效使用维数只有 4.3 ‖ 5.1 ‖ 7.6 / 24**（按桌形变，§一）——比一枚**随机权重包**的 ~9 还低。⇒ 训练把表示**压扁**了，不是宽度不够用满了。加宽/加深买的是"更多已经被压扁的东西"。
2. **"局面确实驱动排序"，但这个依赖是**包级的**、不是结构必然。** 把状态段贡献置零 ⇒ 组内 top-1 换手率：线上包 **3 人桌 14.2% ‖ 5 人桌 64.0%**（long/3 人 24.7%）；**第二枚对象 `U2-77001` 复现时否证了"随桌形上升"这半句**——它是 **38.6%(n=3) ‖ 36.9%(n=5)**，几乎**平坦**。⇒ 结论改成：**"换桌形就换打法"目前只有线上包做到了（且只在人多的桌上做到），U2 无论人多人都靠状态段排序 ⇒ 两枚包在"环境适应"这条上是真正的个体差异**。这恰好是 2.0 该把它做成**显式输入 + 显式判据**的理由（而不是"结构自带"的期待）。⚠ 换手率的分母是"组"，而组大小本身随桌形变（13.1 ‖ 15.8 个候选/组）⇒ 跨桌横比要带这一句。
3. **在册的四条便宜路都实测关掉了**（§E197 重学权重净兑现 8.4%‖10.0%、§E198 交互基净增 ≈0、§E203 手写加深搜索只收 2.6~5.0pt、§E205 给学出来的头再加一层搜索 ≤0）。⇒ 剩下唯一没量过的通道是**"把落点算准"这一侧**：不是搜得更深，而是**把结算后果变成输入**。
4. **今天下午把最后那一格量了（§E816，新尺 `tools/probe-settle-info.mjs`）**：现有 235 维把**"我打算打出多少"**表达得近乎完全（组内 R² 84%~99%），把**"这手的失败模式"**表达得近乎没有——跨**四枚对象**复现后的**诚实分级**（§六表）：**"这一手会不会立起真防御（白防）" 4/4 对象组内 R²<20% ⇒ 硬真空** ‖ **"会不会直接终局（收门）" 4/5 格 ⇒ 次硬** ‖ **"会不会弹回自己（反弹）" 2/4 格 + 一枚无分母 ⇒ 证据不足，待补**。⇒ (B) 从"没量过"升成**有证据**，但**不是一句"三个真空"**；其中硬的那两条正对着验收线的**白防率**与**场B 清场/收割**，而**反弹墙**那一行今天仍是弱侧（要换一枚真会撞墙的包补分母）。
5. 所以 2.0 的表示层改三件事，按价值排序：**(A) 席位可变 = 集合编码**（不再 4 槽补零）→ 一套权重跨 2–10 人真的成立；**(B) 结算摘要进输入**（每个候选带一份"这手落地后会怎样"的确定性前滚摘要，**重点装失败模式**，不必再装第二份伤害/费用统计）；**(C) 输出拆两头**（打哪张卡 / 打谁，外加一个不参与组内排序的 `Q(s)` 校准头）。**层数保持单隐层**，宽度只作为 (A)(B) 的被动结果调整，并且**用 §E815 这把尺验收**（判据：等效维数必须随容量上升；不升 = 白加）。
6. 兼容按用户的话降级：**只承诺"旧格式仍然读得进"**（`canUpgradeStateOnly` + `embedLegacy` 这条缝已经写好在 `js/train/policy.js:819-856`），**不承诺旧权重变成新网络**。

## 三、表示层草案（三件事，按价值排）

### (A) 席位可变 = 集合编码，不是固定补零
- 病：`OPP_SLOTS=4` 编译期钉死，不足补零（`:277`/`:301`/`:315`）⇒ 2 人桌有 3 个槽恒零；>5 人根本放不下；而"地雷 = 除自己外全场各 1 点"（`js/core/rules.js:81` + `resolve.js:421-439`）、"避雷针 = 当回合全场雷系无效"（`:71` + `:794-796`）这类**随人数上升**的红利，只能靠"槽位填了几格"间接猜到。§E815 的 14%→64% 与 §E680 的 6→14 项，都是这件事的症状。
- 2.0：**每席一个共享编码器** `g(seat_descriptor) → R^k`，再对存活席位做 **pooled 统计**（mean / max / 存活数 / 相对排位），席位身份不进下标。⇒ 同一套权重在 n=2..10 上语义一致；人数成为**显式输入**而不是数组形状的副作用。
- 代价：这是**结构改动**，`embedLegacy` 救不了（它只搬列，不搬拓扑）⇒ 归到 §四"不承诺兼容"那一档。

### (B) 结算摘要进输入（唯一没量过的通道）
- 病：§E197 的根因句说状态段在同一决策内**恒定**、排序要靠 ReLU 门控间接调制；§E198 加交互基**净增 0**；§E205 再加一层搜索**≤0**。⇒ 网络缺的不是"更多组合方式"，是**"这一手真打下来会怎样"这个量本身**。
- 2.0：每个候选带一份**确定性 1-ply 前滚摘要**（同一份 `S.attemptAction` + `X.resolveActions`，不带随机、不带未来信息）：我造成伤害 / 承受伤害 / 谁倒下 / 珠与环的变化 / 冷却与费用余量 / 是否被反弹（这一项直接对上"反弹墙"那一行）。⇒ 特征从"赌局面"变成"读后果"。
- ⚠ 三条要先写死的判据：① **不许泄漏未来**（前滚只到本回合结算结束，否则考卷会被做成 oracle）；② **成本**（每候选多一次 resolve ⇒ 训练吞吐要实测，这决定代数/种群要不要降）；③ 兑现判据 = §E197 那台仪器（同一批 dump、同一套配对、减掉置换对照），**不许**只看"练完分数涨了"。
- 这条与 §E205 关掉的那条不一样：E205 是"在**已学到的标量头**之上再搜一层"，这里是"把结算变成**头的输入**"。

### (C) 输出拆两头 + 一个不参与排序的校准头
- 病：现在"打哪张卡""打谁""此刻局面值多少"三件事挤在同一个标量里；两级 softmax（`:690-700`）是**采样层**的补丁（当年修的是"条目多的技能概率被放大"），没有改变打分本身。⇒ 组内排序与跨决策估值互相污染，也是"强度考卷量程太小、两把尺 2pt 内翻面"（验收线 §十.2）的怀疑对象之一。
- 2.0：`π_card(c|s)`（卡类）· `π_target(c|s)`（打谁）· 一个 `Q(s)` 只做跨决策校准，**明确不参与组内排序**（§E205 里"纯状态 V 下 max_j ≡ mean_j"那条恒等陷阱就是因为把这两件事混了）。
- 附带好处：目标头可单独验收（§E701 破盾那一格的"代理精确率 1.4%~12.8%"就是目标选择的质量问题，现在无处安放）。

### 层数与宽度（回答"层数怎么设"）
**建议：仍是一层隐层。** 理由不是"简单"，是实测：等效使用维数 4.3~7.6 且低于随机包 ~9 ⇒ 现有容量已经在被**压扁**使用；加深度会让 §E815 这类"用了几个自由度"的诊断更难归因（多层 + 单标量头 = 谁在起作用读不出来）。
宽度：(A)(B) 会自然把输入维度抬高，**隐元 32~48 只作为配套**，且**验收判据写死**：加宽后中心化等效维数必须**同向上升**；若加了 24 元、等效维数还是 ~5 ⇒ 判"白加"，退回并把这条读数控回 §E815 的表。

## 四、训练怎么配（与当选面、池级配额接线）

1. **当选面 = 无权词典序**（接受 DS `REVIEW-POOL12ROW…` §三.1）：先最小化"违反的行数"，同数者比"最差行的余量"。**不做 13 行加权和** —— 那等于 13 个新超参，正是 L1「剂量抽签」的形状重演。
2. **适应度按 (n, hp) 分格取分位/最小值，不许平均**：现在 12 行全部只在 **5 席 ×(multi‖long)** 上量（验收线 §五 建议二），"5 人桌会打、2 人桌不会打"会被平均掉。§E815 显示这种差别是**结构级**的（14% vs 64%），不是噪声。
3. **覆盖率归池不归包**：`tools/champion-gate.mjs` 的 `POOL_QUOTAS`（含地雷/避雷针按座位分档的 `perSeats`）已经落了；训练侧的用法是**反推派单**——配额差几枚就开几枚臂，而不是要每枚冠军都会所有技能。
4. **奖励要先于行为存在**（用户 10-27 裁定）：(B) 的结算特征是**输入**不是奖励 ⇒ 不需要新剂量；若将来要奖励"跨桌一致"，走训练侧旗标、**不进产品门禁**（10-27 口径：训练问题不进产品门）。

## 六、§E816 实测：哪些"后果量"是当前 235 维**表达不出来**的（维度预算的直接答案）

**⇒ 修正后的维度预算（把"三个真空"降级为"一个硬 + 一个多数 + 一个待复测"）**：
**① 这一手会不会立起真防御（还是白防）**——4/4 对象 ⇒ 优先做；**② 这一手会不会直接终局**——4/5 格 ⇒ 做，但要按桌形分格验；**③ 这手打出去会不会弹回自己身上**——2/4 格 + 1 枚无分母 ⇒ **证据不足**，先补分母（换一枚真会撞墙的包重跑）再决定。
- 现有 235 维把**"我打算打出多少"**表达得近乎完全（四枚包 R² 83%~100%），对**"这手的失败模式"**普遍弱。⇒ 加维按上面的分级加：先**白防/真防御立起**（4/4 硬）、再**收门/终局手**（4/5 次硬）、**撞墙被弹回**那一格今天只有 2/4 ⇒ **先补分母再进设计**（换一枚真会撞墙的包重跑，别拿弱格当已证）。
- 这三条**正好**是验收线上那三行的对象：反弹墙 ‖ 白防率 ‖ 场B 清场/收割。⇒ 表示层与判据层第一次对上同一批缺口（不是我为维度编的理由）。
- **不必加**：第二份伤害/费用/珠的统计（上表 R²>83% 的那三行）——那是"用满了的信息"，加了是把同一件事说两遍（与 §E815"容量不是瓶颈"同向）。
- **口径条款**（引用必带）：这一版是**焦点席单独结算**（他人这一回合不动）。⚑ 我一开始把它写成"产品形状的下界版"，**那句话是错的**：`autoGameN` 先逐席收齐 picks、**之后**才 `attemptAction` + `resolveActions`（`js/core/play.js:56-71`）⇒ 轮到 0 号席时他人的这一手**根本还不存在**。所以"solo 1-ply"不是保守近似，而是**决策时刻唯一算得出的结算形状** ⇒ 2.0 的结算特征只能是"solo 1-ply + 他人上一手残留"，别的设计拿不到输入。
- 由此再看那两行恒零（**目标 ep 余量**、**回合是否推进**）：它们不是"没有信息"，是**这一拍结构上不会动** ⇒ 恰好是"他人回合那一拍看不见"的证据（要看见只能靠输入里带他人的历史/残留，即 (A) 席位编码那一侧）。
- 与 §E197/E198 的关系：那两节量的是"**在现有信息上换算法**不兑现"（净 8.4%‖10.0%、交互基 ≈0）；本节量的是"**现有信息里缺哪一块**"。两把尺不同对象，本节是 (B) 的第一块正面证据。
