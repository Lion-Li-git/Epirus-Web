# 预登记：归档 + 形状终选（`--arenaShapePick`）（DS · 2026-10-30）

> 动机：v2 的"每个子代都过形状闸"把搜索饿死（s13：43 次送验只有 5 个过闸；两阶段对 s11/s13 逐字节无操作，md5 相同）。
> 改成：**搜索不因形状拒绝任何子代**，但每次接受把候选连同形状存进 archive；终局在**形状合格**的归档里挑 fit 最高的一枚。

## 一、干预

```
--arenaShapePick=1        # 开关（默认 0）
--arenaShapeCap=0.50      # 合格线：单卡 ≤50%（在 --arenaShapeTemp 上读）
--arenaShapeTemp=0.05
--arenaShapeGames=4
--arenaDefCap=0.35
--arenaJiCap=0.70
```

归档内容 = 起点 + 每次接受的子代（含 cf.fit 与形状）；终选 = 合格归档里 fit 最高者。
若归档里**一枚都不合格** ⇒ 印"产物形状不合格"并退回 fit 最高者（不许静默）。

## 二、臂

3 粒 s7/s11/s13，6k 局，其余同 15 对配方（分层场、词典序、clean、temp 0.15）。

## 三、判据（合取）

1. 3/3 终选产物在 CLI（40 局/桌形、最佳温度）上 单卡 ≤52%、防御 ≤40%、ji ≤75%；
2. 三粒 CLI clean 中位 ≥0.05；
3. 无一粒 < −0.10；
4. 8P ≥ v7−3pt（≈0.056）至少 2/3。

## 四、停线

- ① 不过 ⇒ 归档里根本没有合格候选（搜索没走到可行域）⇒ 转 MAP-Elites/改起点；
- ① 过、② 不过 ⇒ 合格候选本身就弱（结构问题，不是选择问题）⇒ 需要改目标/环境，不是改筛法；
- ② 过 ⇒ 归档终选成立，写进标准配方（并保留 v2 的闸作可选）。

## 五、不许写成什么

- 不许写"形状约束生效"——这是**选择**不是**约束**：搜索轨迹与无约束版逐字相同（可查 md5），只是终选不同；
- 不许拿归档里最好那枚与无约束终态横比"同预算"——归档枚数/接受次数必须一起报。
