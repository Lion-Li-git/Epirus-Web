## 2. 机理（读码 + 数据）

1. **防御是 0 费**（`js/core/rules.js` 的 `guard`：`cost: 0`），而挡掉的枪是 1 ジ、激光剑是 2 ジ ⇒ 守方天然赚。
2. 能穿【防御】的只有：坦克(2 ジ·火)、狙击(2 ジ)、电磁炮(2 ジ+1 电珠)、大雷(5 ジ)、过载炮(3 ジ起)、小雷(2 ジ·只废招)。
   ⇒ **破墙的最低门票是 2 ジ**，而枪是 1 ジ ⇒ 只要网络把「枪」的价值估得略高，它就永远迈不出那一步。
3. 训练池里没有这种形状的对手：`server/opp-pool.mjs` 的默认池有 `defend`，但【纯防御】11 回合就被打穿（上表），
   暴露不出洞；真正卡死的是「防御 + 攒钱 + 大雷」的组合，而它不在池里。
   同时 **hard 带自身防御类出手 = 0%**（README 的档位普查）⇒ 冠军之间的对局里「有墙要破」这件事几乎没有梯度。
4. 选冠判据要求对每个基准 >50%（README「冠军按真实胜率挑选」），但基准里没有一条是「墙 + 攒钱」⇒ 过门不覆盖这个洞。

## 3. 建议的三个方向（都还没做，等裁）

1. **加一条对手人格，不写新代码**：仓里已有 `pickReflectSpam` / `pickDeepSaver` / `pickGuardSpam`，
   组合成 `guard+saver`（我这把尺用的就是这个组合）加进 `OPP_SPECS` 的**默认前 9**，再跑一轮看它是否被学会破。
2. **加一条档位读数**（不改训练）：在 `docs/debug/tier-census.mjs` 旁边加一格「对防御墙胜率」，
   与现有的均回合 / top3 / G 并排；这样「档位强度」不再只由冠军互打决定。
3. **奖励项**：给「打穿防御的那一次命中」单独的 credit（仓里已有 `pierceReward` / `wallBreakReward` 两个旋钮，
   默认值未调）——先量「开档前后 坦克/过载炮 出手率」，别直接改默认。

## 4. 边界（引用前必读）

- 样本：每格 30~40 局，只够看方向，不够给点估计；对照臂（困难 vs 困难 11:19）说明夹具没有系统性偏向。
- 「攒钱+反弹」是我的组合，不是产品原型表里的那 6 个之一（那 6 个里它对应 `deepsaver+reflect`，已 `humanPrototypes` 收录）。
- 2P 表用的是 `standard`（回合上限 60、无收缩）⇒ **平局是这张桌的产物**；同样的局在 multi/long 上会先被终局收缩清场，
  但那时双方 HP 同步下降 ⇒ 仍大概率是平局（这也是 v2.0.1 顺带把页面缺省改成「跟随模式」的原因之一）。
- 读数来自**本机**（Windows / Node 24）；脚本在 `scratch/ds-1106-review/`（11-06 夜进仓——原来只在本机，干净克隆里下面这些命令跑不出来），要复现见下。
