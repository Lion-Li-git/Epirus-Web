# 为什么 2.0 冷启动有"盆"而 v7 没有（DS 机制分析 · 11-04 晚）

> 问题（用户）：「v7 冷启动过程中种群有多样性、最终得到相对均衡的包；2.0 要调参数才有多样性，最后还收进窄包。为什么？最重要的是为什么 2.0 训练会有明显的盆而 v7 没有。」
> 本文用**代码 + 新测的出生点读数**回答，不引用"两盆"那套结论本身。

## 一、先钉住两边的初始化不一样（这是根）

| | v7（`js/train/policy.js`） | 2.0（`tools/proto2/arch2.mjs`） |
|---|---|---|
| 初始化 | `p[i] = randn() * 0.25`，**不除扇入** | 每段 `init std = 0.25 / √fanIn`（`arch2.mjs:708` 同一公式） |
| 隐含后果 | 隐层预激活 ∝ √fanIn·0.25 ⇒ 大、接近饱和 | 预激活 ∝ 0.25 ⇒ **近乎线性、输出量级 ~0.1** |
| 参数 | 6842/5689（v7 面） | 7993（obs3b/gen3） |
| 适应度 | 26 项 shaping（`evo.js` gFit：伤害/存珠/穿透/宽度/环/反弹…）+ 名次 | **纯名次**（rankCredit 1.0/0.3，其余项默认 0） |

## 二、出生点实测：2.0@0.25 的分数**并列到 0.000**

同一批真桌 5P long、4 个随机种子、纯前向取 argmax（`scratch/logit-spread.mjs`）：

| 面 @scale | 每粒 top1−top2 中位 | 贪心选出的键（四粒） |
|---|---|---|
| **2.0 @0.25（出厂）** | **0.000 / 0.000 / 0.000 / 0.000** | guard 99% ‖ ji 100% ‖ bagua 99% ‖ ji 98% |
| 2.0 @4 | 1.032 / 1.035 / 0.784 / 0.999 | bagua 96% ‖ ji 85% ‖ reflect 86% ‖ ji 97% |
| v7 @0.25 | **0.012 / 0.048 / 0.075 / 0.047** | tank 50%+snipe 29% ‖ miniT 56%+ring 18% ‖ tank 72%+ring 12% ‖ holo 43%+sword 24% |

三行读法：
1. **2.0@0.25 的候选分数完全相同**（差 0.000）⇒ 产品温度 0.15 下 softmax 退化成**对菜单均匀抽样** ⇒ 每个个体都是"同一台均匀抽样器"（千问测的粒间 sd 0.9pt 就是它的另一种读法）；
2. 均匀抽样的行为分布 = **菜单的组成**。而菜单里防御卡（guard/reflect/bagua/holo/shift/jinshield/armor/proto/transfer）**费用 0、每回合都合法、数量多**；ジ之外攻击要攒 ep ⇒ 菜单先验本来就是 **~75% 防御族**（零参数实测 75.1/75.4%）⇒ **"墙"不是学出来的局部最优，是出生点的先验本身**；
3. **v7@0.25 的分数不并列**（差 0.01~0.08，是 2.0 的 30~100 倍），而且不同种子落在不同键上（tank/snipe、miniT/ring、holo/sword）⇒ **v7 的出生点就是"每个种子一个粗糙但连贯的策略"**，种群有方差、有攻击倾向。

## 三、那就把 2.0 的幅度抬上去？——抬上去得到的是"随机专家"，不是"均衡玩家"

`2.0 @4` 的分数差 ~1.0（temp 0.15 下已接近确定性），但**每粒只锁一张卡**（bagua/ji/reflect/ji 95%+）。
⇒ 2.0 的（基因 → 行为）映射是**单一共享主干 + 每键一个头**：只要 logits 有了量级，某个键的头就会在整个状态分布上赢下来 ⇒ **一出生就是单卡专家**。0.25（全并列=均匀）与 4（单卡专家）之间**没有"多样且宽"的中间区**。
v7 是**每个键一套独立权重**（`value(state,pid,key)`），随机初始化下"哪个键划算"随状态变化 ⇒ 同一粒会混合 tank+snipe、miniT+ring 等 ⇒ 出生点天然"有性格但不锁死"。

## 四、为什么 v7 没有盆、2.0 有盆（机制链）

**2.0 的盆 = 菜单先验（墙）+ 名次选择（无方向）+ 每粒是同一台抽样器（无方差）**
1. 出生：全并列 ⇒ 均匀抽菜单 ⇒ 墙侧；
2. 选择：粒间行为差异 ≈ 0（sd 0.9pt）⇒ 8–24 局的夺1 差异全是噪声 ⇒ GA **没有可爬的坡度**；
3. 一千多代只在这一个点上随机走（`CB13` 跑满 1200 代仍 61% 防御族、强度 11%）；把幅度抬到 4 才第一次"有的选"（`HS4b` 强度 36.4/38.1、G5 四格归零）——但那时每粒已是单卡专家，所以**宽度掉到 4~6**。

**v7 没有盆，靠的是两条同时成立**：
1. **出生点就有方差**（未归一化的 0.25 ⇒ logits 有量级 ⇒ 种子间行为不同）；
2. **适应度有方向**（26 项 shaping 直接给"打伤害/存珠/穿透/变宽"付钱）⇒ 即使名次噪声大，梯度仍把种群往"会打、会攒、会变宽"推。
⇒ 这两条缺一条都不行：只有方差没方向 ⇒ 随机漂（2.0@4 的专家化）；只有方向没方差 ⇒ 全群一个点（2.0@0.25）。

## 五、可证伪的三条（便宜、按顺序）
1. **并列假设**：把 2.0@0.25 的 chooser 从"抽样"改成"贪心+随机破并列"，若行为从"均匀菜单"变成"随机单卡"⇒ 证实 0.000 是并列而非偏好（本表已给贪心读数：guard/ji/bagua/ji）；
2. **候选项权重假设**：给 act-encoder（22 维）单独一个更大的初始化倍数，让"候选差异"先于"上下文偏置"出现；若在 0.25 下就出现"多样且不锁死"⇒ 2.0 的盆是**结构**（候选项被上下文项淹没）而非幅度；
3. **shaping 假设**：把 v7 的 26 项 shaping 全关、只留名次，看 v7 是否也长墙/收窄（同一批种子）。若也塌 ⇒ "v7 均衡"的主因是 shaping，不是 init。

## 六、结论（一句话）

**v7 是"出生就有性格 + 训练有方向"；2.0 是"出生全并列（=菜单先验的墙）+ 训练只看名次（无方向）"**。2.0 的"盆"不是优化器掉进去的坑，而是**它出生时站的那块平地**——把幅度抬到 4 能离开平地，但落地就是单卡专家，因为它的打分结构只允许"一个键赢"。要"宽而均衡"，要么改结构（让候选差异可学），要么把 v7 的方向（shaping）补回来。
