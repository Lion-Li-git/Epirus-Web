# 为什么 2.0 冷启动有"盆"而 v7 没有（DS 机制分析 · 11-04 晚）

> 问题（用户）：「v7 冷启动过程中种群有多样性、最终得到相对均衡的包；2.0 要调参数才有多样性，最后还收进窄包。为什么？最重要的是为什么 2.0 训练会有明显的盆而 v7 没有。」
> 本文用**代码 + 新测的出生点读数**回答，不引用"两盆"那套结论本身。

## 一、先钉住两边的初始化不一样（这是根）

| | v7（`js/train/policy.js`） | 2.0（`tools/proto2/arch2.mjs`） |
|---|---|---|
| 初始化 | `p[i] = randn() * 0.25`，**不除扇入** | 每段 `init std = 0.25 / √fanIn`（`arch2.mjs:708` 同一公式） |
| 隐含后果 | 隐层预激活 ∝ √fanIn·0.25 ⇒ 大、接近饱和 | 预激活 ∝ 0.25 ⇒ **近乎线性、输出量级 ~0.1** |
| 参数 | 6842/5689（v7 面） | 7993（obs3b/gen3） |
| 适应度 | 26 项 shaping（`evo.js` gFit：伤害/存珠/穿透/宽度/环/反弹…）+ 名次 | **纯名次**（rankCredit 1.0/0.3，其余项默认 0） |

## 二、出生点实测：2.0@0.25 的分数**并列到 0.000**

同一批真桌 5P long、4 个随机种子、纯前向取 argmax（`scratch/logit-spread.mjs`）：

| 面 @scale | 每粒 top1−top2 中位 | 贪心选出的键（四粒） |
|---|---|---|
| **2.0 @0.25（出厂）** | **0.000 / 0.000 / 0.000 / 0.000** | guard 99% ‖ ji 100% ‖ bagua 99% ‖ ji 98% |
| 2.0 @4 | 1.032 / 1.035 / 0.784 / 0.999 | bagua 96% ‖ ji 85% ‖ reflect 86% ‖ ji 97% |
| v7 @0.25 | **0.012 / 0.048 / 0.075 / 0.047** | tank 50%+snipe 29% ‖ miniT 56%+ring 18% ‖ tank 72%+ring 12% ‖ holo 43%+sword 24% |

三行读法：
1. **2.0@0.25 的候选分数完全相同**（差 0.000）⇒ 产品温度 0.15 下 softmax 退化成**对菜单均匀抽样** ⇒ 每个个体都是"同一台均匀抽样器"（千问测的粒间 sd 0.9pt 就是它的另一种读法）；
2. 均匀抽样的行为分布 = **菜单的组成**。而菜单里防御卡（guard/reflect/bagua/holo/shift/jinshield/armor/proto/transfer）**费用 0、每回合都合法、数量多**；ジ之外攻击要攒 ep ⇒ 菜单先验本来就是 **~75% 防御族**（零参数实测 75.1/75.4%）⇒ **"墙"不是学出来的局部最优，是出生点的先验本身**；
3. **v7@0.25 的分数不并列**（差 0.01~0.08，是 2.0 的 30~100 倍），而且不同种子落在不同键上（tank/snipe、miniT/ring、holo/sword）⇒ **v7 的出生点就是"每个种子一个粗糙但连贯的策略"**，种群有方差、有攻击倾向。

## 三、那就把 2.0 的幅度抬上去？——抬上去得到的是"随机专家"，不是"均衡玩家"

`2.0 @4` 的分数差 ~1.0（temp 0.15 下已接近确定性），但**每粒只锁一张卡**（bagua/ji/reflect/ji 95%+）。
⇒ 2.0 的（基因 → 行为）映射是**单一共享主干 + 每键一个头**：只要 logits 有了量级，某个键的头就会在整个状态分布上赢下来 ⇒ **一出生就是单卡专家**。0.25（全并列=均匀）与 4（单卡专家）之间**没有"多样且宽"的中间区**。
v7 是**每个键一套独立权重**（`value(state,pid,key)`），随机初始化下"哪个键划算"随状态变化 ⇒ 同一粒会混合 tank+snipe、miniT+ring 等 ⇒ 出生点天然"有性格但不锁死"。

## 四、为什么 v7 没有盆、2.0 有盆（机制链）

**2.0 的盆 = 菜单先验（墙）+ 名次选择（无方向）+ 每粒是同一台抽样器（无方差）**
1. 出生：全并列 ⇒ 均匀抽菜单 ⇒ 墙侧；
2. 选择：粒间行为差异 ≈ 0（sd 0.9pt）⇒ 8–24 局的夺1 差异全是噪声 ⇒ GA **没有可爬的坡度**；
3. 一千多代只在这一个点上随机走（`CB13` 跑满 1200 代仍 61% 防御族、强度 11%）；把幅度抬到 4 才第一次"有的选"（`HS4b` 强度 36.4/38.1、G5 四格归零）——但那时每粒已是单卡专家，所以**宽度掉到 4~6**。

**v7 没有盆，靠的是两条同时成立**：
1. **出生点就有方差**（未归一化的 0.25 ⇒ logits 有量级 ⇒ 种子间行为不同）；
2. **适应度有方向**（26 项 shaping 直接给"打伤害/存珠/穿透/变宽"付钱）⇒ 即使名次噪声大，梯度仍把种群往"会打、会攒、会变宽"推。
⇒ 这两条缺一条都不行：只有方差没方向 ⇒ 随机漂（2.0@4 的专家化）；只有方向没方差 ⇒ 全群一个点（2.0@0.25）。

## 五、可证伪的三条（便宜、按顺序）
1. **并列假设**：把 2.0@0.25 的 chooser 从"抽样"改成"贪心+随机破并列"，若行为从"均匀菜单"变成"随机单卡"⇒ 证实 0.000 是并列而非偏好（本表已给贪心读数：guard/ji/bagua/ji）；
2. **候选项权重假设**：给 act-encoder（22 维）单独一个更大的初始化倍数，让"候选差异"先于"上下文偏置"出现；若在 0.25 下就出现"多样且不锁死"⇒ 2.0 的盆是**结构**（候选项被上下文项淹没）而非幅度；
3. **shaping 假设**：把 v7 的 26 项 shaping 全关、只留名次，看 v7 是否也长墙/收窄（同一批种子）。若也塌 ⇒ "v7 均衡"的主因是 shaping，不是 init。

## 六、结论（一句话）

**v7 是"出生就有性格 + 训练有方向"；2.0 是"出生全并列（=菜单先验的墙）+ 训练只看名次（无方向）"**。2.0 的"盆"不是优化器掉进去的坑，而是**它出生时站的那块平地**——把幅度抬到 4 能离开平地，但落地就是单卡专家，因为它的打分结构只允许"一个键赢"。要"宽而均衡"，要么改结构（让候选差异可学），要么把 v7 的方向（shaping）补回来。
## 七、证伪实验 ①（候选项幅度）：**部分成立，结论要修正**（11-04 19:1x）

代码：`arch2.mjs` 的 `make()` 新增 `EPIRUS_INIT_ACT_K`（默认 1 = 历史臂逐字不动），对 **actEnc + cand** 两段同乘 K（候选路径的整条链路）。

`scratch/logit-spread.mjs` 在 0.25 幅度下扫 K：

| K | 2.0@0.25 的 top1−top2 中位 | 贪心键分布（四粒） |
|---|---|---|
| 1 | **0.000 / 0.001 / 0.000 / 0.000** | bagua100 ‖ ji100 ‖ reflect96 ‖ bagua100 |
| 4 | 0.002~0.005 | ji52+curse47 ‖ reflect50+shift49 ‖ ji82 ‖ ji99 |
| 16 | **0.194 / 0.021 / 0.035 / 0.062** | bagua100 ‖ guard100 ‖ ji100 ‖ bagua100（2.0@4 档则 ji40~61 + 副键） |

- ⇒ **候选路径的幅度确实能抬**（0.000 → 0.19），说明"logits 太小"这件事发生在 actEnc→cand 的**乘积链**上（单放大 actEnc 只到 0.004，见同日前一版读数）；
- ⇒ 但抬上去之后**仍然是"一个键霸占"**（bagua/guard/ji），没有出现"多样且宽"的中间区 ⇒ **"结构假设"只对了一半**：病灶更准确的说法是 **初值下"每个键的常数项"支配了分数，而 state×candidate 的交互项太弱**；
- ⇒ 结论修正：**2.0 的盆不是"幅度不够"也不是"候选被上下文淹没"，而是打分形式让"键身份"比"局面"更响**（v7 的 `value(state,pid,key)` 天然是 state×key 交互，所以它出生就随局面换键）。

## 八、下一步（结构实验，未跑）
- 给打分加一条**显式的 state×candidate 交互项**（或把 `inter`/`tinter` 段按 ACT_K 放大），判据：0.25 幅度下 top1−top2 中位 ≥0.1 **且** 四粒的贪心键分布既"种子间不同"又"种子内多键"（主键份额 <70%）；
- 若成立 ⇒ 2.0 冷启动的方差问题有了结构解（不用 INIT_SCALE=4 那种"单卡专家"的代价）；若不成立 ⇒ 回到 shaping（把 v7 的方向补进 2.0）。

## 九、证伪实验 ②（结构头）：**能力在、初始化叫不醒**（11-04 19:1x）

2.0 的布局里**早就有**两条双线性头（`arch2.mjs:171/183`，默认 K=0 关着）：
- `inter=K`：`logit += Σ g_k·tanh((u_k·ae)·(v_k·hctx) + b_k)` —— 候选 × 局面；
- `tinter=K`：`logit += Σ g_k·tanh((u_k·ae)·(w_k·te1) + b_k)` —— 候选 × 目标。

打开并放大初始化（ACT_K 同时作用于 actEnc/cand/inter/tinter）后实测：

| 配置 | 2.0@0.25 分数差中位 | 四粒主键 |
|---|---|---|
| inter=8, K=1 | 0.000 | reflect62 ‖ guard75 ‖ guard100 ‖ ji100 |
| inter=8, K=16 | 1.512 / 0.013 / 0.671 / 0.026 | guard100 ‖ guard65+ji33 ‖ ji100 ‖ reflect91 |
| tinter=8, K=16 | 0.028 / 0.065 / 0.024 / 0.039 | guard100 ‖ bagua100 ‖ reflect89 ‖ bagua100 |

⇒ **结构头能造出分数差（甚至 1.5），但行为仍是"单键死忠"**（主键 90~100%）；"种子间不同"有了，"种子内换招"没有。
⇒ 结论：**"看局面换招"不是初始化或结构缺失，是训练信号缺失**——没有任何压力要求"同一粒在不同局面选不同键"。

⚑ 顺带修一条潜在崩溃：`arch2.mjs:493` 原写死 `L.seg[6].off`，只在 inter 与 tinter 同时存在时才是 inter 段；单开 inter 直接 `undefined.off`。inter 默认 0，所以一直没被跑到过。

## 十一、E2 教师蒸馏 + 原生 `keyHead`：**两条路都装上了"换招"**（11-04 19:2x）

### A. 教师蒸馏（`supfit-gd`，教师 = 线上 v7，起点 `L5-D4a-s13`，800 步）
产物 `scratch/arms/KD-V7.bak`；用 `scratch/state-dep.mjs` 在同批 613 个决策上量：

| 包 | 主键份额 | **换招率** | 防御族 | 分差中位 | top 键 |
|---|---:|---:|---:|---:|---|
| **KD-V7（2.0 蒸馏产物）** | **47%** | **70%** | 2% | 1.75 | sword47 / bigT35 / charge9 / ji5 |
| v7 教师（参照） | 45% | 43% | 1% | 10.0 | bigT45 / sword45 / ji4 / gun3 |

- ⇒ **蒸馏把"看局面换招"装进了 2.0**：主键份额从出厂单键 100% 降到 47%（与 v7 的 45% 同级），换招率 70%；
- 代价：强度还没起来（arena2 5long **−0.125** / 5multi 0）⇒ 它现在只是"会换招的弱包"。

### B. 原生打分改：`keyHead=1`（新结构，默认关）
`logit += w_key · hctx + b_key`——v7 `value(state,key)` 的形状，挂在 2.0 的状态编码器上。**不训练**、0.25 幅度初始化下：

| ACT_K | 分差中位 | 每粒 top（四粒） |
|---|---|---|
| 1 | 0.007~0.031 | **ji50+armor50** ‖ guard98 ‖ **reflect50+gun50** ‖ **ji50+holo45** |
| 4 | 0.028~0.073 | guard100 ‖ ji100 ‖ guard100 ‖ ji100 |
| 16 | 0.007~0.074 | **ji51+gun49** ‖ **reflect50+armor46** ‖ **ji50+gun49** ‖ reflect100 |

- ⇒ **原生结构改就能"看局面换招"**：初始化即出现"两键择一"（对照：不开 keyHead 时是单键 100%）；
- 但只到"两键"，且 K=4 档又退回单键 ⇒ 初始化尺度仍会压过结构；需要训练把它用起来。
