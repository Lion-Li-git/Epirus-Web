## §1 P0：过线壳 → 加一条**比较带宽**滑轨（用户点题 · 唯一的大件）

### 1.1 现在这个壳是什么（读完代码的事实，不是推测）

`champion-map/viewer.mjs`：

- **场** = 高斯加权的局部过线占比（`isoField='ok'`）或势（`'pot'`）：
  `f = ESS·p̂/(ESS + M0)`（**E401 改成向 0 收缩**，没证据=0），再乘一道**平滑密度门** `min(1,(den/DREF)²)`（E400）。
- **σ** = 显示度量下**第 6 近邻距离的中位**（今天 **0.19** 显示单位）⇒ 核支撑 `R = 2.6σ = 0.50`。
  现值：`DM0 = 2`（旧值 5）· `DGATE = 1` · `isoT = 0.30`（ok）/ `0.67`（pot）· `isoGN = 72`（52/72/96）。
- **抽面**：surface nets（每格一个顶点 = 12 条跨阈值棱交点的平均）+ 2 轮拉普拉斯松弛 + **退化片闸**（对角 > 2.2×格对角就丢）。
- **读数**：在**每一枚自己那个坐标**上再算一次场、数 ≥ 阈值的枚数（含自己 / 留一两列）。

### 1.2 用户那三个现象，各自是**必然**（附实测）

| 现象 | 机制 |
|---|---|
| 过线密集区里的**未过线点被包住** | 场问的是"这一片过线的占多数吗"，**不是**"这一枚过不过线" ⇒ 它在一坨过线点里，邻域占比照样过阈值 |
| 未过线密集区里的**过线点不画** | E400/E401 那两道闸**故意**把孤立过线证据拉回 0（注释原话："一座壳至少要几个过线的挤在一起才长得出"） |
| **一个壳里一个点都没有** | 网格场是点与点之间的**连续函数**，等值面可以在**没有任何点达到阈值**的地方存在；而读数是逐点数自己那个坐标 ⇒ "读数 0 但看得见壳"可同时成立 |

### 1.3 为什么"调阈值 / 调面数"都救不了（**这一节是判决书，请逐条复算**）

- **调面数在原理上不可能影响误包/漏画**：读数是在每枚自己坐标上重算场再比阈值（`viewer.mjs:2246-2247`）——**根本不经过网格**。
  `isoGN` 只决定同一个平滑场被画得多细（+2 轮松弛磨棱面，注释说代价"重建时间平方涨"）⇒ **只改观感**。
- **调阈值只是同一个旋钮的两个方向**（σ第6 / M0=2 / 门开）：阈值 0.15 ⇒ 壳内 335 / 误包 **243** / 漏画 58 ‖ 0.30 ⇒ 69 / 42 / **123** ‖ 0.50 ⇒ 19 / 7 / **138**。没有两全的工作点。
- **缩 σ 也没用**：σ(第3近邻) 误包 47 / 漏画 124 ‖ σ(第12近邻) 误包 30 / 漏画 122 —— 漏画几乎不动。
- **真正的墙（务必引用这一条）**：**过线那 150 枚在这张投影里不构成"团"**。我拿"逐点多数票"做上限对照：
  24-NN 多数票 ≥0.5 ⇒ 纯度 45%、**误包 24 / 漏画 130**；12-NN ⇒ 误包 31 / 漏画 128。
  ⇒ 任何**包面**式判据（含最强局部判据）都会漏掉大多数过线点。**这是数据的性质，不是分辨率。**

### 1.4 用户要的"折中滑轨"：**存在，而且不是两个场加权，是一条带宽轴**

关键洞察（我实测确认）：**"局部占比"与"签名场"是同一个比值场的两个带宽极端**——
`r(x) = K过线(x) / (K过线(x) + K未过线(x))`，同一个高斯核；**带宽 b→0 时 r 就是 1-NN**，等值面 `r=0.5` = Voronoi 边界 = 签名场。
⇒ 所以凸组合（`w·q + (1−w)·f_occ`）是绕路，且被带宽轴**严格压制**：我实测凸组合 w=1 时 **误包 9 / 漏画 131**，而 b=0.35σ 就能做到 **误包 5 / 漏画 29**。

**实测曲线**（阈值 0.5 = 多数边界；连通分量 = 壳内点按"间距 ≤ 2b"连边的块数，是"碎片度"的代理，与网格画出来的面同向）：

| b/σ | 壳内 | 纯度 | 误包 | 漏画 | 连通分量 |
| --- | --- | --- | --- | --- | --- |
| **0.05** | 150 | **100%** | **0** | **0** | **213** |
| 0.10 | 150 | 100% | 0 | 0 | 205 |
| 0.20 | 147 | 100% | 0 | 3 | 173 |
| 0.35 | 126 | 96% | 5 | 29 | 98 |
| 0.50 | 92 | 92% | 7 | 65 | 60 |
| 0.70 | 63 | 89% | 7 | 94 | 32 |
| **1.00** | 51 | 80% | 10 | 109 | **18** |

**两个端点正是用户的两句话**：b→0 = "签名场，绝大多数点都准确"（150 枚过线全在壳内、0 枚未过线被包）；b=σ = "平滑的局部占比壳"。
**代价轴是碎片度**（213 → 18 块），而误包/漏画是**同向**被压下去的 —— 这正是这个滑轨比"两个场加权"强的原因。

### 1.5 设计（建议照这个来，改动很小）

1. **只加一个场函数 + 一根线**，`isoBuild` 的抽面 / 松弛 / 退化片闸**一行不动**（它只吃 `F` 这一张网格场）：
   - 新场：`r_b(x) = K过线(x)/(K过线(x)+K未过线(x))`，同一个高斯核，**带宽 b = c·σ**（`c` 就是滑轨）。
   - 建议**同时**把 `M0`/密度门在 c 变小时退场（它们是给"稀疏区长假壳"打的补丁，而小带宽**天然**解决那件事）：
     `M0(c) = 2·(1−c)`、`gate(c) = max(0, 1−c)`，阈值 `t(c) = 0.30 + 0.20·c`（c=0 ⇒ 今天的场与 0.30，**逐字不变**；c=1 ⇒ 纯比值 + 0.5）。
2. **UI 给一根滑块**：`isoBW`（或叫"签名 ↔ 平滑"），范围建议 **c ∈ [0.15, 1.0]**，默认 **c=1**（= 今天）。
   再加两个**预设按钮**："今天的壳"（c=1）与"签名场"（c=0.05），省得她来回拉。
3. **读数必须同时印两个错**（现在一个都没印）：`壳内未过线 X 枚`、`壳外过线 Y 枚`。这是"让误差可见"的那条腿，也是 1.7 节的判据。
4. **工程上限（我量到的，务必写进注释）**：**在签名端瓶颈从"场"变成"网格"**。小泡尺寸 ~0.01 显示单位 < GN=72 的格（~0.02）
   ⇒ 想用 c < 0.2 必须同时把 `isoGN` 抬到 **96~128**，否则小泡会被退化片闸吃掉（那时"签名场"看着像"什么都没画"）。
   相反在平滑端 `isoGN` 与准确度无关（见 1.3 第一条）。⇒ 建议 `c` 与 `isoGN` 联动，或至少在 UI 上提示"小 c 要配大 GN"。

### 1.6 验收判据（每条都要有牙，"默认零剂量"纪律必须过）

1. **c=1 的输出与今天逐字相同**（同参数下 `ins/cov` 不变）—— 不许把默认值悄悄改掉。
2. **c=0.05 时 `壳内未过线 = 0`**（机械判据，可离线算，不必看图）。
3. 中间 c 的读数表落进 `champion-map/iso-sweep.mjs`（那台量具要**同时**按 §3 与页面同步）。
4. 页内自检加两条：`壳内未过线枚数`、`壳外过线枚数`（今天没有这两条腿）。
5. 四视图页检仍各 **85 PASS / 0 FAIL**，浮层被压住仍 < 线 20%、标签压住 ≤ 线 110。

## §5 本节所有数字的复跑入口（**必须能复算，否则不许引用**）

DS 的读取出自一个**一次性离线复刻**（住在 `%TEMP%\iso-error-probe.mjs`，**未进仓**）；它的算式与页面/量具逐字同式，可直接重建：

```
样本 = coords.tsv 的 x3/y3/z3（有现成列）；标签 = feas-s1..s3 的 ok（1/0/null，null 不进核也不进分母）
第三轴 C = (z3 − q(z3,.005)) / (q(z3,.995) − q(z3,.005)) × (0.26 × max(q(x3,.995)−q(x3,.005), q(y3,.995)−q(y3,.005)))
σ = 第 6 近邻距离的中位（显示度量）  ‖ 核 = 高斯，R = 2.6σ
场（今天）= (ESS·p̂)/(ESS+M0)，ESS=(Σw)²/Σw²，M0=2；再乘门 min(1,(den/(0.6·median(den)))²)，阈值 0.30
场（滑轨）= K过/(K过+K未)，带宽 b = c·σ，阈值 0.5
读数 = 逐点数自己那个坐标；四列：壳内 / 真过线 / 误包（壳内未过线）/ 漏画（壳外过线）
```
**建议**（等用户点，今晚可不做）：把这个复刻升级成 `docs/debug/iso-error-probe.mjs` 进仓（研究量具、不进判据），
这样 §1.4 那张表以后每次改场都能一键复算 —— 否则它又是"一份说不清口径的旧数"（README §④ 那条老病）。
