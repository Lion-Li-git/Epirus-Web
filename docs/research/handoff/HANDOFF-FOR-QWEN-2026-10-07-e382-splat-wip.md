## 二、已经改完的部分（代码在盘上，未提交的那一节）

`buildBitmap` 里 §E381 的"每格最近 12 名（按全库算）+ 过滤可见"整段删掉，换成**点-major 泼溅**：

- 每个可见点把自己的核 `w = 1/d^KEXP` 泼到它覆盖到的格子上；每格 `值 = Σw·F / Σw`、`覆盖 = Σw/(Σw+kcov)`。
- 截断半径 `RR = 6·fscale`（那里 `w ≈ kcov/88` ⇒ 覆盖度贡献 ~1%，看不出边界）。
- 为此在 `NBK[key]` 里补存了 `bx` / `byy`（比例尺），因为半径是按**显示像素**量的。
- 可见名单 = `VIS[i] && inWin(P[i])`（批次筛掉的 + 窗口切掉的都算摘出去）。

**为什么 §E381 只修了一半**（这条判断已经验证，写进注释了）：候选池仍是"全库最近 12 名"⇒
摘掉大半之后那 12 个里剩下的可见点太少 ⇒ 晕接不上 ⇒ 范围一收窄超过 1/3 就冒黑块。她截图那一档是 288/917。

## 三、当前这一条红，以及下一步怎么查（**从这里接着做**）

```
FAIL 地板的场值必须全在"可见点的 F 区间"之内（带外 = 0 ⇒ 既不钳成纯色也不会淡成黑洞）‖ 且地板真的被涂出来
  → 实测 涂了 26.8% 格 ‖ 带外 0 格 ‖ 参与铺色的点 917/917
```

读数拆开看：**带外 0 格 = 用户要的那件事已经成立**（不再有纯色/黑洞由钳位造成）。
红的是我顺手加的第二半句 `painted > cells × 0.55` —— **26.8% 说明泼溅之后地板只盖住四分之一**，这是**另一条真病**，不是阈值写错了：

按格子尺寸反算：`TOT = 40000`、显示跨度约 1576×625 ⇒ `gx≈316 / gy≈126` ⇒ **一格约 5 显示像素**，
而 `RR = 6·fscale ≈ 6×29 = 174px` ⇒ 每点应覆盖 `π·(174/5)² ≈ 3800` 格 ⇒ 917 点 × 3800 ≫ 40000 格 ⇒ **平均重叠 ~87 层，覆盖应当接近 100%**。
实测只有 26.8% ⇒ 说明**实际生效的半径远小于 174px**，最可能的三个候选（按嫌疑排序）：

1. **`nb.bx` / `nb.byy` 不是我以为的那个东西**（px-per-数据单位）。`csx = (x1-x0)*bx/(gx-1)` 若被算成"数据单位/像素"的倒数，
   半径就会缩掉平方倍。查法：在页内 `Runtime.evaluate` 打 `NBK[<key>]` 的 `bx/byy/x0/x1/gx/gy` 四个数，
   与 `cv.width`、`(x1-x0)` 对一遍量纲。**这一步没做，是下一班的第一件事。**
2. `fscale` 在这一档实际很小（`d12m` 只有几 px）⇒ `RR` 只有几十 px。查法：印 `fscale / d12m / nmed`。
3. 泼溅的循环边界被 `Math.max(0, …) / Math.min(gx-1, …)` 夹掉了（若 `ox9` 落在网格外很远的地方，那些点一格都泼不到）。
   查法：数一下 `iA>iB || jA>jB` 的点有几枚。

**不许做的事**：把 `0.55` 这个阈值改小让它变绿 —— 那是"喂字符串过关"（用户明确禁过，见 METHODOLOGY 第 89 条 + 记忆里那条）。
要么证明 26.8% 是**对的**（那地板就该只盖 26.8%，需要拿截图与"摘出前"对比说明为什么），要么修到它该是的比例。

## 四、SVG 那条（用户："然后 SVG 继续做吧"）—— 方案已定，**一行代码没动**

目标：谱系图那张底图不再是位图 ⇒ 任何放大倍率下字都不糊。

1. `treeChrome` 改成产出一段 **SVG 字符串**（行带 `<rect>`、家族名/统计 `<text>`、分界线与日期网格 `<line>`、刻度 `<text>`），
   塞进 DOM 里一个 `<svg id="treepaper">`，位置压在画布**下面**（`#wrap` 里排在 `<canvas>` 之前）。
2. 视图变换交给 **CSS**：`treepaper.style.transform = matrix(a,b,c,d,e,f)`，
   矩阵与画布贴纸用的那一个**同源**（同一个 `PS` 的三个角点算出来）⇒ 结构上不可能各走各的。
   ⚠ `transform-origin` 必须设成 `0 0`，否则浏览器默认按中心缩放，与画布的角点仿射对不上。
3. 连带要改的（**这是主要代价，别漏**）：
   - 画布必须**透明**：`clear()` 现在会填底色 ⇒ 底色要挪到 `#wrap`（或 body），画布只画点/边/立柱/标签。
   - 页内自检里**读像素**的那几条要重做：`左栏与数据必须走同一个矩阵`（读的是最终画布 ⇒ 左栏以后不在画布上了）、
     `平面态往左平移左栏必须真被画上东西`、`旧槽位冠军那一行排在最上面`（读的是画布上家族 0 那一行的墨）。
     改法：这些判据改成读 SVG 的 `getBoundingClientRect()` / `getScreenCTM()`，与点的屏幕坐标对同一把尺。
   - 立体态：SVG 的 `matrix` 能吃下 `PL`（正交相机 = 仿射 ✓），但**抬升带**（`padT += LIFT·elev`）会改纸面版式 ⇒ 仍要重排 SVG 的 y。
4. 顺序建议：**先把第三节那条红做完并认证，再开 SVG**（两件事一起改，红的时候分不清是谁）。
