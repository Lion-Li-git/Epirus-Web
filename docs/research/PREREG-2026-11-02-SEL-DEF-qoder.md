## 〇、为什么不做成"奖励防御"而做成"下限"

- 在册反例三条都指向"给防御付钱会把包推向挡起来"：`evo.js:1805` 原话（`BLOCK_W` 同时给 `blocked` 与 `reflect` 付钱 ⇒ **奖励含混**）‖ §廿四 的 v2 门槛（用"出手种类"当目标 ⇒ 搜索拿不打血的键凑数）‖ §六 K-2（15 把键到得了却不选 ⇒ 不是没机会，是不划算）。
- 唯一立住过的形状是 **只罚下界**（v1.6.50 `FIT_G_W`，用户裁定先例）。⇒ 本键**只把"完全不防御"的候选降级**，带内**不最大化防御量**（否则第一发就会被"每回合摆架势"满足）。
- 与在册 `EPIRUS_BREADTH_FLOOR`/`SEL_BIGT` 同形：**只作用在终局当选面，不改 `fit`、不改奖励、不改规则、不改 `js/**`**。

## 一、接线（默认关 ⇒ 产物逐字节不变）

| 旗标 | 含义 | 默认 |
|---|---|---|
| `EPIRUS_SEL_DEF=<分差 pt>` | 同分带宽度：重验分与最高者相差 ≤ 此值的候选进同一带，带内才用这根键 | 0 = 关 |
| `EPIRUS_SEL_DEF_MIN=<手/局>` | **下限**：防御族出手/局 ≥ 此值才算达标（达标组按原重验分序，**不做"越多越好"**） | 0.10 |
| `EPIRUS_SEL_DEF_GAMES` / `_MODE` | 量具局数与桌制（防御要在**短桌**上有意义 ⇒ 默认 `multi`） | 40 / multi |

- **量具不自造**：防御手数取自在册单一来源 `behavior-profile.mjs` 的 `fieldProfile(...).def`（`SEL_BIGT` 用的同一件、同一调用形状）；**"防得有没有用"不进排序键**，改由现成探针 `probe-wasted-play.mjs`（走 `defense-quality.mjs` 的三档：有效 / 被穿透=半 / 白防）在读数阶段判 ⇒ 排序键便宜、质量判定另一把尺，两者不互相遮羞。
- 带内算术放在 `tools/pick-best.mjs` 新增纯函数 `bandPickByFloor(entries, tolPt, usageOf, floor)`（与 `bandPickByUsage` 并排、可被门喂合成表），**全不达标 ⇒ 保留原当选者 + 响亮 `selDefAllBelow`**（不许静默，照 `wideFinalAllNarrow` 先例）。

## 二、臂与判据

- **臂**：配方 = `GATE6-off` 那套（GD3-SWORD 起点、17 席压力面、`GATE=3/GAMES=6/BAND=0.13`、`WIDE_FINAL`、**关注入**、400 代 × N3 × pop8 × games8），唯一变量 = `EPIRUS_SEL_DEF` 开/关；种子 **13 与 41 两粒**（按 11-02 裁定②，晋升级结论要 ≥3 种子批 ⇒ 本批只到"方向"，够不着就明说）。
  标签 `DEF2-on-s{13,41}` ‖ `DEF2-off-s{13,41}`。
- **A-1（这根键推得动吗）**：开档产物的防御族出手/局 > 0 且**在残血快照里也被选过**（用今天那把分层尺 `scratch/pressure-source.mjs`，分母 = 残血决策快照数）。对照基准：v7 冠军残血时 0.0%、代 3 各臂 0.0%。
- **A-2（不是白防）**：`probe-wasted-play` 三档里 **(有效 + 半有效) ≥ 50%**，并报 n（防御手数）。⇒ 若 A-1 成而 A-2 崩 ⇒ 判"被 Goodhart 成摆架势"，**当场撤下这根键**。
- **A-3（强度账）**：开档 vs 关档同种子配对，5P 四骰均值差 ≥ **−5pt**；四骰散布必报。
- **A-4（可迁移，按用户口径不立线只报）**：3P 与 8P 各一档同报 + `isWideVs` 宽窄同报 ⇒ "有效且可迁移才留"这句要能被这几列直接推翻。
- **三条仪器腿**（臂之前）：① 默认关 ⇒ 与 HEAD 版同 env 同种子逐代 `bestFit` 轨迹逐字同、`[防御选人]` 打印 0 行；② 牙 `SEL_DEF_MIN=999` ⇒ 全不达标 ⇒ 产物与关档**逐位同**且自己打印 `selDefAllBelow`；③ 40 代小臂 开 vs 关 ⇒ 逐代轨迹或产物至少一处不同（同 §五③ 的教训：4 代/40 代小臂的**产物**分辨力不足，判"不同"要落在校验过的量上，这条腿允许只读到"轨迹不同"）。
