## 二、结构性死维（15 维，v7 的真 bug 级重复）

| 维 | 位置 | 为什么恒 0 |
|---|---|---|
| `B[*].guardPrev` | `policy.js` 的 EFFECTS 第 2 行 | 读的是 `p.guardNext`，而它在**回合末就被清空**（`resolve.js:172`）⇒ 决策时刻恒 `false`。"上回合摆过防御"这层语义**从未进过网络** |
| `B[*].copiedGuard` | EFFECTS 第 3 行 | 镜面反射复制来的架势只在**结算那一回合**存在 ⇒ 决策时刻不可见 |

## 四、这批"死"里有多少只是没覆盖到

死维名单里 `vampire / nightmare / revive / infinite / taunt / mine / rodGuard / chains / cannon / ring` 等，
在 A0 这枚包 + 这批局面里没触发 ⇒ **不能据此判"没用"**，只能说"这枚包不用它们"。
要判"维度有没有用"必须让**覆盖到该状态的局面**进来（例如用会打隐藏技能的包、或专造状态的脚本桌）。
⇒ 方法条款：**死维分两类——结构性的（代码上恒 0）与分布性的（覆盖不足）；只有前者能直接删。**

## 五、"技能用了但没产生结果"——网络能不能从事件里学到

规则上的确有这件事：`激光眼` 命中防御族 ⇒ 该架势无效（N23）；`小雷/大雷` 命中 ⇒ 该技能无效（R16/N5/N6）；
藤甲/无极变速被这样打掉时，**效果不产生**。

v7 的编码方式是：**B 块只记"效果在不在"**（挂了什么、剩多少），不记"这次为什么没生效"。
⇒ 网络看到的是"他没挂上架势"，而"他这一手其实用了无极变速、被激光眼打掉"只能去历史技能位里找；
**因果被拆成两处、且没有结果位**。这与在册的"条件性"证据一致：手写的"最近真被枪打过才弹"8/8 进线，而奖励/BLOCK_W 剂量买不到同样的行为。

⇒ **2.0 的结论（要写进观测集）**：事件必须带**结果类**，而不是只带"用了什么"：
`applied / blocked / invalidated(laser) / invalidated(thunder) / whiff / fizzled`（6 类，可再并）。
这样"用了但没生效"是一个**显式事件**，模型不需要从"效果位缺失"反推原因（缺失有四种来源：被挡/被弹/被无效/自己没出，混在一起学不动）。

## 六、对 2.0 的直接改动

1. L1 事件序列的每个事件 = `(技能 id, 目标, 结果类)`，结果类用上面 6 类——这条今晚已写进观测集 v2/v4，本节给出**证据**：v7 缺的正是结果位。
2. L4 增一维"本次尝试是否落空"（事件级，不是状态级）：只对"这一手会被激光眼/小雷/大雷打掉"的候选有值。
3. 验证（离线、不开臂）：给 dump 的行补"上一手结果类"特征，重跑 `rank-signal`；判据 = head regret 至少降 0.02pt 且优于现役 net。
