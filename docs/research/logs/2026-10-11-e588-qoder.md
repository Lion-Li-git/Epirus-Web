## 2. 坑：`SHIPPED-Ldemo` 那一行的 path 与它自己的读数**不是同一枚包**

`champion-map/attach-path.mjs` 原来把这一行**无条件**指到 `js/bundled-champion-3p.js`（活槽）。
换包这个动作就是把另一枚包写进那个文件 ⇒ 从 17:30 起，图上"写着 Ldemo 读数（H=51.30 ‖ Hp=48.90 ‖ distinctKeys=10 ‖ charges=2.10…）的那一行"
指向的文件里躺着的是 `T8-s114`。下游每一把按 `path` 列找包的尺（`duel-run --ref=SHIPPED-Ldemo` ‖ `usage-probe --ids=` ‖
`ruler-measure` ‖ `seatassoc` 的 path→id）**量的与行里那串数不是同一枚，而且一字不报**。

还有一条更硬的潜在损失（读规则核出来的，不是"可能发生"）：`viewer.mjs` 的去重保留规则第一优先是 `d.id === 'SHIPPED-Ldemo'`，
而 `attach-dup` 的分组按 **path 文件的权重指纹** ⇒ 换包之后任何一次重跑 `attach-dup`/`rebuild-coords` 都会把
`SHIPPED-Ldemo` 拉进 `T8-s114`/`T-s114` 那一组并**当保留那枚**，把 `T8-s114` 从图上摘掉、父边改指。

**修法**（`attach-path.mjs`）：现役行的 path 不再按名字硬接，改按 `pack-id.mjs` 的 `widOf`（sha1(权重) 前 16 位，
与 `server/train-server.mjs` 的 `weightsId()` 同口径）解 —— 活槽文件**只有在它仍是同一枚权重时**才有资格当这一行的 path；
解不出/多份快照对不上就 `exit 2` 点名，不猜。`coords.tsv` 那一格已改（diff=1 行）指到 DS 钉住的
`docs/artifacts/SHIPPED-Ldemo-2026-10-11-pre-T8s114.bak`。**另：`attach-path` 用默认 `--ruler=` 跑不完**（79 枚 `SLOT-*` 会退回"猜顶层 .bak"）
⇒ 得走 `rebuild-coords.mjs`（它带全名单），本班因此是**手改那一格**（同 DS 改 `dupOf` 的先例），工具里的解法留给下一次重建。

**验据（三条，含"坏了会不会红"）**：
- 新 path 的 wid = `d490dc13…`，与它自己 `dupOf` 组里另外三枚（`Ldemo`/`C5-02-31`/`C5-02-71`）**逐字相同** ⇒ 行自洽；
  改之前那一格是 `24d8fa30…`（=`T8-s114`=`T-s114`）而组串写着 d490 那一族 ⇒ 指错了是**可判的**。
- 行为面：`usage-probe --ids=SHIPPED-Ldemo --games=10` 现在与直接传钉住快照**读数完全一致**（狙击 1.500 ‖ 环 13.600 ‖ ジ 52.000），
  而活槽是 0.200 / 3.000 / 63.100 ⇒ 指错就会看见不同数，这条检查有牙。
- `duel-run` 头行现在印 `参照 = …（path · wid=…）`，且 `--ref=` 支持直接传文件（换代当天"现役"会换主人）；

### 2.1 跑 D233 的时候顺带露出来的一条：**56 条"权重身份可核"的父边是自证清白的**

⇒ 那一"权重身份可核"从来没证明过"这枚臂是从那枚包长出来的"，它证明的是"路径没换主人"。

## 4. 上槽自动跑的那份 skill report 错在哪（用户："这个 skill report 甚至没有小雷"）

三处，都是口径不是造假：

1. **人数传错了**：`promote-champion.mjs` 的自动档传的是 `meta.n` = **这枚包训练时的粒数**（`T8-s114` 是 **3**），
   而冠军在产品里坐的是 **5 席桌**。所以 `docs/skill-report.html` 里明写着"人数 3"，整份是 3 人局的。
   同一枚包、同一台工具，两档人数的使用率列实测差到 6 倍：全息屏障 **5.1%(3人) ↔ 0.8%(5人)** ‖ 聚能环 0.0% ↔ 0.3% ‖ 真正的落雷 0.2% ↔ 0.4%。
   ⇒ 改成传 **5**（并打印"产品形态 5 席"）。
2. **不传 `--champ=`** ⇒ `skill-report` 按人数自己挑文件（`N<=2` 会去读 **2P 槽** `js/bundled-champion.js`）：
   一台只写 3P 槽的 promote，遇到 n=2 的包会给**另一颗包**出报告。⇒ 现在把刚写进去的文件点名。
3. **"实际使用率"这一列的装配是"1 个冠军席 + 4 个脚本席"**（座位轮转 · temp 0.15 · 不吃 ε）⇒
   **反制卡与"要对手先施法才有意义"的卡在这一列结构性读 0**。小雷（雷击之枪）就是这一类：
   报告里 0.0%，而 DS 的战报复算在用户那 6 局里读到 **0.9%（5 次）**、用户本人"被小雷精准劈了两次" ——
   用户那局自己 聚能环 占 28%，**AI 有得反制了**。
   ⇒ 这一列的表头与页首现在写明装配，并写"**0.0% ≠ 不会用**；要问会不会用请配镜像谱 `usage-probe --mode=… --eps=…`"。

⚠ 顺带一条**该重述的旧引文**：v1.6.62 提交信息里那句"报告判词「坑：无 / 没学会的强招：无」"引的是这份 **3 人局 + 1v4 脚本场**的报告，
它的"没学会的强招：无"**盖不住**反制卡与珠经济那几张（这一列在它的装配里读不到）。
