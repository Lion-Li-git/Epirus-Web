## 2. 新增：`champion-map/pool-sync.mjs`（同步器）

- 读真源 ⇄ 读图内联 `var DATA`（按括号扫描取 JSON，**不用正则**）⇒ 逐枚比三类：**新增 / 移除 / 换带**，逐枚点名；
- 默认：**重烘**（`viewer.mjs --out=index.html`，实测 **0.28 秒**）+ **回读复核**（写完再比一次，不信"我写了"）；
- `--check`：只报不写；有漂移 ⇒ **exit 1**（给门用）‖ `--chart=` / `--table=` 可覆盖读入点（正对照用）；
- 路径口径与 `seat-rule.mjs:resolve()` 同族：带盘符或前导 `/` 视为绝对路径（今晚第三次撞"多拼一层"⇒ 统一修在这里）。

## 3. 门 D234 加 ⑩ 腿（**只加腿，不新增门**：278 条不变）

- ⑩a：图与真源必须逐枚一致 —— 直接调 `pool-sync.mjs --check`，**exit 0** 才算过；
- ⑩b **合成正对照**：拿一份"被改掉一枚带的图"（`os.tmpdir()` 夹具）当输入 ⇒ `--check` 必须 **exit 1**
  （否则这条腿只是"跑了个命令"，钉不住"图 ≠ 表"这件事）。

## 4. 自动：`tools/pool-add.mjs` 写盘后自己同步

在**真写盘**之后自动调同步器（`--dry`／拒绝入池都不调），并印 `↻ 演化图已自动同步：…`；
失败**不阻断入池**（表已写成功）但**响亮印出来**并提示手跑 —— 分工是：`pool-add` 负责"改完就同步"，**门负责"同步不了就红"**（两条一起才叫不会烂）。

## 5. 两向验证（都实测过）

| 步骤 | 读数 |
|---|---|
| 图里被改掉一枚带（人为制造漂移）⇒ `--check` | **exit 1** ✓ |
| 同一状态下跑一次**真** `pool-add`（加 `v7t2-31`） | 打印 `✔ 已写…（现 28 枚）` + `↻ 演化图已自动同步` |
| 再 `--check` | **exit 0** ✓ ⇒ 证明确实是**钩子把图重烘好的**（否则图仍坏的） |
| 撤销：表回滚 + 再同步 | `--check` exit 0 ✓（工作树只留本笔该提交的四个文件） |
| 页内自检（重烘后） | `shot.mjs --hash=mode=<tree/1d/3db/map>&check=1 --dump` ⇒ **86 PASS / 0 FAIL ×4** ✓ |

⚠ 顺带记一个工具坑（今晚踩了两次）：`shot.mjs` 的页内断言必须**`check=1` 放进 `--hash=` + 加 `--dump`**；
把 `--check=1` 当命令行旗标传、或漏了 `--dump` ⇒ 它只截图、一条断言都不跑（"看着像跑过"的那种假绿）。
