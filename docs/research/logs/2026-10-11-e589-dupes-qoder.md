## 2. 铸出拷贝的五个机制（都有对得上号的证据，不是猜）

1. **命名按"实验系列"，不按内容**（最大那组的成因）。17 份 `653a1d66` 的 META **配方一字相同**
   （`gens=250 pop=16 seed=35 opps=random,balanced,aggro,defe hotstart=d13d3c85`），而且**时间戳成对相同**：
   `v7l7-31` = `v7phase-35` = `15:18:44`，`v7l7-46` = `seedtest2-31` = `15:34:08`
   ⇒ 这不是"17 个配方各自收敛到同一粒"，是**同一次跑的输出被按当时那一批的系列名各存了一份**。
   ⚠ 这条要单独记：任何引用"我试了 N 个配方"的旧账，先按 wid 折一遍再看还剩几粒（§E330 那次 181 枚叠在同一秒是同一件事的另一面）。
2. **每批一个 `eNNN-out/` 目录**：分析与训练工具的缺省落点写死在当批目录上
   （`analyze-5p-envfit` → `docs/artifacts/e142-out`、`analyze-fitcal-ab` → `e146-out`、`analyze-swap-gain` → `e136-out`、`battle-test` → `battle-out`、`soup-pack` → `soup-out`）
   ⇒ 同一枚包被**每一批重新落一次**，名字还带上当批的前缀（`e71-out/L05-31` 与 `e78-out/G08-31` 与 `e124-out/blk0t00-s31` 是一粒）。
3. **`kept/` 是故意的第二份**（`tools/keep-artifact.mjs` 头注：`docs/artifacts/` 被 gitignore，
   §E120 结案所需的对照包实测已经不在盘上 ⇒ 于是把"结论所依赖的包"**复制**进 `kept/` 入库，带 sha256 账本与 `--verify`）
   ⇒ 这一层重复是**有意的耐久性代价，不是事故**，去重时不能顺手删掉；
   但连它内部也在重复：**D191 早就量到 kept/ 的 25 个文件只有 19 粒不同权重**（09-28 §E128）。
4. **线上槽与量具夹具各是一份**：`js/bundled-champion-3p.js` = `e528-out/T8-s114.js` = `e521-out/T-s114.js`（同 wid `24d8fa30`）；
   `d180-bands/D180-band1..3.bak` 又是 Ldemo 那粒的三份夹具。
5. **旧的"每次评估把冠军另存一份"**：`eval-out/win-C0s31` = `win-C1s31` = `win-C2s31` = `win-Lctl`（四份同权重）
   ⇒ 当年 `win-<name>.bak` 这个写法本身就是拷贝制造机（`chain-scan.mjs:174` 还在把 `win-Ldemo` 当别名核）。

**在册的既有认识**（本次不是第一个发现者）：`attach-dup.mjs:5-7`（"4 行 = 现役本身，图上把现役画成四枚、F 上占 22/23/24/25 名"）
‖ §E330（同名旧拷贝会被当本体 ⇒ `coords.tsv` 才加了 `path` 列）‖ §E128/D191（kept/ 按权重分组）‖ §E464（同一枚包有 v6/v7 两个合法身份）。

## 3. 方案（**还没动手，等裁**）

**A. 唯一真身 + 别名表（内容寻址）**
- 新增 `champion-map/pack-aliases.tsv`：`wid ‖ canonical（主名，一个文件）‖ alias  这个名字从哪来（coords 行 / 文档 / 夹具 / 系列名）‖ tracked?`
- 主名规则：**被 `coords.tsv`/文档引用最多的那个名字**为主名；并列时取 META.ts 最早的那份。（用户已定"文件名作主名，其余用于文档与谱系图连接"）
- 下游一律指 canonical：`coords.tsv` 的 `path` 列、`lineage.tsv`、ruler 表、`np-test` 里的 `FIXTURE_PACK`。
- 谱系图不受影响：图上节点 id 本来就是名字（= 别名），只有"取权重"这一步走 canonical；
  `attach-dup` 的 `dupOf` 天然就是别名表，可以反过来当它的生成源。

**B. 杜绝新增（出口检查 + 一条门腿，不新增门）**
- 四个会落盘包的出口（`train-3p` / `soup-pack` / `keep-artifact` / `champ-audit`）落盘前先算 wid：
  已存在 ⇒ **不写第二份**，只登记别名并打印 canonical；确实要复制必须 `--force-copy` 并写一句为什么。
- 把这条判据挂进 **D191**（它已经在按权重给 kept/ 分组）：**全库同 wid 的实体文件数必须 = 1**（别名表里登记的不算），红名单点名。

**C. 删除的安全顺序（关键：445 个只在盘上，删了没有回滚）**
1. 先 `--dry` 出一张"删谁 / 留谁 / 谁在引用 / 是不是只在盘上"的清单，落 `champion-map/dupes-cull.tsv` **进仓**当凭证与回滚依据；
2. 要删的**先移到 `docs/artifacts/_quarantine/`**（不删），跑依赖检查（coords/lineage/门腿/文档 grep 全部指得到 canonical）；
3. 定向门绿 + 你点头之后才真删；
4. **可逆的那 35 个（在 git 里）可以先走**；**不可逆的 445 个必须单独批一次**——这是我要你明确点头的那一半。

## 5. 用户裁定 + 隔离实验（**跑完已复位，仓库现状 = 实验前**）

裁定：**主名 = 最早 `META.ts` 的那份；同时间戳按被引用数多的那份**。要求：把冗余权重**移到仓库外面**隔离，然后**试会不会出错**。

工具 `tools/dedupe-artifacts.mjs`（`--plan` 只读 / `--write-manifest` / `--quarantine` / `--restore` / `--check`；
账本 `champion-map/dupes-manifest.tsv` 记 `wid ‖ role  path ‖ canonical ‖ metaTs ‖ refs ‖ tracked ‖ quarantineTo`）。
默认**不动 tracked 的那 28 份**（动了改 git 状态，要单独批；加 `--include-tracked` 才纳入）。

**一轮完整往返实测**（`D:\code\Epirus-Web-artifacts-quarantine`，仓外、保留原相对路径）：

| 步 | 结果 |
|---|---|
| 复位后 `--check` | 断链 **0** 条 |
| `--quarantine` | 移走 **273** 个（30 MB）‖ 账本 480 行 |
| 移走后 `--check` | **断链 444 条**（真实下游引用；此前一版把账本自己也算成引用 ⇒ 虚报到 715） |
| `--restore` | 搬回 **273** 个 ‖ 隔离目录剩 0 |
| 回滚后 `--check` / `--plan` | 断链 **0** ‖ 回到 179 组 / 301 份冗余 ⇒ **可逆 ✓** |

**会不会出错：会，而且错得有声有色**（这就是要付的账）：

1. **191 个"被移走的文件"正被 `coords.tsv` 的 path 列引用** ⇒ 任何按 id 找包的尺都拿不到包。
   好消息是**它响亮地失败**：`usage-probe --ids=K2` ⇒ `⚠ 1 枚文件不在（前 6：K2）` + `⛔ ENOENT ... e234-out/K2.js` + `完成 0 枚`，不静默。
2. **门会"降级成 SKIP"而不是红**（这条最阴）：`D233` 的 ⑤ 腿要 `docs/artifacts/e234-out/K2.js` 与 `e85-out/E20-71.bak`，
   移走之后它**在本地也变成 SKIP**（原来本地是跑的，只有 CI 才 SKIP）⇒ "门在、其实没判"的形态，值得单独加一条腿盯住。
   按主名规则 `K2.js` 不是主名（更早的是 `e70-out/D02-31.bak`，同权重）⇒ 要么把这类夹具路径改指主名，要么给主名规则加一条例外："被门当夹具的 tracked 文件不许被移走"。
3. 断链集中在 `coords.tsv`（986 行的 path 列）+ `lineage.tsv` + ruler/feas 各表 + `np-test.mjs` 里的字面路径。

**顺手抓到并修掉的两个工具 bug**（都是我第一版的）：
- `--restore` 在**读账本之前**先把账本按"移走之后"的状态重写了一遍 ⇒ `role=move` 那批全消失、"搬回 0 个"，
  **回滚依据自己覆盖了回滚依据**。修法不是"记得先读"，而是**回滚以隔离目录为准**（目录本身就是自描述清单），搬完再重算现状账本。
- `--check` 把账本自己当引用源（虚报 715）+ 把门里的"文件不存在"夹具 `__d177_missing__` 当断链 ⇒ 两处都收掉了。

**下一步（等裁，还没做）**：两条路选一条 ——
- **A. 机械改指**：444 条引用按账本 `path → canonical` 重写（`coords`/`lineage`/ruler/feas + `np-test` 的字面夹具路径），然后才把 273 个真移走。
  代价：`coords.tsv` 里会出现"行名叫 `K2`、path 指向 `e70-out/D02-31.bak`"这种读起来别扭的形态（别名表负责解释）。
- **B. 把指针的键从 path 换成 wid**：`coords.tsv` 存 `wid`，读的时候 `wid → 唯一活着的文件` ⇒ 名字与文件彻底解耦，
  "同一权重多份拷贝"这件事从数据结构上就没意义了。代价是要动 `attach-path`/`ruler-measure`/`lineage` 这一串（比 A 大得多，但一次到位）。
