# 2.0 观测集：从规则推导，按正交分层（DS · 2026-10-28 夜 · 第二版）

> 用户 20:5x 裁定：**「不要考虑 v7 维度……根据对规则的研究以及相关测试确定我们需要哪些信息，每个维度尽量正交、不要互相覆盖。」**
> 用户 21:0x 三处打回：① 对手的电珠/爆珠**不可知**（只能看到他用过蓄能）；② 「挑衅限制」不是"被禁族"；③ 行为历史应记录**每个人用了什么技能、打给谁**，而不是六族占比。
> 本文按这三条重写：**事实与派生分层**、**历史用事件序列而不是手工聚合**、**只记录规则上公开的信息**。

## 一、三条原则

1. **规则推导**：每一维必须指回一条规则（RULES-2P 的 R 条目 / RULES-NP 的 N 条目 / `js/core/rules.js` 的卡表字段）。
2. **可见性纪律**：只编码规则上**公开**的信息。对手的珠类型、当前同时选择的手牌都不可知；能看到的只有"他上一手/历史用了什么、打给谁、结果如何"与持续状态。
3. **正交纪律**（§五可检查）：同一事实只出现一次；不做双重编码（原始+比例、连续+分箱、聚合+明细）；归一化只在编码器入口做一次；派生量只在 L4，且不许把 L1/L3 的事实再抄一遍。

## 二、规则的决策相关事实（按公开性分类）

| 类别 | 内容 | 可见性 |
|---|---|---|
| 公开的实体状态 | hp、ep、持续效果（架势/八卦/金刚盾/藤甲/原型/全息/挑衅义务/梦魇/吸血鬼/回魂/铁索/地雷/避雷针剩余/藤甲弱点/无极变速第二回合/聚能环连击/过载炮档/符咒）、大雷禁用剩余回合 | 全部公开（`state.js` 的 `freshPlayer` 字段，无隐私位） |
| **对手的珠** | 只能用"是否持珠（类型未知）"表示；类型与枚数**不可知**；他自己**用过蓄能**这件事在事件序列里 | 半公开 |
| 自己的珠 | 电/爆 枚数（自己可见） | 私有→只给自己的席位编码 |
| 上一手 | `lastSkill` / `lastTarget` / `lastTarget2`（公共） | 公开 |
| 同时选择 | 本回合各席的出招**不可知**（秘密同时选招） | 不可知 |
| 未知项 | 判定概率（八卦/金刚盾）只作为规则常量，不进观测 | — |

**从 v1 的 18 里删掉/合并的 5 个**：`fireWeakNow/Next` 合成 1 个有序量 ‖ `tauntActive/Pending` 合成 1 个有序量 ‖ `mineArmed` 并入 `mineTurns`（0 就是无雷）‖ `copiedGuard` **删**（N14 复制的架势只在"结算它的那个回合"存在，决策时刻不可见）‖ `chains 数` **删**（归属在 L2 的 `chained` 逐对表达，计数是它的求和，重复）‖ `vampHeal>0` **删**（是上一回合结算的派生量，序列结果位已含）。
| **事件序列** | **K×3 → 编码器** | 近 K=6 个事件：**技能 id（嵌入）+ 目标（自己/我/其他人）+ 结果（ok / 被挡 / 被弹 / 空放 / 无效）**，用**逐席共享的小序列编码器**（embedding + mean 或 GRU）压成 1 个向量 | 公开（`lastSkill/lastTarget` + 事件流） |

⇒ 每席 = 4 + 18 + 1 + 序列向量。**不再有**"六族占比""上一手类别""结果记忆"三个手写块——它们都是这个序列的函数，重复。

> 为什么用序列而不是占比：① 顺序（连开环、连招、刚被弹）在占比里丢失；② 目标（打给谁）在占比里根本没有；③ 不同 K/族划分会引入任意的超参。

## 四、明确排除（写清理由）

- **对手的珠类型/枚数**：规则上不可知；只留"持珠（类型未知）"+"上一手蓄能"。
- **hp 比例 / ep 归一 / cost 归一 / dmg 归一**：归一化只在入口做一次；同一事实不出现两遍。
- **六族频次 / 上一手类别 / 结果记忆**：都是事件序列的函数，删。
- **技能 30 位 one-hot**：L3 的费用/类别/伤害/穿透/目标型已生成；one-hot 是重复编码。
- **座位编号**：池化后不需要，且会诱导身份特化。
- **"他对我的命中次数""他的反弹率"**：从序列统计得出，不手工喂——否则是同一事实的第二种写法。
- **判定概率**：八卦/金刚盾的成功率是规则常量，不是状态。

## 五、正交性怎么检查

1. **覆盖清单**：R1..R61、N1..N27 逐条对到某一维，或写"为什么不影响出招"；对不上 ⇒ 缺维。
2. **重复检查**：训练分布上算维间相关，|r|>0.9 必须合并或写理由。
3. **消融**：L1 资源/状态 ‖ L1 序列 ‖ L2 关系 ‖ L4 派生 各摘一次，用同一把离线尺量 regret 回升；<0.01pt 的块不留。
4. **增益**：每层加进去 head 的 regret 至少降 0.02pt；全套 ≤0.20pt 且优于现役 net 0.321（随机 0.347、可达地板 0.093）。

## 六、规模

- L0 8 ‖ L1 4+18+1 + 序列向量 ‖ L2 5/对 ‖ L3 15 ‖ L4 7。
- 序列编码器与实体编码器**逐席共享**；席位不固定 ⇒ 与 arch2 的 set encoder 同形。
- L4 的 `killsIfUndefended` / `pierceVsVisible` 是确定性计算，成本 ≈ 每候选一次查表（不是 rollout）；预算先按"决策数 × 候选数"在 preflight 里量。
