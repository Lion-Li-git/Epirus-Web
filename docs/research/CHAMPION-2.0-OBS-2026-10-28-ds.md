# 2.0 观测集：从规则推导，按正交分层（DS · 2026-10-28 夜）

> 用户 20:5x 的裁定：**「不要考虑 v7 维度，兼容性是最后的问题……2.0 维度还没开始，不要想到要加的时候再加在后面。根据对规则的研究以及相关测试，确定我们需要哪些信息，每个维度尽量正交、不要互相覆盖。」**
> 所以本文不是「v7 + 几维」，而是**从规则重新枚举"做一次出招决策需要知道什么"**，再按层分配。v7 只在"哪些已证够用"的地方被引用为证据。

## 一、三条原则

1. **规则推导**：每一维必须能指回一条规则（RULES-2P 的 R 条目 / RULES-NP 的 N 条目 / `js/core/rules.js` 的卡表字段）。指不回去的维不进。
2. **事实与派生分层**：原始事实（谁有多少、这招多少钱）与派生量（这招能不能杀死他、会不会被弹回）**分两层**；派生量必须写清它的规则依据。
3. **正交纪律**（可检查，见 §五）：
   - 同一事实**只出现一次**；
   - **不做双重编码**（原始值 + 比例值、连续值 + 分箱、全局 + 逐席再汇总）；
   - 归一化只在编码器入口做一次（每维一个固定缩放），**不额外增加"比例维"**；
   - 派生量只在 L4，且不允许把 L1/L3 的事实再抄一遍。

## 二、规则里哪些事实会改变最优出招（枚举）

| 规则面 | 决策含义 | 需要的原始事实 |
|---|---|---|
| 费用与资源（R2/R3） | 出得起吗、出完还剩多少 | 自己的 ep；本回合可付的珠（电/爆）；技能 cost（含动态：聚能环首下 3、之后免费；过载炮/激光眼按档） |
| 回合结构（R6/N2） | 同时选招、按优先级结算 | 优先级、当前回合/上限、收缩起点（N25） |
| 合法性（R7/N3） | 目标必须存在、目标型（敌/自/他/无） | 技能 target 型、存活席、被禁族（大雷 3 回合、避雷针免雷、挑衅） |
| 伤害与穿透（卡表 pierce） | 打得穿谁 | dmg(amt,type)、pierce{def,reflect,transfer} |
| 防御矩阵（R7/N7） | 攻 vs 防/反/八卦/金刚盾/藤甲/原型/全息 | 对方本轮举什么？未知 ⇒ 只能给历史与"能穿谁"的静态关系；**不给"他一定在防"的确定性位** |
| 优先级两两相抵（N4） | 同层谁压谁 | 双方优先级（对方未知 ⇒ 历史频次） |
| 隐藏技能（N9/N14/N15/N16/N17 + 4 隐藏） | 触发条件是否满足 | 铁索：链关系；吸血鬼：hp 状态；梦魇：?；回魂：死亡触发；聚光炮/反复横跳/合二为一：卡面条件 |
| 多人机制（N20/N22/N23） | 地雷/大雷/激光眼在 N 人桌上的放大 | 存活人数、交互关系（谁打谁） |
| 经济（R 系列珠规则） | 攒 / 花 / 过期 | 自己的珠、蓄能回合、珠时效（只供下一回合） |
| 资源曲线与集火（N1/N12） | 谁快死了、该不该收 | hp、存活数、击杀阈值 |

## 四、明确排除（写清理由，避免以后又"想到就加"）

- **hp 比例 / ep 归一 / cost 归一 / dmg 归一**：归一化只做一次、放在编码器入口；同一事实不出现两遍。
- **技能 one-hot（30 位）**：L3 的费用/类别/伤害/穿透/目标型已经生成，one-hot 是重复编码；技能的特殊性由 L4 的派生量与 L3 事实组合表达。
- **座位编号 / 座位顺序**：池化后不需要，且会诱导"某个座位 = 某种策略"。
- **"对手一定在做什么"的确定性位**：同时选招 ⇒ 对手本回合动作不可知；只能给 L1 的历史与 L4 的"能穿谁"。
- **第二份伤害/费用/珠统计**：§E816 实测 R² 84~99%，再加是同一件事说两遍。
- **版本 / 门号 / 名字**：与研究无关。

## 五、正交性怎么检查（不是写完就算）

1. **覆盖清单**：把 RULES-2P 的 R1..R61 与 RULES-NP 的 N1..N27 逐条对到"哪一维"或"为什么不影响出招"。对不上的条目 ⇒ 缺维。
2. **重复检查**：在训练分布上算维间相关；|r| > 0.9 的对子必须合并或写清理由（规则上真的需要两份）。
3. **消融**：每层（L1 状态 / L1 历史 / L2 关系 / L4 派生）单独摘掉，用同一把离线尺量 regret 回升；回升 <0.01pt 的块不留。
4. **增益**：每块加进去，head 的 regret 至少降 0.02pt；全套目标 ≤0.20pt（当前 235 维线性头是 0.313、随机 0.347、可达地板 0.093）。

## 六、规模与成本

- L0 8 ‖ L1 33/席（池化后 2×hid）‖ L2 6/对 ‖ L3 15 ‖ L4 8 ⇒ 总输入约 **L0 8 + 2×hid + L2 6 + L3 15 + L4 8**；
- L4 的 `kills/bounced/blockedBy` 需要一次**确定性前向结算**（solo 1-ply，clone+resolve），成本 ×候选数；先在 preflight 量"每局决策数 × 候选数"，预算 ≤2× 现状，超了只对 top-k 候选算或缓存同状态。
