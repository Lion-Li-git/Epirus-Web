### ① D15 已经定性到代码行了：**门断言的是一个"少了一项"的恒等式**

用户贴回来的红行是 `D15 ep 奖罚门槛…→ fit 必须 = 池子分 + 熵奖励 + 风格切片（实测 fit=0.51750）`。把引擎那行原文摊开：

- `js/train/evo.js:2422`：`fit = wallReject ? -5.0 : (fitAgg + divBonus + STYLE_W*styleRate **− seatPen + shapeBonus + gBonus**)`
- `js/train/evo.js:2425/2450/2455/2457` 把 `fitNoDiv=fitAgg` ‖ `styleWeight=STYLE_W` ‖ `gBonus` ‖ `seatPen` 都随评分返回（**只有 `shapeBonus` 没返回**）
- 而 `tools/gates/train-evo.mjs:695` 那条断言只写 `fit === fitNoDiv + divBonus + styleWeight*styleRate`（容差 1e-9）

⇒ **这条恒等式只在 `seatPen == 0 && shapeBonus == 0 && gBonus == 0` 时才成立**，而门把它当无条件式在用。三项里：
· `gBonus` 由 `FIT_G_W` 门控，默认 0（`evo.js:1607`）；· `shapeBonus` 由 `S4_W` 门控，默认 0（`:1643`）；
· **`seatPen` 不是开关** —— `SEAT_PEN_W = 1.0` 是写死的常数（`:2370`），`seatMaxPct ≥ 70` 就上罚项。
而 D15 只跑 **2 局**（`scoreMemberN(p, [random], 2, 3, 1, 0, 0)`）⇒ 座位占比天然容易冲到 ≥70%（两局同一席全赢就是 100%）。
⇒ **机制候选（代码级，尚未跑出来验证）**：D15 红不红取决于那 2 局的座位分布，而座位分布取决于当时的 RNG 消耗位置 ⇒ 任何在它之前多动/少动一次随机的改动都能把它翻绿翻红。这与"runner 摆动"完全不同形状：**它是运气绿，不是产品坏，也不是机器慢**。
