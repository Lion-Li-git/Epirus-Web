## 一、一句话

2.0 的包以前**只有自己认得自己**：长度能骗过检查、`arch` 会标错、观测面换了没人知道、
一半参数算了但不参与决策。现在它必须自证三件事才准进训练环与尺——**段表=功能层、每个下标都被读、观测面对得上**。

## 二、"代"（`dims.gen`）的定义 —— 三条不变量

一代理 = 一组同时成立的**结构不变量**；动其中任何一条就是一代，不许叫"修个 bug"。

| # | 不变量 | 谁在守 | 坏了会怎样 |
|---|---|---|---|
| I1 | **段表 = 功能层**：第 `k` 层的权重确实落在 `seg[k].off … seg[k].off+rows*inDim` | `selftest2` **T18①** + `pack2-audit` C 段 | 变异/交叉/`mutOnly`/`fanIn` 定标/参数量解释的都是段表，不是那张网络（代 1 就是这状态） |
| I2 | **没有既不权重也不 bias 的下标**（声明的每条都被读） | `pack2-audit` B 段（逐下标覆盖表） | 优化器把预算花在零梯度坐标上；"等效维数/容量"这类量被死坐标污染 |
| I3 | **容器自证**：`v` ↔ `dims.gen` ↔ `dims.dof` ↔ `arch` ↔ `dims.input` 五者互相对账 | `arch2.packInstallCfg` / `checkPack`（`reason: version/length/gen/arch/dof`） | 旧包被新网络静默解释 ⇒ 读数一路绿而对象已经换了 |

代 1 = `f996c2a3` 那一刻的全部臂（10-28~10-30 白天，含 COMBO/LEX/BONS/RATS/CB/PERN 系）。
代 2 = 本文这批改动。**代 1 不提供运行时开关**：它的观测面维度（210 vs 208）、池化口径、段偏移都和代 2 不同形，
"只切偏移"会造出第三种对象——那正是这仓反复栽的半旧口径陷阱。
要复算代 1：`git worktree add --detach ../Epirus-gen1-frozen f996c2a3`（用完 `git worktree remove`）。
**本次已经这么做并留了原件**：`scratch/gen1-frozen-arms/GEN1-s{7,11,13}.bak(+meta,log)` 是与代 2 同预算同配方的对照臂。

## 三、容器字段（唯一真源 = `arch2.pack()`，不许在别处再拼一遍）

```js
{ v: 91,                       // V_FOR_GEN[gen]：代 1 是 90，代 2 是 91
  arch: 'S1' | 'S1o',          // 由实际布局写，不由调用方填
  dims: { seatH, actH, hid, hid2, input, inter,
          gen: 2,              // ← I3
          dof: 208 },          // ← 观测面维数，仅 obs3 档有；由 obs3.dims(R) 算，不手写
  layout: { seg:[{name,off,len}], fanIn, n },   // ← 段表随包走：下游照它算，不再各写一遍下标
  a: [...], n: 6122 }
```
外加臂的回执 `scratch/arms/<名>.bak.meta.json` 里新增 **`container`** 段：每段的
`{off, len, weight:[起,止), bias:[起,止), fanIn}` ⇒ "这枚包的参数地图"是机器读的，不是注释。

## 五、每一维的标注规范（obs3 的 `MANIFEST` 就是登记册）

`MANIFEST` 每条带 `{i, name, block, note}`；`pack2-audit` 的 D 段在**真局分布**上逐候选扫可见性，
自己造夹具（不读 `scratch/*.jsonl`，所以干净克隆里也跑得成——这是 `dimgate/audit-dims/check-align` 做不到的）。

四条纪律，新增/改维度时必须逐条过：

1. **出处**：指回一条规则（`docs/RULES-2P.md` 的 R 条目 / `RULES-NP.md` 的 N 条目 / `js/core` 的字段行号）。
2. **量程**：写死分母并保证值域 ⊆ [0,1]。代 2 把人数族统一到 `/10`（2.0 目标上限就是 10 人）；
   代 1 的 `n/6`、`alive/6`、`pool.count=seats/6`、`aoeCount=opp/5` 四种写法三种分母 ⇒ 已并。
3. **可达性**：要么给出"哪个夹具能点亮它"的构造，要么进恒零清单。代 2 的实测（720 决策 / 24812 枚候选，
   原件 `scratch/qoder-1030-probe11.mjs`）：
   - **构造性恒零（已删）**：`epRegen`（全仓没有任何路径写 `regen` ⇒ 产品与 arena2 恒 0）、`tgt.none`（30 张牌 `target` 全非空：self 13 / enemy 16 / other 1）。
   - **稀有但可达（保留）**：`rel.chained`（要两席互摄魂且过 HP 门）、`ownBoom`/`needBead`/`skill.railgun`（电磁炮要先攒到 3 ジ 再蓄能，窗口窄）、`skill.laserEye`、`infiniteEnergy`（回魂）。
   - **教训**：我第一版扫描按"编码数封顶"采样 ⇒ 116 个"恒零维"，第二版按"每决策只采 4 枚候选"⇒ 53 个，
     第三版"逐候选 + 按决策数封顶 + 逐桌形配额"才落到 10 个。**恒零清单的分辨率等于抽样形状**，报它必须带分母。
4. **重复禁令**：同一事实只写一处。代 2 删掉的两处重复：`pierceVsVisible`/`t1stance` 里混进的
   `tauntActive`（挑衅义务不是盾，且 `t?obligation` 已各写一遍）与 `fireWeakNow`（`t?fireWeak` 已单列）；
   `pool.count` 与 `G.alive` 重复 ⇒ 删前者。

## 六、两把尺的语义必须同形（代 1 的反例）

`obs3.encode()` 的 `pool.mean.*`/`pool.max.*` 只算对手；而**网络**那条路把 `isSelf` 那一席也平均了进去
（`arch2.mjs` 旧 `for (const s of sc.seats)`），既违反设计文档 L1.5 的 `mean_{i≠self}`，又让
离线路尺（dimgate/fit2/rankfit/project-blocks）与训练时真吃的列不是同一个量。
代 2 的修法：**自己单列 `h_self`，池子只算对手**（obs3 档的 `ctxDim = selfDim + 3*seatH`）。
为什么不是"直接把自已排除"：obs3 档的 `xin` 里原本没有"你自己"的任何席位列，排除就等于把自己弄丢。
这条由 `selftest2` **T18③** 钉住（构造网络只读 `h_self` ⇒ 改自己血必须动、改对手血必须不动；只读 `mean` 反之）。

## 七·补、"打分有没有牙"（代 2 同批加的第三条读数，判据只在 `head-health.mjs` 一处）

**为什么要这一格**：换代之后我自己训了 3 粒 300 局短臂，结果 `game-record` 打出来的两局**正文逐字相同**，
再拿一枚**随机初始化**的代 2 包喂同一个记录器 ⇒ 还是同一局。也就是"包在被打分为候选打分，但分数说不上话"。
这是"覆盖式接入要自证真被调用"的**下一层**：调用了前向 ≠ 前向有信息。

**判据 = 同一串固定骰子下，与"随机起点包"打出同一手的比率**（`agreeRandom`）。标定实测（60~72 个真局决策点、t=0.15）：

| 对象 | 与随机起点同骰一致 | 集中度 max(p)×K | 熵占比 | 判 |
|---|---|---|---|---|
| 随机起点彼此（同架构不同种子） | 93% / 97% / 93% | ≈1~3 | ≈0.95 | 底 |
| 代 2 · 300 局短臂 s7/s11/s13 | 70~82%（彼此 65~85%） | 2.0~2.8 | 0.95~0.96 | **平头** |
| 未训臂（evals=8，其实就是那枚随机粒） | **94~100%** | 2.8 | 0.95 | **平头** |
| 代 1 · 6k 在册臂 PERN-s13/s7、CB-s13、BONS-s11、LEX-s13、MILD-s11、COMBO-s7 | **5.6~6.9%** | 12.6~21.4 | 0.30~0.42 | 有牙 |
| v7 参照 | —（架构不同，不比这一列） | 27~53 | 0.000 | 有牙 |

⇒ 平头线取 **60%**（夹在随机底 93±4 与 v7 量级 5~7 之间）。**代 1 那批要用代 1 的尺量**——跨代比"随机起点"没有意义，
那次测量是在 `git worktree add … f996c2a3` 的临时树里做的（原件 `tools/proto2/gen1-agree.mjs` 随树销毁，读数在上面这张表）。

**两条否定，写在纸上也算账**：
- 我第一版想用 **argmax 分歧率**：标定直接否掉——随机起点彼此就有 43~100% 的 argmax 分歧，比"训练 vs 未训练"的差还大 ⇒ 没有分离力（`scratch/qoder-1030-headcalib.mjs`）。
- **集中度 max(p)×K** 只当并报刻度，不当判据：它是相对量，我定不出"2.8 算不算平头"的有依据阈值。

**接法**：`probe-cem-arm --headGate=1` ⇒ 平头就 `exit 9`（产物仍落盘，可事后复盘，但回执不许被当合格臂引用）；
缺省关 ⇒ 不带旗标的批次逐字不变。`pack2-audit` 的 E 段永远只报不判，要它判加 `--requireTeeth=1`。**没加任何产品门禁。**

**顺带纠正我上一轮说过头的一句**："2.0 的头几乎不分候选"——那句只对 **300 局短臂**成立；
DS 的 6k 臂一致率 5.6~6.9%、集中度 12~21，**与 v7 同量级**。所以这不是 2.0 的结构病，是预算没花够；
而"最佳温度要压到 0.02 才有代差"这一格反而有了机制解释：短臂的头太平，只能靠降温硬掰出差别。

**裁定（用户 10-30 傍晚，逐字）**：「**训练侧的门禁就留在训练侧用，产品前台才接到发布门禁里面**」。
⇒ 本节所有量具（`selftest2` / `preflight2` / `pack2-audit` / `head-health`）**只进臂的回执与审计出口，不进 `np-test`**；
反过来，凡是要钉"包能加载 / 规则不回归 / 页面契约"的才配进 171 条那一侧（与 `CHAMPION-2.0-RESEARCH` 末段同一条规矩，这次是用户复述裁定）。

## 七·再补、"换代值不值"这条**还没测清**（我这次比较带了混淆，如实记）

同配方（esa/1125/pop14/games4/n3/分层场 mild/clean/每 N 地板）跑代 2 三粒：**accepted=0 ‖ verifications=0**

| 配置 | accepted | verifications | 同骰一致 | 集中度 | 熵占比 |
|---|---|---|---|---|---|
| 代 2 · 每 N 地板 · 随机起点 · 1125 | 0 | 0 | 78.2% | 2.74 | 0.959 |
| 代 2 · 每 N 地板 · 随机起点 · **4000** | 0 | 0 | 61.6% | — | — |

⇒ 三点判读：① **代 2 的头能醒**（换验收规则后 accepted 从 0 变 5、同骰一致掉到线以下），所以"平头"不是代 2 的结构病；

   与 DS 自己在 `RESULTS-2026-10-30-PICK-COMBO` 写的那句"**起点可行 ⇒ 合格归档首次出现非起点子代**"是同一件事的另一半。
③ 所以**"换代值不值"仍未判**：要判得让两代吃同一个起点，而代 2 没有可用的代 2 热启动起点（代 1 的包被代闸拒读）
   ⇒ 要么先给代 2 造一个可行起点（词典序预热几代再切每 N 地板），要么承认这条只能等代 2 自己的第一枚在册臂。

**顺带一条给 P0 的账**：`--arenaPerN=1` 值得加一条自检——"**整批零送验就当场红**"（`verifications=0` 而 `evals>0`
本身就是异常，不需要等到复盘才发现搜索根本没跑）。这一格也留在训练侧，不进产品门。
