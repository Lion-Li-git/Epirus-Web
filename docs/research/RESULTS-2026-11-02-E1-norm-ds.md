# E1 输入标准化：负结果（DS · 2026-11-02 晚）

> 用户：「新网络不停过拟合，MoE 没用；24 隐元只用 4 个，现在什么情况，怎么更好发挥。」→ 我提 E1（输入标准化）并执行。

## 设计（配对）
- 同一热启 `L5-D4a-s13`、同课程（5P long、混合池、150 代），只差 `EPIRUS_NORM`（134 维 ctx 输入按固定 mean/std 标准化；统计量来自 long40+multi20 语料，53 维被 std 下限 1e-2 夹住）；
- `dims.norm` 随包存取 ⇒ 评测自动复用；旧包无该字段 ⇒ 逐位不变。

## 读数（arena2 mild，30 局/桌形，最佳温度）
| 臂 | 5:long | 5:multi |
|---|---:|---:|
| `E1-N-s13` | 0.167 | 0.292 |
| `E1-N-s41` | −0.042 | −0.042 |
| `E1-N-s7` | 0.250 | 0.333 |
| **N 中位/均值** | **0.167 / 0.125** | 0.292 / 0.194 |
| `E1-C-s13` | **0.458** | 0.292 |
| `E1-C-s41` | **0.542** | 0.458 |
| `E1-C-s7` | −0.042 | −0.167 |
| **C 中位/均值** | **0.458 / 0.319** | 0.292 / 0.194 |

⇒ **标准化在 5:long 上是负结果**（中位 0.167 vs 0.458，均值 0.125 vs 0.319）；5:multi 打平；方差没有改善（N 极差 0.29、C 极差 0.58，但 C 是单粒崩、N 是三粒都低）。

## 为什么会负
- 输入本来多为 [0,1] 量纲，标准化的"归一"收益很小，但 **53 个近恒定维被 std=1e-2 的下限放大 ~50 倍** ⇒ 把噪声喂进 ctx；
- 热启包是在原尺度上训出来的，换尺度等于"整层输入重标定"，150 代不够重新适应；
- ⇒ 结论：**尺度不是病根**，静态标准化这条不必再走；要动就动"恒定维要不要留"（E2）与"选择信号/早停"（E3）。
