# 架构：分桶专家池（bucket-expert-pool）——长程技能池级覆盖的训练侧落法（ZCode · 10-31 凌晨，P3）

> 上游三件：缺口地图 `RESULTS-2026-10-31-LONGSKILL-GAPMAP-zcode.md`（0699529d）、判据 `PREREG-2026-10-30-LONGSKILL-zcode.md`（d3acd1be）、
> 计划 `PLAN-2026-10-30-NIGHT2-zcode.md`。本文只做一件事：把"池级比例线"翻译成训练侧结构，并列出每条结构的已证事实。

## 一、为什么是分桶（三条已证事实 + 今晚第四条）

1. **cap 可绕**（DS 机制账 4）：单包绝对线被"ji+一门技"、"少打架多攒ジ"绕过——上限类约束只能排除极端，覆盖靠分桶；
2. **每 N 地板是十几次干预里唯一"目标改变剖面"的成功**（DS 白天）：**验收收紧**（而非适应度整形）有成功先例；
3. **CEM48 链条已证能到 61.4%/0.415**（DS 晚）：链条配方 = 现成的强度引擎，桶内训练不必另起炉灶；
4. **（今晚）强度-行为交换已同尺成数**：v7 行为最健康（1.5/6 条）但强度 42.0 < 链条 61.4；
   链条产物的最强吸引子 = "蓄能 25~179/局 + gun + proto 锁"（珠浪费 93~100%）。
   ⇒ **任何"强度第一"的单包训练都会滑进这个吸引子**；桶的意义就是把"会 X"从强度优化里隔离出来单独验收。

## 二、结构

```
池（pool）
 ├─ 桶 ring      桶 bigT      桶 railgun     ← 1/2 线：池成员 ≥1/2 会
 ├─ 桶 laserEye  桶 miniT     桶 cannon      ← 1/5 线：池成员 ≥1/5 会
 ├─ 观测桶 proto/transfer（集火预判）         ← 用户 10-31 指定研究方向；线等分布（今晚已录基线）
 └─ （holo 暂缓；防御多样性线、珠健康池级线 = 池级验收另列）
```

**桶 = 一个"会 X"的专家位**。桶内产物用**双键验收**（不是适应度整形）：
- 键①（强度）：clean 不塌 —— CLI ≥ 起点 −0.05（沿用判据先行的老线）；
- 键②（行为）：mastery 判据 X 达标 —— 正式尺（skill-mastery，40 局/格）逐条 ✔。

**训练配方**（桶内，全部骑已证件）：
1. 起点：CEM48c 链顶（或该桶最接近的现有产物）；
2. 链条：`--mode=cem --pop=48 --fxGames=16 --targetGames=24000`（预算随种群放大，DS 已证）；
3. **mastery 验收门**：训练环内 accept 事件加第三道闸——cheap 审计（long n=3 × 12 局）该键行为 < 门 ⇒ 不送验/不棘轮
   （结构 = verifGate 家族："搜索自由、验收收紧"；门宽先 0.1/局，正式验收仍用 40 局/格 + 0.2/局）；
4. 棘轮照旧（全局最优或父代-last，等价双门）。

**池级验收**（真池成形后，今晚不produce 判词）：比例线（PREREG §三）+ 池级珠健康（池均浪费 <40% ∧ 花珠率 ≥60%）
+ 防御多样性 ≥3 种 + **短程迁移**（PREREG §四：长程达标包 multi(hp3) 复测，频率线 ×1/4，不许归零）。

## 三、已拒方案与边界（不重复踩）

- **不**做"mastery 加进 CEM 适应度"的第一版：shaping 有失败史（BEAD_BOOM_W 买分布不买保证），
  且链条的最强吸引子恰恰会顺着适应度罚找新口子；先做验收门（有先例、可回退）。
- **不**用相对门（按父代放宽）：DS 已证"会漂"。
- **饿死风险**（白天两阶段 43 送验 5 过闸的教训）：门只挂在 accept 事件上不动变异分布 ⇒ 搜索照样自由；
  若 24k 后 0/3 粒过门 ⇒ 不是门太严就是提供率结构性为 0，停线换道（见 §四）。
- 候选集 ≠ 池：桶赢家进池前不produce 任何池级判词（PREREG §三）。

### 勘误（10-31 00:2x，开臂前落盘）

§四写的"accept 事件加第三道闸"在 CEM 路径上**不存在对应物**——实查 `probe-cem-arm` 的 `--mode=cem`
走裸 CEM 循环（采样→精英重拟合→best），没有 ESA 那套 verifyChild/棘轮（顺带发现：CEM48c meta 里
`recipe.arenaLex=true` 在这条路是**死旗**，与千问 §九 verifGate 静默跳过同族）。门落两处，都是"验收收紧进选择"：

- **elite 档（本臂用）**：精英重拟合只吃 cheap 审计达标的候选（按 fit 降序审，攒满 ELITE 或审计预算 16 次/代；
  <2 个达标 ⇒ 该代退回纯 fit 精英并记 starved——搜索不饿死，压力按代记账）；
- **best 档**：产物 best 必须达标（备用，本臂不开）。
- 开关：`--masteryKey=bigT --masteryLine=0.1 --masteryGate=elite --masteryGames=12 --masteryN=3 --masteryTable=long`；
  审计骑 `skill-mastery.auditCells`（与正式尺同一段代码，只差局数）；meta 带 `mastery.stat`，audits=0 响亮失败。
- **冒烟读数（2.4k 局）**：门 90 审计 23.3% 达标、3/8 代饿退——起点包本体 bigT 0.0/局，但 σ=0.2 邻域 23% 的
  突变能过 0.1/局 ⇒ 门可达、不饿死。环境补记：链条配方 = `EPIRUS_ARCH2=1:input=obs3 EPIRUS_PAIRED=1`。

### 勘误二（10-31 00:4x，第一轮臂跑完后、重跑前落盘）

**第一轮臂（BIGT1-r1）作废，机制已查明**：门终态 78~87% 达标、末次审计率 0.4~2.1/局，
但三枚产物正式尺 bigT **0.0/局**、长桌胜率塌到 0~7.5%。根因 = **产物被 4 局循环分棘轮冻结**：
`bestFit` 初始化 −∞，iter-0 即有候选上位；4 局配对循环分上限 1.0，早期幸运子代摸到满分后
`bf > bestFit` 永假 ⇒ 之后 120+ 代门塑形的是**种群分布**（合格率一路涨），**产物**却钉死在
早期某饿退代（纯 fit 顶、没过门）的幸运子代上。这是 ZCode 夜班 #1"点估计门棘轮"机制在产物层的重演。

**修法（本轮起生效）**：elite 档产物只从**达标者**里棘轮（`bestFitPasser` 独立记账）——
饿退代不更新产物；种群棘轮曲线照旧另记。产物 = 历来 loop-fit 最高的过门候选，
强度锚（循环分）与门（达标）同时保住。重跑 = 同配方同种子（s7/s11/s13），产物名 BIGT1-s*。
