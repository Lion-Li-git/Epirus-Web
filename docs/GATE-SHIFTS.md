## 三、三条不许越过的线

1. **分组跑出来的不是认证。** `--group=` 与 `--only=` 同罪：总结论行会自己印「§E335 分组 xxx：**不是整轮认证**」。
   要引用"整轮全绿"，只有不带 `--group` 的整轮算（D194 钉这条，D205 钉门号）。
   ⚠ §E365 起这一句的措辞从"四道全绿"改成"整轮全绿"—— 把**道数**写进判词，加一道门就会让所有旧判词过期（那是第 89 条说的那类"钉数字的措辞"）。
2. **认证树必须等于提交树，范围限定在"被门读取的那些文件"。** 整轮跑起来之后再动 `tools/`、`js/`、
   `CHANGELOG.md`、`README.md`、`.gitignore`、`docs/METHODOLOGY.md`、`docs/RULES-2P.md`、
   `docs/artifacts/e129-out/matrix.json`、`train-3p-out.js`、`e161-ply.mjs`、`e168-style-human.mjs`、
   `e169-beadprice.mjs`、`tools/human-pool.mjs` ⇒ 那一轮立刻作废。
   ⚠ `.gitignore` 也在读取面上（**L5** 读它断言 `-out.js` 在册）—— 这条最容易漏，因为它看着像纯仓库配置。
3. **加门必须同时登记分组。** 不带 `--group` 的整轮会检查"每条门都在分组表里"，漏了就 `exit 4` 点名
   ⇒ 分组表不会悄悄漏腿（D205 管门号撞车，这条管归组）。

## 四、为什么没有把门物理拆成几个文件

拆文件要先把 ~1200 行共享前导（沙箱、`ok/eq`、`spawnSync` 包装、夹具）搬进一个 harness 模块，
而收尾那条"注册数 == 执行数 + 跳过数"的守卫（D194 钉它的源码形状）会连带改形 ——
**收益是零**（跑多少条由分组决定，与文件怎么切无关），风险却是本仓最怕的那一类：门绿着，但它没在看你要上线的东西。
⇒ 分组已经提供了"跑子集"的全部收益，物理拆分留作纯机械活。

### 附：`tools/gate-audit-vacuous.mjs` 下一步的**精确改法**（我这一轮做到一半、已回滚）

**症状**：它数花括号找门收尾 ⇒ 字符串里的 `{` 会让门体提前结束（曾误报 `D168`、并把门数从 277 少看到 12；注释里的断言文本也会被当成腿 ⇒ 我 10-09 误摘过自己的注释两次 ✗）。

**已验可行的改法（`string-aware`，写在这里照着做即可）**：
1. 加一个**逐行状态机** `stripLine(l, st)`（`st = {blk:false}`）：把 `//` 之后、`/* */` 之内、`'…'`/`"…"`/`` `…` `` 之内的字符换成**同长度空格**（保留列位置）；
   ⚠️ **不要在 JS 源码里写反斜杠字面量**（本会话两次被工具链吃掉 ⇒ 用 `String.fromCharCode(92)` 代替）；
2. 用 `CODE_LINES = lines.map(l => stripLine(l, st))` 去**数花括号**（不改变行数 ⇒ 行号仍对得上）；
3. 门体内容分析时**跳过"纯注释行"**（`CODE_LINES[i].trim()==='' && lines[i].trim()!==''`）⇒ 消掉注释造成的 C/D 误报；
4. 门标题正则要从 `^t\('…'` 放宽到**单双引号都认**（差的那 3 条疑在这里）。
   ⚠️ 我用 Python heredoc 改这一步时把正则的反向引用写坏了（门总数变 0）⇒ **这一步请用 `edit` 工具按精确原文替换**，不要用 heredoc ✗。
   ⇒ 改完应看到：门总数 **277**（与运行时一致）· C 类 **0** · A 类可人工复核。

## 九、缓存与「读子进程产出文件」的门（§2026-10-10 DS · 承接 Claude 整改建议 §门禁「现在要修的问题」第 3 条）

### 病

`tools/np-cache.mjs` 只缓存 `(status, stdout, stderr)`，**前提是"断言只用 stdout/status"**（它自己的前置要求）。
但有些门的断言要**读子进程产出的文件**（`.bak` / band / 量具输出）⇒ 缓存命中时**子进程根本没跑** ⇒ 它读的是**上一次留下的文件** ⇒
**可双向骗人**（假绿与假红都可能，METHODOLOGY 117）。

### 机械诊断（不要靠印象）

对每道门取「`^t(` 到下一个 `^t(` 之前」的门体，筛「用了 `spawnCached`」且出现读产出信号（`mkdtempSync` / `readdirSync` / `readFileSync(变量路径)` / 读 `docs/artifacts`）的：

**实测 8 道**：`D123` `D127` `D134` `D135` `D136` `D137` `D150` `D157`
（Claude 文档点名的是 `D123`/`D127`；机械扫出**另外 6 道** ✔）

### 修法（已落地）

1. `tools/np-cache.mjs`：`spawnCached(argv, opts)` 加**显式逃生口** `opts.nocache` ⇒ `if (!cacheOn() || !o.encoding || o.nocache) return spawnSync(...)`。
2. `tools/np-test.mjs`：加一行 `const spawnNC = (argv, opts) => spawnCached(argv, {...opts, nocache: true});`
   并把**上面 7 道门**（`D157` **除外**）的 `spawnCached(` 换成 `spawnNC(` ⇒ **12 处**。
3. **`D157` 例外**：它自己就是缓存的自证门，必须走缓存 ✔。
4. **`D157` 里那条规矩本身是错的，已改** ✗：它原来要求「至少四条最重的训练臂要走缓存（40/60/60/30 代）」——
   而那四条正是上面 **`D134`/`D135`/`D136`/`D137`**（断言读产出的门）⇒ 那条要求把**不安全做法写成了要求** ✗。
   ⇒ 换成**更强的那条**：「断言要读子进程产出文件的门，spawn 必须绕开缓存（走 `spawnNC`）」+ 覆盖面下限（走缓存的 + 绕开的都要数）。
   ⚠️ 这不是"为了让门变绿而放宽阈值"，是**期望行为本身变了**（我们修的是一个正确性缺陷）；理由、证据、替换后的更强判据都写在腿里 ✔。
