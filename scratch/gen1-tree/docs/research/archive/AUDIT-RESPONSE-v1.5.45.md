## 3. 座位偏置（本轮新发现，建议优先级最高）

### 3-1 [实测] 现象

同一种子族、5 席全部加载**同一个**冠军包、temp 0.15，200 局：

```
long  自对局各座位夺冠率： 0号 81%   1号 4%   2号 3%   3号 5%   4号 7%   平 1%
multi 自对局各座位夺冠率： 0号 59%   1号 6%   2号 6%   3号 13%  4号 10%  平 7%
```

对称策略的期望是每座 20%。**这不是噪声，是 3~4 倍的系统性偏置。**
而 `resolve.js:37 turnOrder()` 每回合都会轮转行动起点（`start = (round-1) % n`），
所以**不是"先手出招"这种回合内优势**造成的。

### 3-2 [实测 代码事实 + 推断] 机制候选

```js
// js/train/policy.js  function oppSlots(state, pid)
a.sort(function (x, y) { const d = state.p[x].hp - state.p[y].hp; return d !== 0 ? d : x - y; });
```

并列时按 **pid 升序**。开局全员血量相同 ⇒ 对 1~4 号座来说，它们的"槽位 0"**永远是 0 号座**；
而 0 号座自己看别人时槽位 0 是 1 号座。
⇒ **特征向量里存在一个与实力无关的"座位身份泄漏"**：0 号座在所有对手的网络输入里占据同一个固定位置。
值网络是位置相关的（`FEAT_S` 里 4 个槽 × 10 维是硬编码下标），完全可以学出"槽位 0 的人该怎么对待"。

**[推断]** 81% 的偏置很可能就是这么来的。这条**一枪就能验**：把并列改成与 pid 无关（按 `(x - turnStart + n) % n` 或 `state.rng` 决定），
重跑同一批种子；若座位夺冠率塌回 ~20%，因果确认。

### 3-3 为什么这条比"打断环"更该先修

它污染的是**一整类指标的地基**：

- `champ-audit` 的 **B（自对局伤害/局）、零伤害率、平局率、回合数**；
- `evo.js` 的 `mirrorHealth`（"5 座同一冠军"的健康门槛）；
- **D 反弹墙 / C 盾/局** 里 `seat = g % N` 的轮座虽然轮了，但每个冠军席位的**对手特征排布**并不对称；
- 以及**我自己上轮的 D 项对照**（"0 号座滚环 75% vs 0 号座当冠军 80%"）——那 80% 就是座位偏置本身，
  不是策略强度。**这条我要主动更正**：正确的说法是"滚环这个一行代码的策略，在长程里几乎不输给从同一座位出发的冠军策略"。

而且这是他们**自己记录过的教训形态**：`np-test` 里有 `L7 rankOf 不得有座位偏置（并列时不许按 pid 升序）`。
同一个 bug 类在 `rankOf` 里被修了，在 `oppSlots` 里还活着。

⇒ **[建议] 给 `L7` 补一条守门**：所有"对玩家列表排序"的地方，并列键不得是 pid（可扫 `sort(` 调用点 + 断言比较器不含裸 `x - y` 于 pid 位），
或更直接：**加一条统计守门**——同策略自对局 200 局，各座位夺冠率极差 > 25pt 就红。

### 3-4 [实测] v1.5.46 的修复**没有让症状消失**，而 D50 已经绿了

`e563e54 v1.5.46 修座位偏置（复核 §3，最高优先级）：oppSlots 并列不再按 pid 升序` —— 修法正确（并列键改成按回合行动起点轮转），
指纹已重记（`be74b3d3`，与包内一致），`np-test 98/98`。**但我重跑了同一批种子：**

```
             0号   1号  2号  3号  4号   极差
long  修前   81%   4%   3%   5%   7%    78pt
long  修后   76%   7%   5%   5%   8%    72pt      ← 基本没动
multi 修前   59%   6%   6%  13%  10%    53pt
```

**① 我上轮的机制假设被证伪为"唯一原因"**：`oppSlots` 的 pid 并列键确实是一个真实的座位身份泄漏（改掉它是对的），

⇒ **"偏置在引擎还是在策略"这个问题尚未判定**，不能说"脚本没偏置所以是策略的问题"。
要判：需要一个**能稳定分出胜负**的对称策略做对照（例如带蓄能+大雷的脚本），这一枪值得他们开。

**③ D50 是源码检查，不是行为检查。** 它的三条断言是：

这正是本项目 `L1`（"断言不得是恒真式/近乎恒真"）想防的那一类，只是这次的形态是**"断言锁源码而非行为"**。

## 4. "打断环"课题：这轮的三条判语

### 4-1 强迫探索把一个**假相关**写进了策略

训练池里 `ringspam` 必须先攒 3 ジ ⇒ **第一次开环永远落在第 4 回合**；而特征里有 `state.round / maxRounds`。
两者完全共线，网络于是拟合更便宜的那个。三条实测支撑：

- 187 次出手里 **160 次在第 4 回合**；
- 那 160 次在决策时点上**根本没有可见的滚环者**（同步落子、行动前决策 ⇒ 第 4 回合看不到这回合才开的环）；
- 判别场（1 滚环 + 3 快攻）里小雷 **0 次** ⇒ 有真实战斗压力就消失。

⇒ 结论：**"0 次出手"和"187 次但不瞄人"是同一个病的两个阶段**，问题不在探索量，在于**探索注入的时刻与回合数共线**。
只要还从"强迫出手"这条路走，就必须同时**随机化环流对手的开环节拍**，否则换个奖励形状还会重演。

### 4-2 验收场地结构上测不到它声称要测的东西

`ringWallProbe` 的场地是 `pid === seat ? policy : wall` ⇒ **1 冠军 + 4 席全滚环**。
那种场地下，把小雷砸向**任意**对手都自动算"砸中滚环者"、自动算"可归因作废"。
所以 `自然小雷 25 / 可归因作废 25` 这两个数**不可能失败**——它测的是"有没有出手"，不是"会不会瞄准"。
（`byPid` 那步修得对，但"归因到我"≠"我打对了人"。）

⇒ **[建议] 验收换成判别场 + 一条能失败的反证**：
1. 场地 = `1 滚环 + 3 个不滚环的对手 + 1 冠军`，判据 = **砸向滚环者的比例 > 50%**（随机是 25%；现值 0%）；
2. **把场上唯一的滚环者换成不滚环，小雷出手数必须显著下降**——这条现在必然失败（它看的是回合数），
   所以它才是真正区分"读状态"与"记节拍"的测试；
3. 模式必须含 **long**（multi 里滚环只有 10% 胜率，根本不值得打断）。

### 4-3 顺带：产出仪式冠军那条臂，把 `ringspam` 加权到了 4/18

[实测] 已回退的 `v7r2-35` 的 meta：`opps` 共 18 项，其中 **`ringspam` 出现 4 次**
（`...,ringspam,reflectspam,guardspam,ringspam,ringspam,ringspam`）。
现上线的 `v7wall-31` 则是 **15 项、无重复、`ringspam` 仅 1 次**。

[推断] 把同一种对手加权 4 倍，会让"第 4 回合有人开环"这件事在训练分布里更常成立 ⇒ **直接加重 §4-1 的共线**，
也就更容易学出"到点播小雷"而不是"看到环才播"。
⇒ 请确认这个加权是有意（为了逼出动作）还是拼接产生的重复；若是有意，**它和强迫探索是同一类干预，同样需要"开环节拍随机化"来配对**，
否则下一次做环相关实验还会掉进同一个坑。

## 5. 如果只做三件事

1. **修 `oppSlots` 的并列键 + 加一条座位偏置守门**（§3）。它同时影响一整类指标的可信度，
   而且是他们自己 L7 教训的复现——**优先级高于"打断环"本身**。
2. **把"打断环"的验收换成判别场 + 换人反证，并加 long 模式**（§4-2）。
   在此之前不要再接收任何"会打断环"的冠军——现在的探针会让任何"早期齐射"都通过。
3. **正面处理长程的滚环 exploit**（现值 75% 夺冠、0 伤害）。可选路子里我认为最便宜的是：
   让"复利经济"在长程里**有代价**或**有可见的早期信号**——例如把 `ringStreak` 加进每对手槽位（+5 维，
   他们自己在 `PLAN-RING-FEATURE.md` 里也承认"那时也只需加已有的 ringStreak 信息"），
   或者让滚环者的高 ep 更容易被"大雷前摇"这类既有特征捕捉。
   注意这与 §4-1 不冲突：**给信息 ≠ 强迫动作**，强迫才会造出仪式。
