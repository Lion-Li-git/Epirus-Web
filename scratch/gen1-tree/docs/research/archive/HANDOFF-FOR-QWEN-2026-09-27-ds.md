## 3. 今天的实测结果链（都可复跑，命令见 §10）

### 3.1 大雷（真正的落雷，5ep）是**瞬态**性状，不是"训练就能有"

- **21 个种子**（同配置：713 热启动 · 无旋钮 · 1200 代 · `3 8 8`）⇒ **只有 1 粒真学会**（seed31：multi 0.588 / long 1.488 次每局）⇒ **≈5%**（95% 上界 ~28%）。
- **续训必掉**：从学会者（`win-Lctl`）再训 1200 代，三臂（纯续训 / spend 两键 / spend·换种子）**全部掉回 ~0**。
- 机制：适应度是 **3 局对局的即时收益**，而 5ep 的机会成本是"3~5 回合不还手" ⇒ **选择压力方向与它相反**。

### 3.2 `Ldemo` 上槽（今天唯一的产品变更）

- **"三合一"首次出粒**：宽 ✔（净兑现 3.33/3.18 ≥ 现役−0.10）· 闭环 ✔（花珠率 60.7%、得珠 168）· 抗克 ✔（最克 24/26 ≤ 现役 38/35）。
- **5P 产品口径**（同 seed 77000 · 同池 14950 组合 × 4 局 · **各 59,800 局**）：**42.5% vs 37.4%（+5.1pt）**；含深经济对手 39.9% vs 35.4%。
- 五道门 `exit 0` 无阻断 · 座位极差 **5.4pt（历史最好）** · skill report 常用却亏损**无**。
- ⚠️ 已知顾虑（照实记账）：**反弹墙主动伤害 2.00/局（在位包 21.00）** · 1 个种子 1 条路径 · **不玩大雷**。

### 3.3 "闭环判据"与"贵卡"的张力（**这个假设已被实测否掉**）

- 原假设：`花珠率 ≥0.5` 与"会用贵卡"方向相反。**实测否掉**：`Lctl` 的珠子**不是花掉而是过期烂掉**

- ⇒ 闭环分形态版 **保留在库里但不启用**（门 D169 把反例钉死，`probe-pool-frontier` 仍走 `isClosed`）。

## 5. 红线包 META 的损坏与修复（今天最"脏"的一件，已结）

- **现象**：`promote-champion` 读**线上槽**必崩（`SyntaxError: Expected double-quoted property name ... position 311`）。
- **两个独立成因**：① 工具用**懒惰正则** `\{[\s\S]*?\}` 抽 JSON ⇒ 遇嵌套（v1.5.226 的 `recipe.env`）就在第一个 `}` 截断；
  ② **两个线上槽的 META 真的坏了** —— `js/bundled-champion{,-3p}.js` **都**少了 `fingerprintRefresh` 的起始引号（**全仓无代码写该键** ⇒ 当初手改丢的）。
- **修法**：`audit-lib` 新增**唯一一份** `extractJsonObject(src, marker, avoid)` 与 `parseMetaTolerant(json, label)`
  （严格优先；只修"缺起始引号"这一种；**合法输入零改动**；修不动就抛原来的错；修成功则**响亮指名**）；
  两个红线包各 **+2 字节**（给该键补开/闭引号）—— **权重槽 sha1 逐位不变**，反向比对证明只改了那两处。门 **D168**（含**直接读两个真线上槽**防回归）。
- ⚠️ **教训**：我第一版用 `readFileSync → split("\r\n") → 写回`，而文件是**混合行尾** ⇒ 一次写回改了 **10 万+ 字节**，
  **而"权重哈希没变"完全看不出来**。已回滚改**纯字节替换**（`Buffer.indexOf` + `concat`）。
  ⇒ 规矩：**改已交付产物必须按字节操作；"权重哈希没变"证明不了"文件没被动"。**

## 6. 根因：**"闸放行 ≠ 线接通"**（今天最有复用价值的一条）

- **现象**：`costlyW` 取 0 / 0.05 / 0.2，三族实验（各 2 种子 × 1200 代；长程场；从"会出贵卡"的 `win-Lctl` 出发）
  跑出**逐字节相同的当选权重**，连 `bestFit` 都一模一样。
- **根因**：`tools/train-3p.mjs` 对 econ 旋钮是**逐个键各写一块**下达代码（`bigtChainW` 一块、`fitTailW` 一块…），
  **没有名单驱动的通用派发** ⇒ 我在 `econ-env` 两处 + `CLI_ECON_REWARD_KEYS` 登记的名字**通过了黑键闸、却从没送给引擎**。
- **修复**（v1.5.262）：名单驱动下达 + **逐键回执比对**（不一致 `exit 7`），位置在 `T = sb.window.EpirusTrainer` **之后**。
- **新门 D174** 钉五条，其中一条**禁止 `typeof <常量> !== 'undefined'` 这类**静默守卫** ——
  我在这条路上被它坑两次：它把"接线 bug"变成"静默无效果"。**要么硬 `exit 7`，要么别写。**

## 9. 今天的踩坑清单（可直接当规矩用）

1. **`typeof x !== 'undefined'` 当守卫** ⇒ 把"接线 bug"变成"静默无效果"（我栽两次）。**要么 `exit 7`，要么别写。**
2. **脚本拼代码**（模板字符串里嵌反引号、`node -e` 引号地狱）⇒ 一律**把替换文本放文件里** + 改完必 `node --check`。
3. **改已交付产物要按字节**（§5 的 10 万字节事故）。
4. **长任务输出绝不接 `tail`/`head`/`grep`**（会缓冲/截断，看不到进度）；写文件再 grep。
5. **发长任务前先读工具的组合/代数枚举 + 先标定秒数**（我用 `eval-5p 60 --pool=all` = 179 万局 ≈ 2.8 小时，被自己的 timeout 掐死在 3%）。
6. **先量剂量，再谈剂量大小**（§4.2：四处 fit 逐位相同才查出"线没接"）。
7. **一个"静默什么都不做"的机制比没有更坏** ⇒ 未通过行为验证就**回退**（瞬态快照钩子、第一版通用派发都是这么处理的）。
