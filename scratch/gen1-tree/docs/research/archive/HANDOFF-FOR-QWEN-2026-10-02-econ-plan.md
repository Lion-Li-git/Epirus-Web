## §1 用户点名的那一问：覆盖熵当年为什么排除ジ（**原文 + 我的更正**）

`js/train/evo.js:1614-1623` 的原文（v1.5.8，**用户裁定**）：

```
/* ===== 技能覆盖熵（v1.5.8：**只统计非ジ动作**，用户裁定）=====
 * 为什么要排除ジ：熵是按**动作分布**算的，而"攒钱/等待"就是反复出ジ ⇒ 攒钱会把熵压到极低
 * ⇒ 熵奖励其实在**惩罚攒钱**，与 ep 攒钱奖励（stock 项）互相打架。
 * 实测（v1.5.7 的奖励 A/B，同一引擎、只差奖励设置）把熵奖励从 0 提到 0.06：
 *   **最高 ep 44.8→12.8、ep≥3 决策占比 34.3%→5.8%**（出手种类 13.7→14.8 确实变广）。
 * ジ 是"这一回合不做事"的基线动作，把它算进"广度"是在量错东西。
 * 归一化分母也要**排除ジ**（否则分母里那个ジ会让熵永远到不了 1）。
 * 反证（np-test D17）：把 `k === R.SK.JI` 的排除去掉，D17 立刻红。 */
```

**结论（这就是用户要的那一问的答案）**：排除ジ**不是**为了压攒钱，**恰恰是为了不压攒钱** ——
v1.5.7 量到"加了熵奖励 ⇒ 最高 ep 44.8→12.8、ep≥3 占比 34.3%→5.8%"（攒钱被熵惩罚压没了），
v1.5.8 的修法就是**把ジ从熵的分布与分母里请出去**。

⇒ ⛔ **因此我在 v1.5.320 §2 / v1.5.321 §3 / v1.5.324 里写的
"覆盖熵只统计非ジ动作 ⇒ **在惩罚攒钱**"，方向是反的。** 这是我今天的第四次自我更正，

## §3 于是有一个**必须先分开的分叉**（这一节是本文件的核心）

"为什么攒不到"至少有两条互斥的解释，**它们的修法完全相反**：

- **(W) 世界问题**：在**训练对手分布**里，"花掉"确实是更优策略（训练世界里没有值得为之攒钱的威胁）
  ⇒ 那么让它多攒只会**压低胜率**，要改的是**对手分布/装配**（把"值得攒钱"的世界造进训练池），**不是奖励**。
- **(R) 奖励问题**：`DIV_K=6` + 熵择优在"同胜率"时系统性偏好更花的个体
  ⇒ 那么要改的是**那条择优/权重的口径**。

⚠️ **两者的判词会完全不同**，所以**不许跳过诊断直接改权重**。诊断方案（**零训练、只读/只跑现成量具**）：

| 步 | 做什么 | 判据（跑前写死） |
|---|---|---|
| **D1** | 在**训练用的对手池**（`server/opp-pool.mjs` 的 `OPP_DEFAULT`）上，各跑一次**现役冠军**与**"会攒钱"的对照**（如 `pickDeepSaver` / 探针 `saver`），量**原生** `Δ1st` | 若"会攒"在训练池上**显著为负** ⇒ **(W) 成立**，奖励不是首因 |
| **D2** | 量 `DIV_W` 的**实际剂量**：把 `divW` 抬到 0 与 0.06 两档跑**同一种子**的短训练，看产物 `effSkills` 与**决策时 ep 均值**的差 | 若 `divW=0` 与 `0.06` 的 ep 均值差在噪声内 ⇒ **(R) 不成立**（熵不是成因） |
| **D3** | 只读：从现役产物的自对局里取"**同胜率容差带内**被择优淘汰的候选"，看落选者与胜出者的 `ep` 均值/`effSkills` | 若落选者系统性地"更会攒、熵更低" ⇒ **(R) 成立** |

## §4 方案 A：**身份维**（治"转移伤害"的编码混叠）—— 单卡、好归因，建议**先做**

**问题**（v1.5.320 已定）：`转移伤害`（`TRANSFER`）与 `挑衅`（`TAUNT`）在**动作编码**上**混叠**（逐字相同的现象：合法 0.74→0.75、入围 0.0%）。
③ 又给了它价签：`rich` **+7.3 ±2.8**（付得起时是正的）⇒ **它值得被分开**。

**做法（一个自由量）**：给动作/状态面加一条**能区分这两张卡**的通道（v7 已有 `FEAT_A=22` 的通道先例），**只加身份、不改任何权重**。

**预注册判据**：
1. **必要条件**：在**同一装配、同种子**下，加维后 `转移伤害` 与 `挑衅` 的**入围率不再逐字相同**（当前是逐字相同，这是可机检的签名）；
2. **不许伤到现有**：整轮门禁四道全绿；两槽冠军的**行为构成**（`tools/behavior-profile.mjs`）与 `effSkills` **无明显漂移**；
3. **上限不要吹**：`rich` 的 +7.3 是**方向**（工具头注：每回合持续垫 + 补贴对基线臂也生效，光垫钱 **+38~42pt**）⇒ **不许**写"加维能涨 7pt"；
4. **失败长什么样**：若入围率仍逐字相同 ⇒ 说明混叠**不在动作面**而在别处（那就回来查 `legalActions` 的构造，而不是继续加维）。

## §5 方案 B：**经济口径**（治大雷/摄魂的"够得着"）—— 必须**等 §3 的诊断**

**前置**：§3 的 D1/D2/D3 必须先给出 (W) 还是 (R)。

- **若判 (W)**（花掉在训练世界里更优）：**不要动奖励**。改的是**训练对手分布/装配** ——
  而这里正好接回 `P-econ-exam` 那条线：**考场里唯一能区分的轴是"防 vs 打"**（§E226），
  经济轴造不出来（v1.5.313/314）⇒ **先得有一个"值得攒钱"的世界**，才谈得上让它学攒钱。
  ⚠️ 这条与"③ 说三招值得用"**不矛盾**：③ 量的是**付得起时这张卡的价值**，(W) 说的是**在原生世界里攒钱到付得起这件事本身的代价**。
- **若判 (R)**（熵择优在偏好更花的个体）：**只动那一处口径**，第一刀建议**极小**：
  把**胜率容差带内的择优键**从"覆盖熵最高"改成**中性**（或把 `DIV_K` 从 6 往下调一档），
  **一次只动一个**、并**先验剂量**（v1.5.260/261 的教训：`costlyW` 三档逐字节相同 = 剂量恒 0，
  ⇒ 任何权重类改动**必须先报"开火计数"**，否则你可能在改一个从不生效的数）。

**预注册判据（两个方向都必须先写死）**：
1. **主判据**：改动后**决策时 ep 均值**是否**真的抬起来**（现役 `packT` = **2.0**）—— 这是"够得着"的直接读数；
2. **不许换来胜率**：`1st` 不得**显著下降**（显著 = `dm + dci < 0`）；若抬了 ep 而胜率显著掉 ⇒ 判"**攒钱不划算**"⇒ 回到 (W)；
3. **不许把三招当收益吹**：`rich` 的 `Δ1st` 只作方向；产品侧要不要让三招更常见，是**用户的产品偏好**，不由本方案背书；
4. **一次一个自由量**，且每次改动都要带**剂量回执**（开火计数非零才算真的改了）。
