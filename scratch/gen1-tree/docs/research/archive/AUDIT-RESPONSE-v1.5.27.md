## 3. 新冠军到底多强（我的独立测量）

### 3-1 关键退化：反弹墙从 85% → 0%，机制是**激光剑这条线整个丢了**

它们体检表的 D 列（长程 4 座纯反弹）从 85% 掉到 0%。我一开始怀疑是指标口径，于是**不借它们的工具**、
自己搭同一种场地（1 席冠军 + 4 席纯反弹，60 局轮座）定点测：

```
[long]  新 v7      终局HP 0.00  受伤 5.00/局  主动伤害 0.00  激光剑命中 0.00  枪命中 0.00  胜0% 和100%
[long]  旧 eco-34  终局HP 1.13  受伤 3.87/局  主动伤害 9.83  激光剑命中 3.97  枪命中 0.00  胜40% 和45%
[multi] 新 v7      终局HP 1.03  受伤 1.97/局  主动伤害 0.00  激光剑命中 0.00  枪命中 0.00  胜0% 和100%
[multi] 旧 eco-34  终局HP 1.90  受伤 1.10/局  主动伤害 5.23  激光剑命中 1.70  枪命中 0.00  胜35% 和62%
```

**读法**：旧冠军面对 4 面反弹墙，每局用**激光剑**（唯一穿反弹的攻击）命中约 4 次、打出 9.8 点伤害；
新冠军**一枪未发**（主动伤害 0.00），在长程里被终局收缩活活耗死（终局 HP 0.00）。
两边都**没有**"枪被自己反弹回来"的自伤（`被自己反弹 0.00/局`），所以不是自伤，是**彻底不出手**。

⇒ **[实测] 这是一条真实的能力退化，不是指标口径问题。** 而它恰好被 G 列掩盖了：
G 从 4.15 涨到 6.55（覆盖变宽），但**丢掉的是那一张能穿反弹的卡**。

### 3-2 与上轮同口径的场地扫描（80 局/格，种子相同）

| multi | 新 v7press-36 | 上轮 eco-34 |
|---|---|---|
| 农夫场 p=0 | 胜 0% 和 100%，伤害 1.0/局 | 胜 0% 和 100%，伤害 1.0/局 |
| p=0.05 | 胜 39% 和 56% | 胜 46% 和 51% |
| p=0.2 | 胜 59% | 胜 69% |
| p=0.6 | 胜 29% 负 71% | 胜 29% 负 70% |
| p=1 | 胜 14% 和 56% | 胜 13% 和 70% |
| 混合场（4 风格脚本） | **胜 31%** 和 4%，非ジ有效技能 **6.65** | 胜 29%，非ジ有效技能 ≈2.0 |

**[实测] 三点**：① 对"不还手"的对手，新旧**一模一样**地不会收尾；② 交互场里新冠军略强（+2pt，80 局下仍在噪声内）；
③ **覆盖的改善是真的、而且是这一版最大的实质进步**（2.0 → 6.65）。

### 3-3 1v1（真·2P 冠军，200 局）——这一侧没问题

```
玩家只攒钱   胜  0% 负 100%  回合 8.2      玩家只枪     胜  0% 负 100%  回合 15.9
玩家只防御   胜  0% 负 100%  回合 8.4      玩家只激光剑  胜 18% 负  82%  回合 7.4
```

**多人冠军的毛病没有传染到 2P 冠军**——这点对用户体验很关键，也说明问题出在多人训练信号，不在引擎。

## 4. 本轮新发现（按可执行性排序）

### 4-1 ⚠️ 冠军对"不还手"的场仍然 0% 收尾，且这版**多了一条 0% 的墙**

农夫场新旧逐位相同（0% 胜 / 100% 和 / 1.0 伤害），而反弹墙从 85% 掉到 0%。
上轮我给的那条"让摆墙不进攻至少被判负而不是判平"（`SUDDEN_DEATH=100` 在 multi/standard 上限 60 面前永不触发）
**仍未处理**——`rules.js` 里 multi 的 `maxRounds` 还是 60。
⇒ 建议：要么把 multi 的收缩起点降到上限以内，要么把"终局仍全员存活"直接判为负而不是平。

### 4-2 **[实测] G 列会被"变宽但丢关键卡"骗**——指标设计缺陷

`G 有效技能数` 只看出手分布的熵，**不看哪张卡**。这一版就是活例：G 从 4.15 涨到 6.55 的同时，
把唯一能穿反弹的激光剑用到 0。
⇒ 建议二选一（都很便宜）：
 (a) G 改成**按落地伤害加权**的有效技能数（`Σ p_k·dmg_k` 型），关键穿透卡归零时 G 必须掉；
 (b) 保留 G，另加一条硬门槛：**每张"能穿反弹/穿防御"的攻击卡（激光剑、坦克、狙击、电磁炮、大雷）
     在自对局里的落地命中数 > 0**，为 0 就阻断。这条和它们已有的"30 技能穷举归类"是同一风格。

### 4-3 **[实测] `battle-test` 现在是概率性失败的交付门**

我连跑 **5 次：1 次 `BATTLE FAILED`、4 次 `BATTLE OK`**（全部 0 JS 错误，所以不是崩，是**没在时限内跑到终局**）。
而且成功的那几次本身也在报长局——`P0 能持续出招 [出招 54 回合，其中无攻击技可打 33 回合]`、
`[出招 72 回合，其中无攻击技可打 38 回合]` ⇒ **[推断] 长局对峙是一个分布的尾部，不是偶发**，
这条门今后会长期随机红。失败那次的日志尾部是第 48→58 回合的**确定性 2-周期对峙**：

```
第48回合 玩家1=【枪→玩家4】 玩家4=【枪→玩家1】 → 双方攻击相抵，均无效
第49回合 玩家1=【ジ】      玩家4=【ジ】
第50回合 玩家1=【枪→玩家4】 玩家4=【枪→玩家1】 → 相抵 …（一直重复到上限）
```

[推断] 成因：双方都"互为目标 + 同优先级同技能"⇒ 每回合必相抵，而谁都不换目标/不换招 ⇒ 只能靠回合上限收场。
这与 §4-1 是同一个病（不会打破对称），只是换了个表现。
⇒ 建议：(i) 把这条对峙做成**引擎级守门**（N 人局里"连续 K 回合全员动作完全相同"必须红），
 (ii) `battle-test` 的等待改成"直到 `state.over` 或回合上限"而不是固定墙钟，否则这条门会长期随机红。

### 4-4 **[实测] D29 是"逐条点名"，不是"整表穷举"——同类漂移仍无人守**

我用上轮同一批注入复测：

| 注入 | 上轮 | 本轮 |
|---|---|---|
| 雷系集合删电磁炮 / 小雷豁免名单加八卦阵 / 大雷花费 / 判定 0.5 / 全息花费 / 爆头 3→1 | **只有指纹在响** | ✅ 全部被 **D29** 抓住（含"2 胜 1 负 ⇒ 不爆头"这条正好钉住那个"3"） |
| **坦克花费 2→1** | — | ❌ **仍然只有指纹在响** |
| **狙击枪不再破防御** | — | ❌ **仍然只有指纹在响** |
| 蓄能不枚举两珠 / enemy 不枚举目标 / `setFeatMask` 静默失效（我新造的） | — | ✅ 全部被 **D33** 抓住 |

⇒ **修法建议（一次写完、永久免疫，比继续点名便宜）**：
- **费用**：`for (const s of R.skills)` 断言"`ep = cost-1` 必须 `insufficient`、`ep = cost` 必须 `ok`" —— 30 张卡 60 条断言，一张都不漏；
- **穿透**：把"攻击卡 × 防御族"做成**伤害矩阵真值表**（`pierce.defense/reflect/transfer` 三轴 × 8 种架势），
  逐格断言挡/穿/弹回，而不是只测激光剑与枪这两条被讨论过的边。

### 4-5 **[实测] "目标进网络"对 `target:'other'` 的卡是例外**

我直接调 `P.candidatesFor` 数候选（5 人局、全员 9 ジ）：

```
gun/snipe/armor/mirror/dualGun  → 4 个候选 [1,2,3,4]   ✅ 目标进网络
charge                           → 2 个候选（elec/boom） ✅ 珠类型进网络
holo（全息屏障，target='other'） → 1 个候选 [null]      ⚠️ 目标不进网络
mine/self 类                     → 1 个候选 [null]      ✅ 本就不需要目标
```

`candidatesFor` 只对 `def.target === 'enemy'` 展开，而全息屏障是 `'other'` ⇒ 落进 else 分支。
影响小（这张卡实测 0 次使用），但**`shippedAs` 里"目标真的进输入"这句话的范围应当注明不含全息屏障**，
否则下一个人会以为它覆盖了所有可选目标的卡。

### 4-6 **[实测] 2P 侧的 AI 标签仍然无条件报"2人冠军"**

多人侧已经修好了：`aiInfo()` 在冠军包缺失/不兼容时返回 `'脚本·多人强档（冠军包缺失/不兼容，已回退）'`。
但 2P 侧是 `ui.js:359`：`if (!B.multi) return { source: B.diff === 'hard' ? '2人冠军' : '脚本', ... }`
——**不看 `Champ.store.load()` 的结果**。而 `chooseAI`（`:553-564`）在 load 返回 null 时回退到 `Bots.pickAdaptive`。
⇒ 潜在：内置 2P 包不兼容时，页面会在用脚本兜底的同时告诉玩家"对手=2人冠军"。
（本地旧包被清除这条它们已经处理得好：`trainer.js:22` 会 `removeItem` 且 `ui.js:1156` 有 alert 提示。）
⇒ 修法照抄多人侧那一句即可，5 分钟。

### 4-7 **[实测] 上轮 §5-6 未修**

`resolve.js:197` 的 `EPIRUS_FIREWEAK_PERSIST` 仍在游戏核心层，而 `rules-fingerprint.mjs` 不读 env ⇒
"改行为必改指纹"的保证对 env 门控分支失效。默认关，所以线上行为正确；属卫生问题，不紧急。
