# 结果：形状硬约束（`--arenaShapeCap=0.40`）首测（DS · 2026-10-30）

> 预登记：用户裁定「必须先有多样性再考虑强度」；假设 = 把"非ジ单卡 ≤40%"做成**词典序第一关键字**（子代过线直接不可接受），
> 在可行域里再比 clean。默认 0 = 关、逐字不变。3 粒种子（s7/s11/s13，6k 局、分层场、temp 0.15）+ CLI 40 局/桌形、三温度取最佳。

## 二、按预登记四条判：**全不过**

| 判据 | 要求 | 实测 | 判 |
|---|---|---|---|
| ① 形状 | 3/3 单卡 ≤40% | 训练期 3/3 ✔，**CLI 只有 1/3**（40.1 / 81.4 / 37.5） | **✘**（按报告口径） |
| ② 强度 | clean 中位 ≥0.05 | **−0.010** | ✘ |
| ③ 不崩 | 无一粒 < −0.10 | s7 **−0.287** | ✘ |
| ④ 高人数 | 8P ≥ v7−3pt 至少 2/3 | s11 25% ✔，s7/s13 5% | ✘ |

⇒ **硬卡 40% 在当前实现下不成立**：约束在"训练期测量"上生效、在"报告期测量"上失效，且代价是 2/3 种子强度掉。

## 三、三条机制结论（比判据值钱）

**1. 约束被"测量相位 × 温度"骗过去了。** 约束读的是 **frozen 相位、temp=0.15、88 局**；报告读的是 **holdout 相位、三温度取最佳**。
s11 在训练期 36.2%、在报告期（t=0.05）**81.4%** —— 同一粒权重，只因采样更锐（0.05 比 0.15 尖）就从"线内"变成"单卡"。
⇒ 形状约束必须**在与报告相同的相位/温度上测**（至少 t=0.05 与 0.15 各测一次、取更严），否则它只是一张训练期的合格证。

**2. "单卡 ≤40%"本身可被"换一种单卡"绕过。** s7 的终态是 `reflect 40% + ji 60%`：单卡过线，行为仍是反射墙；
而 s11 的 CLI 是 `tank 81%`：在训练期它靠 ji 稀释到 36%，报告期温度一锐就露馅。
⇒ 只卡"非ジ最大单卡"不够，必须同时卡**防御占比 / ji 占比 / 技能族分布**（行为桶）。

**3. 形状优先的代价是真金白银的，但 s11 给了反例。** s7/s13 的 clean 掉到 −0.287 / −0.010；
而 **s11 在单卡 81% 的情况下拿到 clean 0.138、8P 25% / 10P 20%** —— 这是迄今最好的高人数读数。
⇒ "先形状后强度"不能一刀切硬卡；**要么按行为桶分桶保留（MAP-Elites），要么两阶段**（前期松 cap 只防退化、后期收紧）。

## 四、下一版怎么改（预登记前先写清）

1. **约束测在报告相位**：`verifyChild` 里对同一子代在 **t=0.05 与 0.15** 各算一次 `maxCard`，取更严；
2. **多键约束**：`maxCard ≤0.40` **且** 防御占比 ≤0.35 **且** ji 占比 ≤0.65（三条同时），或改成"行为桶"（族 × 攻防比）；
3. **两阶段/分桶**：前 1/3 预算只按形状筛（不强化），后 2/3 加 clean 且形状作硬下限——避免"一开始就被 cap 饿死"；
4. **报告口径**：任何形状读数必须写"相位 + 温度"；跨相位不可比（本次就是被这个坑的）。

## 五、一句话

**"先多样"这个方向成立，但"卡非ジ单卡 40%"这一条实现不成立**：它测错了相位、可被 ji 稀释绕过、且代价不均。
下一版把约束改成"报告相位 + 多键/行为桶"，再判一次。
