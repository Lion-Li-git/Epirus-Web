## 二、建议但**未做**（要不要做请你定；每条都附代价）

1. **D82（24 小时内落盘的 `.bak` 必须在 CHANGELOG 被点名）**：它的结果取决于**运行时钟 + 文件 mtime** ⇒
   同一份代码今天跑绿、明天可能红；它测的是"记账有没有做"而不是代码对不对（§E499 我就被它红过一次）。
   建议：**降级为警告**（打印但不进 `ok()`），或把它挪进"只在 `--night` 之类的显式模式下才判"。
   代价：改动落在 meta 组 ⇒ 我建议单独一笔提交，并在 commit 里写清"这是从红灯降为记账"。
2. **`docs/artifacts/` 里仍有 186 个文件被跟踪**（磁盘 3845 个）：那里按仓规本该 gitignore。
   建议照第 3 条同样的办法做**引用扫描**后再逐个取消跟踪；**不要一次性 `git rm --cached -r`**（有些产物是门/工具的输入，
   例如测试里就点名读 `champ-agent-*.bak`）。
3. **244 个门号的"变异测试"**（Claude 的建议，我赞成）：对每个门号**把 bug 加回去**，仍然不红的记为**废门**候选。
   代价与做法：需要**逐门知道它防的是什么**（门名/注释里大多写了）⇒ 不是纯机械可做；
   可行的折中是**分三批**：先做 `meta`+`ship`（约 50 门，改一行就能反证的），再做 `train`，`probe`/`engine` 放最后。
   产出应是一张表：`门号 · 加了什么 bug · 反证结果 · 判`.
4. **`README`/`CHANGELOG` 的体量**（8024 行 / 91 条方法论）：不是错，但建议**按版本分段折叠**（或把已发布版本的细节挪去 `docs/research/archive/`），
   免得每个 agent 每轮都要读全量。

## 三、一条通用判据（我加在第 89 条旁边的经验）

**"门禁是 agent 的记事本"这个错，根在"没有跨会话记忆"**：所以新学的教训**先写 METHODOLOGY**，
只有当它能被**行为**验证时**才**升级成门。
反过来说：**任何一条门，如果删掉被它检查的那行文字/那个文件而游戏逻辑不变，它就不是行为门。**
