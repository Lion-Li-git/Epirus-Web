规则说明 Epirus

这一页写的是这个程序实际跑的那套规则 —— 下面的桌子参数、技能表与难度档都是本页现读引擎常量渲染的，不是文档摘录。

规则文本的出处：本仓库 docs/RULES-2P.md（2 人，冻结在 v1.0.0）与 docs/RULES-NP.md（多人 N 人裁定清单，含 N1~N27）。 上游原始规则：国际拍手游戏规则制定协会 · 规则文档 v2.1.0 —— Lion-LiHaoyi/Epirus（本页实现的是它的可运行子集，凡两者不一致，以本仓库的裁定清单与引擎为准）。

⚠ 引擎脚本没加载成功 ⇒ 下面三张表会空。本页与对局页同级，直接用 http(s) 或 file:// 打开都可以。

一、桌子：人数 × 血量是两根正交的轴N26 / N24

人数 2~5 与血量 3 / 4 / 5 各自是一根轴，上面这张表就是把两根轴钉在一起的那份配置（本页逐字段现读 EpirusRules.MODES，"回合硬上限"和"收缩起点"两格里空着的走全局 MAX_ROUNDS / SUDDEN_DEATH，读法与引擎一致）。 4 血只是"多一格血"，不是第四套规则：除血量与显示名外逐字段与 3 血多人格同值，这条设计决定由门禁 D226①c~①f 逐字段钉着，以后谁想给 4 血单配一套门槛，必须同时改判据（= 再过一次裁定）。 2 人局与 3 人以上共用同一套结算：优先级、相抵、目标口径同规，只是"第三方"相关的分支天然不触发。

这张表读的是模式配置；对局页另有一个「终局收缩」输入框（缺省 100，会存进浏览器本机），每次建新局都拿它覆盖模式自带的起点（ui.js:110 把 sdOpts() 喂给 createState）。两张数要分开看： standard（2 人 · 3 血）配置里就是全局 100，而它的硬上限是 60 ⇒ 实际进不了收缩，长局由硬上限判； 多人桌配置里自带 45（3/4 血那两格），但页面缺省的 100 会盖掉它 ⇒ 你在浏览器里也几乎看不到收缩，除非把那格改成 45。 考卷与门禁量的是模式自己的 45。长程那一格反过来：配置走全局 100、安全网 140，所以收缩正是它的主要终局。 （N25 把收缩从 "long 专属" 升级为全局规则时，只有 multi 用自己的字段把起点提前 —— v1.5.65。）

二、一回合是怎么走完的N2 / N3 / N4

  • 同时选招：所有人各自选一个技能 + 目标（架势/自增益类无目标），然后统一结算。
  • 按优先级分层结算：优先级 5 → 4 → 3 → 2 → 1，同优先级 = 同时结算（层入口对全场行动拍快照，层内一律按快照判定，最后统一落地"作废"与伤害）。
  • 相抵只在"互为目标"时成立：A→B 与 B→A 同优先级 ⇒ 二者都作废；高优先级压制低优先级同样只在互为目标时成立。 所以"两家同时打同一个第三人"→ 两击都落地，不会互相抵消。攻击相抵意义上的环（A→B→C→A）按逐边处理，不做整环无效化（N4）——但三家小雷连成环是另一条规则，见第四节。
  • 目标规则：攻击/负面技能必须指定目标；死者不能被指定为目标；目标在本回合中途死亡时，尚未结算的攻击落空（不转移）。双枪射手要指定两个不同目标。
  • 回合末统一判定：死亡、挑衅义务、符咒老化、禁用递减。
  • 胜负：最后一名存活者获胜；同一回合全员死亡算平局（例外见第四节"回魂"）。打到回合上限则比剩余血量，并列才是平局。 全员同时倒下（收缩最容易造成这种场）不自动平局，而是取累计造成伤害最多者胜、并列才平局（v1.5.65：否则"谁都没打过人"也能被判胜，龟着拖是免费的）。 N12 / resolve.js 的 checkOver

三、技能表30 张，其中 3 张多人专用

"费用"的单位是 ジ（能量），"目标"这一列引擎只对 self 分支（其余都必须指定别人）。费用里的 — 不是免费，而是这张牌的费用不是固定数（聚能环 / 过载炮 / 激光眼 这三张按"第几次用它"变价，条件写在"作用"那一列）。 除能量还要蓄能珠的牌会在费用格里标出来（珠由"蓄能"产生：电/爆自选、只保留到下一回合、同类最多 1 枚）。 other 这个目标值全表只有全息屏障一张在用，它是"这张牌的受益者是别人"的标记（v1.5.34 曾把它误做成"自己"，历史读数因此作废）。 标注"多人专用"的三张（双枪射手 / 镜面反射 / 全息屏障）在 2 人桌上不可用：D226④ 逐血量格（standard / multi4 / long）各判两件事 —— canUseSkillInMode 说它不可用、且 UI 赖以画图的 Play.legalActions 那张合法表里也不出现它（"牌亮着而引擎拒"是明令要防的分裂）， 另带"5 人局三张全亮"的正对照。

四、常见问答

Q：小雷（雷击之枪）到底挡的是什么？
它无效化目标本回合的"攻击类"行动，不阻止防御/架势；互用小雷（A↔B 互指）则双方该行动都作废。 三家连成环（A→B→C→A）不是"各自成立"：v1.5.138 起在指向图上游走找到环，环上成员整体作废（发一条 thunderRing 事件）， 不打不成环的链仍按座位序逐边结算。另外最基础的防御、反弹、原型制御不吃小雷（豁免名单见 MINI_T_IMMUNE）。 N5（该节"按 pid 升序逐条结算"那句是 v1.5.138 之前的旧口径，本页按引擎现状写）；代价 2 ジ
Q：大雷（真正的落雷）为什么是这游戏最重的一张？
5 ジ，对目标 2 点电伤 + 把它正在用的那个技能禁用（基数 4 回合）+ 非防御类技能无效化；目标若当回合出防御类，2 电可以全挡。 还有连带伤害：与本回合和目标发生过交互的第三方，吃与直击同口径的 2 点电伤、行动同样作废、禁用 3 回合（施法者自己不参与连带，否则等于自伤）。 N6 / N22 —— 早期文案写"连带 1 点"，与代码不符，已按裁定以代码为准（维持 2 点）
Q：全息屏障是给自己套的盾吗？
不是，它是"给别人套的盾"：目标必须是其他玩家，被套者当回合获得"原型制御"式架势（挡技能伤、≥3 点伤害各自转移给作用者、小雷豁免，但大雷的 3 回合禁用照旧）。 想拆掉这张盾，得去打施放者——屏障这个动作本身不在小雷豁免名单里。 N7（v1.5.4 修正；旧的"只护自己"语义下的全部历史读数已作废）
Q：反弹能把大雷弹回去吗？
雷电不被反弹；防御 / 金刚盾 / 原型制御可以挡。反弹族真正反弹的是"技能伤害"这一类。 N6 / N14（镜面反射，多人专用）
Q：挑衅有什么强制力？
被挑衅者下回合必须使出一个"算被满足"的攻击类技能（名单就是 TAUNT_SATISFY：枪 / 剑 / 坦克 / 狙击 / 摄魂 / 磁轨 / 加农 / 激光眼 / 双枪）， 否则回合末扣 1 血。多人桌上可以同时压多个目标，各自独立结算义务。它是少数能改变别人出招的一张。 N10（TAUNT_SATISFY 是唯一来源，页面、引擎与门禁共用同一份名单）
Q：铁索连环连环住之后会怎样？
先说怎么连上：同一回合互相使用摄魂指法的一对玩家之间建立一条边（多人下链条是一张图，不是固定串）。 连上之后任一环上者受伤，与它直接相连的其他玩家各受同量同类型伤害，且不递归（连环伤害不再触发下一跳）。 最要紧的一条：这条边是一次性的 —— 共享过一次后两侧立刻同时解除，要再连必须重新互勾一次摄魂。它曾被实现成"只有死亡才解除"的持久光环，v1.5.18 按原文改回。 N9；守门 np-test N8 + D30（走真实摄魂路径，不是手搓事件）
Q：地雷在多人桌上是 AoE 吗？
是，而且分两种触发：直接触发（雷被攻击引爆）这一波没有次数上限，持有者自己被攻击的伤害照常结算； 因吃到地雷伤害而引爆自己已装雷的属于间接触发，同一波里所有间接触发合并为 1 次伤害，且这一下不打各个间接触发者的雷。 两个人都装了雷时会出现不对称：持雷者各受 1 点、非持雷者受 2 点。另有三条豁免：狙击枪那一次攻击不引爆该雷（只豁免那一次）、 火弱（藤甲 debuff）只让挂了它的目标 +1、而且地雷伤害没有来源（source = null）⇒ 不被铁索共享、不被转移伤害转移、不被大雷传导。 N20；"无来源"这一条 v1.7.66 才真正落到链闸门上并补了牙（此前只在文档里成立）
Q：激光眼能不能一发废掉一整套防御？
能。旧实现要求两个激光眼才能破原型制御/全息屏障，用户裁定把它改成单个激光眼即可失效所有防御类 + 转移伤害 （判据只剩"目标行动属于 GUARD_FAMILY"一个分支，原来的 laserNoEffect 成死代码已清）。 反过来别忘了上一条：小雷打不动最基础的防御、反弹、原型制御 —— 这两张反制的覆盖面不一样。 N23（用户裁定 2026-09-11）
Q：打到回合上限怎么办？
不再是"硬截断"，而是终局收缩：过了收缩起点之后，每回合末每个存活玩家各扣 1 血，把"龟着不出手"变成一条会死的路线；硬上限只作安全网。 起点按模式配置（各格读数见第一节那张表：多人 3/4 血自带 45，长程走全局 100、安全网 140）。 三处细节值得知道：收缩不挡（防御 / 反弹 / 原型制御 / 金刚盾 / 全息都拦不住它，因为它不是攻击）、不引爆地雷、 而且没有来源（source = null）⇒ 它不计入任何人的"造成伤害"，所以"靠收缩熬死全场"不会把你抬成那个"累计伤害最多者"。 N25（用户裁定 2026-09-12 + v1.5.10 把它从 long 专属升级为全局规则）；守门 D19
Q："回魂"复活的当回合能立刻放技能吗？
先说它怎么触发：只有挑衅的施放者在本回合末死亡才会回魂（下回合以 1 HP 复活、当回合一切花费为 0、回合结束立即死亡）； 被挑衅的那一个若死了不会复活，反而给施放者挂上梦魇。 复活回合只免"花费"，不免"条件"：省能量的照省，但需要前置状态（珠子 / 时机 / 目标）的技能仍然要满足条件才放得出来 —— v1.5.166 追一个摄魂 bug 时在这里找到三处"无限能量"短路，逐处删掉了。 还有个少见的边界：回合结算后全员 HP ≤ 0，但其中一人挂着回魂（尚未确认死亡）⇒ 判他胜，不算平局（实测约 2/1500 局，此时你会看到"你赢了"而血量显示 0）。 R48（docs/RULES-2P.md §回魂"一切花费为 0"；守门 D126）‖ 边界裁定 N12（2026-09-10 补）
Q：为什么同一招连用会被看穿？
桌面状态里带着最近若干步的出招历史，AI 的特征向量里有它；连用同一张牌会让"读招反制"那一类脚本对手命中反制。 这也是"随机性"被留在探索层、而不是留在结算层的原因。

五、难度档一根轴：同一颗冠军包上的探索剂量

难度不是"换一批发度的对手"，而是同一颗冠军包上改它的探索剂量（ε / 抽牌温度 / 是否带退火斜坡），所以全人数共用一条阶梯，档位含义可迁移。 N27（js/train/bots.js 的 DIFF_TIERS 是唯一来源，页面与量具都读它）

  • 剂量之外还换了牌桌：弱档从 champion-map/pool-members.tsv 的 soft 带抽、困难档从 hard 带抽（"带"是池表里的字段，不是另一批人）；简单档还会掺几席脚本对手，掺的是"多见几张牌"而不是难度。
  • 2 人桌换一颗冠军包：人数 = 2 用 2P 那颗（v1.0 为 1v1 训的），≥3 人用多人那颗。理由是实测不是传统 —— 拿多人那颗跑 1v1，人类替身夺冠 27.5%，用 2P 那颗只有 15.5%（数字越大对手越软），而且剂量梯反号（ε=0 那格比 ε=0.5 还软）⇒ 用它当"困难"是个假档。 N27 第 2 条
  • 下面那张风格表不排强度：v1.6.6 起"风格即档位"这句话作废，风格只是口味。依据是 §E286（tools/probe-diff-ladder.mjs，1500 局/格、同一批种子跨格配对）—— 四个风格在 5 人桌上统计上并列，而换一个桌形排名就重排（"激进快攻"5 人桌最硬、3 人桌掉到中游；"憋大招"反之）⇒ 强度是桌形的函数，不是它的属性。
  • 这一节两张表都直接读代码现状。要提醒一句：docs/RULES-NP.md 的 N27 那一节还写着它 2026-10-03 落笔时的五档阶梯（含"入门"和"极限 · 读招"）—— 那两档后来被合掉了（同带改剂量量不出台阶），"极限 · 读招"回到了风格组。以本页读到的 DIFF_TIERS 为准。

六、AI 看得见什么、看不见什么公开它的短板比藏起来有用

  • 常规桌面事实（各家血量/能量/珠子、上回合行动、防御与架势状态、威胁与穿透、回合数等）都在它的输入里，而且改动这些事实确实会让它换招。
  • 对手的能量/新珠这类"手牌信息"故意不给（早期版本泄漏过座位身份，被明确修掉了）⇒ 它不许靠读牌打。
  • 已知的一条真短板，有数也有对照：在配对的合成桌上把"某个存活对手正连着开聚能环"这一格摆出来（两个世界只差这一枚事实，且两边都付得起小雷才进分母）， 冠军确实读它 —— 74.3% 的桌子会因它换招，而"对手能量"那一维的换招率是 0%（说明它不是"数字一动就乱换"）； 但它换出来的那一手，400 副里一次都不是小雷打断。换一枚本来就"会攒钱"的包复跑，换招率掉到 25.0%、方向仍是 +0.0pt。 ⇒ 缺口既不在看不见、也不在"不会因环境改行为"，而在那一支动作根本不在它的选择集里。这是训练目标的问题，不是感知的问题。
