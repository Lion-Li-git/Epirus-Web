# 拍手游戏 Epirus — 2~5 人 × 3/4/5 血 对战（网页）

依据国际拍手游戏规则制定协会的规则（[原仓库 Lion-LiHaoyi/Epirus](https://github.com/Lion-LiHaoyi/Epirus)，规则文档 v2.1.0）
重新实现的一整套 **2 人可玩、可自对战训练** 程序。

> **当前版本：v1.7.5** · **人数 2~5 × 血量 3/4/5 两根正交轴**（2 人那一档规则仍冻结在 v1.0.0）+ **全人数共用一条难度阶梯** + **技能齐全 · AI 状态特征 v7，FEAT_S=213**；规则见 `docs/RULES-2P.md` / `docs/RULES-NP.md`（血量轴见 NP 的 **N26**，难度阶梯见 **N27**）。
>
> ⚠️ 本文件**只留当前版本**：逐版改动、实测数字与门号**只记在** [`CHANGELOG.md`](CHANGELOG.md)（README 不是账本 —— 这里此前抄过四次、漂过四次，最长那次落后 63 条门）。
> ⚠️ **老用户要点页面「用内置冠军」才会换到新包**（本机包优先：`localStorage['epirus.champion']` = 2P ‖ `['epirus.champion3p']` = 多人）。
> ⚠️ 而且**只要本机包在场，冠军池整桌不生效**（判定只在一处：`js/ui/ui.js` 的 `poolPlan`，它会连带把席位标签一起改掉 ⇒ 不会出现"标签说池在跑、实际用你那枚"）—— 想打「每席随机抽一枚冠军」的桌子，先把本机包清掉。

- **游戏部分零依赖、纯静态**：双击 `index.html` 即可游玩，不需要装任何东西、不需要联网。
- **训练部分可选**：另起一个 Node 服务（只用内置模块 `http` / `worker_threads` / `vm`），用于练出"冠军 AI"。

## 快速开始

1. 双击 `index.html`（推荐 Chrome / Edge）。
2. 默认「标准模式 + 中等难度」直接开打：点技能出招，双方同时行动，回合日志逐条结算。
   技能按钮按当前资源实时置灰——**ジ/珠子不足或条件不满足的技能直接不可点**（不会"点了才提示无效"）。
3. 想打"练出来的 AI"：双击 `tools/start-train-server.cmd` 启动训练服务 → 训练场点「开始训练(Node服务)」→
   页面自动连接、实时显示进度与多条种子曲线 → 训练完冠军自动写进内置文件并载入内存 →
   把对局难度切到「困难 · 冠军」即可与冠军对战。⚠️ 走这条路之后，**本机包会压过冠军池**（见上面那条 ⚠️）。
4. 冠军策略可「导出 JSON」分享给朋友，「导入」别人的冠军。

## 功能

### 对局

- **人数 2~5 × 血量 3/4/5 是两根独立的轴**（v1.6.5 起；2 人 · 3 血那一格 = 标准模式，v1.0.0 冻结）· 27 个可用技能（卡表共 30 张，其中 3 张多人专用 ⇒ **人数到 2 时按"当前存活人数"自动置灰**，`alive<=2` 就不可点）。
- **难度是一条全人数共用的阶梯**（v1.6.6 起；档表只有一份：`js/train/bots.js` 的 `DIFF_TIERS`，页面下拉由它生成 ⇒ 本文件不抄档位措辞）。三档 = 简单 · 陪练 ‖ 普通（默认）‖ 困难 · 冠军，两根正交的轴：
  ① **探索剂量**（ε / epsK / 前几回合斜坡，形状的唯一来源是 `tierEps`）；② **桌上是谁**：AI 席**逐席各抽一枚冠军**（多人池 `js/bundled-champion-pool.js` ‖ 2P 原生池 `js/bundled-champion-pool-2p.js`；v1.6.66 起 2 人桌也走池，但走的是 2P 那一份而不是把 3P 搬到 1v1），
  允许重复、不许整桌同枚；装配 / 抽签 / 降级的规矩写在 `docs/POOL-CONTRACT.md`，页面、量具与门 `D234` 都对齐那一份契约。
  简单档另外**掺脚本席**（`scriptMix` ⇒ 掺几席、掺谁的推导只在一处：`js/pool-draw.js` 的 `scriptSeats`）。
- 脚本人格共 6 个（`EpirusBots.STYLES`）。其中「杂货铺」自 v1.6.69 起带一条**计划层**（攒钱 ‖ 连开聚能环 ‖ 挑目标的大雷 ‖ 贴贴窗口 ‖ 过载炮三档花费 ‖ 看威胁用避雷针），是阶梯里唯一按显式逻辑推理出招的席。
- HP（含 0.5 血）、ジ、电/爆能量珠、地雷/符咒/挑衅/梦魇/回魂等状态全部可见；技能按钮悬停显示手势与说明。
- 「悔一步」可退回本回合开始前（每局限用一次）；可导出对局记录。

### 训练场

- 轻量对抗自对战（类 GAN 的对抗思想，零 AI 框架）：候选策略群每代与「当前冠军 + 脚本基准群」对战打分。
  **基准名单有两处真源，本文件不抄第二份**：2P 那侧是 `js/train/evo.js` 的 `buildOpps`（1 枚冠军 + 19 条脚本基准），
  多人那侧是 `server/opp-pool.mjs` 的 `OPP_SPECS`（**默认只取前 9 条**，其余是专项压迫线，只在显式实验里按名字加入 ⇒ 别照名单数"训练时桌上有几个对手"）。
- 2P 基准包含：连招反制、破防、防御墙、永久架势（反弹/防御/八卦）、**坦克线 / 重火力 / 防御+枪三拍**（人类式硬门槛）、**原型制御墙**、**空放型**、**三条节奏型**（反弹→枪→坦克 / 反弹→反弹→坦克 / 防御→反弹→枪）、**珠爆发**。
- 精英保留 + 变异/交叉繁殖；适应度 = 胜负 + 换血 + 拖时长惩罚 + **出招多样性（熵）奖励**。
- **冠军按真实胜率挑选**：任一基准不高于 50% 直接失去冠军资格（纯平局 0.5 也不过门），过门后按 `0.5×平均 + 0.5×最差对局` 排序；
  **另有一层"不回归"**（v1.5.130，`tools/pick-best.mjs`）：把**现有冠军已过的**基准打回 ≤50% 的候选**一律不许当选**
  —— 否则"修一个新洞、开两个旧洞"会被择优当成最优（v1.5.130 实测反例：avg 89%→85%、`defend`/`reflectspam` 双双重归 0%）。
- 训练在 **Node 多核并行**（`worker_threads`）上跑，页面 SSE 实时进度 + 多条种子曲线（y 轴自适应，最优分可 >1）。
- 多种子 × 多轮 + 种子谱系：轮末保留前 ⌈√n⌉ 名作父代，再按"越靠前分得越多"分配 n 个新种子
  （n=3→2+1，n=4→2+2，n=5→2+2+1，n=8→3+3+2）；「从头训练」只在**第一轮**清空旧冠军。
- 导出训练 CSV 为**标准长表**：`round,global_gen,gen,seed_id,parent_seed_id,best,baseline,champAge,champChanged,sigma`，
  行序严格 `[round] → [seed_id] → [gen]`，可直接做折线图。

### 规则完整性

- **蓄能珠只供下一回合**：蓄能获得的能量珠仅可在下一回合使用，该回合结束时未使用即清空（原规则"累计一个单位…供给下一回合"；
  早期实现误判为"可无限累加"，会让 AI 囤珠失衡）。同回合重复蓄能只刷新，不叠加。

- 2 人可用的 27 个技能（30 张卡 − 多人专用 3 张：双枪射手/镜面反射/全息屏障，见 `docs/RULES-2P.md` v1.5.7 条）+ 4 个隐藏技能（铁索连环 / 吸血鬼公爵 / 回魂 / 梦魇——不是可点的卡，是结算触发）全部实现。

## 规则裁定说明

原规则文档面向真人手势对局（及 3 人以上场景），存在若干未写死的细节（如判定概率、蓄能珠时效、

## 训练（Node 并行）

```bash
node tools/train-fast.mjs 500          # 500 代：本机 10-13 实测 123.5s ‖ 128.5s（同 seed 两跑**不等价** ⇒ 它不可复现，别拿它做配对实验）
                                       #   ⚠ 默认**不碰内置包**：产物落 `docs/artifacts/train-fast-out.js`；只有 `EPIRUS_PUBLISH=1` 才写 `js/bundled-champion.js`
node tools/train-best.mjs 4 600        # 4 个候选择优（推荐；2P 那颗内置包的 META 自报"3 候选择优，500 代，总 541s"）
```

- 跨候选与轮末择优**同口径**：任一基准不高于 50% 直接失去冠军资格，过门后按 `0.5×平均 + 0.5×最差对局` 排序。
- **评测口径与实战一致**：`js/core/play.js` 的 `autoGame` 中双方都基于"行动前状态"决策
  （旧实现是"先手已落子再问后手"，会让训练/评测数字与页面手感产生系统性偏差）。
- **绝不空放（贷款兜底）**：`autoGame` 对任何脚本/AI 返回的"买不起或条件不满足"的招一律兜底改按ジ——
  否则招式作废会让对手 `lastSkill=null`，值网络掉进未训练区（曾出现"对手每回合空放 → 冠军 100% 拖成 60 回合平局、出招锁死 ジ↔贴贴"）。
  同时 `policy.js` 给 `lastSkill` 补了两位显式"上一招无效"特征（原先 `idxOf(null)===0` 与"上一招是ジ"同码），
  并把 `whiff` 空放型对手放进池里让它真的见过这个状态（该对手带 `whiffOk` 标记，是唯一被兜底放行的）。
- **连招反制训练（无运行时连招防护）**：池内 `combocounter` 脚本会读对手最近 5 次出招、预测其最常用招并选克制技
  （枪→反弹、坦克→狙击、防御架势→坦克、电系→防御等），模拟"正常对局里明显连招会被对手针对"。
  因此游戏内**不再使用运行时连招防护**——困难档直接用冠军策略（`P.choose(temp 0.15)`），
  游戏口径与训练口径完全一致，AI 靠训练学会"别被看穿"。

### ② 两张贵卡：大雷与摄魂

**结论先说**：训练侧（奖励 / 示范 / 世界 / 选人 / 承接体 / 教师标签，共十一条便宜路）、费用表（把大雷降到 2~4 珠）、
部署层（强制注入与"提顺位"两种机制）在 10-02 夜到 10-03 午全都量过（逐条见 CHANGELOG 的 v1.5.32x~v1.5.33x），结果是：

- **大雷在任何剂量、任何机制下都不赚钱** —— 最温和的软档仍 **−1.0 ~ −1.6pt**。
- **摄魂只在"自己 `HP≤1` 且 3 血桌"这一格为正** —— **+1.39 ±0.26**，换一批桌子 **+1.26**。
- **要不要为这 +1.4pt 换代**（动 `js/train/policy.js` ⇒ 规则指纹 + 两槽重测）：**当前答案是不值**。
  天花板已实测：概率下界从 0.6 抬到 1.0 只多 **+0.18 ‖ +0.05pt**。

**玩家多久看见一次**（剂量不由常数决定，由"这一席装的是什么"决定）。

### ③ 三个没修的洞

1. **对"开环的人"零反应**（用户 19 回合实测）：对手连开 9 回合聚能环把 ジ 刷到 +3/回合，
   四个冠军座位没有一次用小雷/攻击惩罚。根因是**训练池里没有环流对手**（`ringspam` 只作 `?opps=` 旋钮），
   且环在 3 血赛程里回不了本。
   ⇒ v1.6.69 之后**简单档桌上的脚本席自己会连开环**（计划层 P1），但这一格判的是**冠军**会不会惩罚，**没修**。
   池装配模拟里聚能环 **简单 0.54 ‖ 普通 3.18 ‖ 困难 1.79 次/局** ⇒ 三档都会开环；要复现"冠军不惩罚开环的人"得专门去连开环。
2. **贴贴 × 天火在 3 血下算术锁死**（符咒 `age≤3` vs 铺符速率）⇒ 冠军会互相贴符咒，但从不引爆。
   10-13 又量到同一堵墙的**脚本侧版本**：那只脚本的珠在真装配里 P95 只有 2，所以她给的 3/5/7 珠门槛原本一条都够不到
   （读数与复跑命令见 `docs/research/CARD-VALUE-2026-10-13.md` §8-b）。
   池装配模拟里：贴贴 **简单 0.58 / 普通 0 / 困难 0** 次/局（简单档那 0.58 是脚本席打出来的）‖ 天火 **简单 0.03 / 普通 0 / 困难 0**
   ⇒ **冠军席（普通 / 困难）在真装配下连"铺符"都不发生**，不只是"不引爆"。
3. **原型制御墙只能靠地雷 / 转移绕过**，冠军目前是**硬打过去**，不是"会用解法"。
   「为什么学不会」在 v1.6.68 查到尽头：不是没接线，而是它在候选里**从未进过前 3**（同 §5-d）——
   这条洞因此**不是训练调参能补的**，要不要为它动产品还挂在她那里（待裁 #12，见 `docs/research/logs/2026-10-12-incumbent-realtime-soup-qoder.md`）。
   池装配模拟里原型制御 **简单 0.64 / 普通 0 / 困难 0.00** 次/局 ⇒ 只有**简单档的脚本席**会用它，冠军席一次都没用，与那 8,697 次"从未进前 3"同向。
